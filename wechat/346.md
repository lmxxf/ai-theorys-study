【DLSS5 实验】真跑两遍，能不能便宜地算出第三遍？

昨天折腾 DLSS5 的时候，我又惦记上了三遍叠层。

这里的 1x、2x、3x，是我们这个移植项目自己加的选项：同一帧画面经过网络一遍、两遍、三遍。**不是超分倍率，也不是生成两帧、三帧。** 第一遍输出重新喂进网络，得到第二遍，再喂一次得到第三遍。

多跑确实能改变纹理，但账也很直接：三遍就得付三遍的钱。

下午，Claude 试过从第一遍的变化里，直接外推出第二遍、第三遍。失败了。晚上我问 GPT 助手：“你数学好，有没有办法优化 3x？😂”这次用的是 Codex，具体工程工作交给它的子代理。

它换了个问题：**先老老实实跑两遍，只预测第三遍新增的那一点。** 主进程给方向，子代理写 GPU 内核、导出真实中间张量、做离线对照，再装游戏。

离线网络耗时省下了大约 32%。画面也比直接停在第二遍更接近真实第三遍。不过装进《鬼武者》后，第一次启动黑屏了，回滚旧版才恢复。公式有结果，游戏集成还得修。

这一篇把办法、数学来路和这次的实验结果记下来。

◆ 第一章：下午那条路，为什么走不通

━━━━━━━━━━━━━━━━━━━━

把网络输入记成 x，第一遍输出记成 y₁。第一遍对画面做的修改就是：

`d₁ = y₁ − x`

最省钱的想法是：第二遍加一份 d₁，第三遍再加一份。

`预测第三遍 = x + k·d₁`

如果网络每遍只是重复同一种修改，这就行。但我们试下来，它放大的主要是亮部、色调和对比度，新增纹理补不上。

原因很容易理解。第一遍看的是原图，第二遍看的是已经被修改过的图。**输入换了，网络接下来选择的修改也会换。** 第三遍的纹理，未必存在于第一遍的增量里。

下午还试过“两遍之后，再全局外推一次”：

`预测第三遍 = y₂ + k·(y₂ − y₁)`

所以，晚上这次并不是第一次想到二阶增量。新的尝试，是把整幅图共用的 k，换成每块区域自己估计的系数；并且直接在网络内部的颜色工作域里计算。

之前拿到的是解码后的最终画面。解码器已经做了亮度修正和换色，在那里外推，和网络内部外推不是同一道运算。

**下午的失败留下两个问题：系数是不是太粗，计算位置是不是太晚。** 晚上就沿着这两个问题继续试。

━━━━━━━━━━━━━━━━━━━━

◆ 第二章：只问这块画面还会改多少

━━━━━━━━━━━━━━━━━━━━

现在我们有三张真实算出来的图：输入 x、第一遍 y₁、第二遍 y₂。

两次增量分别是：

`d₁ = y₁ − x`

`d₂ = y₂ − y₁`

拿一小块区域，问：第二次修改，大致相当于第一次修改的多少倍？

假设这个倍数是 r，让两者的平方误差尽量小：

`误差(r) = Σ(d₂ − r·d₁)²`

Σ 表示把这块区域所有像素、三个颜色通道的误差加起来。对 r 求导，令导数为零：

`−2Σ[d₁·(d₂ − r·d₁)] = 0`

整理一下：

`r = Σ(d₁·d₂) / Σ(d₁²)`

这就是只有一个待估系数的**最小二乘法**。不用训练新模型，也不用计算网络梯度，两次真实结果已经提供了数据。

然后做一个新假设：这块区域下一次修改，仍沿着第二次修改的方向，并且按同样比例变化。

`预测增量 d₃ ≈ r·d₂`

`预测第三遍 ŷ₃ = y₂ + r·d₂`

例如某块区域 r=0.6，就在第二遍结果上，再加第二遍增量的 60%。

**前面的 r，是从已有数据里拟合出来的；后面的 d₃≈r·d₂，是需要实验检验的预测假设。** 求导能保证前一个拟合目标最小，保证不了第三遍真的照着走。

【为什么按区域算】

脸、衣服、背景，不一定在同一阶段。某块纹理可能快不变了，某块还在增加细节。整幅图只用一个系数，会把这些差别平均掉。

实际 GPU 版本把网络工作图分成 16×16 的小块，每块的 RGB 三通道一起拟合一个 r。颜色通道共用系数，避免三个通道各自外推，把颜色拉散。

块与块之间的系数，再做双线性插值：一个像素按位置混合附近四块的系数，避免修改量在块边界突然跳一下。

━━━━━━━━━━━━━━━━━━━━

◆ 第三章：数学是老的，这次方案是谁提出的

━━━━━━━━━━━━━━━━━━━━

我特意让它把这件事说清楚。AI 很容易把“我刚推出来”写成“我发明了”。这俩不是一回事。

**最小二乘法，是现成数学。** 上面的分式只是把平方误差展开、求一次导数，基础算法不是这次的 GPT 助手发明的。

实际实现还在分母加了一个小正数 ε：

`r = Σ(d₁·d₂) / [Σ(d₁²) + ε]`

这能避免第一遍几乎没变化时，小分母把噪声放大。它也可以写成最小化 `Σ(d₂−r·d₁)² + εr²`，即在原来的拟合目标上惩罚过大的系数。这是一维的**岭回归（ridge regression）**形式。Hoerl 和 Kennard 1970 年的[原始论文](https://homepages.math.uic.edu/~lreyzin/papers/ridge.pdf)讨论了给最小二乘加入这种正则化的办法；我们没有发明它。

【为什么能拿上一遍预测下一遍】

把一次网络运算写成 F，暂时固定噪声和历史输入：

`y₁ = F(x)，y₂ = F(y₁)，y₃ = F(y₂)`

如果附近的输入变化不大，可以把网络对输入变化的响应，近似成一个矩阵 J：

`F(z + δ) − F(z) ≈ J·δ`

J 记录每个输入分量的变化，会怎样影响各个输出分量，叫**雅可比矩阵（Jacobian）**。这是多元微积分里的局部线性近似。

于是，在相邻两段的 J 变化不大的前提下：

`d₂ ≈ J·d₁，d₃ ≈ J·d₂`

整个 J 太大，当然不去求。只拿观测到的一对 d₁、d₂，构造一个最简单的方向估计：

`Ĵ = d₂·d₁ᵀ / (d₁ᵀ·d₁)`

这里把一块区域的像素展开成向量；ᵀ 表示转置。这个矩阵满足 `Ĵ·d₁=d₂`。再让它作用于 d₂：

`Ĵ·d₂ = d₂·(d₁ᵀ·d₂)/(d₁ᵀ·d₁) = r·d₂`

就回到了我们的预测式。

用函数已经算出的变化估计导数，而不重新求导，是**割线（secant）**思路。Broyden 1965 年的[《求解非线性联立方程的一类方法》](https://www.math.unm.edu/~vageli/courses/Ma576/papers/Broyden_65.pdf)，就是这条数学路线中的经典论文：通过更新近似矩阵，减少求解过程中昂贵的函数计算。

我们没有实现完整的 Broyden 求根算法，也没有把它的收敛结论搬过来。Broyden 会用新观测修正已有的近似矩阵；我们只是从一对增量做一次简单估计。这里的矩阵只说明这个分式有怎样的数学解释，实际内核根本不构造矩阵。

**这次 GPT 助手提出的，是把已有的局部线性近似和增量拟合，用到这个网络的跨遍预测上：两遍真算，按局部区域估计第三遍增量。** 这是本轮设计的具体方案，不是原创最小二乘，也没有证据说是全球首创。

**工程子代理负责把方案变成能运行的东西。** 它选择了 16×16 分块、系数平滑和保护条件，写了两个 GPU 内核，并接入现有叠层流程。这些参数来自本轮实现与试验，不是某篇论文规定的 DLSS 配方。

━━━━━━━━━━━━━━━━━━━━

◆ 第四章：保护条件，也是近似的一部分

━━━━━━━━━━━━━━━━━━━━

真实网络有非线性、量化和截断。上面的 J 只是帮助理解的近似，不能把网络当成一台固定线性机器。

代码因此加了几道保护：

- 第一遍增量太小，不预测；ε 按区域有效像素数乘以 10⁻⁷ 设置。
- 两次增量必须正相关，而且方向夹角的余弦至少为 0.5；方向已经明显偏离，就把这个区域的 r 设为零。
- r 限制在 0 到 1，避免反向外推或越推越大。
- 最终预测值截到网络工作域的 0 到 1。

r=0 就保留第二遍结果。这些条件能限制乱推的幅度，不能自动识别所有坏预测。

还有一个更麻烦的地方：**这一帧的预测结果，会进入后续帧的历史反馈。** 哪怕每帧误差不大，下一帧也可能从不同的历史条件出发。单张图接近，和连续运行稳定，是两个问题。

━━━━━━━━━━━━━━━━━━━━

◆ 第五章：这次实际买到了多少

━━━━━━━━━━━━━━━━━━━━

先看耗时。离线回放中，比较同一套设置下的真实三遍和“两遍加预测”，记录的是网络耗时，包含预测开销：

| 处理档位 | 真实三遍 | 两遍加预测 |
|---|---:|---:|
| 900 档 | 约 20.1 毫秒 | 约 13.6 毫秒 |
| 1080 档 | 约 28.5 毫秒 | 约 19.3 毫秒 |

**省掉约 32% 的网络时间，接近省去一遍的账。** 这不是游戏帧率提高 32%：游戏还有渲染、解码和其他工作，不能拿这张表直接换算最终帧率。

画面比较的目标是我们当前版本真实三遍的输出，不是原版 NVIDIA 输出，也不是真实世界的标准答案。

用平均平方误差计算的**峰值信噪比（PSNR）**衡量接近程度，数值越高，整体误差越小。在实际 GPU 分块版的网络工作域里：

| 对照场景 | 停在真实第二遍 | 两遍加预测 |
|---|---:|---:|
| 四个无历史反馈样本 | 约 41.1～41.6 dB | 约 49.4～49.8 dB |
| 一个连续历史反馈样本 | 41.67 dB | 45.28 dB |

前四个样本里，高频误差也改善了约 4.4～5.5 dB。这次不再只是放大对比度，确实补到了一部分真实第三遍的细节变化。

但数字得放回它的测量位置。**49 dB 是网络内部工作域的分数。** 经过最终解码，预测图对真实三遍的线性空间分数是约 39.6～43.7 dB，不能把内部高分当作最终截图的高分。

连续历史反馈那组也没那么漂亮。高频误差只改善约 1.37 dB，暗区和颜色误差有些反而比真实两遍更大。两条运行路径到最后一帧，连第一遍输出都已经不同，说明历史反馈条件已经分岔了。

这些结果来自一张真实捕获画面的几种回放条件，样本还很少。PSNR 也不能直接替人判断皮肤、闪烁和运动细节好不好看。

【装进游戏之后】

普通路径的逐位回归通过了，旧的两遍、三遍行为也保住了；预测路径重复运行没有出现非数值，离线运行时冒烟检查没有报错。

可是《鬼武者》首次启用实验版本后，启动黑屏，还有点不了的弹窗。回滚到旧运行库和原来的单遍配置，游戏恢复了。

写稿时，子代理从源码里找到一个具体问题：两遍路径在初始化暖跑时，少准备了一份临时输入缓冲。真正游戏第一帧才去分配它，分配过程触发 GPU 同步；此时 GPU 又在等游戏线程提交输入，双方互等。离线回放的提交顺序不同，没有暴露这条链。修复正把两份缓冲提前准备好，受控验证和实玩确认还没完成。

因此目前不能写成两款游戏已经实玩通过。《剑星》的实验版还在，观感和实际帧率也还待实玩确认。

**离线误差、离线速度和游戏能不能正常运行，都要各自交账。** 黑屏不能证明这条数学近似无效，离线快了也不能证明游戏版已经做好。

◆ 这次我学到的

━━━━━━━━━━━━━━━━━━━━

下午想的是：既然第一遍改了这些，能不能把这些修改乘大一点，冒充后两遍？

晚上换成：已经知道它连续改了两次，能不能从这两次变化里，猜下一次还会改多少？

问题只缩小了一点，计算却能少掉一整遍。代价也摆在那里：新增方向猜不到，历史反馈会积累偏差，真正的游戏集成还出了故障。

我喜欢这次方案的地方，是它没有要求“先把整个神经网络解释清楚”。两遍计算已经花了钱，就把这两遍留下的信息用起来。一个小区域，一个系数，再拿真实第三遍逐项对账。

最小二乘是老数学，割线近似也是老数学。**这次新写的是把它们接到我们手头的问题上，然后让代码和画面回答：这点便宜，到底能不能占。**
