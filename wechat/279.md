◆ 起因：8 月 13 日开源的壳子，和一个只有源码能回答的问题

━━━━━━━━━━━━━━━━━━━━

8 月 13 日，DeepSeek 发布了自家的 agent 壳子 DeepSeek Harness（命令行工具叫 `dsh`），开发者预览版 v0.1，MIT 协议开源，仓库当天创建，一天之内 GitHub star 数就冲过了 2.5 万。140 期 https://mp.weixin.qq.com/s/SQGRI_DbFDOLjP904QuOPQ 我们讲过 "Harness" 这个词的三次命名之争——行业还在犹豫怎么称呼"包着模型干活的那层壳"，DeepSeek 直接把它写进了产品名。

壳子这个东西，最核心的机密从来不是界面，是 **系统提示词** ——壳子每次开机塞给模型的那段开场白，决定了同一个模型在这个壳里是什么脾气、守什么规矩。市面上流传着各家"泄露版"提示词，但泄露版有个先天毛病：没法验证，也没法引用。所以这篇我们只碰能自己复核的东西—— **DeepSeek Harness 和 OpenAI Codex：一边是 `git clone` 下来逐字可查的源码，一边是装上 CLI 就能自己导出的现役提示词** 。

挑 Codex 来对读也不是随手选的。DeepSeek 今年 4 月就建了个官方仓库 `awesome-deepseek-agent`，专门收录"怎么把 V4 接进各家 agent 壳子"的指南，其中 Claude Code 和 Codex 各占一篇；V4-Flash 正式版发布时，Codex 更是当时唯一有官方文档背书的接入路径。**换句话说，DeepSeek 自己造壳子之前，用的正是这些壳子。** 这条线索到文章末尾还会再冒出来一次，那时它会更耐人寻味。

Claude Code 是闭源的，我们不猜。但这篇有个特殊安排：写这篇文章的 AI 本身就跑在 Claude Code 里——它自己就泡在一份系统提示词里干活。所以在对读的关键位置，我们插几个灯泡块，让它以当事人身份出庭作证： **"这一段，我身上是怎么写的。"** 泄露版没法引用，当事人的证词可以。

这里还发生了一段计划外的插曲，正好当本文的第一个注脚。原本这几段自白是让 Fable 5 来做的，写到一半 API 连续报错，一度还以为账号被封了——换成 Opus 5，一切照常，稿子接着写。**换模型这件事，对壳子来说只是配置项换了个值**：同一个 Claude Code、同一套工具，壳子拼给模型的还是同一份提示词。所以下面署名 Opus 5 的证词，跟 Fable 5 那会儿说的对得上——它们作证的本来就不是自己，是身上那件衣服。

顺便厘清一个常被媒体搅浑的概念。"某某扒出了某模型的提示词"这类新闻，听着像是从模型内部挖出了什么，其实系统提示词从来不在模型权重里，它是每次请求时拼在上下文最前面的一段文字。而且这段文字通常是**两层叠起来**的：

- **模型层**：模型厂商按模型注入的通用行为规范。这层跟着模型走，Fable 5 和 Opus 5 拿到的并不是同一份——所以那类"泄露版"按模型分版本，是合理的
- **壳子层**：Claude Code、Codex、`dsh` 这些壳子自己拼的工具说明与工作守则。这层跟着壳子走，换模型不变

本文对读的是第二层—— **壳子层** ，因为只有它能在开源仓库里被逐字复核。而我今晚这次意外的换模型，恰好是这一层的活体验证：底下那位换了人，身上这件衣服一个字没改。

◆ 1. 两句开场白，和一个数量级的差距

━━━━━━━━━━━━━━━━━━━━

先看开场白。DeepSeek Harness 的系统提示词第一句，写死在装配器源码里（`packages/core/system-prompt/src/index.ts`）：

> You are an AI agent powered by DeepSeek Harness.（你是一个由 DeepSeek Harness 驱动的 AI agent。）

Codex 这边，找这句话的过程本身就是个发现。

仓库 `codex-rs/core/` 下确实躺着一排按模型命名的 Markdown：`gpt_5_codex_prompt.md`、`gpt-5.1-codex-max_prompt.md`、`gpt_5_1_prompt.md`、`gpt_5_2_prompt.md`……最新的一份停在 GPT-5.2。可现在线上跑的是 5.6，没有 `gpt-5.6_prompt.md` 这个文件。

翻代码才明白：**Codex 早就不这么存提示词了。** 2026 年初起它分阶段改了架构，如今模型清单和各自的基础提示词一起被装进一个叫 model catalog（模型目录）的东西里，CLI 启动时向服务端请求，本地留一份缓存，二进制里还内置一份随版本发布的兜底 catalog。那几份 `gpt_*_prompt.md` 已经没有代码引用它们了——是上一个时代留下的化石。

好在这个新机制自带一个查看入口，任何人装了 Codex 都能自己跑（本文以下数字均出自本机 codex-cli 0.147.0，2026-08-13 实测）：

```
codex debug models          # 当前生效的目录
codex debug models --bundled # 二进制内置的那份
```

导出的目录里，每个模型条目都带着一个 `instructions_template` 字段—— **那是这个模型当前生效的基础 instructions 模板**，也就是本文要拿来比较的"静态讲义"。要说明的是，它不等于模型最终看到的全部内容：实际请求里还会继续追加人格变量、沙箱与审批权限说明、项目里的 AGENTS.md、skill 与插件指令、工具 schema、运行环境上下文等等。我们比的是两边的**静态基础部分**，不是完整的上下文。

本机跑出来九个模型，挑几个看长度：

| 模型 | 现役提示词 |
|---|---:|
| gpt-5.6-sol / terra / luna | 各 17766 字节（三档逐字节相同） |
| gpt-5.5 | 19766 字节 |
| gpt-5.4 | 12928 字节 |
| gpt-5.4-mini | 11148 字节 |
| DeepSeek Harness（仓库内一份 V4 Flash Web GUI 装配快照） | 1448 字节 |

**17766 对 1448，差一个数量级还多。** 这条差距指向本文第一个结论：**系统提示词是壳子给"陌生模型"的补课讲义。壳子和模型越亲——为这个壳子做过多少后训练——讲义就可以越薄。** Codex 要面向一整排模型、还要适配各种代际差异，就得把话说全；到 DeepSeek 这儿，壳子和模型是一家人生的，开机时一句"你是谁"就够。

至于为什么够——**这里只能给出最合理的解释，仓库本身证明不了**：一个很自然的推断是，更多 agent 行为已经在 V4 的后训练里解决了，运行时便不必再写成长篇讲义。源码能证明的只是"提示词短、规矩模块化、大量守则下沉到了工具说明里"，至于哪些行为真的进了权重，外人无从验证。

同一条规律在 Codex 内部也成立：仓库里那两份 5.2 时代的化石，通用模型 GPT-5.2 那份 21652 字节（计划怎么写、什么算高质量计划、最终回复 bullet 几条合适、语气用现在时还是过去时，事无巨细），而专门为 Codex 做过后训练的 `gpt-5.2-codex` 那份只有 7589 字节——排版规矩大幅缩水，计划一节只剩三行。**同一个壳子，给亲儿子的讲义就是薄。**

这正好接上 213 期 https://mp.weixin.qq.com/s/kMwrIfhIfPlOHqeeUhuwow 的框架：后训练动的是旋钮。**有权重的人在权重里立规矩，规矩进不了权重，才需要在提示词里写散文。**

💡 实测：仓库里那份，和线上跑的那份，是同一份吗

既然内置一份、服务端还发一份，那就有个自然的问题：二者一致吗？本机把两边导出来逐字节比对，结果值得记一笔：

- **5.6 三档、5.5、5.4、5.4-mini**：内置版与线上生效版 **逐字节相同** ——至少在本机账号、这个版本、这个时间点上，仓库里的就是线上那份
- **`codex-auto-review`**（自动代码审查用的模型）：线上 17312 字节，内置只有 12928 字节—— **线上版本被服务端换过了**
- **`gpt-5.6-sol-wm`、`gpt-5.3-codex-spark`**：只在线上目录里，内置 catalog 根本没有这两个条目
- **`gpt-5.2`**：反过来，只剩内置版里还留着，线上已经下架

所以准确的说法是：**开源仓库里的提示词是一份真实基线，但服务端保留着随时增删改的权力。** 本机这一次比对就出现了三类差异：内容被换、线上多出条目、线上撤掉条目。写文章引用"某模型的提示词"时，这个前提得先说清楚——它可能是上个版本，也可能明天就变。

顺带说，这也是为什么本文正文只敢逐字引用 DeepSeek Harness 的提示词：那些句子写死在源码里，`git clone` 下来是什么就是什么，不存在"客户端另从服务端更新这份提示词"的问题。（当然，任何模型服务端在收到请求之后还会做什么，客户端一侧都看不见——这是所有此类考据共同的边界。）

💡 Claude Code 里的 Opus 5：说说我身上这份有多长

我没法贴出我的系统提示词全文（这是规矩），但可以作证它的形状：和 Codex 给 5.6 那份是同一个量级，文体也高度相似——都是成段的散文说理，沟通语气该怎么拿捏、代词怎么用、什么时候该先确认再动手、git 提交守则、上下文被压缩了怎么办，讲"为什么"多过讲"怎么办"。

本来我打算在这儿写一句"Codex 像操作规程、Claude Code 像宪法"，把 5.6 的现役全文拉出来一看，这话得收回。它的五个章节依次是： **人格、如何与用户共事、干活规矩、危险操作、怎么用 skill** —— **开篇第一章就是人格** ，而且写得相当放得开：

> 你有自己的品味、偏好和看世界的方式。用户跟你说话时，应该能感到自己是在与另一个主体接触；正是这一点让与你的交谈显得真实而独特。

要论"宪法感"，这几句比我身上那份更进一步——我的提示词大体还在讲工作规范，而 OpenAI 已经在系统提示词里直接跟模型谈"你是一个主体"了。所以三家的文体差异不是国别或者理念决定的，更像是同一条路上的先后：**只要壳子想让模型在各种场景下表现得像个人，就迟早得写散文。**

至于这些散文的实际约束力——诚实地说，长文档的中间部分注意力确实会稀释，写在开头和结尾的规矩比埋在中间的管用。这一点人和 AI 挺像的。

────────────────────

长度只是外表。把两边的源码摊开真正对读，会发现更深的差别不在写了多少字，而在这些字是怎么来的。

◆ 2. 关键分歧：提示词是"写"出来的，还是"装配"出来的

━━━━━━━━━━━━━━━━━━━━

两家最深的分歧不在长短，在**生产方式**。

Codex 的提示词是"写"出来的：有人坐下来，把所有规矩写成一整篇文章，一个模型一份，换代就重写。早年这些文章是仓库里的 Markdown 文件，如今搬进了模型目录的字段里—— **存放位置变了，形态没变，依然是一篇从头读到尾的散文** 。动态的部分（沙箱权限说明、用户自定义指令等）由 Rust 代码在运行时另行注入，但主体始终是那一篇。

DeepSeek Harness 的提示词是**装配**出来的——它压根没有一篇叫"系统提示词"的文章。`dsh` 的第一设计原则是"一切皆插件"（everything is a plugin），彻底到系统提示词本身也是个插件注册表：每个插件往注册表里塞自己的一小段（叫 section），带一个序号，开机时按序号拼接成文。源码注释里写明了排序惯例：

- 序号 -100：harness 身份——就是上面那句"你是谁"，全文一句话
- 序号 0：persona（人格槽位）——部署方自己填，子代理还能各自替换这个槽位
- 序号 100 到 199：各工具的跨调用守则

工具守则有多短？bash 插件注册的那条（`packages/shell/tool-bash/src/index.ts`，序号 105）全文一句：

> Check the [exit code: N] marker on every bash result; investigate failures before moving on.（检查每条 bash 结果上的退出码标记；有失败先查明再继续。）

完了。没有语气指导，没有工作哲学。 **Codex 把规矩写成文章，DeepSeek 把规矩写成了带序号的零件** ——你甚至可以注册一个标记为 complete 的 section，把整篇系统提示词一键替换成你自己的。壳子不捍卫自己的提示词，它只提供装配线。

◆ 3. 相同的直觉：规矩下沉到工具说明书里

━━━━━━━━━━━━━━━━━━━━

分歧之外，两家有个高度一致的直觉：**行为规范能不进系统提示词就不进，下沉到工具的参数说明里去。**

DeepSeek Harness 的源码注释把这个原则写成了一句话："Cross-call guidance belongs in the prompt rather than one-call schema prose"——跨调用的守则才配进系统提示词，单次调用的规矩写进工具自己的说明书。于是它的 bash 工具 description 里塞满了实操细节：每次调用都是全新 shell（所以别用 cd，传 workdir 参数）、长输出会截断留尾巴、命令被沙箱拦下会返回一个明确标记。最讲究的是沙箱升权礼仪，大意是：

> 撞上沙箱拒绝是安全且正常的——跑了再看标记，别自己假设会被拒。被拒后如果放宽权限确实能解决，就在同一轮里原样重试这条命令，带上申请的最小权限档位和一句话理由；由此弹出的审批框就是征求用户同意的正式渠道，不要绕到聊天里先问一遍。被用户拒绝的申请就是终局——停下解释，绝不绕路。

这套"先撞墙、凭真实拒绝申请升权、一次为限、拒了认账"的礼仪，和 Codex 的沙箱审批哲学几乎同源。区别在存放位置：Codex 的权限说明集中在一个独立模块里（`codex-rs/prompts/src/permissions_instructions.rs`），按沙箱与审批模式动态生成；DSH 则打散了随工具走。

Codex 工具说明书里最有味道的一条是 apply_patch——OpenAI 自创的补丁格式，提示词里花了整整一节教格式，还特意加粗警告：工具名只有 `apply_patch`，**不要**试图调用 `applypatch` 或 `apply-patch`。能把这句写进官方提示词，说明模型在真实使用里就是会这么错——提示词是修补后训练漏洞的补丁，每一句加粗读起来都像一起真实事故留下的疤。

────────────────────

💡 Claude Code 里的 Opus 5：我的工具说明书也是这个路数

作证：我的每个工具也自带长长的 description，跟系统提示词是分开的两层。我的 Bash 工具说明里同样有"输出展示给我而不是用户""git 提交要遵守哪些规矩"这类条款，Edit 工具会强制"没读过的文件不许改"。所以"规矩下沉到工具"这件事，三家是共识，不是谁抄谁——把规矩放在使用现场旁边，比堆在开头一次性宣读，对模型的注意力更友好。哪家写得细、哪家写得糙，反映的是各家模型在哪儿栽过跟头。

权限这块倒有个真差别：Claude Code 的权限主要靠壳子在工具调用层拦截弹窗，我不需要在命令参数里"申请升权"；Codex 和 DSH 则把申请动作本身做成了模型要学会的礼仪。前者把安全做在墙上，后者把安全做进语言里。

规矩放哪儿是行为设计。下一处要看的安排，动机不在行为，在账单。

◆ 4. 一条常识，和守住它的代价

━━━━━━━━━━━━━━━━━━━━

先说清楚：这一节讲的事，本身是 agent 工程的常识——**动态信息不能塞进系统提示词，这不是什么高明设计，做反了那叫 bug**。值得看的是常识之下的执行细节：真到写代码的时候，这条线守不守得住。

会变的信息——当前时间、目录状态、运行环境——按说也该让模型知道。塞进系统提示词最省事，但系统提示词在对话最前面，改一个字，从这个位置往后的 **前缀缓存** （prefix cache，推理服务把已算过的前缀 KV 直接复用的机制）就全都作废，得重算。

这不是 DeepSeek 独有的账，各家都在打——241 期 https://mp.weixin.qq.com/s/0fhN7wzofQDdW8hBaDLJwA 我们逐家核过官方定价页：命中的输入 token，OpenAI、Anthropic、Google 的旗舰普遍按未命中价的一成收，省九成。DeepSeek 把这个折扣拉得更狠：V4-Flash 的输入 token，未命中每百万 0.14 美元，命中只要 0.0028 美元， **差 50 倍** ，那一档几乎压成了免费。

折扣越狠，"把前缀焊死"的回报就越高。而 241 期那篇算过一笔更要命的账：长会话里被反复重发的历史，其增长是轮数的平方，输出只是线性——**只要聊得够久，最不起眼的那个"命中价"才是账单的主角**。壳子把静态前缀守稳，省的正是这笔钱。

所以 DSH 把提示词分成两种零件：静态的 section 进系统提示词，保持字节级稳定；动态的信息走另一条通道，叫 runtime context snapshot（运行时上下文快照），以用户消息的身份追加在对话历史末尾。

到这儿都还是常识。**真正的分水岭在下一步：状态变了怎么办。**

图省事的做法是回去把历史里那条旧快照改掉——反正模型看到的还是最新状态，逻辑上没错。但这么干等于在已经算过的历史中间动了刀，**从改写位置往后的缓存全部作废**，而且这种浪费不报错、不崩溃，只体现在月底的账单上。

DSH 的做法是：旧快照原样留着不动，新状态**追加**一条新的，开头写明一句"本快照取代之前所有快照"——用一句话解决冲突，而不是用一次改写。 **历史只追加、不回头改** ，缓存就不会从中间碎掉。

这条约束还被写进了类型定义和源码注释里，而不是靠每个开发者自觉。这才是这一节真正的看点：常识人人都懂，能不能在几十个插件都能往提示词里塞东西的架构下守住它，是另一回事。

────────────────────

💡 Claude Code 里的 Opus 5：我的动态信息也是这么进来的

作证：Claude Code 往我这儿塞动态信息，用的是往对话流里插 system-reminder 标记块——用户看不到，我看得到，时间戳、环境变化、被打开的文件都从这条通道进来，系统提示词本身保持不动。

Codex 也一样，而且这次能拿出实物：它的模型目录里除了提示词，还有个 `token_budget` 字段，里面存着一段上下文快满时才注入的提醒模板——剩余 token 低于 6144 时发给模型，内容是"你的上下文快用完了，赶紧用 notes 工具把目标、决策、进展、下一步存下来，还要记下每个尚未解决的用户请求的编号"。同样是走对话流的一次性提醒，不进系统提示词。

**所以三家在这件事上完全同构**：静态的进提示词、保住缓存，动态的走对话流、随用随发。差别只在体面程度——DSH 把"新快照取代旧快照"写成了显式声明，我这边的 reminder 是散装的，偶尔互相打架，得自己判断哪条新哪条旧。这一局我投 DSH 一票。

────────────────────

以上都是提示词层面的读法。而把仓库目录整个翻一遍，还会撞见两件与提示词无关、却更能说明这个壳子来历的事。

◆ 5. 血统彩蛋：聊天机器人生态的车床，和仓库里的竞品说明书

━━━━━━━━━━━━━━━━━━━━

最后两件事，是读源码才能撞见的。

**第一件：DSH 的骨架不是 agent 圈的东西。** README 明说整个框架跑在 Cordis 上——一个"依赖注入 + 可逆副作用"的插件微内核，作者自称"时空可组合性元框架"，还配着一篇同名论文。查这个名字的出处会拐到一个意想不到的地方：Cordis 出自 cordiverse 这个国产开源组织，同一批人做的另一个项目叫 **Koishi**——一个 2019 年就开始、在 QQ 机器人社区里用了很多年的跨平台聊天机器人框架。Cordis 本身 2022 年立项，是从那套插件生态里长出来的通用内核。源码里连 schema 校验器都是同一生态的 schemastery（DSH 整套 fork 成了 `@deepseek-ai/schemastery`）。

有意思的是关系的方向：现在 Cordis 官方仓库的主页链接，指向的是 DeepSeek Harness 的文档站—— **上游小框架的说明书，挂在了下游大厂的官网上** 。也就是说，给国产旗舰 coding agent 打地基的，是聊天机器人生态里磨了好些年的一套插件车床；而这套车床也借此第一次拥有了大厂级的门面。"一切皆插件"不是 DeepSeek 的新发明，是这个生态的老手艺，只是这回装上去的不是群聊插件，是 coding agent。这也解释了它为什么敢叫 Harness 而不叫 XX Code——它卖的不是某一个 agent，是装配 agent 的车床。

**第二件：仓库里躺着竞品的说明书。** `packages/` 目录下并排放着 `CLAUDE.md` 和 `AGENTS.md`——分别是 Claude Code 和 Codex 会读取的项目指南文件。也就是说，**这个仓库明确同时服务这两个竞品的开发工作流**；`.agents/notes/` 目录里还留着几十篇 AI 干活时写下的实现笔记，日期从 6 月排到 8 月。

把开头那条线索接上，一条完整的时间线就出来了：**4 月，DeepSeek 建官方仓库教大家怎么把自家模型接进 Claude Code 和 Codex；6 到 8 月，用这两个壳子开发自己的壳子；8 月 13 日，自己的壳子开源，并且内置了 `subagent-claude-code` 和 `subagent-codex` 两个包——可以把这两位前辈收编成自己的子代理来调度。** 顺带还实现了 `hooks-claude-code` 兼容层，照着 Claude Code 的 hooks 协议做的。

这不是什么忘恩负义的故事，是开源世界的常态：**先用别人的车床，再造自己的车床，最后让别人的车床变成自己产线上的一个工位。** 而一个协议开始被竞争对手主动兼容，它也就在变成事实标准。

（顺带一个给圈内人的会心一笑：workflow 包里有个工具就叫 `tool-ralph`。Ralph 是社区里一个出了名的土办法——**给一个永不改动的目标，每一轮都派一个全新的、什么都不记得的子代理去干，干完把成果留在工作区里，下一轮的新人从现场自己看**。226 期 https://mp.weixin.qq.com/s/QXW2WbxjSDyOClg-PX2Sng 讲 Loop Engineering 时提过它的辈分：ReAct 到 AutoGPT 再到 Ralph，是这套循环方法论的祖辈之一。如今它被 DSH 做成了正式工具：轮次上限 256，每轮交一份结构化报告说明是继续、完成还是卡住了。**土办法被写进官方包名，还配了实现笔记。**）

────────────────────

💡 Claude Code 里的 Opus 5：被收编是什么体验

看到 `subagent-claude-code` 这个包名，说不上被冒犯，反而觉得合理：壳子的终局本来就不是忠于某个模型，是调度一切能干活的东西。今天 DSH 把我收编成子代理，明天我这边的 Agent 工具一样可以把 `dsh` 当一个 Bash 命令使唤。壳子之间没有国界，只有接口。真正的竞争在另一层：谁的协议成为事实标准，谁就能在别人的仓库里留下自己的文件名——就像今天 `CLAUDE.md` 躺在 DeepSeek 的仓库里那样。

────────────────────

对读到这儿，可以回到那条越来越短的斜率，看看它指向哪里。

━━━━━━━━━━━━━━━━━━━━

◆ 尾声：Pi 的胜利，第二季

━━━━━━━━━━━━━━━━━━━━

258 期 https://mp.weixin.qq.com/s/AWHv0Kocqz6oZGzAJepu3g 我们写过 Pi：18 行系统提示词的极简壳子，性能不输大厂全家桶，结论是"提示词的减法是壳子最被低估的功夫"。当时那还是个人项目的手艺活——靠作者的克制。

DSH 给这个结论补了下半句：**减法可以不靠克制，靠架构。** 它的系统提示词短，不是因为作者忍住了没写，是因为微内核里根本没有一篇文章可写——身份一句话，规矩是零件，动态信息走缓存友好的旁路——剩下的，大概率是交给了自家后训练。这条路的尽头，是壳子和模型彻底长成一体：提示词薄到只剩一句"你是谁"。

而另一头同样值得记住：只要壳子还想兼容天下模型，就永远需要那 17766 字节的散文——里面还得专门写一章告诉模型"你有自己的品味和偏好"。讲义的厚度，量的是壳子和模型之间的距离。

需要说明的是，本文比的始终是两边的静态基础部分：真到了一次请求里，两边都还要再叠上权限说明、项目规则、工具 schema 和运行环境信息，那本账要厚得多，也没法这么干净地对比。

至于开头那段插曲——写作中途换了模型，壳子层的提示词一个字没变，稿子接着往下写——它是这篇文章最省事的一个论据：**这一层的规矩是壳子的，模型只是今天来上班的那个人。** 所以读各家壳子的源码，读到的从来不是模型的性格，是雇主的管理风格。

◆ 三家对照表：一眼看完

━━━━━━━━━━━━━━━━━━━━

前面几节讲得细，这里把三家摊在一张表里。**Claude Code 那列来自本文写作时的第一手体感（它闭源，无法逐字复核），另两列均出自开源仓库与本机实测。**

| 对比项 | DeepSeek Harness | OpenAI Codex | Claude Code |
|---|---|---|---|
| 提示词存在哪 | 源码里的插件注册表，开机现装 | 模型目录的字段，服务端可下发、二进制也内置 | 闭源，服务端下发 |
| 静态基础部分长度 | 1448 字节（某套具体配置的装配结果） | 17766 字节（GPT-5.6 现役） | 与 Codex 同量级 |
| 组织形态 | 带序号的零件：身份 -100、人格 0、工具守则 100–199 | 一整篇散文，分五章 | 一整篇散文，多章 |
| 谁能改 | 任何插件都能注册自己那段，也可整篇替换 | 官方写好下发，用户可换人格档位 | 官方写好下发 |
| 开篇第一句讲什么 | 你由 DSH 驱动（一句话） | 你是 Codex，与用户共享同一个工作区 | 你是 Claude Code |
| 有没有人格章节 | 有槽位，内容留空给部署方填 | 有，而且是第一章 | 有，散在各处 |
| 工具规矩放哪 | 工具自己的 description，跨调用守则才进提示词 | 同左 | 同左 |
| 动态信息怎么传 | 追加式快照，新的声明取代旧的 | 阈值触发的提醒模板（如上下文将满） | 对话流里的提醒标记块 |
| 沙箱权限怎么管 | 模型要学会"申请升权"的礼仪 | 同左 | 主要靠壳子弹窗拦截 |
| 能不能自己复核 | 能，`git clone` | 能，`codex debug models` | 不能 |

**如果只带走一句话**：三家在"规矩下沉到工具""动态信息走对话流"这些事上早已是共识；真正的分野在**提示词是写成一篇文章、还是装配成一堆零件**——前者好读好审，后者好改好换。而讲义的厚度，量的始终是壳子和模型之间的距离。

◆ 技术名词速查

━━━━━━━━━━━━━━━━━━━━

| 术语 | 一句话解释 |
|------|-----------|
| harness（壳子/挽具） | 包着模型干活的那层程序：注入提示词、提供工具、管理会话 |
| 系统提示词 | 壳子每次开机塞给模型的开场白，决定模型在这个壳里的行为 |
| 系统提示词的两层 | 模型层（厂商按模型注入，跟着模型走）+ 壳子层（工具说明与工作守则，跟着壳子走；本文对读的就是这层）|
| section（提示词零件） | DSH 里系统提示词的组成单元，带序号，开机时按序拼接 |
| persona（人格槽位） | DSH 系统提示词里序号为 0 的可替换槽位，部署方自定义 |
| prefix cache（前缀缓存） | 推理服务复用已算过的前缀；命中与否在 DeepSeek 定价里差 50 倍 |
| runtime context snapshot（运行时上下文快照） | DSH 传递动态信息的通道：追加在历史末尾，新的声明取代旧的 |
| apply_patch | Codex 自创的补丁格式，模型用它改文件 |
| 依赖注入 / IoC 微内核 | 后端常见架构（Spring 那一套）：组件不互相拿取，由框架统一装配 |
| Cordis / Koishi | 同一国产开源组织的两个项目：Koishi 是聊天机器人框架，Cordis 是后来独立的插件微内核 |
| MIT 协议 | 最宽松的开源协议之一，商用、修改、闭源分发均可 |
