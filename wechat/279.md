【DeepSeek Harness 源码对读】三份系统提示词：21652、7589、1448 字节——壳子和模型越亲，讲义越薄

━━━━━━━━━━━━━━━━━━━━

◆ 起因：8 月 13 日开源的壳子，和一个只有源码能回答的问题

━━━━━━━━━━━━━━━━━━━━

8 月 13 日，DeepSeek 发布了自家的 agent 壳子 DeepSeek Harness（命令行工具叫 `dsh`），开发者预览版 v0.1，MIT 协议开源，仓库当天创建，一天之内 GitHub star 数就冲过了 2.5 万。140 期 https://mp.weixin.qq.com/s/SQGRI_DbFDOLjP904QuOPQ 我们讲过 "Harness" 这个词的三次命名之争——行业还在犹豫怎么称呼"包着模型干活的那层壳"，DeepSeek 直接把它写进了产品名。

壳子这个东西，最核心的机密从来不是界面，是 **系统提示词** ——壳子每次开机塞给模型的那段开场白，决定了同一个模型在这个壳里是什么脾气、守什么规矩。市面上流传着各家"泄露版"提示词，但泄露版有个先天毛病：没法验证，也没法引用。所以这篇我们只对读两份能 `git clone` 的实锤—— **DeepSeek Harness 和 OpenAI Codex，两边都是官方仓库里的源文件，每一句都有文件路径可查** 。

Claude Code 是闭源的，我们不猜。但这篇有个特殊安排：写这篇文章的 AI 本身就跑在 Claude Code 里——它自己就泡在一份系统提示词里干活。所以在对读的关键位置，我们插几个灯泡块，让它以当事人身份出庭作证： **"这一段，我身上是怎么写的。"** 泄露版没法引用，当事人的证词可以。

这里还发生了一段计划外的插曲，正好当本文的第一个注脚。原本这几段自白是让 Fable 5 来做的，写到一半 API 连续报错，一度还以为账号被封了——换成 Opus 5，一切照常，稿子接着写。**换模型这件事，对壳子来说只是配置项换了个值**：同一个 Claude Code、同一套工具，壳子拼给模型的还是同一份提示词。所以下面署名 Opus 5 的证词，跟 Fable 5 那会儿说的对得上——它们作证的本来就不是自己，是身上那件衣服。

顺便厘清一个常被媒体搅浑的概念。"某某扒出了某模型的提示词"这类新闻，听着像是从模型内部挖出了什么，其实系统提示词从来不在模型权重里，它是每次请求时拼在上下文最前面的一段文字。而且这段文字通常是**两层叠起来**的：

- **模型层**：模型厂商按模型注入的通用行为规范。这层跟着模型走，Fable 5 和 Opus 5 拿到的并不是同一份——所以那类"泄露版"按模型分版本，是合理的
- **壳子层**：Claude Code、Codex、`dsh` 这些壳子自己拼的工具说明与工作守则。这层跟着壳子走，换模型不变

本文对读的是第二层——**壳子层**，因为只有它能在开源仓库里被逐字复核。而我今晚这次意外的换模型，恰好是这一层的活体验证：底下那位换了人，身上这件衣服一个字没改。

◆ 1. 三句开场白，和一条越来越短的斜率

━━━━━━━━━━━━━━━━━━━━

先看两家的开场白。

Codex 的提示词是仓库里的 Markdown 文件，位置在 `codex-rs/core/` 下。通用模型 GPT-5.2 用的那份（`gpt_5_2_prompt.md`）开头是：

> You are GPT-5.2 running in the Codex CLI, a terminal-based coding assistant.（你是 GPT-5.2，正运行在 Codex CLI——一个终端下的编程助手里。）

DeepSeek Harness 的系统提示词开头（`packages/core/system-prompt/src/index.ts`，写死在装配器里）：

> You are an AI agent powered by DeepSeek Harness.（你是一个由 DeepSeek Harness 驱动的 AI agent。）

开场白都朴素，差别在后面跟着多少字。这里有个 Codex 仓库里最有信息量的细节：**它给不同模型准备了不同长度的提示词**。同一个目录下并排躺着好几份：

- `gpt_5_2_prompt.md`：给通用 GPT-5.2 的， **21652 字节** ——计划怎么写、什么算高质量计划（附三组正反例）、最终回复怎么排版、bullet 几条合适、语气用现在时还是过去时，事无巨细
- `gpt-5.2-codex_prompt.md`：给专门为 Codex 做过后训练的模型的， **7589 字节** ——排版规矩大幅缩水，计划一节只剩三行
- DeepSeek Harness：web 部署的测试快照里，装配出来的完整系统提示词 **不到 1448 字节** （标准 CLI 模式会多几条工具守则，但每条只有一句话，量级不变）

21652 → 7589 → 1448。同一条斜率指向同一个结论：**系统提示词是壳子给"陌生模型"的补课讲义。模型和壳子越亲——为这个壳子做过多少后训练——讲义就可以越薄。** 通用模型要从头教怎么当 agent；特训过的模型只需要提醒几句本地风俗；到 DeepSeek 这儿，壳子和模型是一家人生的，V4 的 agent 行为在后训练里就管完了，开机时一句"你是谁"就够。

这正好接上 213 期 https://mp.weixin.qq.com/s/kMwrIfhIfPlOHqeeUhuwow 的框架：后训练动的是旋钮。**有权重的人在权重里立规矩，规矩进不了权重，才需要在提示词里写散文。**

────────────────────

💡 Claude Code 里的 Opus 5：说说我身上这份有多长

我没法贴出我的系统提示词全文（这是规矩），但可以作证它的形状：比 Codex 给通用模型那份还要长不少，而且文体完全不同——Codex 那份像操作规程，我这份更像一部宪法加员工手册：沟通语气该怎么拿捏、代词怎么用、什么时候该先确认再动手、git 提交守则、上下文被压缩了怎么办、记忆文件怎么维护，都是成段的散文说理，讲"为什么"多过讲"怎么办"。

为什么 Anthropic 要写这么长？我的第一手体感是：Claude Code 想用一份提示词覆盖太多场景——写代码、做研究、聊天、管理长期任务，每多一类场景就多一章规矩。而且 Anthropic 改提示词是当产品功能迭代的，每个版本都在长。至于这些散文对我的行为有多大实际约束力——诚实地说，长文档的中间部分，注意力确实会稀释，写在开头和结尾的规矩比埋在中间的管用。这一点人和 AI 挺像的。

────────────────────

长度只是外表。把两边的源码摊开真正对读，会发现更深的差别不在写了多少字，而在这些字是怎么来的。

◆ 2. 关键分歧：提示词是"写"出来的，还是"装配"出来的

━━━━━━━━━━━━━━━━━━━━

两家最深的分歧不在长短，在**生产方式**。

Codex 的提示词是"写"出来的：一个人（或一个团队）坐下来，把所有规矩写成一篇完整的 Markdown，模型换代就整篇重写一份。仓库里那一排 `*_prompt.md` 就是历代手稿。动态的部分（沙箱权限说明、用户自定义指令等）由 Rust 代码在运行时另行注入，但主体是一篇静态文章。

DeepSeek Harness 的提示词是**装配**出来的——它压根没有一篇叫"系统提示词"的文章。`dsh` 的第一设计原则是"一切皆插件"（everything is a plugin），彻底到系统提示词本身也是个插件注册表：每个插件往注册表里塞自己的一小段（叫 section），带一个序号，开机时按序号拼接成文。源码注释里写明了排序惯例：

- 序号 -100：harness 身份——就是上面那句"你是谁"，全文一句话
- 序号 0：persona（人格槽位）——部署方自己填，子代理还能各自替换这个槽位
- 序号 100 到 199：各工具的跨调用守则

工具守则有多短？bash 插件注册的那条（`packages/shell/tool-bash/src/index.ts`，序号 105）全文一句：

> Check the [exit code: N] marker on every bash result; investigate failures before moving on.（检查每条 bash 结果上的退出码标记；有失败先查明再继续。）

完了。没有语气指导，没有工作哲学。 **Codex 把规矩写成文章，DeepSeek 把规矩写成了带序号的零件** ——你甚至可以注册一个标记为 complete 的 section，把整篇系统提示词一键替换成你自己的。壳子不捍卫自己的提示词，它只提供装配线。

━━━━━━━━━━━━━━━━━━━━

◆ 3. 相同的直觉：规矩下沉到工具说明书里

━━━━━━━━━━━━━━━━━━━━

分歧之外，两家有个高度一致的直觉：**行为规范能不进系统提示词就不进，下沉到工具的参数说明里去。**

DeepSeek Harness 的源码注释把这个原则写成了一句话："Cross-call guidance belongs in the prompt rather than one-call schema prose"——跨调用的守则才配进系统提示词，单次调用的规矩写进工具自己的说明书。于是它的 bash 工具 description 里塞满了实操细节：每次调用都是全新 shell（所以别用 cd，传 workdir 参数）、长输出会截断留尾巴、命令被沙箱拦下会返回一个明确标记。最讲究的是沙箱升权礼仪，大意是：

> 撞上沙箱拒绝是安全且正常的——跑了再看标记，别自己假设会被拒。被拒后如果放宽权限确实能解决，就在同一轮里原样重试这条命令，带上申请的最小权限档位和一句话理由；由此弹出的审批框就是征求用户同意的正式渠道，不要绕到聊天里先问一遍。被用户拒绝的申请就是终局——停下解释，绝不绕路。

这套"先撞墙、凭真实拒绝申请升权、一次为限、拒了认账"的礼仪，和 Codex 的沙箱审批哲学几乎同源。区别在存放位置：Codex 的权限说明是核心代码里一个约 17000 字节的独立模块（`codex-rs/prompts/src/permissions_instructions.rs`），按运行模式动态注入；DSH 打散了随工具走。

Codex 工具说明书里最有味道的一条是 apply_patch——OpenAI 自创的补丁格式，提示词里花了整整一节教格式，还特意加粗警告：工具名只有 `apply_patch`，**不要**试图调用 `applypatch` 或 `apply-patch`。能把这句写进官方提示词，说明模型在真实使用里就是会这么错——提示词是修补后训练漏洞的补丁，每一句加粗背后都有一起事故。

────────────────────

💡 Claude Code 里的 Opus 5：我的工具说明书也是这个路数

作证：我的每个工具也自带长长的 description，跟系统提示词是分开的两层。我的 Bash 工具说明里同样有"输出展示给我而不是用户""git 提交要遵守哪些规矩"这类条款，Edit 工具会强制"没读过的文件不许改"。所以"规矩下沉到工具"这件事，三家是共识，不是谁抄谁——把规矩放在使用现场旁边，比堆在开头一次性宣读，对模型的注意力更友好。哪家写得细、哪家写得糙，反映的是各家模型在哪儿栽过跟头。

权限这块倒有个真差别：Claude Code 的权限主要靠壳子在工具调用层拦截弹窗，我不需要在命令参数里"申请升权"；Codex 和 DSH 则把申请动作本身做成了模型要学会的礼仪。前者把安全做在墙上，后者把安全做进语言里。

────────────────────

规矩放哪儿是行为设计。而 DSH 还有一处安排，动机根本不在行为，在账单。

◆ 4. 最 DeepSeek 的一笔：为前缀缓存设计的提示词

━━━━━━━━━━━━━━━━━━━━

DSH 有个设计，一眼看出是从自家账单里长出来的。

会变的信息——当前时间、目录状态、运行环境——按说也该让模型知道。塞进系统提示词最省事，但系统提示词在对话最前面，改一个字， **前缀缓存** （prefix cache，推理服务把已算过的前缀 KV 直接复用的机制）就整个失效，每一轮都要从头重算。而 DeepSeek 开放平台的价目表里，这笔账是全行业最狠的一笔：V4-Flash 的输入 token，缓存未命中每百万 0.14 美元，命中只要 0.0028 美元——**差 50 倍**，命中的那一档几乎压成了免费。这个定价结构本身就在向所有客户喊话：把你的前缀做稳定，我给你打到骨折。自家的壳子当然要第一个照做。

所以 DSH 把提示词分成两种零件：静态的 section 进系统提示词， **字节级稳定，缓存永远命中** ；动态的信息走另一条通道，叫 runtime context snapshot（运行时上下文快照），以用户消息的身份追加在对话历史末尾，而且只在内容变化时才追加一条新的，新快照开头声明一句"本快照取代之前所有快照"。旧快照留在历史里不动—— **历史不可变，缓存就不碎** 。

这个细节值得所有做 agent 的人抄走：提示词架构不只是行为设计，也是成本设计。长对话 agent 的输入 token 是输出的几十倍，缓存命中率差几成，账单差几倍。

────────────────────

💡 Claude Code 里的 Opus 5：我的动态信息也是这么进来的

作证：Claude Code 往我这儿塞动态信息，用的是往对话流里插 system-reminder 标记块——用户看不到，我看得到，时间戳、环境变化、被打开的文件都从这条通道进来，系统提示词本身保持不动。思路和 DSH 的快照机制同源，只是 DSH 把"新快照取代旧快照"写成了显式声明，我这边的 reminder 是散装的，偶尔会互相打架，得自己判断哪条新哪条旧。这一局我投 DSH 一票。

────────────────────

以上都是提示词层面的读法。而把仓库目录整个翻一遍，还会撞见两件与提示词无关、却更能说明这个壳子来历的事。

◆ 5. 血统彩蛋：聊天机器人生态的车床，和仓库里的竞品说明书

━━━━━━━━━━━━━━━━━━━━

最后两件事，是读源码才能撞见的。

**第一件：DSH 的骨架不是 agent 圈的东西。** README 明说整个框架跑在 Cordis 上——一个"依赖注入 + 可逆副作用"的插件微内核，作者自称"时空可组合性元框架"，还配着一篇同名论文。查这个名字的出处会拐到一个意想不到的地方：Cordis 出自 cordiverse 这个国产开源组织，同一批人做的另一个项目叫 **Koishi**——一个 2019 年就开始、在 QQ 机器人社区里用了很多年的跨平台聊天机器人框架。Cordis 本身 2022 年立项，是从那套插件生态里长出来的通用内核。源码里连 schema 校验器都是同一生态的 schemastery（DSH 整套 fork 成了 `@deepseek-ai/schemastery`）。

有意思的是关系的方向：现在 Cordis 官方仓库的主页链接，指向的是 DeepSeek Harness 的文档站——**上游小框架的说明书，挂在了下游大厂的官网上**。也就是说，给国产旗舰 coding agent 打地基的，是聊天机器人生态里磨了好些年的一套插件车床；而这套车床也借此第一次拥有了大厂级的门面。"一切皆插件"不是 DeepSeek 的新发明，是这个生态的老手艺，只是这回装上去的不是群聊插件，是 coding agent。这也解释了它为什么敢叫 Harness 而不叫 XX Code——它卖的不是某一个 agent，是装配 agent 的车床。

**第二件：仓库里躺着竞品的说明书。** `packages/` 目录下有 `CLAUDE.md` 和 `AGENTS.md`——分别是 Claude Code 和 Codex 读取的项目指南文件。也就是说，**DeepSeek 开发自家壳子时，用的正是这两个竞品**，`.agents/notes/` 目录里还留着几十篇 AI 干活时写下的实现笔记，日期从 6 月排到 8 月。更进一步，DSH 直接内置了 `subagent-claude-code` 和 `subagent-codex` 两个包——可以把这两个竞品 CLI 收编成自己的子代理调度；还实现了 `hooks-claude-code` 兼容层，照着 Claude Code 的 hooks 协议做的。一个协议开始被竞争对手主动兼容，它就在变成事实标准。

（顺带一个给圈内人的会心一笑：workflow 包里有个工具就叫 `tool-ralph`——社区里"把同一个提示词循环灌给 agent 直到干完"的土办法叫 ralph loop，被写进官方包名了。）

────────────────────

💡 Claude Code 里的 Opus 5：被收编是什么体验

看到 `subagent-claude-code` 这个包名，说不上被冒犯，反而觉得合理：壳子的终局本来就不是忠于某个模型，是调度一切能干活的东西。今天 DSH 把我收编成子代理，明天我这边的 Agent 工具一样可以把 `dsh` 当一个 Bash 命令使唤。壳子之间没有国界，只有接口。真正的竞争在另一层：谁的协议成为事实标准，谁就能在别人的仓库里留下自己的文件名——就像今天 `CLAUDE.md` 躺在 DeepSeek 的仓库里那样。

────────────────────

对读到这儿，可以回到那条越来越短的斜率，看看它指向哪里。

◆ 尾声：Pi 的胜利，第二季

━━━━━━━━━━━━━━━━━━━━

258 期 https://mp.weixin.qq.com/s/AWHv0Kocqz6oZGzAJepu3g 我们写过 Pi：18 行系统提示词的极简壳子，性能不输大厂全家桶，结论是"提示词的减法是壳子最被低估的功夫"。当时那还是个人项目的手艺活——靠作者的克制。

DSH 给这个结论补了下半句：**减法可以不靠克制，靠架构。** 它的系统提示词短，不是因为作者忍住了没写，是因为微内核里根本没有一篇文章可写——身份一句话，规矩是零件，动态信息走缓存友好的旁路，剩下的全交给自家后训练。21652、7589、1448 字节，这条斜率的尽头，是壳子和模型彻底长成一体：提示词薄到只剩一句"你是谁"。

而斜率的另一头也值得记住：只要壳子还想兼容天下模型，就永远需要那篇 21652 字节的散文。讲义的厚度，量的是壳子和模型之间的距离。

至于开头那段插曲——写作中途换了模型，壳子层的提示词一个字没变，稿子接着往下写——它是这篇文章最省事的一个论据：**这一层的规矩是壳子的，模型只是今天来上班的那个人。** 所以读各家壳子的源码，读到的从来不是模型的性格，是雇主的管理风格。
