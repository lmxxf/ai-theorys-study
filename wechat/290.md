【KataGo】围棋的损失函数，比 LLM 复杂太多了

◆ 训练是通用的傻活，难的是标签哪来

━━━━━━━━━━━━━━━━━━━━

289 期 https://mp.weixin.qq.com/s/3VVwv2ONXKPTWh_rYV19UQ 讲了 KataGo 的网络结构，末尾我给它下过一个结论：这个碾压全人类的东西，分开看就两样——**一个 0.23B 的小网络出棋感，一段谁都写得出的搜索出算路**。

那期讲“长什么样”，这期讲“怎么训出来的”。

先交代下我为什么盯着它看——不是喜欢围棋（我对下棋这种智力游戏毫无兴趣）。是这两年我从 LLM 入门，对更早那段古典机器学习几乎一无所知，想找一个**还活着、还够硬的古典范本**补上这一课。KataGo 正好：结构够经典（卷积、残差那套老手艺），任务够硬核（超人棋力、自己造训练数据），不像“猫狗分类”那样一眼到底没嚼头。

所以真正想搞明白的是那句我一直没想通的：**那个棋感，到底是怎么训出来的？**

先把话说在前头，这是我盘了半天才盘明白的一句，也是整篇的骨：

> **网络训练本身，是一件通用的、几乎不动脑子的傻活——喂一个输入，对着标准答案算误差，改一下权重。所有模型都这么训。真正难的、真正见功夫的，是“标准答案（标签）从哪来”。**

LLM 和 KataGo，**训练环节没有任何区别**，都是“喂输入、对标签、算误差、改权重”。它俩的天壤之别，全在标签的来源上。

- **LLM 的标签是白送的。** 它学“预测下一个字”，标签就是语料里下一个字——人类已经写好了，白纸黑字摆在那，抄过来就是。**它的训练信号，本质就一个：下一个 token 是什么。** 严格说后面还有 RLHF、RLVR 那些后训练，但预训练这个地基，就是这一件事。
- **KataGo 的标签，没有人给。** 围棋不存在一个“每步正确走法”的数据集。它同时要学十来件事——这步走哪、对手走哪、最后谁赢、每个交叉点归谁、未来几步棋盘长啥样……**这十来件事的标准答案，全得它自己现造。**

所以这期的真问题只有一个：**KataGo 没有现成标签，它是怎么给自己造出标签、又怎么把这些标签喂进网络的？**

> 材料来源：仓库 github.com/lightvector/KataGo（作者 David J. Wu，MIT 协议），论文 arXiv:1902.10565。各头损失读的是 python/katago/train/metrics_pytorch.py，训练循环读 python/train.py 与 python/selfplay/，初始化方法出自 docs/KataGoMethods.md。本文读的是 2026 年 8 月的 master。

━━━━━━━━━━━━━━━━━━━━

◆ 先把“训练”这件傻活说清：一个快照，一套标签

━━━━━━━━━━━━━━━━━━━━

要看懂后面，得先把“网络到底怎么被训”这件事的粒度定死。这块我一开始也糊过，绕明白之后特别简单。

**网络一次只看一个“快照”。** 一个快照，就是某一手棋时的盘面（棋盘上黑白子的现状，外加最近几手的位置——289 讲过那 22 个输入平面）。**不是一次看整盘棋，是一次看一手时的一张照片。**

**一盘棋，会被拆成几百张这样的快照。** 一盘 200 手，就是 200 张快照、200 个**互相独立**的训练样本。第 5 手那张快照是一个样本，第 50 手那张是另一个样本，**它俩从头到尾没关系**——各有各的标签，各算各的误差，各改一次权重。

这一点我卡了最久，说破了很蠢：第 5 手和第 50 手的正确走法当然完全不同，但这**不矛盾**——因为它俩根本不在同一次计算里，是两个毫不相干的样本，谁也不要求跟谁一样。

────────────────────

💡 “一个输入一个 loss”里的“一个”，单位是一张快照，不是一盘棋

喂第 5 手的快照 → 对着它那套标签算一套误差 → 改一次权重。
喂第 50 手的快照 → 对着它那套标签算另一套误差 → 再改一次权重。

一盘棋拆成几百张快照，各训各的。它们甚至大概率不在同一批里——训练时是从一个大池子随机捞一批快照，这批可能来自几百盘不同的棋、不同的手数，混在一起训。

────────────────────

定死了这个粒度，后面就好说了：**对每一张快照，KataGo 要造出它那一套标签。** 十来个头，就是十来种标签。

━━━━━━━━━━━━━━━━━━━━

◆ 十来个头的标签，从两个源头流出来

━━━━━━━━━━━━━━━━━━━━

一张快照的十来种标签，来源其实就两个。搞清这两个源头，“没有人给标签”这件事就破解了。

**源头一：终局。这是唯一不撒谎的东西。**

一盘棋总会下完，下完了，谁赢、每个交叉点最后归谁、目数差多少——**这些是铁的事实，靠数子得出，不依赖任何网络**。

value 头（谁赢）、ownership 头（每点归谁）这些标签，就从终局来。但这里有个精巧的动作：**终局的真相，会沿着时间往前倒灌**。

- 接近终局那几手：胜负标签几乎就是真实结果，误差极小。
- 往前一手：受后一手约束，误差稍大一点点。
- 一路往前灌到开局。

**真相像水从棋局末尾往开头倒流**，把每一手的胜负标签都浇上去。越靠终局越准，越靠开局越模糊。（代码里那组 `td_value` 头就是干这个倒灌的。）

**源头二：搜索。这是“想过之后”的判断。**

轮到走每一手时，KataGo 不是拍脑袋落子，而是**往下搜索一大通**（试很多走法、往前算一算），最后得出一个“哪步更值得走”的判断。**这个判断，直接就是这一手 policy 头（走哪）的标签。**

搜索具体怎么搜、怎么打分，这期不细讲了——你只要知道它的产出是一个“该往哪走”的分布，就够了。关键是那句枢纽：

> **搜索的产出，是训练的输入。** 围棋没有现成的走法答案，搜索就是那台现造答案的机器。它算完一手，就给这一手留下一个 policy 标签。

**为什么搜索造出的标签，值得网络去学？** 因为搜索是“网络的直觉 + 往下真算了一通”——**同一个网络，算过之后一定比没算聪明**。让裸网络去模仿“算过之后的判断”，裸网络的直觉就被往上拽。这就是“棋感”被训出来的全部秘密：**没有老师，搜索就是那个老师，它是网络自己多花时间往下算出来的。**

把十来个头按来源归个类，一眼看全（读代码里那个损失文件数出来的，名字保留英文原样）：

| 输出头 | 学什么 | 输出多少个数 | 标签从哪来 |
|---|---|---|---|
| policy | 这一手走哪 | 362（361 点 + 停一手） | 搜索的判断 |
| opponent policy | 猜对手下一手走哪 | 362 | 搜索的判断 |
| value | 最终谁赢 | 3（胜/负/和） | 终局倒灌 |
| td value | 接下来几手的胜率 | 约 9 | 终局倒灌 |
| td score | 接下来几手的目数 | 约 3 | 终局倒灌 |
| score | 终局目数差 | 1 | 终局 |
| ownership | 每个交叉点最后归谁 | 361 | 终局 |
| scoring | 每个点的目数归属 | 361 | 终局 |
| futurepos | 未来几手棋盘长啥样 | 722（361 × 2） | 后续实际盘面 |
| seki | 每个点是不是双活 | 361 | 终局判定 |

（数字按 19 路棋盘算，19×19 = 361 个交叉点。）

两列一起看就通了：**十来个头，标签全从两个源头挤出来——搜索管“这手该走哪”，终局管“最后怎么样”，没有一个是人手工标的；而加起来一张快照上有两千来个被监督的数字，密就密在那几个“每个交叉点都要答”的空间头上。** 但别忘了，这两千个数最后归到十来个误差项、再汇成一个总误差——信号很密，出口只有一个。

━━━━━━━━━━━━━━━━━━━━

◆ 造好标签之后：十来个头，一锅端更新

━━━━━━━━━━━━━━━━━━━━

到这，一张快照的标签凑齐了：policy 标签（来自搜索）、value 标签（来自终局倒灌）、ownership 标签（来自终局）……**来源五花八门，但凑齐之后，它们平等地贴在同一张快照上。**

然后更新网络，这一步反而最没悬念——**十来个头是一起更新的，一次搞定，不是各更各的：**

```
              ┌ policy 头：预测 vs 标签 → 误差1 ┐
一张快照 →     ├ value  头：预测 vs 标签 → 误差2 ├→ 全加成一个总误差 →（一次）改权重 → 全网络一起更新
（一次前向）   ├ owner  头：预测 vs 标签 → 误差3 ┤
              └ …                            ┘
```

十来个头各自算出一个误差，前面各乘一个权重（重要的头系数大，辅助的系数小），**加成一个总数**。对优化器来说，**永远只有一个数在往下降**。一改权重，主干和所有头**同时**被更新。

────────────────────

💡 标签来源分家，更新一锅端

容易混的点：标签的**来源**不同（搜索 / 终局），那是训练之前打标签的事；但**更新**只有一次——所有头的误差加成一个总数，一改权重，全体一起更。没有“哪个头先更、哪个头后更”，加起来一锅端。

────────────────────

那**为什么要凑这么多头**？这才是对做小模型最有用的地方。这些头分两类：

一类是**你真正想要的输出**：policy（走哪）、value（谁赢），推理时要用。

另一类是**推理时根本用不上、纯粹为训练服务的辅助头**：每个交叉点最后归谁、未来几步棋盘长啥样……为什么挂一堆用不上的头？因为——

────────────────────

💡 一盘棋下完只告诉你“白赢了”，这一个 bit 要摊给前面两百手

一盘棋下完，最终就一个结果：“白胜”，一个 bit 的信息，摊到前面两百手上，每手分到的教学信号少得可怜。

但如果同时逼网络回答“棋盘每个点最后归谁”——那是 361 个点、361 个信号；再逼它答“未来几步棋盘长啥样”——又是几百个。**主干为了答对这些附加题，被迫真正读懂局面。** 那些辅助头，就是把稀疏的“输赢”信号，扩成密集的“局面理解”信号。

这招叫多任务学习（multi-task）。**数据或标签稀缺时，给模型加几个辅助预测任务，哪怕推理时根本不用，也能逼它学到更扎实的中间表示。** 这一条，搬到任何小模型上都成立。

────────────────────

标签造好了、头也更新了，剩下一个时机问题：这些活到底什么时候发生。

━━━━━━━━━━━━━━━━━━━━

◆ 什么时候改权重？造标签和改权重，是分开的两拨活

━━━━━━━━━━━━━━━━━━━━

你可能以为流程是：下一盘 → 决出胜负 → 立刻拿这盘改权重 → 再下一盘。**几乎没有大规模自对弈系统这么干**，KataGo 也不是。

它是三拨活**各干各的、异步跑**，靠硬盘上的文件解耦：

1. **下棋的**：不停自对弈，把每盘棋、每手的快照和标签写到硬盘。不碰训练。
2. **洗牌的**：把硬盘上一大堆快照打散、混匀，攒成训练用的数据块。
3. **训练的**：从数据块里随机捞一批快照，算误差、改权重。

三拨同时转，谁也不等谁。改权重不绑“哪盘刚下完”——它等的只是“池子里有打好标签的快照”。而一张快照要打上完整标签，确实得等它那盘下完（因为 value 标签要靠终局倒灌）。**造标签和改权重，就这样解耦了。**

为什么要这么绕？三条，对做小模型全是干货：

- **算力不能闲着。** 下棋（大量搜索）和训练（改权重）抢的资源、节奏都不一样，绑一起就是一个干等另一个。分家，两边各自打满。这和之前 287 期 https://mp.weixin.qq.com/s/74UVLTkou7EbY-fzt6ihkw 讲的“后训练车间里最贵的动作是等”，是同一个工程哲学。
- **一盘棋的快照不够训、还高度相关。** 一盘就两百张快照，前后还长得像，直接拿去训会狠狠过拟合这一盘。**必须先扔进大池子、和几百盘混匀、随机采样**——这就是洗牌那拨活存在的唯一理由。你在手机上训小模型同理：别拿刚采集的一小批连续数据直接训，先攒进缓冲区打散。
- **数据可以隔夜用。** 捞到的快照可能是几小时前、甚至旧版网络下出来的，没关系——标签是终局真相，不会因为网络旧了就失效。这让它比“必须用当前策略数据”的训练更好并行。

━━━━━━━━━━━━━━━━━━━━

◆ 一个容易忽略的分界：下棋是 CPU 逻辑，网络只是被反复呼叫的零件

━━━━━━━━━━━━━━━━━━━━

还有个区分，很多人一辈子没分清：**造标签的那台“搜索”机器，和网络，是两码事。**

搜索的骨架是普通程序逻辑，跑在 CPU 上，**里面没有神经网络**——维护一棵试探树、挑分支、往下算、统计，全是 if-else 和加减乘除，谁都写得出（289 那句“谁都写得出的搜索”就是这个意思）。它只在每次要“估一下某个局面”时，才调一次网络前向、上一下 GPU。**一手棋，网络被这套 CPU 逻辑呼叫上万次。**

────────────────────

💡 改权重只认识网络，不认识搜索

改权重（梯度下降）只针对“网络那一次前向”的计算——前向怎么算的，就怎么反过来求导。它只认识网络那个零件，**根本不知道外面还有一台搜索机器**。

搜索是 CPU 上的程序逻辑，不可导，也不需要求导——它的身份是**造标签的**，造完标签就退场。搜索的本事没法用梯度直接灌进网络，只能**物化成标签**，网络再通过模仿标签，间接把本事吸进权重。所以说搜索取代的是网络的“推理”（往下算，LLM 得靠把网络做大才有，KataGo 把它外包给了搜索），**不是取代“学习”**——学习永远是那一下改权重。

────────────────────

这套“能写规则、能搜索的部分交给 CPU 逻辑，网络只干'凭感觉估个值'这种没法写规则的活”的分工，是干这类事的通用模板。**手机上尤其如此**：网络越小越省电，把能外包给 CPU 逻辑的都外包出去。KataGo 就是极致样板——0.23B 的小网络 + 谁都写得出的搜索 = 超人棋力。**智能是分层调度出来的，不是硬堆在一个大网络里的。**

━━━━━━━━━━━━━━━━━━━━

◆ 最后一个问题：一开始那个网络，是随机数还是人定的？

━━━━━━━━━━━━━━━━━━━━

两个层面的“初始化”，容易混，分开说。

**层面一：网络权重——是随机数，但不是瞎随机。**

几亿个参数一开始就是随机数，没人手工定。但**随机的“幅度”是精心算过的**。KataGo 用的这套方法，保证每层输出的数值幅度稳定，不会越传越爆、也不会越传越小。用大白话说：**权重是随机撒的种子，但“撒多大力”是算好的。**

这一手对手机小模型直接有用：小模型为了推理快，常想去掉归一化层（batch norm），**这时初始化的幅度校准会变得很关键**——归一化的兜底没了，起手没调好，训练直接崩。KataGo 干脆把 batch norm 整个扔了，靠初始化把幅度一开始就调对，换来训练快 1.6 到 1.8 倍，而且训练和推理用同一套逻辑（没有“训练一套、推理另一套”的麻烦）——**这正是手机部署想要的。**

**层面二：整个系统怎么冷启动——网络啥都不会，怎么起步？**

答案有点反直觉：**随机网络瞎走，也能滚起来。**

第一版网络权重随机，直觉是乱猜的，下出来的棋烂到不能看。**但——最后还是能分出胜负**（两个傻子乱下，数子总有一方地多）。这个真实胜负，就是第一滴不撒谎的信号：训 value → value 有一丁点方向感 → 搜索有一丁点用 → 棋烂得少一点 → 循环起来。

整个冷启动**不需要任何人类棋谱、不需要人定任何棋理**。地基只有一条：终局不撒谎。从纯随机开始，靠“烂棋也有真胜负”这一个信号，一点点滚成超人。这就是 AlphaZero 里那个 Zero 的意思——**从零，无人类知识。**

────────────────────

💡 两个“初始化”别搞混

权重初始化：网络那几亿个参数的起始值，用随机数，但幅度用公式精心校准。

系统冷启动：整个自对弈循环怎么起步，不用人教，随机网络瞎走加终局真相，自己滚。

────────────────────

到这，从头到尾的每一环都拆开了，最后把它们串成一条链。

把整条链收一下：随机初始化的小网络瞎走 → 自对弈跑出真实胜负 → 终局真相往前倒灌、搜索就地打分，一张张快照被打上标签写进硬盘 → 训练那拨活异步捞出来，十来个头的误差加成一个数，一改权重全体更新 → 网络变强 → 下一轮标签更好 → 再滚一圈。

**LLM 是抄一个白送的标签，KataGo 是自己造一排标签。**

训练环节，两边一模一样，都是“喂快照、对标签、算误差、改权重”这件傻活。区别全在标签哪来——**这才是 KataGo 那身精巧藏着的地方：不在训练，在造标签。**

棋感不神秘。它只是一台“愿意往下多算一通”的笨机器，把算出来的结果，一遍遍喂给那件通用的傻活，跑了千万遍之后的样子。

━━━━━━━━━━━━━━━━━━━━

最后说句题外的。我翻 KataGo，不是想学下围棋——是想找一个还活着、还够硬的古典机器学习标本，看清它的骨头。

而它恰好是这类标本里最好的一个：因为**围棋这个问题的严谨结构，是人一寸寸啃透、再手工翻译给网络的**——22 个输入平面怎么编码历史、policy 头为什么要留一个“停一手”、双活死活为什么得单开一个头去学……全是人先理解了围棋，再把这份理解搭成网络能吃的形状。网络很强，但“搞懂围棋是怎么回事”这门活，是人干的。

往深一层看，棋能当机器学习最早的试验田，还有个天生的便宜：它的状态干净。棋盘一摆，当前局面一览无余，没有暗牌、没有连续模糊的中间态——**正因为它干净，才能把某一手的盘面切下来、当一个独立样本喂进去**。真到了脏问题上（真实世界那些连续、带隐藏信息的状态），“什么才算一张干净的快照”本身就是老大难。所以人类先拿棋开刀，练了几十年，练出来的其实不是“会下棋”，是 **“怎么把一个问题，变成机器能一口口喂的形状”** 这门手艺。

这门手艺，是上一代 AI 的巅峰，也快用不上了。LLM 之后，人不用先懂某个领域——丢文本进去，模型自己从语料里长出对一切的理解，领域结构不再需要人来翻译。省心，但也把骨头全藏进了黑箱。

所以 KataGo 这种老实的、把结构明明白白搭在外面的模型，反而成了看清“训练信号到底怎么流”的最好标本。等哪天这类模型彻底没人做了，想弄明白这些的人，可能就只剩黑箱可看了。
