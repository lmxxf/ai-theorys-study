◆ LLM 只学一件事，KataGo 要学十来件

━━━━━━━━━━━━━━━━━━━━

289 期 https://mp.weixin.qq.com/s/3VVwv2ONXKPTWh_rYV19UQ 拆了 KataGo 的网络结构，末尾我给它下了个结论：这个碾压全人类的东西，分开看就两样——**一个 0.23B 的小网络出棋感，一段谁都写得出的蒙特卡洛搜索出算路**。

那期讲的是"长什么样"。这期接着问一句我自己一直没想明白的事：**那个棋感，到底是怎么训出来的？**

先把 LLM 这边的底摸清楚，好有个参照物。

一个 LLM，主体训练信号简单到就一句话：**预测下一个 token**。给它半句话，让它猜下一个字，猜错了就调权重。就这一个信号，一个出口。语料里下一个字白纸黑字写着，标签是**现成的**——严格说后面还有 RLHF、RLVR 那些后训练，但预训练这个地基，就是"下一个字是什么"这一件事。

KataGo 不是。它同一时刻在学十来件事：这步该走哪、对手会走哪、最后谁赢、接下来几步胜率怎么变、每个交叉点最后归谁、终局目数差多少、未来几步棋盘长什么样……

**而且最要命的差别不在"件数多"，在标签的来源。** LLM 的标签是抄来的（人写好的下一个字），KataGo 这十来件事，**没有任何人给过它标准答案**——围棋不存在一个"每步正确走法"的数据集。它的标签得自己造。

这期就顺着两个问题走：这么多信号，怎么一起训？这些没人给答案的标签，又是怎么被造出来的？

◆ 十来个信号怎么一起训？答案朴素得让人失望：加起来

━━━━━━━━━━━━━━━━━━━━

我原以为"多信号训练"是什么精巧的调度。读完代码发现，机制上一点不神秘，就是**加法**。

每个信号各自算出一个损失（一个数），然后：

```
总损失 = policy 损失 + value 损失 + ownership 损失 + …
```

代码里每一项前面还乘一个权重系数，重要的头系数大，辅助的头系数小。比如 value 那一项乘的是 `1.5`，某个目数相关的头乘的是 `0.0008`。加成一个总数，反向传播照常跑一次。

关键在这句：**对优化器来说，永远只有一个数在往下降。** "多信号"只是说，这一个数是由十来项加出来的。它不需要"同时优化十个目标"这种玄学，加法之后就还是一个标量，梯度下降一次搞定。

那**为什么要凑这么多头**？这才是对做小模型有用的地方。这些头分两类作用，代码里差不多各占一半：

第一类是**你真正想要的输出**：policy（走哪）、value（谁赢）。这俩是主菜，推理时要用。

第二类是**纯粹给主干加信号密度的辅助头**：每个交叉点最后归谁、未来几步棋盘长什么样……**这些推理时根本不用**，只在训练时挂着。

为什么要挂一堆推理时用不上的头？因为——

━━━━━━━━━━━━━━━━━━━━
💡 一盘棋下完只告诉你"白赢了"，这一个 bit 要摊给前面两百步
━━━━━━━━━━━━━━━━━━━━

一盘棋两百多手，下完了，最终就一个结果："白胜"。这是一个 bit 的信息。要靠这一个 bit 去教前面每一步棋，摊到每步头上的信号少得可怜。

但如果同时逼网络回答"棋盘每个点最后归谁"——那是 361 个点、361 个 bit；再逼它答"下一手大概落哪"——又是一个分布。**主干为了答对这些附加题，被迫真正读懂局面。** 那些辅助头，就是把稀疏的"输赢"信号，扩成密集的"局面理解"信号。

这招在业界叫多任务学习（multi-task）或者辅助任务（auxiliary task）。**数据或标签稀缺的时候，给模型加几个辅助预测任务，哪怕推理时根本不用，也能逼它学到更扎实的中间表示。** KataGo 是把这招用到极致的样板。
━━━━━━━━━━━━━━━━━━━━

顺一句过渡，免得下面撞上另一个"头"。

━━━━━━━━━━━━━━━━━━━━

◆ 打断一下：这个"头"，和 289 讲的注意力"多头"不是一回事

━━━━━━━━━━━━━━━━━━━━

上一期讲结构时，我说过 transformer 块里注意力是"16 个头、每头 32 维"。这一期又冒出来一堆"输出头"。两个"头"撞名了，得先分清，不然一定混。

**注意力的多头（multi-head attention），在主干内部。** 一个注意力层拆成 16 份并行去"看"棋盘不同的关系，看完**拼回去，继续往下传**。它是中间的、结构性的，属于 289 讲的那部分。

**输出头（output head），在主干末端。** 主干算出一套对局面的理解——一个共享的特征——然后**分叉**成好几个小网络，各自输出不同东西：policy 头输出走哪、value 头输出谁赢、ownership 头输出每个点归谁。它们是最后的、并列的分叉。

一张图摆清位置：

```
输入 →[ 主干：一堆残差块，每层里都有注意力的"多头" ]→ 共享特征
                                                      ├→ policy 头 → 走哪
                                                      ├→ value 头 → 谁赢
                                                      ├→ ownership 头 → 每点归谁
                                                      └→ …（一排输出头）
```

注意力的头在**方框里面**，输出头是**方框右边分出去的叉**。

而且——**LLM 也有输出头，只不过只有一个**，就是 289 讲的那个 LM head，把特征映射回词表、选下一个 token。所以本期开头那句对比可以收得更利索：

> **LLM 是一个输出头（下一个 token），KataGo 是一排输出头。** 至于注意力的"多头"，两边主干里都有，不是差异点。

━━━━━━━━━━━━━━━━━━━━

◆ 棋感怎么训出来的？它自己当自己的老师

━━━━━━━━━━━━━━━━━━━━

现在到最神秘、也是我最想搞明白的一块。"棋感训练"我早就听说过，一直觉得玄。拆开之后发现，它是一个特别朴素的机械循环。

整个魔术建在一句话上：

> **搜索之后的判断，永远比裸网络的直觉强一截。**

裸网络看一眼棋盘，凭感觉告诉你这步大概走哪（policy）、大概谁赢（value）。这是**直觉**，快，但糙。

但如果拿这个网络当引擎，往下**搜索**——试走这步、再试走那步，往前展开几千上万个变化，最后统计"哪步走下去赢面最大"——这个结论**一定比一开始那个直觉准**。因为它真的往下算了，用往下走出来的结果，修正了拍脑袋的感觉。

**缺口就在这里：同一个网络，"算过之后"比"没算"聪明。** 自举全靠这个缺口。

循环转四步：

1. **裸网络下棋，但每一步都不直接落子，而是先搜索**（往下算几千步）再决定走哪。
2. 一盘下完，把每一步**搜索得出的结论**记下来当标签——注意，不是记"实际走了哪一手"，是记"**搜索算完后，各步各被试了多少次**"这个分布。
3. **训练网络去模仿这些搜索结论**，让裸网络的直觉，去逼近"算过之后的判断"。
4. 网络变强了 → 拿更强的网络再去搜索，搜索结论又更强 → 回到第 1 步。

一句话：**把"慢而准的搜索"，不断蒸馏进"快而糙的直觉"。**

为什么这不是骗自己的永动机？因为**老师永远领先学生一个身位**。学生（裸网络）再怎么追，老师（网络＋搜索）永远比它多算了几千步。等学生追上老师这一版，老师又因为"用上了追上来的更强学生去搜索"往前挪了一步。**这个身位差，是搜索凭空变出来的算力**——不是从数据来的，是从"愿意多花时间往下算"来的。代价只是时间。

━━━━━━━━━━━━━━━━━━━━
💡 白天棋感给算路打工，晚上算路给棋感上课
━━━━━━━━━━━━━━━━━━━━

下棋的时候，棋感是主力，快速给搜索当起点，让搜索不用把 361 个点都试一遍；训练的时候，搜索把白天算出的成果，反过来喂给棋感。

所谓"棋感"，说穿了就是网络那个 policy 头输出的直觉分布。它不是被人教的——没人知道"正确棋感"长什么样——是被搜索一轮轮蒸馏出来的。神秘感全来自"没有老师却学会了"。现在看清了：**老师就是它自己往下多算的那几千步。**
━━━━━━━━━━━━━━━━━━━━

这里要澄清一个我自己一开始也想岔的点。老师不是"网络出这步、出下步，一路走到分胜负"那样走**一条**线。走一条线完全由直觉决定，没比直觉多任何东西，不能当老师。老师是**同时试很多条路、然后统计**：直觉先初筛几步看着靠谱的，挑一步试走、往下展开一小段估个胜负，再回来换一步试，哪步试出来好就多分点注意力……反复几千次，**把算力堆在有希望的分支上**，最后看的是"这几千次里每步各被翻牌多少次"。

老师 = 学生的直觉 + 几千次现实检验。所以它必然强，强的那部分是花时间试出来的。

━━━━━━━━━━━━━━━━━━━━

◆ 一个要命的问题：不下到底，value 准不准我哪儿知道？

━━━━━━━━━━━━━━━━━━━━

上面有个窟窿，你可能已经看出来了：搜索往下试的时候，靠 value 估"这么走下去谁赢"。可 value 是网络自己估的，网络还没训好，**value 凭什么准？这不循环论证吗——用一个没准的东西，去训练那个没准的东西。**

这是整套机制的死穴。答案分两层。

**第一层：搜索当下——不准的 value 也能用，因为取平均加比大小。**

value 在一次搜索里不是只用一次，是几千次里每条路径都估一下，**成千上万个估计取平均**。单个估计有噪声，偏高偏低都有，平均之后噪声互相抵消。而且搜索要的不是"胜率的精确数值"，是"A 步和 B 步哪个更好"这个**相对排序**。value 哪怕整体偏高一成，只要它对 A、B 的高低判断没错，搜索就能选对。要求低得多。

但这还不够。万一 value 系统性地看错了呢？这就要第二层——

**第二层：终局是不撒谎的锚，误差从终点往回灌。**

value 不是永远悬空、自己估自己。**每盘棋最后是真的下完的，真的分出胜负了。** 那一刻的胜负是铁的事实，不靠任何网络——数子，谁地多谁赢。

然后是关键操作：**拿这个真实终局，回头去修正前面每一步的 value 标签。**

- 接近终局那几步：value 标签几乎就是真实胜负，误差极小。
- 再往前一步：它的标签受后一步约束，误差稍大一点点。
- 一步步往前，**真实胜负这个不撒谎的信号，像水从终点往起点倒灌**，把每一步的 value 估计往真相方向拽。

代码里有一组叫 `td_value`（时序差分）的头，干的就是这件事：不用每步都干等到终局，用"后面几步"的信息去修"前面这步"，一层层把终局的真相传导回去。

所以循环不是空转：**搜索让 value 暂时够用（平均＋比大小），终局让 value 长期变准（真相回灌）。** 两条腿，缺一个都会塌。

回到你那句"value 准不准我哪儿知道"——**网络当下确实不知道。但棋盘知道。你只要一直下到底，棋盘会告诉你。你要做的就是把棋盘每次告诉你的真相，往回记账。**

━━━━━━━━━━━━━━━━━━━━

◆ 那到底什么时候做梯度下降？必须等一盘打完吗？

━━━━━━━━━━━━━━━━━━━━

你可能以为流程是：下一盘 → 决出胜负 → 立刻对这盘做梯度下降 → 再下一盘。**几乎没有大规模自对弈系统这么干**，KataGo 也不是。

真实流程是三个进程**各转各的、异步跑**，靠硬盘上的文件解耦：

1. **自对弈进程（下棋工）**：不停下棋，把棋谱和每步的搜索标签写到硬盘。不做任何训练。
2. **洗牌进程（shuffle）**：把硬盘上一大堆棋谱打散、混匀，攒成训练用的数据块。
3. **训练进程（train）**：从数据块里随机捞一批，做梯度下降，更新网络。

三者同时在跑，谁也不等谁。

回到你的问题——梯度下降什么时候做，必须等胜负吗？拆两半：

**value、ownership 这类"终局标签"的头**：是的，这一步的标签得等这盘下完才知道（谁赢、每点归谁）。所以一盘下完，才能给这盘每一步打上完整标签，写进硬盘。这部分你的直觉对。

**但"梯度下降"本身，跟"这盘刚下完"没有任何绑定关系。** 训练进程根本不在乎数据是哪盘来的、新旧。它就是从硬盘那个大池子里随机捞一批（比如 256 个局面，来自几百盘不同的、可能是几小时前下的棋），算损失，下降一步。捞到的每个局面都早已打好标签了。

准确的说法是：**梯度下降不等某一盘，它等的是"池子里有打好标签的局面"。而一个局面要打上完整标签，确实得等它所在那盘下完。** 两件事解耦了。

为什么要这么绕？三条，对做小模型全是干货：

- **算力不能闲着。** 下棋（大量搜索）和训练（梯度下降）抢的资源、节奏都不一样，绑一起就是一个干等另一个。分家，两边各自打满。这和之前 287 期 https://mp.weixin.qq.com/s/2G4jvJ8gW8VVQEPeJ4hn9w 讲的"后训练车间里最贵的动作是等"，是同一个工程哲学。
- **一盘棋的数据不够训一步，还高度相关。** 一盘就两百个局面，前后局面还长得像。直接拿去训会狠狠过拟合这一盘。**必须先扔进大池子、和几百盘混匀、随机采样**——这就是洗牌进程存在的唯一理由。你在手机上训小模型同理：别拿刚采集的一小批连续数据直接训，先攒进缓冲区打散。
- **数据可以"隔夜"用。** 捞到的局面可能是几小时前、甚至是旧版网络下出来的。没关系，标签是终局真相，不会因为网络旧了就失效。这一点让它比"必须用当前策略数据"的那类训练更好并行。

> 287 期的链接如果你还没看过：那期正好讲了强化学习训练里"等"这件事有多贵，和这里的三进程分家是一体两面。

◆ 一个容易忽略的分界：下棋是 CPU 逻辑，估值才是网络

━━━━━━━━━━━━━━━━━━━━

还有个关键区分，很多人一辈子没分清：**"树搜索"和"网络前向"是两种完全不同的计算，跑在不同地方，由不同东西控制。**

下棋这个过程，是两种计算交替。

**搜索的骨架，是普通程序逻辑，在 CPU 上跑。** 这部分**没有任何神经网络**：维护一棵树（哪些局面试过、各被访问几次、各自估的胜率是多少）、决定接下来试哪个分支、试走一步、把结果回填到树上，循环几千次，最后统计访问分布。这套逻辑是 if-else、循环、加减乘除，**谁都写得出来**——289 结尾那句"谁都写得出的蒙特卡洛搜索"就是这个意思。它不需要 GPU。

**只有每次要"估一个局面"时，才调网络前向，这才上 GPU。** 搜索每展开到一个新局面，要问一句"这局面 policy 怎么看、value 多少"，这一下才是神经网络，才用 GPU。

所以一步棋的真实图景是：

```
CPU 的搜索逻辑：试到一个新局面 →
   "喂，网络，这局面咋样？" → GPU 前向一次 → 拿回 policy＋value →
CPU 继续：更新树、挑下一个分支 →
   又到新局面 → 又问 GPU → …（几千上万次）
→ 最后 CPU 统计访问分布，落子
```

**CPU 的搜索逻辑当调度总管，GPU 的网络当被反复呼叫的估值器。一步棋，网络被呼叫上万次。**

━━━━━━━━━━━━━━━━━━━━
💡 梯度只认识网络，不认识搜索树
━━━━━━━━━━━━━━━━━━━━

梯度下降只针对"一次网络前向"那个计算图——前向怎么算的，反向就怎么求导。它只认识网络那个零件，**根本不知道外面还有一棵搜索树**。

搜索是 CPU 上的程序逻辑，**不可导**，也不需要求导，它就是个数据生成器。所以搜索的智慧**没法用梯度直接学进网络**——梯度到不了搜索那儿。搜索只能把结论**物化成标签**，网络再通过模仿标签，间接把搜索的本事吸进权重里。这就是"蒸馏"的物理形态：不可导的老师（搜索）造标签，可导的学生（网络）学标签。
━━━━━━━━━━━━━━━━━━━━

这套"CPU 逻辑管流程、GPU 网络管重活、两者交替"的架构，是干这类活的通用模板：**能用规则、能搜索、能枚举的部分，别让网络去学**，写成 CPU 逻辑，又快又准又可控；**只有"凭感觉估个值、初筛一下"这种没法写规则的部分，才交给网络。** 手机上尤其如此——网络越小越省电，把能外包给 CPU 逻辑的都外包出去。KataGo 就是极致样板：0.23B 的小网络＋谁都写得出的搜索＝超人棋力。**智能是分层调度出来的，不是堆在一个大网络里的。**

━━━━━━━━━━━━━━━━━━━━

◆ 最后一个问题：一开始那个网络，是随机数还是人定的？

━━━━━━━━━━━━━━━━━━━━

这里有两个层面的"初始化"，容易混，分开说。

**层面一：网络权重的初始化——是随机数，但不是瞎随机。**

几亿个参数，一开始就是随机数，没人手工定每个值（也不可能）。但**随机的"幅度"是人精心算过的**。KataGo 用的这套方法（He 初始化配上一个叫 Fixup 的技巧），干的就是这件事：保证每一层输出的数值幅度稳定，不会越传越爆、也不会越传越小。

它有一手很讲究：残差块里第一个卷积的权重乘上 `1/√(总块数)`，第二个卷积**直接初始化成 0**。为什么这么抠？因为 KataGo 把归一化层（batch norm）整个扔了。归一化层本来靠"运行时强行把数值拉回正常范围"兜底，扔了之后，**就只能靠初始化把数值幅度一开始就调对**，否则网络还没开始学就数值爆炸。

用大白话说：**权重是随机撒的种子，但"撒多大力"是算好的。** 撒太猛，信号传几层就炸；撒太弱，传几层就没了。这套配方就是把力道调到刚好。

这条对手机小模型直接有用：小模型为了推理快，常常想去掉归一化层，**这时初始化的幅度校准会变得很关键**——兜底没了，起手没调好，训练直接崩。KataGo 扔掉 batch norm，换来训练快 1.6 到 1.8 倍，而且训练和推理用的是同一套逻辑（没有"训练时一套、推理时另一套"的麻烦）——**这正是手机部署想要的**。

**层面二：整个系统冷启动——网络啥都不会，怎么起步？**

答案有点反直觉：**随机网络瞎走，也能滚起来。**

第一版网络权重随机，policy 均匀乱猜、value 瞎估，下出来的棋烂到不能看，纯瞎走。**但——最后还是能分出胜负**（哪怕两个傻子乱下，数子总有一方地多）。这个真实胜负就是第一滴不撒谎的信号：训 value → value 有一丁点方向感 → 搜索有一丁点用 → 棋烂得少一点 → 循环起来。

整个冷启动**不需要任何人类棋谱，不需要人定任何棋理**。地基只有一条：终局不撒谎。从纯随机开始，靠"烂棋也有真胜负"这一个信号，一点点滚成超人。这就是 AlphaZero 里那个 Zero 的意思——**从零，无人类知识**。

━━━━━━━━━━━━━━━━━━━━
💡 两个"初始化"别搞混
━━━━━━━━━━━━━━━━━━━━

权重初始化：定的是网络那几亿个参数的起始值，用随机数，但幅度用公式精心校准。

系统冷启动：整个自对弈循环怎么起步，不用人教，随机网络瞎走加终局真相，自己滚。
━━━━━━━━━━━━━━━━━━━━

━━━━━━━━━━━━━━━━━━━━

到这，从头到尾一条完整的链就闭合了：

随机初始化的小网络（瞎走）→ 自对弈产生真实胜负 → 搜索用 CPU 逻辑把直觉修正成访问分布 → 一排输出头（value 靠终局回灌、policy 学访问分布）把标签写进硬盘 → 训练进程异步捞出来做梯度下降 → 网络变强 → 回去搜索更强 → 左脚踩右脚。

LLM 是抄一个信号，KataGo 是自己造一排信号。

它没有现成答案可抄，就用"终局不撒谎"这一条铁律，把自己往下多算的那几千步，一遍遍蒸进快而糙的直觉里。

棋感不神秘。它只是一个愿意花时间往下算的笨办法，跑了千万遍之后的样子。
