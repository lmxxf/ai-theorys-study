◆ 整条产品线都在 1B 以下

━━━━━━━━━━━━━━━━━━━━

288 期 https://mp.weixin.qq.com/s/aT1wn5jsGvNRPl6ic7WRyg 翻了三十年象棋界的账，末尾提到围棋这条线晚二十年、今天一张消费级显卡就能跑到顶尖人类之上。写完我自己留了个疑问：**那个网络到底长什么样？**

带着 LLM 的印象去查，第一个数字就把我打住了。

KataGo 目前最强的那个网络叫 `b40c768nbt`，权重文件 823 MiB。我把它的配置读出来数了一遍参数——**2.3 亿，也就是 0.23B**。次一档的 `b28c512nbt` 是 0.073B，再往下 `b18c384nbt` 只有 0.026B。

习惯了 LLM 那套记法的话，这几个数得愣一下：**它整条产品线全在 1B 以下**。我们平时说“小模型”，说的是 1.7B、7B 这些——KataGo 顶配还不到其中最小那档的六分之一。而它在围棋上早就不跟人类比了，人类不在讨论范围里。

这就是我想写这期的原因。**这几年 LLM 太强势了，强势到我们讨论“神经网络”时，脑子里默认浮现的就是那一套：token、上下文长度、KV cache、下一个词。** 以至于别的模型长什么样，反倒没人讲了。

KataGo 恰好是个特别好的对照物——它 2026 年也换上了 transformer，但**换法和 LLM 完全不是一回事**。

这期就干一件事：把这个网络的结构讲清楚，顺着你熟悉的 LLM 一路对照过去。至于它那些围棋专属的精巧设计，我还没读明白，留着以后学。

> 材料来源：仓库 github.com/lightvector/KataGo （作者 David J. Wu，MIT 协议），论文 arXiv:1902.10565。参数量是我自己建模型数出来的，官方没有现成的表；权重体积是从官方下载站的 HTTP 响应头读的实际字节数。

◆ 先说清楚：它的 token 是什么

━━━━━━━━━━━━━━━━━━━━

聊 transformer 绕不开一个问题：一个 token 是什么。

LLM 里，token 是词或者子词，一句话切成几十个，一篇文章切成几千个。序列长度是变量，从几千到上百万，这几年整个行业都在为了把它拉长而拼命。

KataGo 里，**一个交叉点就是一个 token**。19 路棋盘，19×19 = 361 个交叉点，就是 361 个 token。

代码里这行写得很直白（`model_pytorch.py`）：

```python
seq_len = height * width
```

序列长度就是棋盘面积。**它是个常数**。不会变长，不需要扩展，没有“上下文窗口”这个概念。你下到第 200 手还是第 3 手，喂给网络的都是 361 个位置——因为棋盘就那么大。

那落子之后变的是什么？**是格子里的值，不是格子的个数。**

第 100 手下在棋盘正中心，那个 token 上“空点”那一路变成 0、“己方有子”那一路变成 1，同时周围棋块的气数、能不能征吃这些跟着更新。361 个 token 一个不多一个不少。

一句话记：**LLM 是往后接，序列变长、前面不动；KataGo 是原地改，序列不变、格子里的数变了。**

这一条差别看着朴素，但它是后面一连串差异的总根源。

不过在讲每个格子里装什么之前，得先交代四个围棋词——不然后面看不下去。我自己也是查完才敢往下写的。

────────────────────

💡 四个围棋词，够看完这篇了

**气**（liberty）：一块棋周围紧挨着的空点数。**气全被堵死，这块棋就被提走。** 围棋的死活只有这一条判据，所以“还剩几口气”是最要紧的局部信息。

**劫**（ko）：盘上出现一个双方可以反复提来提去的点。规则禁止立刻提回，得先在别处下一手。**于是棋盘另一头的一手棋，能决定这里的归属**——这就是围棋著名的非局部性。

**征吃**（ladder）：一路连续追打的手段，像走楼梯一样把对方逼向棋盘边缘。它成不成立，**取决于几十路之外的斜线上有没有对方的接应子**——一颗远在天边的子，能让眼前这串追打彻底失效。英文叫“梯子”，画出来确实是一路斜着下楼梯的形状。

**活净**（pass-alive）：这块地已经确定归谁，双方都不用再算了。

后面两个词只在特定段落出现：**目**是围棋的计分单位（谁围的地多谁赢，贴目在代码里叫 komi）；**大龙**指一条连成串、横跨很大范围的棋。

括号里是代码和论文里的用词——想自己去翻仓库的话，按这几个词搜就对了。顺带一个小发现：能直译的用英文（liberty、ladder），围棋独有的干脆搬日语罗马字（ko、komi），因为这套术语是经日本传到西方的。

────────────────────

这四个词里，**气**和**征吃**待会儿会直接出现在网络的输入里，**劫**则是后面解释某个结构时的关键。

回到正题：棋盘只有当前局面，历史怎么办？

────────────────────

💡 那历史着手呢：压进通道里

KataGo 的处理方式不是把历史拉成序列，而是**塞进通道**。

每个交叉点上带着一摞特征平面：这里有没有己方的子、有没有对方的子、这块棋还剩 1 口气 / 2 口气 / 3 口气、这个点是不是因为劫而暂时禁下、最近 5 手分别下在哪、从这里能不能征吃、哪些区域已经算活净了……当前代码里是 **22 个棋盘平面 + 19 个全局值**（贴目、采用哪套劫的规则、是否允许自杀等等）。

换句话说，**时间维度被压进了特征维度**。LLM 用变长序列表达历史，KataGo 用固定长度、更厚的通道表达历史。

────────────────────

知道了输入长什么样，接下来看这些数据进去之后，要穿过什么。

◆ 三层套娃：这个块是怎么长成这样的

━━━━━━━━━━━━━━━━━━━━

在讲 transformer 之前，得先看看它换掉的是什么。因为 **KataGo 的 transformer 不是把原来的结构推倒重来，是塞进了一个已经存在的壳子里**。

那个壳子叫 nested bottleneck residual block，直译是“嵌套瓶颈残差块”。名字长，但它是一层层长出来的，一层层剥开看很好懂。

**第一层：残差块。** 就是 2015 年 ResNet 那个经典结构——算一算，然后把结果加回输入上。`输出 = 输入 + f(输入)`。这一层你肯定熟。

**第二层：瓶颈（bottleneck）。** 通道数多的时候，直接在高维上做 3×3 卷积很贵。于是先用 1×1 卷积把通道压下来，在低维上干活，干完再用 1×1 升回去。以 `b28c512nbt` 为例，主干是 512 通道，进块之后压到 256，出来再回到 512（这两个数在配置文件里就叫 `trunk_num_channels` 和 `mid_num_channels`）。

**第三层：嵌套（nested）。** 这一层是 KataGo 自己加的，2023 年 v1.13.0 进的主训练线，来历写在官方文档 `KataGoMethods.md` 里，我觉得这段最有意思——

标准的瓶颈结构，降维之后中间只放一个 3×3 卷积。KataGo 试下来发现**这笔账不划算**：降维升维本身要花两个 1×1 卷积，中间就干一件事，开销摊不平。放两个 3×3 才回本（原文：“doing two of them does pay back the cost”），放三到四个更划算。

那么问题来了：中间塞了四个 3×3 卷积，这一串怎么组织？作者的原话是：

> 有了四个 3×3 卷积，很自然就会把它们两两配对、各自加上跳跃连接，变成它们自己的残差块。

**于是残差块里面，又长出了残差块。** 这就是 nested——嵌套。外面一个大残差，里面还有两个小残差。

收益也很实在：新的 `b18c384nbt`（18 块 384 通道）跑起来和老的 `b40c256`（40 块 256 通道）速度相当甚至略快，而每次评估的棋力只比两倍重的 `b60c320` 差一点点。**块数少了一半多，通道宽了，总账更划算。**

型号名字到这儿就能读了：**b = 块数，c = 通道数，nbt = nested bottleneck**。`b28c512nbt` 就是 28 个嵌套瓶颈块、主干 512 通道。

◆ 2026 年：壳子没动，芯换了

━━━━━━━━━━━━━━━━━━━━

现在可以说 transformer 了。

KataGo 从 v1.17.0 开始支持 transformer 网络，README 里说主训练线正在切过去。但**它的换法很克制**——代码里那个类叫 `NestedBottleneckTransformerBlock`，注释第一句就说明白了：

> 结构：1×1 卷积（c_main → c_mid）→ N 个 transformer 块 → 1×1 卷积（c_mid → c_main）+ 残差
> 这个结构照搬 NestedBottleneckResBlock，只是把内层的卷积残差块换成了 transformer 块。

上一节那个三层套娃，**外面两层原封不动**：还是残差，还是 1×1 降维升维的瓶颈。变的只有最里面那一层——原来是几个 3×3 卷积组成的小残差块，现在是几个 transformer 块。

型号名字也跟着记了这件事。对比一下：

- `b28c512nbt` —— 28 块，512 通道，嵌套瓶颈
- `b13c1024h16nbttflrs` —— 13 块，1024 通道，**h16 = 16 个注意力头**，后面那串字母是各种特性开关

配置文件里能直接读到这几行：

```python
"trunk_num_channels": 1024,
"mid_num_channels": 512,
"transformer_ffn_channels": 1536,
"transformer_heads": 16,
```

熟悉吧？**注意力头、FFN 中间层宽度**，这些参数名和你读 LLM 配置时看到的一模一样。这一层确实就是标准的 transformer 块：注意力 + 前馈网络，各带残差和归一化，代码里 `TransformerAttentionBlock` 和 `TransformerFFNBlock` 分开写，成对堆叠。

这个网络的参数量是 **1.03 亿**——比最大的那个卷积网（2.3 亿）小一半多。

◆ 对照表：哪些还在，哪些完全不是那么回事

━━━━━━━━━━━━━━━━━━━━

到这儿可以摆表了。左边是你熟悉的 LLM，右边是 KataGo，全部对着代码核过。

| | LLM | KataGo |
|---|---|---|
| 一个 token | 词 / 子词 | **一个交叉点** |
| 序列长度 | 几千到上百万，变长 | **恒定 361**（19×19） |
| 因果掩码 | 有，只能看前面 | **没有** |
| KV cache | 核心优化 | **没有** |
| 位置编码 | 1D RoPE | **2D RoPE**，频率还能学 |
| 分组查询注意力 | 有 | **也有** |
| 前馈网络 | 有，常用 SwiGLU | **有，也能用 SwiGLU** |
| 输出 | 下一个 token 的分布 | **七八个头同时预测** |
| 参数量 | 几 B 到几百 B | **顶配 0.23B** |

**还在的那些**，说明 transformer 这套零件确实通用：多头注意力、分组查询注意力（配置里有 `transformer_kv_heads`，和 `transformer_heads` 分开设）、FFN、SwiGLU、归一化、残差——照搬，不用改。

**下面挑三条差异说说。**

**第一条：没有因果掩码。**

我在代码里搜 `causal`，零命中。

这不是遗漏，是压根不需要。LLM 要因果掩码，是因为它在**逐字往下写**——预测第 5 个词的时候不能偷看第 6 个词，否则训练就作弊了。所以注意力得戴上眼罩，只许往回看。

KataGo 面对的是一整盘棋。361 个交叉点**同时摆在那儿**，没有先后。左上角那颗子当然可以“看见”右下角，它们本来就是同时存在的。要什么眼罩？

所以它的注意力是全连接的：每个点都能直接看见其余 360 个点。

**第二条：没有 KV cache。**

同样是零命中。而这条其实是上一条的推论。

KV cache 存在的意义是：LLM 逐字生成，每写一个字都要把前面所有字重算一遍注意力，太浪费，于是把算过的 K 和 V 存下来复用。**它的前提是“序列在增长，且前缀不变”。**

KataGo 两个前提都不满足。序列不增长，这是前面说过的；前缀也不稳定——它是**原地改**，落一手棋，那个点变了，周围的气变了，被吃的子没了，远处一条大龙的死活可能跟着翻盘。同一个位置的 token 内容一变，之前算出来的 K 和 V 就全部作废。

**不是不想缓存，是没有可缓存的东西。** 它的用法本来就是一次前向、一次输出：整个局面喂进去，网络给出对这个局面的判断，完事。

顺便说，这也是为什么围棋 AI 的算力大头不在网络本身。真正吃算力的是蒙特卡洛树搜索：一步棋要把这个网络调用成千上万次，每次喂一个不同的假想局面。**网络负责“看一眼给个判断”，搜索负责“看很多眼”。**

**第三条：位置编码是 2D 的。**

这条是“零件通用、但必须改造”的典型。

LLM 的 RoPE 处理的是一维序列：第 3 个词和第 7 个词差 4 个位置。棋盘是二维的，一个点和另一个点之间是“差 3 行 2 列”。所以 KataGo 用的是 2D 版本的 RoPE，代码里那个函数叫 `precompute_freqs_cos_sin_2d`。

而且它还做了一件 LLM 那边不常见的事——**让频率变成可以学的参数**。代码注释里给的理由是，固定的 2D RoPE 只包含轴对齐的频率，**表达不了对角线方向的关注**；改成每个注意力头自己学频率之后，头就能自主决定对什么方向敏感。

围棋里斜着的关系到处都是——很多基本棋形就是斜向的，前面说的征吃更是一路走斜线，所以这个改动的动机很具体。

位置编码这块还牵着另一件事，顺带说一句。

────────────────────

💡 一个网络要下三种棋盘

KataGo 一个网络要同时下 9 路、13 路、19 路。做法是把小棋盘放进 19×19 的张量里，用掩码盖住盘外的位置。

这就要求网络**不能依赖“小棋盘摆在大张量的哪个角落”**——挪个位置，结果不能变。所以位置编码必须是平移等变的：它只能表达“这两点差几行几列”，不能表达“这一点在张量的第几行”。

盘外的位置在注意力里被赋予负无穷偏置，softmax 之后自然归零，等于不存在。

────────────────────

到这里，差异都还能归到“棋盘和句子不是一回事”上。最后一条不一样。

━━━━━━━━━━━━━━━━━━━━

◆ 最后一条差异：输出不是一个，是一摞

━━━━━━━━━━━━━━━━━━━━

前面那些差异，根子都在“棋盘不是句子”。这一条不是——它是主动选的。

LLM 的输出很单纯：下一个 token 的概率分布，一个头。

KataGo 的主干跑完之后，接的是一整排头，各预测各的：

- **policy（策略）**：每个点的落子概率——这个对应 LLM 那个头
- **对手的下一手**：预测对方会怎么应
- **value（胜负）**：胜 / 负 / 无结果 三分类
- **ownership（归属）**：**逐个交叉点**预测终局这个点归谁，输出是 361 个 −1 到 1 之间的数——相当于一张“这块地将来是谁的”的热力图
- **最终目差的完整概率分布**：不是“预计赢 7 目”这一个数，是“赢 3 目的概率多少、赢 7 目多少、输 2 目多少”整条曲线
- 外加目差的均值、标准差等若干辅助输出

论文（arXiv:1902.10565）把这个设计当成主要贡献之一，论证我觉得挺漂亮：

> 虽然对局结果是带噪的二值信号，但它是更细变量的直接函数：最终目差，以及每个交叉点的归属。把结果分解成这些更细的变量、一并预测，应当能改善正则化。

翻译成人话：只告诉网络“这盘赢了”，一局棋就学到 1 个比特，太浪费。而**赢多少目、哪块地归谁**——这些信息本来就在同一盘棋里躺着，白扔了可惜。

作者把它提炼成一句通用的经验：

> 预测目标的子成分，能大幅改善训练。

论文里的消融实验显示，去掉辅助的归属和目差目标，学习效率有明显下降；全部改进项合起来的加速倍数约 9.1 倍（作者认为这还是低估）。而摘要里那个更出名的“减少 50 倍算力”，是和 ELF、AlphaZero 这类方法比的总账——**两笔账不是一回事，别混着记**。

◆ 顺手记几笔账

━━━━━━━━━━━━━━━━━━━━

**参数量和权重体积**（参数量是我建模型数的，体积是官方下载站实测字节数）：

| 型号 | 参数量 | 权重 .bin.gz |
|---|---|---|
| b18c384nbt | 2640 万 | 93.4 MiB |
| b28c512nbt | 7290 万 | 259 MiB |
| b40c768nbt | 2.33 亿 | 823 MiB |
| b13c1024h16nbttflrs（transformer） | 1.03 亿 | 未发布 |

拿参数量除一下体积，每个参数占 3.5 到 3.7 字节。权重文件里存的是 32 位浮点数（4 字节），gzip 压完只省了不到一成——**浮点数就是压不动**。文件里也没有量化，FP16 那些是推理后端运行时的事，不写进权重。

**训练规模**（katagotraining.org 首页实时数字，我抓取时是 2026 年 8 月 23 日）：主训练线 kata1 从 2020 年 11 月底跑到现在，累计 **9677 万局**自对弈、**48.2 亿行**训练数据，产出过 945 个网络，**1449 位**贡献者。

最后这个数字值得多看一眼：**这不是某家公司的集群跑出来的，是一千四百多个网友把自己的显卡挂上去，跑了将近六年。**

◆ 还没读明白的部分

━━━━━━━━━━━━━━━━━━━━

这期只讲了骨架。读代码的时候我撞见几处明显更精巧、但我还没读明白的东西，先记在这儿：

**第一个是 global pooling（全局池化）。** 早在 2019 年论文里就有，用来解决“卷积看不见全局”的问题。卷积每次只看一个点周围的一小圈，而开头说的**劫**恰恰是非局部的——这里的死活由棋盘另一头的一手棋决定，那一小圈里怎么看都看不出来。

论文里还有一层更通用的理由，我很喜欢：**强棋手领先时倾向选简单的下法，落后时寻求复杂化**。同一个局部，该怎么下取决于全局是赢是输——这跟围棋没关系，任何策略游戏都这样。

**第二个是注意力偏置。** 代码注释里写了三套方案，其中一套是围棋专属的，出发点是这么一句话：

> 在围棋这类游戏里，一条棋链能让空间上很远的两点变得实际上“相邻”。

一条大龙横跨半个棋盘，头和尾隔着十几路，但它们连成一串——**气是一起算的，死一起死**。这两端在网格上离得很远，在**拓扑**上却紧挨着。

卷积和普通注意力默认的“近”都是空间上的近，可围棋的“近”每落一子就重排一次。作者为此写了一整套基于复数卷积的机制，让注意力能表达“关注这块棋的所有子”、“关注这块棋周围所有的气”。这段我读了两遍还没吃透，不敢现在写。

**第三个不是技术，是那份代码注释本身。** 在实现那套机制的地方，作者留了这么一段：

> TODO：我觉得我这儿犯傻了，我认为这一整套其实可以实现得便宜得多——只保留最后一次旋转、把其余的旋转和反旋转全部去掉。为什么？因为卷积完全可以把这些旋转折进自己的权重里，如果确实需要的话。值得以后测一下——不过暂时留在这儿，作为我们走到这一步的思路轨迹的记录。

一个人维护七年半的项目，把自己想岔的路留在正式代码里当路标。我看到这段的时候愣了一下。
