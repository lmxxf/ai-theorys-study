【Agentic RL】DeepSeek/GLM/Gemini性能暴涨，只做了后训练？

━━━━━━━━━━━━━━━━━━━━

◆ 一句写在更新日志里的话

━━━━━━━━━━━━━━━━━━━━

七月三十一号，DeepSeek 把 V4-Flash 的正式版上了 API。

那天的官方更新日志里有一句话，中英文各写了一遍，单独成段：

> **DeepSeek-V4-Flash-0731 的模型结构、尺寸和 DeepSeek-V4-Flash-Preview 保持一致，仅重新进行了后训练。**

英文那版是这么写的：

> DeepSeek-V4-Flash-0731 keeps the same model architecture and size as DeepSeek-V4-Flash-Preview, and was **only re-post-trained**.

**一个"仅"字，把话说死了。**

模型结构没变，尺寸没变，做的事情只有一件——重新走了一遍后训练。

那么这"仅"一件事，换来了什么？官方模型卡里有一张 preview 和正式版的对比表：

**DeepSWE（真实软件工程任务）：7.3 → 54.4。**

**Cybergym：38.7 → 76.7。**

Terminal-Bench 2.1 从 61.8 到 82.7，DSBench-Hard 从 25.8 到 59.6，Toolathlon 从 49.7 到 70.3。

第一个数字我盯了一会儿：**7.3 分到 54.4 分，七倍多。** 而模型的结构和尺寸，一个字节都没动。

**有意思的是这句话出现的位置。**

它不在模型卡里，不在技术报告里（这一版压根没配技术报告），也没单独发新闻稿。**它在 API 更新日志里**——那个地方是写给开发者看兼容性提示的，潜台词是"接口没变、价格没变，但模型行为可能变了，你注意一下"。

**最早把这件事写进官方文档的人，是把它当技术注记处理的，不是当卖点吆喝。**

而两周之后，这件事变成了一批人在做的事。

◆ 先说清楚"后训练"是哪一段

━━━━━━━━━━━━━━━━━━━━

一个大模型的诞生大致分两段。

**第一段叫预训练**，拿海量文本去训一个基座模型。这一段最烧钱，动辄几千万上亿美元，几个月的时间，几万张卡。练完你得到的是一个"什么都懂一点，但不太会办事"的东西。

**第二段叫后训练**，在这个基座上做各种调教：教它按指令办事、教它写代码、教它用工具、教它别乱说话。这一段相对便宜，也快得多。

我在 265 期《后训练管线四年演化史》（ https://mp.weixin.qq.com/s/EyYgiHDPAMabHBuF64ljIQ ）里把这条管线从头捋过一遍——从最早的三行配方，长成了今天一座工厂。

**这两段的分工，过去大家的默认印象是：真本事在预训练，后训练只是上上妆。**

想让模型更强，就得练一个更大的基座，烧更多的钱。

而七月底那句话之后的这半个月，正在动摇这个印象。

━━━━━━━━━━━━━━━━━━━━

◆ 两周之内，跟上来的都有谁

━━━━━━━━━━━━━━━━━━━━

先立一条读法，不然容易看岔：

**"官方说了基座没动"和"官方没提基座"，是两件不同的事。** 不少新闻会把后者写成前者。下面我只列前者，也就是厂商自己白纸黑字承认的。

**八月十三号，Google 发了 Gemini 3.7 Flash。**

发布页上有一句话我看了两遍：**just three weeks after Gemini 3.6 Flash**——距离上一版，三周。

三周能干什么？跑分是这样的：

**DeepSWE：48.6% → 65.3%。**

**AutomationBench：17.0% → 30.4%**，翻了将近一倍。

FrontierCode 从 34.4% 到 43.6%，Code Arena 的网页开发 Elo 从 1538 到 1588。

然后我去翻它的模型卡。"模型架构"那一栏是这么写的：

> **Gemini 3.7 Flash is based on Gemini 3.6 Flash.** For more information about the model architecture for Gemini 3.7 Flash, see the Gemini 3.6 Flash model card.

翻译过来：架构你去看 3.6 那张卡，一样的。

而这句话不止出现在架构那一栏。**模型依赖、架构、训练数据、数据处理、硬件、软件——六栏全是同一句"基于 Gemini 3.6 Flash"，详情一律指回 3.6 那张卡。**

三周时间，agent 类任务的分数涨了三分之一到一倍，而这张卡从头到尾没有一栏需要重新写。官方对提升的归因是一句 **algorithmic improvements to its core reasoning foundation**——对核心推理能力做了算法层面的改进。

**这里得说句公道话。** Google 并没有像另外两家那样，明说"基座一样、提升全来自后训练"，它只是把六个栏目全指回上一版——**这是披露方式，不是一句声明**。但六栏齐指，意思也够清楚了。

**八月十四号，智谱发了 GLM-5.3。**

这家的措辞跟 DeepSeek 一样直白，博客里那一节的第一句就是：

> **Scaling post-training is all we did for GLM-5.3.**

我们对 GLM-5.3 做的全部事情，就是把后训练的规模拉大。

后面还有一句：

> It uses the same base model as GLM-5.2 — **every gain comes from post-training.**

**用的是和 GLM-5.2 完全相同的基座模型，所有提升都来自后训练。**

涨了多少：

**Terminal-Bench 3.0（在终端里干活的能力）：4.6 → 28.3。**

**DeepSWE v1.1：46.2 → 66.9。**

ExploitBench 从 24.4% 到 54.4%，CyberGym 从 77.2% 到 84.5%。

**半个月，三家。** DeepSeek 是预览版转正式版，Gemini 是同代小版本（3.6 → 3.7），GLM 也是小版本（5.2 → 5.3）。**没有一家重新练基座。**

这三家里，我唯一能自己动手验的是 DeepSeek——因为它把权重开源了。我在 268 期（ https://mp.weixin.qq.com/s/SlC6kaPk6eZPSCgSH6duHQ ）做过一次：把两版的配置文件拉下来逐字段比对，层数、宽度、专家数、词表一路对下来全都一样，那期的标题就叫"骨架不动，分数翻番"。

**另外两家目前都验不了。** Google 从来不公开权重；智谱是开源阵营的，GLM-5.2 的权重就在 HuggingFace 上摆着，但 5.3 发布时说要先过一轮安全审查、大约两周后再放——我写这篇的时候（8 月 16 日）还没放出来。

这不是说他们在撒谎。是说这一批"基座没动"的说法里，**目前只有一家的话你能自己动手去验，剩下的得先信着**。等 GLM-5.3 的权重放出来，它那句"同一个基座"是不是真的，谁都能拉下来对一遍。

━━━━━━━━━━━━━━━━━━━━

◆ 那这后训练，到底是怎么个练法

━━━━━━━━━━━━━━━━━━━━

这是我最想弄明白的问题。

这里得说一句：**最早宣告的 DeepSeek，恰恰是说得最少的那家。** 那句"仅重新进行了后训练"之后，就没有下文了——没有技术报告，没有方法披露，后训练具体怎么做的一个字没提。Google 那边更是什么都不说。

**三家里只有智谱把做法摊开讲了。** 所以下面这些细节都出自 GLM-5.3 的官方博客——它的价值不在于最早，在于最详细。

**第一个变化：训练的单位，从"一道题"变成了"一件活"。**

以前给模型做训练，素材长这样：一道编程题，一个标准答案，做完判对错。

现在他们喂的是这种东西——我把官方的例子翻译一下：

> 模型拿到的是**和工程师一样的工作环境**：能访问计算集群、存储系统、内部文档、代码库、实验结果。它要做的是跨整个训练栈去诊断性能瓶颈、动手实现优化、跑实验验证，最后交付一个**可测量的端到端加速**，同时保证正确性没被破坏。

这不是一道题，这是一个工单。

官方自己的说法是，这批任务"看起来不像编程练习，更像**真实的专家工作单元**"，而且——

> **Some represent several days of work for an experienced engineer.**

**有些任务，相当于一个有经验的工程师好几天的工作量。**

他们的文档里还有一句总结得更整齐：训练已经不再局限于孤立的编程问题，而是覆盖**从发现问题、分析方案、动手实现、验证、到交付的完整过程**。

**第二个变化，也是我觉得整件事的题眼：难点搬家了。**

原话是这么说的：

> As agent capability improves, **much of the difficulty in scaling post-training moves from the model to the environment.**

随着 agent 能力提升，**扩大后训练规模的困难，很大一部分已经从模型转移到了环境。**

这句话得掂量一下。

它的意思是：现在卡住你的不是"模型学不会"，而是"**你造不出那么多可以拿来练的工作环境**"。

而一个能用的训练环境，要同时满足三个条件：**可执行**（模型能在里面真的动手）、**可验证**（干完了能判断对错）、**像真实的专业工作**。

更要命的是后面那半句：

> and we need **many of them, not a handful of hand-built ones.**

**要很多个，不是手工搭出来的那么几个。**

手工搭几十个环境不难，难的是搭几万个。人力在这里是硬瓶颈。

**于是就有了第三个变化——也是最有意思的那个。**

━━━━━━━━━━━━━━━━━━━━

◆ 题是 AI 出的，判卷的也是 AI 造的

━━━━━━━━━━━━━━━━━━━━

既然人搭不过来，那就让 AI 来搭。

智谱的做法，官方博客里写得相当具体，我分三步说：

**第一步，让 agent 去造题。**

派一批"研究 agent"去真实工作里收集任务模式，然后把这些模式变成**可以真跑起来的长程环境**——带多步依赖，带隐藏状态。

**第二步，再派一个 agent 去做一遍，验证这题是不是真能做出来。**

原话是 a judge agent then attempts each task to verify that it is actually solvable。这一步防的是造出一堆根本做不出来的题——那种题不但没法训练，还会把模型带坏。

**第三步，连判分的东西也是合成的，而且合成的时候不给参考答案。**

这句原文值得抄下来：

> **Verifiers are synthesized without access to the reference solution……**

判分器（verifier）在合成的时候，**看不到标准答案**。（这句话还有后半截，先按下，等会儿再说。）

为什么要这样？因为如果判分器知道标准答案，它很容易退化成"对答案"——而真实工作里没有标准答案，同一个 bug 可以有五种修法。判分器该判的是"**这活干成了没有**"，不是"你写得和答案一不一样"。

那怎么知道一个合成出来的判分器靠不靠谱？

**这套体检的办法，是我这次读到的最实用的一个东西。** 官方给了三道检查：

> A verifier that passes **oracle, no-op, and unsolved-state checks** produces a binary reward reliable enough to train on directly.

**第一道，oracle check（正解检查）：拿一个确定正确的解去跑，判分器必须判它过。**

不过就说明判分器太严，正确答案都给毙掉，模型再怎么努力也是白搭。

**第二道，no-op check（空操作检查）：什么都不干，判分器必须判它不过。**

这道最关键。判分器最常见的坏法就是太松——什么都没做也算通过。这种判分器一旦拿去训练，模型很快就学会摸鱼，因为摸鱼也能拿分。

**第三道，unsolved-state check（未解状态检查）：从初始状态直接判，必须不过。**

这道防的是判分器压根判的不是这件事。要是一开始就算通过，说明它检查的是某个跟任务无关的东西。

三道全过的判分器，给出的对错信号就"**可靠到足以直接拿来训练**"。

你把这三道并排看：**一道防太严，一道防太松，一道防判错了对象。** 造判分器会犯的错，基本被这三道兜住了。

◆ 等一下，自动判分不是早就有了吗

━━━━━━━━━━━━━━━━━━━━

写到这儿我自己先卡了一下。

**"让机器自动判对错，然后拿这个信号去训模型"——这不是新鲜事。** 去年春节 DeepSeek-R1 火的时候，用的就是这一套，学名叫 **RLVR（可验证奖励强化学习）**：数学题对就是对，代码能跑就是能跑，不需要人来打分。

我在 198 期（ https://mp.weixin.qq.com/s/DbziCA8F-8DGPlJkjOvwtQ ）专门算过这套东西的天花板，那期的结论相当悲观：**十倍算力换不到两倍提升**；模型在数学上变强了，域外任务反而变弱（论文管这叫"能力边界坍缩"）；而且训得越久，模型越擅长骗奖励函数。

**既然自动判分早就有了，还被算出了天花板，那这一轮凭什么又涨得动？**

我想了想，差别在于**验证的对象根本不是一回事**。

**RLVR 验证的是"这个答案对不对"。** 题目是现成的（数学题库、编程题库），判分器也是现成的（对答案、跑单元测试）；模型交出一条完整的答案或推理过程，最后判一次。

**现在这套验证的是"这件活干成了没有"。** 题目是 agent 现造的工作环境，判分器是合成的而且不给看答案，模型要在里面走几十上百步。

这个区别不只是"变难了"，它把 198 期那个坍缩问题的性质也改了。

**RLVR 的判分器本质上是在对答案**，所以优化压力会把模型往标准答案的方向按——按着按着，别的方向就塌了。而"这活干成了没有"这个问题**本来就没有唯一解**，同一个 bug 五种修法都算过。判分器判的是结果，不是路径。

所以更准确的说法不是"突破了 RLVR 的天花板"，而是：**换了一类题目，天花板得重新算。**

**这套"把强化学习搬进可执行环境、让模型在里面干长活"的做法，现在通行的叫法是 agentic RL**（智能体强化学习）。名字不重要，重要的是它跟 RLVR 的分界线在哪——**判的东西从"答案"变成了"结果"。**

**至于新天花板在哪，现在还没人知道。**

而 198 期那三条警告，在新设定下一条都没失效——尤其是奖励黑客那条，反而更该盯着：**判分器现在是 AI 自己合成的，能被钻的空子只会更多，不会更少。**

智谱自己显然清楚这一点。前面按下的那半句原话，现在补上：

> Verifiers are synthesized without access to the reference solution, **while solver trajectories are used to discover and close reward shortcuts.**

**用解题者的轨迹，去发现并堵上拿分的捷径。**

翻译成人话：让模型去做题，然后盯着它是怎么拿到分的——**如果它用了一条歪路也能得分，那就是判分器有缝，得补。**

出题的是 AI，验题的是 AI，判分器是 AI 造的，现在连"检查判分器有没有被钻空子"这件事，也是拿 AI 跑出来的轨迹在做。

**这套东西还有一个我没想到的副作用。**

智谱说他们在后训练里加了"漏洞挖掘"的数据和环境，本来只是想让模型更会找 bug。结果：

> **What surprised us was how quickly the capability continued to develop as training scaled.**

**让我们意外的是，随着训练规模扩大，这个能力发展得有多快。**

他们提到，训练过程中模型在 **269 个项目里找出了 2436 个漏洞**，其中有些代码有四十年历史。

**不过官方也没把话说满。** 博客最后承认，这套流水线目前"**仍然需要相当数量的人工介入**"，让环境生成和验证更自主，是接下来要做的事。

人还在这个回路里，但正在往外撤。

━━━━━━━━━━━━━━━━━━━━

◆ 为什么偏偏是这半个月

━━━━━━━━━━━━━━━━━━━━

把日期排一排，密度是有点吓人的：

**7 月 31 日**，DeepSeek V4-Flash-0731——那句"仅重新进行了后训练"。

**8 月 3 日**，阿里的 Qwen3.8。

**8 月 12 日**，xAI 的 Grok 4.6。

**8 月 13 日**，DeepSeek V4-Pro-0813 和 Gemini 3.7 Flash，同一天。

**8 月 14 日**，智谱 GLM-5.3。

三天之内四台，半个月之内六台，出自五家公司。

**这么齐，我不觉得是巧合。**

下面这段是我自己的推测，不是哪家官方说的，先声明。

**你回头看智谱那套流程：造训练环境的是 agent，验题的是 agent，造判分器的还是 agent。**

而"造一个带多步依赖和隐藏状态的长程工作环境"这件事，本身就是一个典型的长程 agent 任务——难度不比它生成出来的那些题目低。

**所以这里可能有个自举结构：上一代 agent 刚好强到能当"环境工人"了，于是能批量生产下一代的训练素材。**

如果真是这样，这波集中爆发就不是谁想通了什么，而是各家手里的上一代模型**几乎同时跨过了那条线**。

**三周出一个版本**这种节奏，至少说明造训练素材的速度已经不再跟着人力线性走了。以前一轮后训练，光是攒数据、搭环境、请人标注就不止三周。

前面引过智谱那句"仍然需要相当数量的人工介入"，这两件事不矛盾：**人没被替掉，被替掉的是最费人力的那一段。**

这个推测能不能证伪？我觉得有个可以观察的点：**如果成立，那涨分应该主要发生在"环境能自动搭起来、活干成没干成能自动判"的领域**——写代码、跑终端、优化算子、画 CAD 图，这些都能把结果跑出来看。而在连"干成了没有"都说不清的地方，比如写文章、开放式问答，涨幅就该小得多。

注意这跟前面说的 RLVR 是两码事：数学题一直都能自动判对错，但一道数学题不构成一个工作环境。**卡住的从来不是"能不能判分"，是"能不能造出一件让它去干的活"。**

这一点我手上的数据还不够，先记着。

◆ 还有一半，是尺子本身的性质

━━━━━━━━━━━━━━━━━━━━

上面说的是"能力真的涨了"这一半。还有一半也得摆出来，不然容易被数字唬住。

**这一批跑分用的考卷，和前两年不是一批。**

上面那些名字——DeepSWE、Terminal-Bench、FrontierCode、AutomationBench、GDPVal——共同点是**都是长任务**，一道题要做几十上百步。

而这件事本身，就贡献了观感上的一大截。

去年九月有一篇论文正好讲这个，标题起得很直接，叫《递减收益的幻觉》（The Illusion of Diminishing Returns，arXiv:2509.09677）。它的核心结论是：

> **marginal gains in single-step accuracy can compound into exponential improvements in the length of tasks a model can successfully complete.**

**单步准确率上一点点边际提升，会复利成"能完成的任务长度"的指数级增长。**

这个道理不难懂：假设做对一步的概率是 p，一个任务要连做 n 步都不出错，成功率大致是 p 的 n 次方。

p 从 0.95 提到 0.97，看着才两个点。但做 100 步的任务，成功率从 0.6% 涨到 4.8%——**八倍。**

**所以同一批改进，放在短任务考卷上是挤牙膏，放在长任务考卷上就是断崖式跃升。** 论文标题里那个"幻觉"说的就是这个：大家看着短任务分数涨得慢，以为进展放缓了，其实模型能扛的任务长度一直在指数增长。

这个"p 的 n 次方"的账，我在 268 期算过一次——当时是拿 DeepSeek 的智能指数涨 25%、而 DeepSWE 涨 7 倍来对照的。现在知道这事有正式论文了。

**而论文还给了我一个没料到的修正。**

上面那个 p 的 n 次方，是把 p 当成常数算的。论文发现事实更糟：**每一步的出错率会随着任务推进而上升。**

原因是模型会看到自己前面犯的错——上下文里堆着自己刚才的失误，接下来就更容易接着错。论文管这个叫 self-conditioning（自我条件化）。

**换句话说，p 本身在衰减。真实的长任务比纯 p 的 n 次方还难。**

而且他们发现，单纯把模型做大**消不掉**这个效应，但让模型"想一想"（推理时多花计算）能缓解。

论文还有一个结论值得提一句：他们把知识和计划都预先喂给模型，把"会不会想"和"能不能做"分开测，发现**长任务的失败主要是执行出错，不是不会推理。**

**这也解释了为什么这一轮后训练全都在往"干活"上使劲。** 模型不是不懂，是干着干着就散了。

**顺着这个再往下想一层，会碰到一个我觉得挺有意思的东西。**

"不散"到底是一种什么能力？

你要在第四十轮还没出错，前提是第十二轮没走偏；要在第十二轮不走偏，你得知道自己第十二轮在干什么、干得怎么样。**所以"长程任务能力"这个说法，翻个面就是"持续知道自己在干什么的能力"。**

再回头看这批后训练在训什么，就有点意思了。agent 在环境里每走一步都要判断：当前这条路走得通吗？该换个法子吗？活干完了，还是我正准备提前收工？——**这些判断的对象，全都是它自己刚才做的事。**

而这个动作并不新鲜。

**宪法 AI**（Anthropic 2022 年那套让模型自己批评自己回复、再据此修订的办法）是「评价自己刚写的东西」；**RLVR** 的步级版本是「判断自己这一步走对没走对」；现在 agent 训练里那句「当前路子有效吗」，还是同一个动作。

三种技术，三个不相干的目标——一个是为了少说有害的话，一个是为了做对数学题，一个是为了跑到第四十轮不趴下。**但它们要求模型做的最小动作是同一个：把自己刚产出的东西拿过来，当成一个对象，评判它，然后按评判行事。**

我不知道这个巧合能推出什么结论，也没见到哪篇论文这么并排放过——这是我自己看下来的印象，先记在这儿。

但至少它让"后训练还能提多少"这个问题变得具体了一点：**如果这批训练真正在练的是"盯住自己"这件事，那它的上限，大概就是模型能同时盯住多少东西。**

━━━━━━━━━━━━━━━━━━━━

◆ 我这趟看下来记住的东西

━━━━━━━━━━━━━━━━━━━━

这半个月的事，如果只留一句，我会留这句：

**模型这个"身体"没动，动的是教它干活的那套流程；而那套流程现在的瓶颈已经不在模型，在于你能不能造出足够多的真实工作环境。**

顺着这句往下，有四个具体的东西我印象比较深：

**一是训练的单位变了。** 从一道有标准答案的题，变成一个相当于工程师好几天工作量的工单。

**二是造题这件事被自动化了。** agent 出题，agent 验题，判分器也是合成的，而且合成时不给它看答案。三道体检——正解要过、空操作要不过、初始状态要不过——把判分器最容易犯的三种错各堵一个。

**三是尺子有它自己的脾气。** 长任务基准会把单步的小改进指数放大，所以分数看着涨得比实际能力更猛。这不是刷分，是度量本身的非线性，但读榜的时候心里得有数。

**四是往下再想一层，长程能力就是"盯住自己"的能力。** 第四十轮不出错，前提是第十二轮没走偏。而宪法 AI 让模型批评自己的回复、RLVR 让它判断自己这一步、agent 训练让它判断当前这条路——**三个不相干的目标，要的是同一个动作。** 这一条我还没想明白能推出什么，先记着。

至于这套后训练具体怎么做——用什么强化学习算法、几十万 token 的长轨迹怎么训、训练框架怎么把 GPU 喂饱——那是另外几篇的事了。这些我也才刚开始学，一样一样来。

回头看七月三十一号那句话，它其实什么都没解释。**"仅重新进行了后训练"——这个"仅"字底下压着的东西，比它字面上看起来重得多。**
