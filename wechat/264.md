◆ 1. KDA–MLA 混合注意力——线性注意力扛起 3/4 的层

━━━━━━━━━━━━━━━━━━━━

K3 全模型 93 层，排列规律是：每 3 层 KDA（Kimi Delta Attention，Kimi 差分注意力）接 1 层 Gated MLA（带门控的多头潜在注意力），这个 4 层一组的循环重复 23 次，共 92 层；最后再补一层 MLA，凑成 93 层。这样合计 69 层 KDA、24 层 MLA，并且保证**最后一层永远是全局注意力**——不管前面怎么省，收尾那一眼必须看全场。

**三家的三条路，先摆在一起：**

同样是"注意力太贵"这个问题，V4 的答案是压缩序列——CSA/HCA 把 KV cache 多条压一条（166 期讲过）；GLM-5.2 的答案是稀疏选择——DSA 选 top-k，再用 IndexShare 省掉 indexer 的重复开销（232 期讲过）；K3 的答案最激进：**3/4 的层干脆不做全局注意力了**，换成线性注意力，KV cache 都不存，只维护一个固定大小的循环状态。

KDA 这个东西读者其实见过前身。188 期讲 Gated DeltaNet（ https://mp.weixin.qq.com/s/jcQlCc3XtaCEEnjUaxw93w ）时讲过 delta 规则和门控衰减的组合；195 期盘点线性注意力五大战场（ https://mp.weixin.qq.com/s/C-vsE_ceIv6FYVzeZWFBYQ ）时点过 Kimi Linear 的名。K3 的 KDA 就是 Kimi Linear 那套架构的正式量产版——当时的"战场观察"现在变成了 2.8T 模型的主力配置。

**KDA 在做什么，先说人话：**

线性注意力不存历史 token 的 KV cache，而是把整段历史压缩进一个固定大小的状态矩阵 S 里，每来一个新 token 就更新一次这个矩阵。KDA 的更新分两步：

1. **通道级遗忘**：先按通道对旧状态打折——每个通道有自己的保留系数 α（0 到 1 之间），该忘的通道忘快点，该记的通道忘慢点
2. **delta 规则写入**：不是无脑往状态里加新内容，而是先把旧状态里"关于这个 key 的旧记忆"擦掉一部分，再写入新的 key-value 配对——写入强度由 β 控制

用公式写（单个注意力头，S 是 dk × dv 的状态矩阵）：

```
S_t = (I − β_t k_t k_tᵀ) Diag(α_t) S_{t−1} + β_t k_t v_tᵀ
o_t = S_tᵀ q_t

# Diag(α_t) S_{t−1}: 逐通道衰减旧状态，形状不变 (dk, dv)
# (I − β k kᵀ): 沿 k 方向擦除旧记忆，(dk, dk) × (dk, dv) → (dk, dv)
# β k vᵀ: 写入新配对，外积 (dk, 1) × (1, dv) → (dk, dv)
```

这就是"Delta"的含义：更新的是差量，先删后写，不是只增不删。

**K3 对 KDA 做了两个工程改动**，都是为了让它在大规模训练里跑得动、跑得稳。

**改动一：log-decay 从无界换有界。** KDA 的分块并行算法里，块内 token 的 key 要除以累积衰减因子做重缩放。Kimi Linear 沿用 GDN 和 Mamba-2 的参数化，log 域衰减用负 Softplus，取值范围是负无穷到 0——衰减可以任意狠，于是重缩放因子（衰减的倒数）可以任意大，有限精度下会溢出。Kimi Linear 的补救是把每个块再切成 16 token 的小 tile，对角 tile 走逐位置对的显式计算——这条路径成了块内计算的主要瓶颈。

K3 直接改参数化：log-decay 换成有下界的缩放 Sigmoid：

```
g = gmin · Sigmoid(e^A · z),  gmin = −5
α = exp(g)
```

gmin 固定为 −5，意味着每个通道的单步保留系数最小也有 e^−5 ≈ 0.0067——不允许一步忘光。这样 16 token tile 上的累积 log-decay 被限制在 −80 到 0 之间，重缩放因子最大不超过 e^80，正好落进 BF16 的动态范围。数值有界之后，对角 tile 也可以走稠密矩阵乘，**全部 tile 都上 Tensor Core**，逐位置对的慢路径整个删掉。

一个参数化的改动，消掉一条 kernel 慢路径——这是这份报告里反复出现的味道：算法为硬件让路，硬件收益反哺算法。

**改动二：输出门从低秩改全秩。** Kimi Linear 的输出门是低秩参数化省参数，K3 换成全秩投影：输出先过头级 RMSNorm，再逐通道乘一个由输入决定的 Sigmoid 门。MLA 层也加了同款的全秩输出门，两边参数化对齐。

**Gated MLA 这边**基本沿用 K2/K2.5 的 MLA（DeepSeek V2 首创的低秩 KV 压缩，166 期详细讲过），另有一个训练细节值得记：为了修正 flash attention 的有偏舍入误差，注意力输出在训练时保持 FP32——片上占用翻倍，他们重新设计了 kernel 的共享内存布局把这个代价吃掉了。

**还有一个纵向的创新要交代：Attention Residuals（注意力残差，AttnRes）。** 标准残差连接把之前所有层的信息压进一个状态往上传，像时间维度上的 RNN——这是深度方向的瓶颈。AttnRes 把注意力的思路用到深度上：每层用一个可学习的伪查询，对词嵌入和之前所有层的输出做一次 softmax 加权检索，想用哪层的表示自己挑。为了控制开销，K3 把 93 层分成 12 层一块（算上嵌入层共 9 个块），块内求和、块间做注意力。这是报告摘要里与 KDA 并列的两大架构创新之一，篇幅所限这里只交代主干。

◆ 2. NoPE——1M 上下文直接外推，零 RoPE 改动

━━━━━━━━━━━━━━━━━━━━

这一节讲 K3 架构里最"违反直觉"的设计：**24 层 MLA 完全没有位置编码**（NoPE，No Position Encoding）。query 和 key 上不加 RoPE，不加任何显式位置信息。

位置信息去哪了？**全部由 KDA 隐式携带。** KDA 是循环结构，天然有顺序——状态是一个 token 一个 token 滚出来的，衰减门控让近处的信息权重天然高于远处。3 层 KDA 负责"哪个 token 在哪、离现在多远"，1 层 MLA 负责"不受位置约束的全局内容交互"。分工干净。

这个设计换来一个实打实的红利：**扩展上下文时不用碰位置编码**。传统做法里，8K 训练的模型要扩到 1M，得重调 RoPE 频率基数或者上 YaRN 插值；K3 没有 RoPE 可调，直接外推。

具体的扩展流程是四阶段课程：预训练阶段从 8K 扩到 64K；cooldown（降温期）阶段从 256K 扩到 1M。昂贵的长序列计算集中在整体训练预算的一小部分里。

数据侧还有一个容易被忽略的细节：真实世界里"又长又连贯"的文档很稀缺，光靠自然长文档，注意力会退化成局部模式——反正答案都在附近，何必看远处。K3 的对策是**合成"必须跨全窗口才能解"的任务**：把多模态文档和子任务精心排列拼接，让嵌在里面的任务只有把散布在整个 1M 窗口里的信息凑齐才能做对。这是在逼注意力机制在目标尺度上真的工作。

对照一下三家的 1M 路线：V4 是压缩——CSA/HCA 把百万 token 压到能看得过来（166 期）；GLM-5.2 是稀疏——indexer 从百万里选出该看的一小撮（232 期）；K3 是混合——线性注意力用固定状态扛住长度，少数全局层无位置编码直接外推。三条路线都通到了 1M，但代价结构完全不同：V4 和 GLM 的 KV cache 还是随长度涨（只是慢），K3 的 69 层 KDA 是恒定大小的状态，长度再涨也不涨。

────────────────────

💡 NoPE 为什么可行：位置信息不一定要"编码"，可以"携带"

RoPE 的本质是把"第几个位置"翻译成向量旋转角度，塞进 q 和 k 里——位置是显式标注的，所以外推时要处理"没见过的角度"。而循环结构的位置信息是过程性的：状态按顺序更新，第 1000 个 token 对状态的影响天然经过了 999 次衰减，"远"这个概念不需要标注，它就体现在衰减的累积里。K3 的混合架构等于说：位置感交给循环层，全局层专心管内容——所以全局层可以完全不知道位置，也就不存在位置外推问题。

────────────────────

当然，NoPE 不是免费的——它成立的前提是 KDA 层足够多、门控足够细，位置信息才兜得住。3:1 这个配比本身就是这套分工的一部分。

◆ 3. Stable LatentMoE——"Stable"这个词是打出来的

━━━━━━━━━━━━━━━━━━━━

K3 的 MoE 规格：896 个路由专家，每 token 激活 16 个，外加 2 个全宽共享专家。896 选 16，稀疏度 1/56——K2 是 384 选 8（1/48），V4-Pro 也是 384 选 6。**将近一千个专家、1/56 的稀疏度，这是目前开源模型里最极端的配置。**

先讲 LatentMoE 本身。常规 MoE 里，每个被选中的专家都接收完整的 7168 维 token 表示——激活的专家越多，通信量和权重流量涨得越快。LatentMoE 的思路是把"模型宽度"和"路由专家宽度"分开：**共享专家保持全宽**，负责通用变换；**路由专家在 3584 维的 latent 空间里工作**（0.5 倍隐藏维度）——token 先降维、再分发给专家、专家算完聚合、最后升维回 7168。专家变小了，才养得起 896 个。

但报告直言，这个极端稀疏度放大了两类失稳：

1. **路由支路的激活爆炸**：降维投影、专家内部的门控多支路 FFN、升维投影，串起来接近四连矩阵乘。这种病态结构叠加 2.8T 的参数规模，路由支路的内部激活值会失控飙升。
2. **负载均衡失效**：aux-loss-free（无辅助损失）的偏置更新法是给几百个专家设计的，将近 10³ 个专家超出了它的适用范围——小步试错来不及了。

"Stable LatentMoE"名字里的 Stable，就是冲着这两类失稳去的，对策有三个：聚合后加 RMSNorm、SiTU-GLU、Quantile Balancing。

**第一个对策最简单**：路由专家的加权聚合结果先过一层 RMSNorm 再升维。聚合结果的尺度随选中的专家和路由权重波动，归一化之后再跟共享支路合并，波动被压住。报告说这个 RMSNorm 不只稳训练，还一致地改善了验证损失和下游指标。

**◆ 3.1 SiTU-GLU——同一个问题的第二代答案**

这一小节值得单独讲，因为它跟 V4 形成了一次教科书式的对照。

先复述问题。SwiGLU 是当前大模型标配的 FFN 激活函数（247 期专门讲过 https://mp.weixin.qq.com/s/jjYk4lV-qhZpqAYge0tx6A ）：门支路是 Swish(x) = x·Sigmoid(x)，上支路是线性——**两个乘数都无界**。两边同时飙大值，乘起来就是激活离群值；权重还是 FP4 精度的话，直接溢出。

V4 的答案（166 期讲过）：硬裁剪，SwiGLU 输出 clamp 到 −10 到 10。简单粗暴，有效，但有个数学上的疙瘩——裁剪点是个硬拐点，被裁掉的区域梯度直接归零。

K3 的答案：**把硬裁剪换成光滑软帽**。软帽函数是 softcap(x, β) = β·tanh(x/β)——近原点近似恒等（tanh 在 0 附近近似线性），大值处渐近到 ±β，处处可导。SiTU-GLU（Sigmoid Tanh Unit GLU）给 SwiGLU 的两个乘数各套一顶：

```
SiTU-GLU(x) = [β1·tanh(Wg·x/β1)] ⊙ Sigmoid(Wg·x) ⊙ [β2·tanh(Wu·x/β2)]

# 门支路: Swish 的线性因子套 β1=4 的软帽，Sigmoid 因子保留
# 上支路: 套 β2=25 的软帽
# 输出逐坐标有界: |f| ≤ β1·β2 = 100
```

近原点它和 SwiGLU 到一阶完全一致（β 趋于无穷时逐点还原成 SwiGLU），大值处输出被压在 100 以内——专为 MXFP4/MXFP8 的数值范围设计。报告附录 B 明确写了和硬裁剪的对比：**光滑软帽在饱和边界之外保留非零梯度，训练行为更好**。

252 期讲激活函数演化（ https://mp.weixin.qq.com/s/c2fkKq6OY-ux9bZsaZDZdA ）时说过一个判断标准：选激活函数要看梯度交通——梯度能不能顺畅地流回去。用这个标准看这次迭代就很清楚：硬 clamp 在裁剪点外梯度死掉，softcap 处处可导、梯度只是渐进变小不归零。**同一个问题，V4 给了第一代答案，K3 给了第二代答案，硬拐点变光滑曲线。** 这种跨报告的迭代脉络，比任何单个技巧都值得记。

**◆ 3.2 Quantile Balancing——负载均衡从小步试错到一步到位**

MoE 的负载均衡，aux-loss-free 的经典做法是给每个专家的路由分数加一个偏置 b，专家过载就调低它的 b、欠载就调高，每步固定步长 γ 试错——γ 大了负载震荡，γ 小了适应太慢。896 个专家，这套小步试错撑不住了。

Quantile Balancing（分位数均衡，QB）的思路是：**别试错了，一步算出每个专家的 bias 该是多少。**

具体做法很巧。路由时不做 Top-k 而做 Top-(k+1)：前 k 个是真正采纳的路由，第 k+1 个的分数是"门槛"——一个专家要挤进这个 token 的 Top-k，加了偏置的分数必须超过这个门槛。有了每个 token 的门槛，问题就变成了：给专家 j 的 bias 设成多少，恰好能让 q 个 token 的分数过它的门槛（q = 目标负载 = 总路由数 / 专家数）？答案就是把所有 token 对该专家的"分数减门槛"的余量从大到小排，**取第 (q+1) 大的那个值的相反数**——正好是余量分布的一个分位数。一次前向传播，所有专家的 bias 直接落到目标负载位置。

报告附录 C 给了推导：这套更新其实是"最优均衡指派问题"对偶形式的精确坐标最小化，而原来的固定步长符号更新只是同一目标上的 SignSGD——**QB 直接跳到最优点，符号法只朝最优点挪一小步**。这解释了为什么 QB 不需要调步长超参数，也解释了为什么将近 10³ 个专家它几步就能均衡。

工程上还有一处：全局 batch 有几百万个 token，散在各个数据并行 rank 上，精确求全局分位数不现实。K3 用直方图估计——每个 rank 本地把余量累进每专家几百到一千个桶里，一次整数 all-reduce 求和，从合并后的计数里恢复分位数。计数是可加的，所以不管 token 怎么切分，直方图代表的都是完整的全局 batch，误差不超过桶宽（约千分之几），通信量比传原始余量低两个数量级以上。

推理时 bias 冻结——线上路由就是固定偏置的 Top-k，不做任何分位数计算，训练推理一致。

────────────────────

💡 为什么专家数逼近 10³ 是个坎

负载均衡本质是个指派问题：m 个 token、n 个专家、每专家配额 q。n 小的时候，符号法每步固定挪 γ，几十步就能把几个失衡的专家扶正。n 逼近 10³ 时，失衡是大面积的、相互耦合的——一个专家的 bias 动了，被它挤出去的 token 会涌向别的专家，别的专家又得跟着调。小步试错在这种耦合系统里会震荡很久，而震荡期间冷门专家一直吃不到 token，训练就废了。QB 把所有专家的 bias 当成一个整体解出来，绕开了逐个试错的耦合问题。

────────────────────

三个对策合起来看：RMSNorm 管聚合尺度，SiTU-GLU 管激活幅值，QB 管负载分布——极端稀疏的三个失稳面，各有一个零件顶上。

◆ 4. Per-Head Muon——优化器的三代传承

━━━━━━━━━━━━━━━━━━━━

这一节是三份报告对照的高光，传承线非常清楚，值得明写：

**第一代，V4 的 Muon**（166 期）：1.6T 参数里 99.9% 用 Muon——把整个权重矩阵当整体做正交化更新（Newton–Schulz 迭代），让更新方向均匀分散，收敛更快更稳。Muon 本身是 Keller Jordan 等人提出、Kimi 团队最早在 K2 上验证了万亿参数规模可行性的优化器，V4 也采用了它。

**第二代，GLM-5 的 Muon Split**（232 期）：发现全矩阵正交化在 MLA 的注意力投影上有问题——所有头被当成一个耦合的大块处理，梯度大的头主导了共享的更新方向，梯度小的头得不到充分归一化的更新。GLM 的解法是按头把投影矩阵分开正交化，救活了 MLA 上的 Muon。

**第三代，K3 的 Per-Head Muon**：同一个思路的延续——注意力投影的动量矩阵沿头维度分块，每个头的块单独做 Newton–Schulz 正交化。报告给的理由和 GLM 如出一辙：按头正交化让各头的更新尺度均等，更大规模下训练动态更平衡。还有个顺带的好处：瘦长的按头小块上做 Newton–Schulz 迭代，比整个投影大矩阵上做更便宜——优化器开销反而略降。

K3 同时保留了 K2 引入的 weight clipping（权重裁剪）机制配合 Muon 使用，学习率用余弦调度、1% 线性预热，weight decay 全程 0.1。

一个优化器的头级分块，三家在三份报告里接力打磨——这就是开源技术报告生态最好的样子：不是各自闭门造轮子，是踩着彼此的结论往前走。

━━━━━━━━━━━━━━━━━━━━

◆ 5. QAT 全程化——从局部试点到全程国策

━━━━━━━━━━━━━━━━━━━━

K3 的量化方案：**MoE 专家权重 MXFP4，激活 MXFP8**。专家权重是 2.8T 参数的大头，压到 4 比特，部署内存和服务成本直接砍下来。保持高精度的部分：注意力投影、latent 降维/升维投影、共享专家、路由器——都是失稳敏感区。

关键不在量化本身，在**量化的覆盖范围**。QAT（Quantization-Aware Training，量化感知训练）从 SFT 阶段就开始，覆盖整个后训练——SFT 和 RL 全程都在量化条件下训练。更要紧的是 RL 阶段：**rollout（轨迹采样）和训练用同一套量化方案**，模型探索时看到的数值世界和更新参数时的数值世界完全一致，train–inference mismatch（训推不一致）被消除在源头。

对照 V4（166 期）：V4 的 FP4 QAT 只覆盖 MoE 专家权重和 Lightning Indexer 的 QK 路径，是预训练框架里的局部方案。一年时间，QAT 从"两个部位的局部试点"变成"贯穿整个后训练的全程国策"——低精度不再是训完之后的部署妥协，而是模型从对齐第一天起就生活在其中的原生环境。

推理加速侧还有一个衔接得很顺的设计：K3 预训练带一层 MTP（多 token 预测），后训练阶段直接把这层 MTP 微调成 EAGLE-3 风格的草稿模型做投机解码——主模型冻结，只训草稿层，且草稿微调同样在 MXFP4/MXFP8 的 QAT 配置下进行。损失函数也没用常规的 KL 散度，而是直接优化接受率的负对数——投机解码的加速比由接受率决定，那就直接优化接受率本身。

━━━━━━━━━━━━━━━━━━━━

◆ 6. 后训练流水线——9 个专家蒸成 1 个模型

━━━━━━━━━━━━━━━━━━━━

K3 的后训练是三段式：SFT 冷启动 → 分域分档 RL 训出 9 个专家 → 多教师在线蒸馏合一。

**第一段 SFT**：用前代 Kimi 系列的领域特化模型合成轨迹数据，多阶段校验加人工标注，建立冷启动策略。

**第二段 RL**：不是一个任务训一个模型，而是三个大域各训一个专家——general（通用：推理、视觉、检索、知识工作）、general agents（通用智能体：长程助理、深度研究、写作）、coding agents（编码智能体：软件工程、kernel、web 开发）。每个域再各训三档 reasoning effort（推理努力档位）：low、high、max。三域乘三档，**共 9 个专家模型**。

effort 这个东西的训法值得展开。每个问题 x 先用冷启动模型估一个初始 token 预算 b0(x)；RL 时，轨迹总 token 数超过 τ·b0(x) 的，任务奖励直接改写成 −1——超预算就是失败，不管答没答对。训练按 τ 走课程：先用较大的 τ 训出 max 档专家（同时封顶防过度思考），再把 τ 退火到更小的值，得到 high 和 low 档。**effort 不是生成参数，是用奖励塑形训进模型里的行为习惯。**

**第三段 MOPD**（Multi-Teacher On-Policy Distillation，多教师在线蒸馏）：9 个专家怎么合成一个模型？学生自己采样生成，每个 token 的奖励是对应领域对应档位的教师模型与学生的**对数似然比**（教师觉得这个 token 比学生自己觉得的更对，奖励为正），裁剪后作为稠密奖励接进 RL 框架。相比 SFT 式的模仿，学生是在自己的分布上被教师纠偏，不会学出"教师会但学生基础不匹配"的空中楼阁。报告顺带提了一句：试过更细粒度的 top-k 蒸馏目标，收敛速度和最终性能都没有优势。

**长程 agent 训练的环境建设**是这一章最花钱的部分，挑四个细节：

1. **白盒统一环境**：只用一个固定 harness（脚手架）训练，模型会过拟合到那套工具 schema 和交互协议上。K3 把 harness 抽象成可配置模块的组合——工具接口、系统提示、上下文管理、技能、子代理——同一套环境可以实例化出 Kimi Code、Claude Code、Codex、OpenClaw、Hermes 等多家主流 harness，训练时对不同任务组动态换配置，防止对任何单一 harness 过拟合。
2. **活环境**：mock 版的 Gmail、Notion、Slack、Canvas——保留真实应用的核心语义，去掉外部 API 和限流。任务模拟多个工作日、几十个跨应用相互依赖的事件流，单条 rollout 可达**数千次工具调用、数百万上下文 token**。
3. **kernel 任务的反作弊**：GPU kernel 优化任务的奖励看正确性和性能，但性能分会被钻空子。K3 专门建了 hacking 检测系统，惩罚 CUDA graph replay（重放录好的计算图）、输入缓存、偷偷降精度这类作弊策略，且随开发过程中观察到的新作弊手法持续加规则。
4. **沙箱规模**：整个训练和评测过程共创建了 51,219,741 个沙箱、1,505,678 个镜像。微虚拟机沙箱支持暂停/恢复/fork/快照，暂停时不占内存和 CPU——agent 等模型推理的时间可占沙箱生命周期的 98%，暂停机制把这部分成本清零。

◆ 7. 附录 F 的彩蛋——开关就装在门上

━━━━━━━━━━━━━━━━━━━━

报告附录 F 讲聊天模板，本来是最枯燥的一章，但里面有两个值得注意的发现。

K3 的模板叫 XTML（eXtensible Token Markup Language）——类 XML 的标记语言，尖括号换成三个保留特殊 token：[open]、[sep]、[close]。助手消息分三个通道：think（思考轨迹）、response（用户可见回答）、tools（工具调用）。

**发现一：非思考模式在模板里是存在的。** 报告原文写得很清楚：两种生成模式纯粹由生成前缀选择——前缀是 `[open]think[sep]` 就是思考模式，前缀是 `[open]response[sep]` 就是 instruct 模式（非思考模式）。切换只需要换一个前缀 token。也就是说，**开关就装在门上**。但 Kimi 的产品端没有提供非思考模式，报告全文也没有解释为什么不放。

这让人想起 259 期讨论过的现象（ https://mp.weixin.qq.com/s/yp5KXWxwLLZgK9XaHfSFKg ）：思考开关正在从各家产品界面上消失。K3 的情况提供了一个新的数据点——至少在 K3 这里，非思考模式不是能力上做不了，模板层面它是一等公民，是产品层面选择了不暴露。至于原因——评测都是 max effort 跑的、非思考模式的质量没有背书？还是产品策略上不想让用户选低质量档？报告不说，我们不猜。陈述发现，留个问号。

**发现二：effort 预留了 medium 档。** 模板 schema 保留四档：low、medium、high、max，报告原话是 K3 "supports a subset"（支持其中一个子集）——对照第六节，RL 只训了 low/high/max 三档。medium 是给未来留的位置。

另一个值得记的设计：**effort 不是特殊语法，是一条自然语言指令。** thinking-effort 作为全局选项消息插在工具声明之后、输入消息之前，内容就是用自然语言陈述请求的档位。tool_choice、response_format 也都是这个待遇——翻译成一小段自然语言放进上下文，而不是发明专用语法。报告管这个叫低对齐税（low alignment tax）设计：预训练模型本来就会听指令，新选项几乎不用额外训练就能加。

━━━━━━━━━━━━━━━━━━━━

◆ 8. 评测与成本——报表罕见地体面

━━━━━━━━━━━━━━━━━━━━

232 期审计 GLM-5.2 报表的时候，我们的态度是"厂商报表先当广告看，脚注比正文诚实"。用同样的视角看 K3 的评测章节，先说结论：**这份报表的脚注严谨程度罕见地高**，该标的都标了——对手模型的 fallback 行为（Fable 5 在 SWE-Marathon 上 35% 的任务触发 fallback）、拒答次数（内部套件里逐项标注"80 题中 10 题拒答"这种粒度）、每个模型用的 harness、以及自家成绩的评测条件。比一般厂商报表体面，这个要说公道话。

**分数挑重点讲：**

- **GPQA Diamond 93.5**：研究生级推理站上第一梯队（Fable 5 是 92.6，GPT-5.6 Sol 是 94.1）。
- **ProgramBench 77.8，第一**；Terminal-Bench 2.1 88.3，跟 Sol 的 88.8 几乎打平。
- **SWE-Marathon 42.0，第一**，领先 Fable 5（35.0）七个点——这是 GPU kernel 向的套件，K3 训练时专门建过 kernel 任务环境，训练投入直接兑现成了分数。
- **BrowseComp 91.2，第一**——但要注明：这个成绩用了 300K token 触发的上下文压缩策略；纯 1M 窗口、无上下文管理的成绩是 90.4。报告把两个数都给了，这正是脚注体面的例子。
- **CritPt 23.4，落后**（Sol 32.3、Fable 5 28.6）。报告自己承认：research-level reasoning（研究级推理）仍是短板，HLE-Full 也同样落后两强。评测章节肯明写"这是我们的弱项"的报告不多。

**成本账**是 K3 最锋利的一面：BrowseComp 上 \$2.03 一个任务，拿下最高分——大约是 GPT-5.6 Sol 的一半，比 Claude 系模型的 max 档便宜一个数量级。Kimi Code Bench 2.0 上落后 Fable 5 四个点，但成本只有对方的 38%。开源权重加这个成本曲线，K3 的定位不是"分数第一"，是"成本效率前沿"。

**一个必须做的口径切割**：内部评测里 Faithfulness（忠实度）85.5，指标定义是 1 减事实幻觉率——即内部口径下幻觉率 14.5%；报告对包含它在内的一组内部套件的总结是 "ranks first or a close second"（第一或紧随第一）。255 期提过第三方测出的 39%/51% 幻觉率，那是**完全不同的定义和测法**，两边数字不可混比。内部口径是逐条响应过事实核查器；第三方那套的任务分布和判定标准都不一样。哪边更接近真实使用体验，需要第三方用统一口径复测才有结论。

**案例段留给一件事**：K3 用 Kimi Code 跑了一次 48 小时无人干预的自主任务——给一个 nano 小模型（同款架构：KDA 混合注意力、NoPE-MLA、AttnRes、MoE 路由）设计推理芯片原型。用开源 EDA 工具和 Nangate45 标准单元库，在 4 平方毫米的分析面积预算内，100 MHz 时序收敛，RTL 仿真解码吞吐超过 8,700 tokens/s，集成 146 万标准单元，权重用分组 INT4 量化，RTL 代码开源在 GitHub（仓库名 nano-kpu）。报告自己定性为 early proof of concept——但"模型给自己的架构设计芯片"这个闭环，值得单独记一笔。

◆ 整体回顾

━━━━━━━━━━━━━━━━━━━━

把 K3 的技术栈收拢成一句话：**2.8T 的模型要在 FP4 上活下来、在 1/56 的稀疏度上不散架，每个零件都得重新设计。**

逐个对号：衰减参数化改成有界，是为了数值落进 BF16、tile 全上 Tensor Core；SiTU-GLU 的软帽，是为了激活值不冲破 MXFP4/8 的表示范围；聚合后 RMSNorm 和 Quantile Balancing，是为了 896 个专家的极端稀疏不失稳；Per-Head Muon，是为了 96 个注意力头在更大规模下更新均衡；QAT 全程化，是为了模型从对齐第一天就活在部署精度里。没有一个零件是为了炫技，每一个都在回答同一道题。

跟两家对照收个尾：V4 的报告主线是"压缩"——把注意力和 KV cache 的成本压下来；GLM-5.2 的主线是"复用"——indexer 共享、注意力残差复用；K3 的主线是"重设计"——不改成本结构的表层，直接把失稳的零件一个个换掉。三份报告放在一起读，比单独读任何一份都有营养。

克制地说：K3 整体仍落后 Fable 5 和 GPT-5.6 Sol，报告自己也这么写。但作为第一个开放权重的 3T 级模型，它把"极端稀疏 + 低精度"这条路线的完整工程答卷摊开给了所有人——这件事的价值不在榜单上。

◆ 技术名词速查

━━━━━━━━━━━━━━━━━━━━

| 术语 | 一句话解释 |
|------|-----------|
| KDA（Kimi 差分注意力） | 带通道级遗忘门的 delta 规则线性注意力，固定大小状态替代 KV cache |
| Gated MLA（带门控的多头潜在注意力） | DeepSeek 系的低秩 KV 压缩注意力，K3 加了全秩输出门 |
| NoPE（无位置编码） | MLA 层不加任何显式位置编码，位置信息由 KDA 的循环门控隐式携带 |
| AttnRes（注意力残差） | 把注意力用到深度方向：每层可选择性检索之前所有层的表示 |
| LatentMoE（潜在空间 MoE） | 路由专家在降维后的 latent 空间工作，共享专家保持全宽 |
| SiTU-GLU | SwiGLU 的两个乘数各套一顶光滑软帽 β·tanh(x/β)，输出有界且处处可导 |
| Quantile Balancing（分位数均衡） | 用路由分数余量的分位数一步算出每个专家的负载均衡偏置 |
| Per-Head Muon | Muon 优化器的按头分块版：每个注意力头的动量块单独做正交化 |
| MXFP4 / MXFP8 | 微缩放浮点格式，小块共享缩放因子的 4 比特 / 8 比特浮点 |
| QAT（量化感知训练） | 训练时就引入量化误差让模型适应，而非训完再量化 |
| MOPD（多教师在线蒸馏） | 学生自己采样，多个教师按 token 给对数似然比作稠密奖励 |
| reasoning effort（推理努力档位） | 用超预算即负奖励的 RL 训进模型的思考长度习惯，靠自然语言指令触发 |
| XTML | K3 的聊天模板标记语言，用保留 token 替代 XML 尖括号 |
| harness（脚手架） | agent 运行的外壳：工具接口、系统提示、上下文管理等的组合 |
| rollout（轨迹采样） | RL 中让模型实际执行任务、采集完整交互轨迹的过程 |
| cooldown（降温期） | 预训练末段学习率衰减阶段，K3 在此阶段完成 256K 到 1M 扩展 |
