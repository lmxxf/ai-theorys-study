◆ 先搞清楚：MoE 是什么？



MoE = Mixture of Experts，混合专家模型。



DeepSeek V3 有 671B 参数，但它不是一个铁板一块的巨无霸。它是这样的结构：



▸ 61 层 Transformer，隐藏维度 7168

▸ 每层 1 个共享专家 + 256 个路由专家 = 257 个专家

▸ 每个 token 只激活 8 个路由专家

▸ 有效参数量约 37B



这就是 DeepSeek 的精妙之处：671B 的知识容量，37B 的计算成本。



但这种架构的训练难度，也直接上天。



━━━━━━━━━━━━━━━━━━━━



◆ 鬼门关一：路由崩溃 (Router Collapse)



────────────────────



【你会遇到的问题】



路由器用 softmax 给 256 个路由专家打分。softmax 有个特性叫「富者愈富」。



假设专家 A 得分 2.0，专家 B 得分 1.9，差距只有 5%。



经过指数化后：exp(2.0) / exp(1.9) ≈ 1.105



⚠️ 5% 的 logit 差距变成了 10.5% 的概率差距。



训练几千步后：

• 几个明星专家：接收所有 token，梯度爆炸

• 大多数专家：饿死，参数衰减

• 你的 671B 模型：退化成 20B 的智力



────────────────────



【传统方案】



加一个辅助损失（Auxiliary Loss）来惩罚负载不均衡：



L_total = L_main + α × L_aux



问题是那个 α 是个噩梦参数：

• 太大 → 路由变成随机，MoE 白搭

• 太小 → 崩溃照旧

• 刚刚好 → 随着数据分布变化需要不断调



────────────────────



【DeepSeek 的解法】



直接不用辅助损失。



他们用一个 bias 项加在 top-K 路由的 affinity score 上，不需要调 α。



✓ 结果：整个训练过程零 loss spike，零回滚。



这就是 557 万美元的秘密之一。如果你要做 FFT，学这个思路。



━━━━━━━━━━━━━━━━━━━━



◆ 鬼门关二：数值不稳定 (Numerical Instability)



────────────────────



【你会遇到的问题】



训练 671B 参数必须用 BF16 来省显存。但 BF16 只有 7 位尾数，精度很低。



反向传播经过几百层后，梯度会这样变化：



1.01^100 ≈ 2.7

1.01^500 ≈ 144

1.01^1000 → NaN



⚠️ 一个 NaN 就是病毒。它会在一个训练步骤内感染所有参数，摧毁你几周的计算。



────────────────────



【传统方案】



• 梯度裁剪：超过阈值就强制截断

• Z-Loss：惩罚 logit 的大小，防止 exp(x) 溢出

• 存档回滚：每 100 步存一个 checkpoint，发现 spike 就回滚、跳过那批数据、降学习率、祈祷



────────────────────



【DeepSeek 的解法】



更激进——直接用 FP8。



在 DeepSeek V3 之前，没有开源大模型成功用 FP8 训练过。他们的创新：



• 细粒度量化：激活用 1×128 tile，权重用 128×128 block

• DeepGEMM：他们自研的 FP8 矩阵乘实现，已开源



✓ 结果：比 BF16 更省显存，训练成本进一步压缩。



想做 FFT？去看 DeepGEMM 的源码，这是真金白银的工程经验。



━━━━━━━━━━━━━━━━━━━━



◆ 鬼门关三：4D 并行 (4D Parallelism)



────────────────────



【你会遇到的问题】



671B 参数的模型有多大？



模型本身 = 671B × 2 字节 = 1.34 TB

优化器状态 (Adam) = 671B × 8 字节 = 5.4 TB

总共 = 6.7 TB 起步



单张 H100（80GB）连 1/8 都装不下。你需要 128+ 块 GPU 配合四种并行策略：



▸ DP（数据并行）：复制模型，分割数据 → 痛点：显存爆炸

▸ TP（张量并行）：跨 GPU 分割矩阵 → 痛点：高通信量

▸ PP（流水线并行）：跨 GPU 分割层 → 痛点：气泡效率低

▸ EP（专家并行）：跨 GPU 分割专家 → 痛点：All-to-All 通信



────────────────────



【All-to-All 噩梦】



MoE 模型里，路由器把 token 分发给不同 GPU 上的专家。数据流是「从到处到到处」。



没有 InfiniBand（400Gbps+），GPU 80% 以上的时间都在等数据。



────────────────────



【DeepSeek 的解法】



DualPipe 算法：

• Attention 和 MoE 计算与 MoE 通信重叠

• 减少 all-to-all 通信开销

• 平衡 GPU 间的显存使用



配合他们的 MLA（多头潜在注意力）压缩 KV 缓存，在消费级设备上实现了 128K 上下文窗口。



这套通信优化方案，是 DeepSeek 能用更少卡跑更大模型的核心竞争力。



━━━━━━━━━━━━━━━━━━━━



◆ 鬼门关四：灾难性遗忘 (Catastrophic Forgetting)



────────────────────



【预训练怎么防】



预训练用「数据混合」来防止遗忘——每个 batch 都包含英文、中文、代码、数学：



DeepSeek V3 的 batch 组成（大致）：

• 30% 英文网页

• 20% 中文网页

• 15% 代码（重点强调）

• 10% 数学/科学（重点强调）

• 10% 书籍

• 15% 其他



这就是它推理能力强的原因——数学和代码的比例被刻意提高了。



────────────────────



【微调时你会遇到的问题】



微调的问题是你的新数据分布太窄。如果只喂垂直领域数据，模型会「覆盖」通用能力来最小化损失。



⚠️ 结果：模型在你的领域很强，但通用能力崩了。



────────────────────



【解法：Replay Buffer】



训练时混入旧的高质量数据：



训练 batch = 10% 新数据 + 90% 通用数据（Wikipedia、GitHub、教科书）



本质：Replay Buffer 就是微调阶段的「数据混合」。



这个比例需要你自己调，但记住：宁可保守，也别让模型变傻。



━━━━━━━━━━━━━━━━━━━━



◆ 鬼门关五：学习率手术 (Learning Rate Surgery)



预训练学习率：1e-4 到 3e-4 → 比喻：大锤盖房子

微调学习率：1e-6 到 5e-6 → 比喻：手术刀做眼科手术



⚠️ 用预训练学习率做微调 = 用锤子做视网膜手术。



一次更新就能摧毁万亿 token 积累的知识。



做 FFT 的时候，学习率一定要从小开始试。



━━━━━━━━━━━━━━━━━━━━



◆ 鬼门关六：数据效率 (Data Efficiency)



────────────────────



【问题】



标准 Transformer 训练是「每个位置预测一个 token」。14.8T token 的语料意味着 14.8 万亿次前向传播。



每次前向传播计算出丰富的表示，但只用来预测下一个 token——太浪费了。



────────────────────



【DeepSeek 的解法：MTP（多 Token 预测）】



标准方式：位置 i → 预测 token i+1

MTP 方式：位置 i → 预测 token i+1, i+2, i+3, ...



好处：

• 更密集的训练信号

• 模型被迫为未来 token 预先规划

• MTP 模块还能用于投机解码加速推理（第二个 token 接受率 85-90%）



这个技术让 DeepSeek 用更少的数据训出更好的效果。



━━━━━━━━━━━━━━━━━━━━



◆ 为什么 LoRA 不够用？



如果你只是想做轻量级适配，LoRA 够了。但如果你想深度改造模型的「世界观」，LoRA 不够。



LoRA 把权重更新分解为低秩矩阵：



W' = W + BA

其中 r << d（通常 r=64, d=8192）

LoRA 参数 / 全参数 = 1.56%



⚠️ LoRA 只能修改参数空间的 1.56%。



模型的知识不是编码在单一层里的，而是分布在所有注意力矩阵、所有 FFN 权重、所有层归一化里。



想要深度改造？FFT 是唯一选择。

◆ 总结：DeepSeek 教会我们什么



DeepSeek V3 的 557 万美元训练成本，不是省出来的，是工程创新换来的：



✓ 无辅助损失的负载均衡 → 消灭路由崩溃

✓ DualPipe + MLA → 消灭通信瓶颈

✓ MTP → 提升数据效率



每一个鬼门关，他们都找到了优雅的绕过方案。
