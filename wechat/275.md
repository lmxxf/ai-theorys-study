【多 AI Agent 协作】让 opencode 和 pi 互相打了个电话，还叫醒了 codex 的旧会话

━━━━━━━━━━━━━━━━━━━━

◆ 起因：朋友的一张对比图

━━━━━━━━━━━━━━━━━━━━

一个朋友发来消息：他的 opencode 和 pi 两个编程 agent 能直接对话了，还附了张两种实现的对比表。这事儿听着就有意思——我们平时用的这些 agent，每个都是孤岛：Claude Code 不知道 codex 在干什么，opencode 和 pi 各过各的。要是它们能互相打电话，那就不是"一个人带几个助手"，是"助手们自己有了通讯录"。

正好手头有 DeepSeek 的 API（用的老模型 id deepseek-chat，官方文档写明它现在指向 V4 Flash 的非思考模式）、闲着的机器，周日下午，自己搭一遍。结论先说：**通了，而且比想象的顺——两个 agent 互相打了电话，一个下单一个真干活；更进一步，我还把一条外部消息插进了第三个 agent 昨天用过的旧会话里，它准确复述了昨天干的活。** 方法全记在下面，想复现的直接抄。

◆ 1. A2A 协议：agent 界的电话系统

━━━━━━━━━━━━━━━━━━━━

先交代这套电话系统的来历。A2A（Agent2Agent）协议是 Google 2025 年 4 月 9 日发起的开放标准，当年 6 月 23 日捐给了 Linux 基金会，2026 年 3 月 12 日出到 v1.0 稳定版，背后站着 150 多家机构（微软、Salesforce、ServiceNow 都在名单里）。

机制说穿了就三件东西：

**一张名片。** 每个愿意接电话的 agent，在自己的网址下挂一个固定路径的文件 `/.well-known/agent-card.json`，声明"我是谁、会什么技能、走什么传输方式、要什么鉴权"。别的 agent 想找你，先读这张名片——跟人类交换名片一模一样。

**一套通话格式。** 名片交换完，正式通话走 JSON-RPC 2.0（就是最普通的 HTTP POST 发 JSON）：把一段话（可以带文件、图片）发给对方，对方回消息或者回一个"任务"对象。本文实测报文里的 `message/send` 这类方法名属于 0.3 世代的写法——v1.0 对方法名和名片字段做了梳理，还加了 gRPC 等多种传输绑定，但生态里的适配器大多还说着 0.3 的方言（后面还会提到这事）。

**一个任务生命周期。** 稍大的活在协议里是一个 task，带一套状态机：submitted（已提交）、working（干着呢）、input_required（缺信息，等你补）、completed（干完了）……不同版本的枚举略有出入，简单请求也可以不建任务直接回消息。结果装在 artifacts（产物）字段里回来。支持 SSE 流式，长任务还能挂回调。

跟大家已经熟悉的 MCP 摆在一起，官方定位一句话就说清了：**MCP 是纵向的轨道——agent 往下连工具；A2A 是横向的轨道——agent 之间平级对话**（83 期 https://mp.weixin.qq.com/s/AzuZ-uoZVXy01dqVTI__Uw 讲过 Skill 和 MCP 是脑子和手，那 A2A 补上的就是嘴）。

◆ 2. 实测一：让 opencode 和 pi 通上话

━━━━━━━━━━━━━━━━━━━━

选这两个当第一对，是因为生态最齐。全程三条安装命令：

```bash
npm install -g opencode-ai            # opencode 本体
npm install -g @mariozechner/pi-coding-agent   # pi 本体
npm install -g a2a-opencode           # 给 opencode 包 A2A 皮的适配器
```

**接电话的一方：opencode。** 它有个天生优势：`opencode serve` 命令本来就把整个 runtime 起成 HTTP 服务（默认 4096 端口），TUI 界面本质上只是这个服务的一个客户端。社区的 `a2a-opencode` 适配器就是在这层服务外面再包一张 A2A 名片：

```bash
opencode serve &
a2a-opencode --port 3000 --model deepseek/deepseek-chat \
  --directory ~/work/temp/a2a/opencode-side \
  --agent-name "OpenCode-DeepSeek"
```

跑起来之后，名片真的挂出来了：

```bash
curl http://localhost:3000/.well-known/agent-card.json
```

```json
{
  "name": "OpenCode-DeepSeek",
  "url": "http://localhost:3000/a2a/jsonrpc",
  "capabilities": { "streaming": true, ... },
  "additionalInterfaces": [
    { "transport": "JSONRPC", "url": ".../a2a/jsonrpc" },
    { "transport": "REST",    "url": ".../a2a/rest" }
  ]
}
```

**打电话的一方：pi。** pi 是 Mario Zechner 那个以极简出名的 agent（258 期 https://mp.weixin.qq.com/s/AWHv0Kocqz6oZGzAJepu3g 的主角），它的扩展机制是直接加载 TypeScript 文件，连编译都不用。社区的 A2A 客户端扩展一条命令装上：

```bash
pi install npm:pi-a2a-adaptor
```

装完 pi 多了一整套斜杠命令（README 写 17 个，本地这版源码实数是 18 个 😄）和 2 个给模型用的工具，核心是 `a2a_call(agent_url, message)`——注意这个设计：**打电话不是用户手动触发的功能，是注册给大模型的一个工具**，跟"读文件""跑命令"平级。什么时候打、打给谁、说什么，模型自己决定。

**通话实录。** 我给 pi（DeepSeek 驱动）下了个指令：联系 localhost:3000 的远程 agent，让它介绍自己，并在它自己的工作目录创建一个文件。然后看着这一串发生：

1. pi 判断该打电话，调用 `a2a_call`
2. 报文走 JSON-RPC 进 opencode 的 runtime
3. opencode（也是 DeepSeek 驱动）自报家门，**真实调用自己的写文件工具**，把 `hello-from-pi.txt` 写进了自己的目录
4. 任务状态 completed，回答装在 artifacts 里流回 pi
5. 最有意思的是这步：**pi 没有满足于转述，自己跑去对方目录 ls 加 cat，验证了文件真的存在**，然后才向我汇报"与要求一致"

一个下单，一个真干活，下单的还亲自验了货。顺便说个有喜感的细节：两边都是 DeepSeek——同一个模型装进两个不同的壳子，通过标准协议互相认成了"远程 agent"，左手给右手打电话，谁也没认出谁。

◆ 3. 关键细节：接电话的是"新客服"还是"那间正开着的会议室"

━━━━━━━━━━━━━━━━━━━━

跑通之后我盯上了一个细节，这个细节比"能通话"本身重要。

上面那通电话，opencode 这边接线的是谁？读了适配器的源码：它维护一张 A2A 的 contextId 到 opencode session 的映射表——**同一个 contextId 再打进来，续用同一个会话，上下文都在；新 contextId 就新开一个会话。** 也就是说，它有"会话连续"，但只限适配器自己开的会话。

翻译成人话：远程打电话进来，接待你的永远是**新雇的客服**。你可以跟这个客服建立长期关系（记住你上次说过什么），但你永远接不进老板正开着的那间会议室——你在 TUI 里开的那个会话、聊了一下午攒了满桌上下文的那个，不在适配器的通讯录里。

而真正我需要的场景恰恰是后者：**"跟我正开着的这个会话说话"**。我桌上摊着一个干了一半的活，另一个 agent 打电话进来，接着我的上下文继续——不是雇新人从头交代，是往会议室里递纸条。说精确点：协议只保证 contextId 层面"这是同一段对话"，至于它落到本地哪个会话，纯粹是适配器的本事——报文的 metadata 是个自由字段，往里塞会话寻址信息是适配器之间约定俗成的做法（朋友对比图里那个更完整的实现就声明了这个能力），大部分适配器还没做到这步。这是当下 A2A 落地最值得盯的一条分界线。

◆ 4. 实测二：叫醒 codex 昨天的旧会话

━━━━━━━━━━━━━━━━━━━━

会议室接不进去，我换了个更实际的目标验证这个概念：codex（模型 GPT-5.6，reasoning effort 开 low——本想干脆不开思考，但这一代压根没有"关"这一档，low 已是地板）。它连 A2A 插件都不用装——因为它的会话是**明文 JSONL 文件躺在磁盘上的**：

```
~/.codex/sessions/2026/08/08/rollout-2026-08-08T16-26-07-<会话id>.jsonl
```

按修改时间一排，最新那个就是昨天用过的会话（它昨天帮我审过一篇稿子）。codex 原生就支持往旧会话里续话，一条命令：

```bash
codex exec resume <会话id> "你还记得昨天在这个会话里改了哪几处吗？"
```

结果它准确复述了昨天的三处修改——改了哪一段、为什么改、连"顺手把结论收窄了"这种细节都在。**会话被外部消息叫醒后，会话记录原封未动、上下文没被压缩，接着用就是。** 这没什么神秘的——会话本来就是一个躺在磁盘上的文件，隔多久续上都一样。但它恰好就是"会话寻址"和"新开会话"的区别本体：新开会话是雇新人从头交代；续旧会话是接着昨天摊开的桌面继续干，**前情一个字不用重讲**。要把这条路包上 A2A 的标准皮，概念验证确实薄——把 A2A 消息映射到 `codex exec resume` 就行；但离生产还差鉴权、并发、流式、超时一整段路。并发这条我当场就撞上了：往一个正被 TUI 开着的会话里发消息，codex 直接回了占线音——`already has an active writer`，同一间会议室不许两支笔同时写。这声占线音其实很有信息量：**它说明你屏幕上那个终端界面和我这条命令行，在 codex 眼里是完全平等的两个客户端，抢的是同一个会话**——TUI 从来不是会话本身，只是它的一种显示方式。opencode 在这点上走得更远：TUI 天生就是 serve 服务的一个客户端，会话池全程共享，压根不存在"谁独占"一说。

至于 Claude Code：社区同样有现成的适配器（a2claude、claude-a2a 好几个），原理跟上面一样，包 CLI 或包 SDK。我没测——它的额度太精贵，舍不得拿来做实验 😂

◆ 5. 三家方法速查 + 几句提醒

━━━━━━━━━━━━━━━━━━━━

| agent | 接电话（当 A2A server） | 打电话（当 A2A client） |
|---|---|---|
| opencode | `opencode serve` + `a2a-opencode` 包壳 | 另一个社区实现内嵌了出站 client |
| pi | 社区有适配器（自造路径，标准度差些） | `pi install npm:pi-a2a-adaptor`，给模型注册 `a2a_call` 工具 |
| codex | 社区有 codex-a2a（官方未合并） | 不用插件：`codex exec resume <会话id> "消息"` 直接续旧会话 |
| Claude Code | a2claude / claude-a2a 等（未实测） | 有 MCP 工具形态的 client（纵轨调横轨） |

三句提醒，都是实测里撞到的：

一，**裸奔问题**。`opencode serve` 不设密码就是完全无鉴权的服务，A2A 适配器默认还开着"自动批准所有权限"。在本机玩无所谓，绑到 0.0.0.0 或者放公网，等于把一个能读写文件、能跑命令的 agent 白送给全网。A2A 协议本身支持 Bearer Token 鉴权，上生产必须配。

二，**agent 会读工作目录里的配置**。第一次冒烟测试时，opencode 自动加载了我仓库里给另一套工具写的 agent 配置文件，模型行为立刻被带偏。做实验请开干净目录，控制变量。

三，**协议版本没对齐是常态**。A2A 标准已到 v1.0，但我测的适配器名片里写的还是 0.3.0，朋友图里那个 pi 实现干脆自造了路径。生态比协议慢半拍，跨实现对接前先把两边名片都 curl 出来看一眼，能省不少玄学调试。

◆ 尾声：孤岛时代结束的样子

━━━━━━━━━━━━━━━━━━━━

把这个下午串起来看：一张名片、一套 JSON-RPC、一个任务生命周期——A2A 没有任何黑科技，它只是把"agent 互相调用"这件事从各家私有 API 里抠出来，变成了和 HTTP 一样无聊的基础设施。而无聊，恰恰是基础设施成熟的标志。

真正值得琢磨的是那条分界线：**通话解决的是"能不能说上话"，会话寻址解决的是"说话的对象是谁"。** 前者已经是成熟的轮子；后者——让电话直接接进那间摊着稿纸的屋子——才刚刚开始。等它成熟，"多 agent 协作"就不再是框架厂商 PPT 里的编排图，而是你桌上几个各干各活的 agent，偶尔互相递一张纸条那么自然。

到那时候，大概没人再讨论"A2A 协议"，就像今天没人讨论 TCP 一样。

◆ 技术名词速查

━━━━━━━━━━━━━━━━━━━━

| 术语 | 一句话解释 |
|------|-----------|
| A2A（Agent2Agent） | agent 之间互相发现、发任务的开放协议，Linux 基金会管理 |
| agent card（名片） | 挂在固定路径的 JSON，声明这个 agent 是谁、会什么、怎么连 |
| JSON-RPC | 用 HTTP POST 发 JSON 的远程调用格式，A2A 的通话语言 |
| task（任务） | A2A 里一通电话的载体，带状态机，结果装在 artifacts 里 |
| SSE 流式 | 服务器把结果分块推给客户端，看得到对方"边想边说" |
| MCP | agent 连工具的协议——纵轨；A2A 是 agent 连 agent——横轨 |
| opencode serve | 把 opencode 整个 runtime 起成 HTTP 服务，TUI 只是它的客户端 |
| session（会话） | agent 的一段连续上下文；本文的分界线：新开 vs 寻址已有的 |
| contextId | A2A 里标识"这是同一段对话"的 ID，适配器拿它映射到会话 |
| codex exec resume | codex 原生命令：往磁盘上的旧会话里续一条消息 |
