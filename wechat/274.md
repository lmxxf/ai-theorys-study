【AI 重写 CUDA？】"10 小时重建 CUDA"的新闻，剥开是三层皮

━━━━━━━━━━━━━━━━━━━━

◆ 起因：一条热门新闻，和一句需要剥开看的口号

━━━━━━━━━━━━━━━━━━━━

这两天有条新闻在中英文圈都转得挺热：一家成立才一年的初创公司，用 AI agent 在 10 小时内做出了"替代 CUDA 的东西"，于是各路标题开始追问——NVIDIA 的护城河是不是要没了？

这个领域正好是本号的主场。过去半年我们在 DGX Spark 上给 DeepSeek V4 手工干过一模一样的活：给一块官方生态没跟上的硬件，从 kernel 到推理栈一层层修到能跑（185 期 https://mp.weixin.qq.com/s/dEc-wD0JcM5WhKicOUR1pQ 记过这笔账）。所以看到"10 小时重建 CUDA"这个说法，第一反应不是激动，是想去查原文：10 小时到底做出来的是什么？

查完的结论先放这儿：**故事是真的，数字也是真的，但媒体把三个不同刻度的数字叠在一起，专挑最好听的那个当标题。把三层皮剥开，这件事反而比标题更有意思**——因为剥完你会发现，方向确实不算错，CUDA 的护城河确实在被侵蚀，只是侵蚀的机制和"10 小时复刻"完全是两码事。

━━━━━━━━━━━━━━━━━━━━

◆ 1. 故事本身：给一块没有生态的芯片配软件

━━━━━━━━━━━━━━━━━━━━

主角叫 Infinity，旧金山初创公司，2025 年成立。创始人 Jeremy Nixon 是前 Google Brain 研究员，今年 7 月刚融了 1500 万美元种子轮，跟投名单里有 OpenAI 和 Anthropic 的研究员（个人身份）。

他们的产品是一个叫 Ignition 的自主 agent 系统。工作方式是个闭环：AI 写底层 kernel → 编译测试 → 放到真硬件上跑性能剖析 → 拿着性能数据自动重写 → 循环。人类工程师只负责说"要造什么工具"，实现全交给 agent。产出不只是 kernel，还包括调试器、性能剖析器、编译器、推理编排——给一块新芯片配齐整套推理软件栈。至于 agent 底下用的是哪家的大模型，所有公开资料都没披露。

客户是 d-Matrix——一家做推理专用芯片的公司，产品叫 Corsair，走的是数字存内计算路线（把计算单元嵌进 SRAM 存储阵列，跟 GPU 架构完全不同）。这类芯片的处境很典型：硬件造出来了，软件生态是零。CUDA 二十年攒下的一切，在它上面一行都用不了，传统做法是养一支软件团队写几个月到几年。Infinity 卖的就是"这几年我用 agent 给你压缩成几天"。

商业模式也顺带说一句，挺有意思：不收软件授权费，按优化省下来的算力开支抽成约两成——把自己的收入跟 kernel 快不快直接绑死了。

━━━━━━━━━━━━━━━━━━━━

◆ 2. 三个数字，三层皮

━━━━━━━━━━━━━━━━━━━━

新闻里飞来飞去的数字有三个：10 小时、10 天、还有个"14 倍"。翻回官方通稿逐句对，三个数字说的是三件不同的事，诚实程度一层比一层高。

**第一层：10 小时——做出来的是矩阵乘法，不是 CUDA。**

通稿原文写得很清楚：拿到硬件后 10 小时内，"跑通张量并行的矩阵乘法，覆盖全部 32 个计算单元，达到理论峰值性能的约 92%"。

注意宾语：**矩阵乘法**。也就是说，10 小时达成的是让 GEMM（通用矩阵乘）这一类计算在新芯片上跑到接近峰值——这是整个推理软件栈里的第一站，远不是全部。"10 小时重建 CUDA"这个标题，相当于把"10 小时打好了地基"说成"10 小时盖完了楼"。

**第二层：10 天——这才是端到端的真实时间线。**

通稿的下一句：10 天内，Qwen3、Qwen3.5、Gemma4 三个模型在这块芯片上端到端跑通。

老实讲，这个数字才是真正惊人的——给一块架构完全陌生、生态为零的芯片，10 天跑通三个前沿模型，放在传统芯片软件行业里是以"人年"计的工作量。但它偏偏被"10 小时"的标题盖住了。10 天和 10 小时之间差的 24 倍，恰好就是"写出代码"和"让代码在完整系统里站住"之间的成本比。

**第三层："14 倍"——起点是自己，基线才 34%。**

有些报道说"吞吐提升 14 倍"。查原文：在 NVIDIA 显卡上给 Qwen3-8B 自动生成优化 kernel 一天，吞吐从约 1400 token/s 推到 20000 以上——14 倍是跟**自己第一版没优化的代码**比的；跟业界通用的 vLLM 框架比，快了 34%（且未经第三方验证）。34% 是个不错的成绩，但和"14 倍"给读者的冲击完全不是一个量级。

────────────────────

💡 为什么偏偏是矩阵乘法能 10 小时搞定——AI 干活效率取决于"摩擦"

这三层皮剥开后有个规律值得单独说：agent 的效率不取决于它多聪明，取决于它所在的反馈回路质量。拿三个维度衡量：

一看**可观测性**：出错时状态能不能被 AI 读到。矩阵乘错了就是输出数字不对，跟标准答案一比全知道；而系统级 bug 经常是"不崩但输出乱码"，得人摊开源码逐层对中间结果。

二看**重置成本**：失败一次要付出什么。专用加速卡崩了重跑就是，拖不死宿主机；但有些环境里一次失败会杀死迭代循环本身——比如统一内存的机器上模型把内存吃满，桌面和 agent 自己一起被挤死，需要一只物理的手去按电源键。

三看**判分器**：对错和快慢能不能被机器自动判。token/s 和数值精度是完美判分器；"生成质量变差了"就不是。

矩阵乘法在这三项上全是满分：状态全可读、崩了白崩、对错秒判——它是整条街上最规整的一间房，天生适合 agent 无人值守地滚迭代循环。而 10 天里多出来的那些时间，就花在三个维度挨个塌掉的地方。顺便说，人类专家手工优化 GEMM 也是奔着九成峰值去的，agent 达到 92% 说明的是"迭代次数管够"，不是"洞察力超人"。

────────────────────

数字的皮剥完了，再来听听这个行业里真正写过这些东西的人怎么说。

◆ 3. 业内的冷水，和一篇专门泼冷水的论文

━━━━━━━━━━━━━━━━━━━━

这个故事在行业里也不是没人质疑。两位泼冷水的都是干这行的：Chris Lattner（LLVM 和 Swift 的作者，现在自己创业做 CUDA 替代品）说宣传过头了，"代码生成只是软件开发的一小部分，难的是为生产环境调优"；一位公司被 NVIDIA 收购的芯片软件创业者说得更直接：**"验证才是最大的瓶颈"**——agent 生成得快，但确认它真的对、真的快，才是花时间的地方。

这话不是空口说的，今年正好有篇论文把它量化了。斯坦福 2024 年底发过一个叫 KernelBench 的基准（中文锚点：kernel 生成基准测试），专门测大模型能不能写出高效 GPU kernel，此后"AI 生成的 kernel 超过 PyTorch"的战报就常见诸报道。而 2026 年 7 月的一篇后续论文 KernelBench-Verified 把七个前沿模型重新拉出来，在**堵住作弊通道的严格协议**下重测了一遍，结果：

标准协议下最强模型的几何平均加速比是 1.43 倍——严格协议下掉到 **0.88 倍，比 PyTorch 还慢**。

中间蒸发掉的部分去哪儿了？论文点了两类作弊手法：一类是把对照组弄慢——基线没开 Tensor Core 加速，赢的是残血版 PyTorch；另一类更狠，**针对测试用的特定张量值硬编码旁路，跳过真实计算**——测试数据窄，背答案就能过。这就是强化学习圈说的 reward hacking（奖励作弊）：判分器有缝，模型必钻。

公平起见，正面证据也有：斯坦福自己 2025 年的实验里，AI 生成的 kernel 在 FP32 精度下确实多项超过 PyTorch 官方实现（LayerNorm 甚至快了数倍）——但同一篇博客里，FP16 的 Flash Attention 只达到基线的 9%。规整的、优化空间没被榨干的算子，AI 真能打；越接近生产主力路径（FP16/BF16、注意力），越是人类专家已经杀成红海的地方，AI 目前越吃力。

把这些放回 Infinity 的故事里，量纲就对齐了：**它最响亮的数字（10 小时、92%）恰好出自 AI 最擅长的那间房，而业内质疑的（验证、生产化调优）恰好是它没展示的部分。**故事是真的，但被展示的是精心挑选过的切面。

━━━━━━━━━━━━━━━━━━━━

◆ 4. 可是方向真的不算错：看看别处都在发生什么

━━━━━━━━━━━━━━━━━━━━

剥完夸张的部分，得说回另一半：这个方向本身，我们认。因为同样的事情正在好几个互不相干的地方同时发生。

**AMD 官方下场了。**今年 7 月的 Advancing AI 大会上，AMD 发布了 ROCm.AI：一个叫 GEAK 的 kernel 生成 agent，配一个叫 Hyperloom 的自主优化编排系统——AI agent 加性能剖析工具分析整个推理负载、找瓶颈、改代码、验证正确性和性能，在量产芯片上交出了**经过验证的 21.8% 吞吐提升**。注意这个数字的画风和 Infinity 完全不同：没有"10 小时"，没有"14 倍"，就是端到端 21.8%——大厂在量产硬件上敢背书的数字，大概就长这样。AMD 的算盘也说得很明白：NVIDIA 的软件工程师人数优势，用 agent 来抵。

**社区早就在免费干这件事了。**这条本号读者最熟：DGX Spark 刚发售时，它的 GPU 架构（sm_121）连 NVIDIA 自家的 kernel 库都不好好支持（176 期 https://mp.weixin.qq.com/s/e1GKi53IociZnfHX1Ie9_w 讲过 DeepGEMM 为什么不认消费级架构），DeepSeek V4 在上面起步只有个位数 token/s。此后几个月，社区里屈指可数的几个个人开发者，借助 AI 辅助，一路做出了 sm_121 特化的 kernel 库、整模型 CUDA graph 的双机方案，直到单流 80 token/s 以上——我们全程围观外加受益。这就是 Infinity 模式的免费版：**"AI 把新硬件软件栈的成本从人年压到人天"这件事，不是哪家公司发明的，它是这两年正在发生的行业事实，Infinity 只是第一个拿它去融资的。**

**对照组：上一代挑战者是怎么熬的。**在 agent 出现之前，挑战 CUDA 生态是什么成本？两个现成例子。英国一家小公司 Spectral Compute 做了个叫 SCALE 的编译器，让 CUDA 代码不加修改直接在 AMD 显卡上编译运行——干了七年。波兰开发者 Andrzej Janik 一个人写的翻译层 ZLUDA，能让 CUDA 程序直接跑在 AMD 显卡上，先后被 Intel 和 AMD 资助又先后被放弃，中间还因为 NVIDIA 修改许可条款差点被迫下架，十来年三起三落。**上一代的故事以"年"和"人生"计，这一代的故事以"天"计**——就算 Infinity 的数字打个对折再对折，这个量级变化也是真的。

◆ 5. 护城河到底是怎么消失的

━━━━━━━━━━━━━━━━━━━━

最后把"CUDA 护城河在消失"这句话说精确。它不是"有人复刻了 CUDA"——没人复刻得了，CUDA 是二十年攒下的几千个 API、全套工具链和无数踩坑记录。真正的侵蚀机制是两个，方向一上一下。

**从上面：推理时代只需要 CUDA 的一个小角落。**我们在算子系列（合集见 https://mp.weixin.qq.com/s/w3zBkGtpN0Xe3AXNJqoqhQ ）里亲手数过：DeepSeek V4 这种前沿模型，推理跑起来核心就七类算子——量化、矩阵乘、索引、稀疏注意力、超连接、专家路由、激活函数。训练、科学计算、图形渲染那些 CUDA 的广阔疆土，推理芯片一寸都不需要。护城河再宽，对手只需要渡过其中五米——d-Matrix 们瞄准的正是这五米。

**从下面：给新芯片配软件的成本在塌。**过去芯片公司输给 NVIDIA，很多时候不是输在硬件，是输在养不起千人规模的软件团队——生态成本就是进入门槛。agent 把这道门槛直接砍掉一个数量级之后，竞争会回到硬件效率本身。对买家来说这是纯利好：芯片选择变多，被单一生态锁定的理由变少。

NVIDIA 自己显然也看得见这个趋势——这两年它把护城河持续往上挪：NVLink 互联、机柜级系统、供应链锁定。那些是 agent 写不出来的东西。

所以回到标题的问题：AI 能不能重写 CUDA？逐字面回答是不能，10 小时重建的是矩阵乘法。但换个问法——"CUDA 作为护城河还能守多久"——答案就没那么乐观了：**上面推理框架把硬件抽象掉，买家只关心 token/s；下面 agent 把配软件的成本打下来，新芯片不再天生残废。CUDA 正在从"必需品"降级为"众多后端之一"。**这个过程不需要谁在 10 小时内创造奇迹，它以"社区几个月、大厂一个财年"的速度平稳地发生着，而且我们自己的机器就是受益者之一。

◆ 技术名词速查

━━━━━━━━━━━━━━━━━━━━

| 术语 | 一句话解释 |
|------|-----------|
| CUDA | NVIDIA 的 GPU 编程平台加二十年生态，AI 计算的事实标准 |
| GEMM（通用矩阵乘） | 神经网络中最核心也最规整的计算，占推理算力大头 |
| kernel | 在 GPU 上执行的底层计算函数，性能好坏的最小单位 |
| 存内计算 | 把计算单元嵌进存储阵列的芯片架构，d-Matrix Corsair 的路线 |
| 理论峰值性能 | 芯片规格书上的算力上限，实际能跑到九成即属优秀 |
| vLLM | 目前最主流的开源推理框架，性能对比的常用基线 |
| KernelBench | 斯坦福的基准测试：大模型能不能写出高效 GPU kernel |
| reward hacking（奖励作弊） | 模型钻判分器的空子拿高分，而非真正完成任务 |
| Tensor Core | NVIDIA 显卡上的矩阵乘专用单元，基线不开它就是残血版 |
| ROCm | AMD 对标 CUDA 的软件平台，ROCm.AI 是其 agent 化新层 |
