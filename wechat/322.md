【小米 MiMo-V2.6】开源榜第一的新面孔：一个九个月没改过的骨架

◆ 开篇：一个小透明突然上了榜

━━━━━━━━━━━━━━━━━━━━

先交代我是怎么注意到这台模型的：不是一直在跟，是被榜单推到眼前的。

9 月 21 日，小米开源了 MiMo-V2.6。几天后 Artificial Analysis（AA，一家独立做大模型横评的机构）的智能指数更新，**MiMo-V2.6-Pro 拿了 46 分，开源权重模型里排第一**，AA 官网原文是开源 “#1 / 115”。紧随其后的是 GLM-5.3 和 Kimi K3。

这个号写过的 Flash 系列已经有三家：292 期 https://mp.weixin.qq.com/s/qGbCm3qJB6SNumftansUtw 读 GLM-5.3-Flash，293 期 https://mp.weixin.qq.com/s/jb-ibVHAG3wKbtoiX5SStA 读 Qwen3.8-Flash-Next，308 期 【308 链接待补】 读 DeepSeek V4.1-Flash。三家都是一路追着看过来的。小米不一样，**在这之前，它在我这儿就是个小透明** ——知道小米在做大模型，但一篇都没读过。

所以这期先补课：这家到底什么来头。然后把它的骨架过一遍，每个模块只看基本配置，最后放进前三家 Flash 的对照表里。模块之间怎么权衡、各版本文档之间怎么对得上，留到后面的期数再细读。

> 材料来源：Hugging Face 上 V2-Flash、V2.5、V2.5-Pro、V2.6-Flash-RL、V2.6-Pro-RL 五份 config.json 逐字段对比；V2.6 仓库自带的推理代码 modeling_mimo_v2.py；V2-Flash 技术报告（arXiv:2601.02780）与 V2.6 技术报告（PDF 放在 Hugging Face 仓库里）。简史部分的日期和说法，能找到小米官方原文的以官方为准，只有媒体报道的会注明。

◆ 第一章：补课，小米做大模型这一年半

━━━━━━━━━━━━━━━━━━━━

**第一段：7B 小模型，一个模态一个模态地铺（2025 年 4 月到 11 月）**

2025 年 4 月底，小米的 LLM-Core 团队放出第一个模型 MiMo-7B，定位是“为推理而生”：7B 参数的稠密模型，约 25T token 预训练，Base、SFT、RL 几个版本一起开源。有一处细节后面还会用到：**这台 7B 就已经带了多 token 预测（Multi-Token Prediction，MTP）** ，一直延续到今天的 V2.6。

接下来半年，小米没有急着放大参数，而是拿 7B 这个尺寸把各个模态挨个做了一遍：5 月的视觉模型 MiMo-VL-7B，9 月的音频模型 MiMo-Audio，11 月的具身模型 MiMo-Embodied-7B。V2.6 里用的视觉编码器和音频分词器，就是从这条线长出来的。

**第二段：换了负责人，直接上 MoE（2025 年 11 月到 2026 年 3 月）**

2025 年 11 月，前 DeepSeek 研究员罗福莉在朋友圈宣布加入 Xiaomi MiMo，此后以 MiMo 负责人的身份出面发布（头衔来自媒体报道和发布会，没找到小米的任命公告）。V2.6 技术报告的通讯作者也是她。

12 月中旬，**MiMo-V2-Flash** 开源：309B 总参数、每 token 激活 15B 的 MoE（混合专家，Mixture of Experts），27T token 预训练，技术报告挂上了 arXiv。媒体把它叫作罗福莉加入后的“首秀”。**后面要讲的骨架，就是这一版定下来的。**

2026 年 3 月有一段插曲。小米官方页面的原话是：一个代号 Hunter Alpha 的匿名模型挂上了 OpenRouter（一个聚合各家模型 API 的平台），调用量一路涨，**多日登顶日榜，累计超过 1T token**。社区当时猜的是 DeepSeek 新模型。3 月 18 日揭晓，是小米的 **MiMo-V2-Pro**。这一代 Pro 只开放了 API，没有放权重。

**第三段：两个尺寸一起开源（2026 年 4 月至今）**

4 月下旬，V2.5 和 V2.5-Pro 同时开源，**Pro 这一档第一次放出权重**：1.02T 总参数、激活 42B。这里有个命名上的小坑：Flash 那个尺寸的 V2.5 叫 “MiMo-V2.5”，名字里不带 Flash。

9 月 21 日，V2.6 发布，Pro 和 Flash 两个尺寸加一个 9B 蒸馏版，仓库名都带了 “-RL” 后缀。然后就是开头那一幕。

回头看，小米其实一直不算默默无闻：V2-Pro 的官方页面就自称在 AA 指数上排全球第八、国产第二。是我一直没往那边看。

◆ 第二章：骨架九个月没动过

━━━━━━━━━━━━━━━━━━━━

把五个开源版本的 config.json 摆在一起逐字段对，结论出乎意料地简单。

| 版本 | 发布 | 尺寸 | 骨架 | 相对上一版的变化 |
|---|---|---|---|---|
| V2-Flash | 2025-12 | 309B / 15B | 48 层 | 首发，上下文 256K |
| V2.5 | 2026-04 | 310B / 15B | 与 V2-Flash 相同 | 上下文扩到 1M，加视觉和音频 |
| V2.5-Pro | 2026-04 | 1.02T / 42B | 70 层 | Pro 首次开源权重，纯文本 |
| V2.6-Flash-RL | 2026-09 | 310B / 15B | 与 V2.5 相同 | 专家权重改存 MXFP4 |
| V2.6-Pro-RL | 2026-09 | 1.02T / 42B | 与 V2.5-Pro 相同 | 加视觉和音频，专家权重改存 MXFP4 |

**Flash 这条线，从 2025 年 12 月到现在，层数、隐藏维、专家数、注意力头数、窗口大小，连每一层是什么类型的排列顺序都一模一样。** Pro 这条线从 4 月的 V2.5-Pro 起也没再动过。

这张表里有一格值得多看一眼：V2.5-Pro 的 config 里没有视觉部分，是纯文本模型；而 V2.6 技术报告写的是，Pro 的全模态预训练只有 3T token，Flash 是 22T。两条放在一起，看起来像是**在 V2.5-Pro 的底座上补了一段多模态训练**，而不是从头重新预训练。这是我对着两份材料推出来的，报告没有这么说。

有意思的是 V2-Flash 技术报告自己的结论一节，原话是：

`our current architectural exploration remains preliminary, with limited analysis of design trade-offs. Future work will focus on designing more robust and efficient, agentic-oriented model architectures.`

说架构探索还很初步，以后要设计新架构。结果九个月、三代，一个字段没改。**这也是一种判断：骨架够用就不动，新的投入全放在训练上** ——V2.6 技术报告 44 页，讲架构的只有两页，其余几乎都是强化学习。那部分留到后面单独写。

◆ 第三章：每个模块过一遍

━━━━━━━━━━━━━━━━━━━━

下面按 V2.6 的 config.json 和推理代码，一个模块一个模块地看。两个尺寸并排列，Flash 在前、Pro 在后。

**主干**

| | Flash | Pro |
|---|---|---|
| 层数 | 48 | 70 |
| 隐藏维（hidden_size） | 4096 | 6144 |
| 总参数 / 激活 | 310B / 15B | 1.02T / 42B |
| 词表 | 152,576 | 152,576 |

每一层都是最常见的前置归一化（pre-norm）写法：RMSNorm → 注意力 → 加回残差 → RMSNorm → 前馈网络 → 加回残差。推理代码里就这么几行，没有 DeepSeek 那种改残差流的超连接。

唯一的例外是**第 0 层：全局注意力配一个稠密前馈网络**，中间维 16384。从第 1 层起，前馈网络全换成 MoE。V2-Flash 报告给的理由只有一句，“稳定早期的表征学习”，没附实验。

**注意力：大部分层只看眼前 128 个 token**

这是整台机器最有辨识度的地方。每一层要么是滑动窗口注意力（Sliding Window Attention，SWA），要么是全局注意力（Global Attention，GA）：

- 滑动窗口层：每个 token 只看自己和前面最近的 **128 个** token 以内
- 全局层：看全部历史

| | Flash | Pro |
|---|---|---|
| 滑动窗口层 / 全局层 | 39 / 9 | 60 / 10 |
| 官方说的比例 | 5 : 1 | 6 : 1 |
| 窗口大小 | 128 | 128 |
| 查询头 | 64 | 128 |
| KV 头（滑窗层 / 全局层） | 8 / 4 | 8 / 8 |
| 每个头的维度（QK / V） | 192 / 128 | 192 / 128 |

排列方式是 config 里一串 0 和 1（`hybrid_layer_pattern`，0 是全局、1 是滑窗）。Flash 除了开头那一层，大体是“五层滑窗、一层全局”循环；Pro 大体是“七层滑窗、一层全局”，末尾两组少一层。

128 这个窗口很小。Gemma 系列的滑动窗口在一千到四千；和小米一样开到 128 的是 OpenAI 的开源模型 gpt-oss。两家靠的是同一个配套零件，叫注意力汇（attention sink），V2-Flash 报告明说是照 gpt-oss 的设计做的。它在推理代码里是这样的：每个头多一个可学习的标量，拼在注意力分数的最后一列，一起做 softmax，**算完再把这一列扔掉**。被扔掉的那一列分走的概率，就是“这一步哪儿都不看”的份额。这个零件为什么让 128 的窗口成立，V2-Flash 报告里有一组对照实验，留到后面细读。config 里还有个细节：**只有滑动窗口层开了注意力汇，全局层没开**。

**位置编码**

每个头 192 维的查询和键，**只有前 64 维加旋转位置编码（RoPE），后 128 维不带位置信息** （config 里 `partial_rotary_factor` 是 0.334）。而且全局层和滑窗层各用一套：全局层的底数是 1000 万（为了撑 1M 上下文），滑窗层是 1 万（反正只看 128 个，用不着大底数）。

推理代码里还有一处文档没交代的：V 在进注意力之前乘了一个常数，Flash 是 0.707，Pro 是 0.612（`attention_value_scale`）。技术报告、模型卡、配置注释里都没解释它，我也不替它补一个理由。

**MoE**

| | Flash | Pro |
|---|---|---|
| 路由专家 | 256 | 384 |
| 每 token 激活 | 8 | 8 |
| 共享专家 | 无 | 无 |
| 每个专家的中间维 | 2048 | 2048 |

路由用的是 sigmoid 打分，再加一个只影响“挑哪几个”、不影响加权的纠偏项——这是 DeepSeek-V3 那套不靠辅助损失做负载均衡的办法，246 期 https://mp.weixin.qq.com/s/EwUO9tVfrpCrcwsyPI42uw 讲 MoE 路由时写过。**没有共享专家**，这点和 GLM（1 个）、Qwen（1 个）都不同。

Pro 和 Flash 在推理代码里的区别只有一处：Pro 把 Q、K、V 三个投影矩阵存成一个，Flash 分开存。代码注释原话是只管权重怎么存，算完投影之后的计算完全一样。

**多 token 预测（MTP）**

主干后面挂着一个小的草稿模块，一次猜后面好几个 token，再交给主干并行验证，用来加速生成。V2-Flash 的 MTP 每块只有 0.33B，用稠密前馈加滑动窗口注意力，故意做得很轻；报告给的数字是 3 层 MTP 最多一次接受 3.6 个 token、解码最多快 2.6 倍。V2.6 换成了 5 层、一次猜 7 个 token 的新草稿模块，放在仓库的 `dflash/` 目录里单独加载。

────────────────────

💡 视觉塔又撞在同一个量级上

V2.6 的视觉编码器叫 MiMo-ViT，28 层（24 层滑窗、4 层全局），隐藏维 1280，**约 6.8 亿参数**。音频那边是两段：约 3.1 亿参数的音频分词器，把声音切成离散编码；再加一个约 1.3 亿参数的编码器，把每四帧打成一包送进主干。

292 期数过 GLM-5.3-Flash 的视觉塔约 0.5B，293 期 Qwen3.8 约 0.4B，308 期 DeepSeek V4.1 不到 0.5B。**小米这台的眼睛稍大一点，但仍是同一个量级**，挂在 310B 和 1.02T 的主干旁边，Flash 那边约千分之二，Pro 那边不到千分之一。

视觉编码器里也用了滑动窗口：滑窗层在“按行扫”和“按列扫”之间交替排 token，横竖两个方向的信息都能传开。

◆ 第四章：放进四家 Flash 的对照表

━━━━━━━━━━━━━━━━━━━━

零件清单先摆出来：

| | GLM-5.3-Flash | Qwen3.8-Flash-Next | DeepSeek V4.1-Flash | MiMo-V2.6-Flash |
|---|---|---|---|---|
| 总参 / 激活 | 320B / 18B | 125B / 6B（另有 51B 词典） | 552B / 解码 16B（另有 196B Engram） | 310B / 15B |
| 省长上下文的主要办法 | 3/4 层换线性注意力 | 3/4 层换线性注意力 | 压缩 KV + 跨层共享 | 大部分层只看 128 个 |
| 查表记忆 | 无 | N-gram 词典 | Engram | 无 |
| 共享专家 | 1 | 1 | 1 | 无 |

**四家里，小米的零件是最少的**：没有线性注意力，没有 KV 压缩，没有查表记忆，连共享专家都没有。就是标准的注意力，大部分层把窗口收到 128。

零件少，代价落在 KV 缓存上。照 277 期 https://mp.weixin.qq.com/s/j8Dr2sdRUZIdPfGWr9r5nw 的算法，用 config 里的数字现算一遍：只有全局层要存全部历史，每层每个 token 存 K 和 V 两份。

```python
# 每 token 全局 KV（bf16，2 字节）
# = 全局层数 × KV 头数 × (192 + 128) × 2 字节
Flash = 9 * 4 * 320 * 2     # 23,040 字节 ≈ 22.5 KiB
Pro   = 10 * 8 * 320 * 2    # 51,200 字节 = 50 KiB
```

乘上 1M 上下文：**Flash 约 22.5 GiB，Pro 约 50 GiB**。滑动窗口层每层只留最近 128 个 token，整台机器加起来不到 40 MiB，可以忽略。

| | 1M 上下文的主 KV（bf16） | 出处 |
|---|---|---|
| DeepSeek V4.1-Flash | 不到 1 GB | 308 期，官方 README 的 890 字节/token |
| DeepSeek V4-Flash | 6.72 GiB | 277 期 |
| GLM-5.3-Flash | 约 11 GiB（不含线性层的定长状态） | 292 期 |
| **MiMo-V2.6-Flash** | **约 22.5 GiB** | 本期按 config 现算 |

口径要说在前面：这张表只看数量级。几家的数字都是按主缓存算的，不含索引器之类的零头；小米这一行是我按 config 推的，不是官方数字，推理时如果用 FP8 存 KV 还能再减半。

**同样是撑 1M 上下文，四家走的是三条路：GLM 和 Qwen 换线性注意力，DeepSeek 把 KV 往死里压，小米让大部分层只看眼前。** 前两条路都在省 KV，小米这条路省的主要是计算——128 窗口的层，算注意力的开销跟上下文多长几乎无关。KV 的大头留给那 9 层全局注意力，所以在显存这个刻度上，它比另外三家大出一截。

◆ 第五章：家里能不能跑

━━━━━━━━━━━━━━━━━━━━

V2.6 的专家权重用 MXFP4（一种 4 比特浮点格式）存，其余大部分权重是 FP8。我用 Hugging Face 的接口把 Flash 仓库的文件加了一遍，**一共约 178 GB**；Pro 约 573 GB。

对照手边的硬件：两台 DGX Spark 各 128GB 统一内存，加起来 256GB。Flash 的权重放得下，剩下七十多 GB 给系统、运行时和 KV 缓存。按上一章的算法，KV 每 1 万 token 约 0.2 GiB，**聊个几十万 token 的上下文是有空间的，1M 就比较紧了**。Pro 那 573 GB 就不用想了。

不过这只是容量上装得下。推理框架在 Spark 这类机器上对 MXFP4 的支持磨没磨好，我还没实测，这里只说到“理论上装得下”为止。

◆ 技术名词速查

━━━━━━━━━━━━━━━━━━━━

| 术语 | 一句话解释 |
|---|---|
| AA 智能指数（Artificial Analysis Intelligence Index） | 独立机构 AA 的综合跑分，MiMo-V2.6-Pro 46 分，开源第一 |
| MoE（混合专家，Mixture of Experts） | 前馈网络分成几百个专家，每个 token 只挑几个来算；小米 Flash 256 挑 8，Pro 384 挑 8，无共享专家 |
| SWA（滑动窗口注意力，Sliding Window Attention） | 每个 token 只看最近一段；小米的窗口只有 128 |
| GA（全局注意力，Global Attention） | 看全部历史，KV 缓存主要花在这些层上 |
| 注意力汇（attention sink） | 每个头多一个可学习的“哪儿都不看”选项，拼进 softmax 后丢掉；小米只在滑窗层开 |
| 部分 RoPE | 每个头只有一部分维度加旋转位置编码，小米是 192 维里的前 64 维 |
| MTP（多 token 预测，Multi-Token Prediction） | 草稿模块一次猜多个 token 交给主干验证，加速生成；小米从 7B 起就有 |
| MXFP4 | 4 比特浮点格式，一组 32 个数共享一个缩放因子；V2.6 的专家权重用它存 |
