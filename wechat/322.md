◆ 开篇：一个小透明突然上了榜

━━━━━━━━━━━━━━━━━━━━

先交代我是怎么注意到这台模型的：不是一直在跟，是被榜单推到眼前的。

9 月 21 日，小米开源了 MiMo-V2.6。几天后 Artificial Analysis（AA，一家独立做大模型横评的机构）的智能指数更新，**MiMo-V2.6-Pro 拿了 46 分，开源权重模型里排第一**。AA 模型页上写的是 “#1 / 115”，这个 115 是它所在的 150B 以上大模型组里的开源模型数。媒体报道里紧随其后的是 GLM-5.3 和 Kimi K3。

这个号写过的 Flash 系列已经有三家：292 期 https://mp.weixin.qq.com/s/qGbCm3qJB6SNumftansUtw 读 GLM-5.3-Flash，293 期 https://mp.weixin.qq.com/s/jb-ibVHAG3wKbtoiX5SStA 读 Qwen3.8-Flash-Next，308 期 【308 链接待补】 读 DeepSeek V4.1-Flash。三家都是一路追着看过来的。小米不一样，**在这之前，它在我这儿就是个小透明** ——知道小米在做大模型，但一篇都没读过。

先把对象说清楚：**上榜的是大份的 Pro（1.02T 总参），不是 Flash。** 但 Pro 和 Flash 是同一套骨架的两个尺寸，前面三家我读的又都是 Flash，所以这期除了补课和版本线两处带上 Pro，后面的模块速览和对照表都以 **Flash** 为主。

所以这期先补课：这家到底什么来头。然后把它的骨架过一遍，每个模块只看基本配置，最后放进前几款 Flash 的对照表里。

> 材料来源：Hugging Face 上 V2-Flash、V2.5、V2.5-Pro、V2.6-Flash-RL、V2.6-Pro-RL 五份 config.json 逐字段对比；V2.6 仓库自带的推理代码 modeling_mimo_v2.py；V2-Flash 技术报告（arXiv:2601.02780）与 V2.6 技术报告（PDF 放在 Hugging Face 仓库里）。简史部分的日期和说法，能找到小米官方原文的以官方为准，只有媒体报道的会注明。

◆ 第一章：补课，小米做大模型这一年半

━━━━━━━━━━━━━━━━━━━━

**第一段：7B 小模型，一个模态一个模态地铺（2025 年 4 月到 11 月）**

2025 年 4 月底，小米的 LLM-Core 团队放出第一个模型 MiMo-7B，定位是“为推理而生”：7B 参数的稠密模型，约 25T token 预训练，Base、SFT、RL 几个版本一起开源。有一处细节后面还会用到：**这台 7B 就已经带了多 token 预测（Multi-Token Prediction，MTP）** ，一直延续到今天的 V2.6。

接下来半年，小米没有急着放大参数，而是拿 7B 这个尺寸把各个模态挨个做了一遍：5 月的视觉模型 MiMo-VL-7B，9 月的音频模型 MiMo-Audio，11 月的具身模型 MiMo-Embodied-7B。V2.6 里用的视觉编码器和音频分词器，就是从这条线长出来的。

**第二段：新负责人亮相，模型上 MoE（2025 年 11 月到 2026 年 3 月）**

2025 年 11 月，前 DeepSeek 研究员罗福莉在朋友圈宣布加入 Xiaomi MiMo，此后以 MiMo 负责人的身份出面发布（头衔来自媒体报道和发布会，没找到小米的任命公告）。V2.6 技术报告的通讯作者也是她。

12 月中旬，**MiMo-V2-Flash** 开源：309B 总参数、每 token 激活 15B 的 MoE（混合专家，Mixture of Experts），27T token 预训练；技术报告 2026 年 1 月挂上 arXiv。媒体把它叫作罗福莉加入后的“首秀”，不过这只说明发布时间，模型未必是她到岗后才开始做的。**后面要讲的骨架，就是这一版定下来的。**

2026 年 3 月有一段插曲。小米官方页面的原话是：一个代号 Hunter Alpha 的匿名模型挂上了 OpenRouter（一个聚合各家模型 API 的平台），调用量一路涨，**多日登顶日榜，累计超过 1T token**。社区当时猜的是 DeepSeek 新模型。3 月 18 日揭晓，是小米的 **MiMo-V2-Pro**。这一代 Pro 只开放了 API，没有放权重。

**第三段：两个尺寸一起开源（2026 年 4 月至今）**

4 月下旬，V2.5 和 V2.5-Pro 同时开源，**Pro 这一档第一次放出权重**：1.02T 总参数、激活 42B。这里有个命名上的小坑：Flash 那个尺寸的 V2.5 叫 “MiMo-V2.5”，名字里不带 Flash。

9 月 21 日，V2.6 发布，Pro 和 Flash 两个尺寸加一个 9B 蒸馏版，仓库名都带了 “-RL” 后缀。然后就是开头那一幕。

回头看，小米其实一直不算默默无闻：V2-Pro 的官方页面就自称在 AA 指数上排全球第八、国产第二。是我一直没往那边看。

◆ 第二章：主干骨架九个月没换

━━━━━━━━━━━━━━━━━━━━

把五个开源版本的 config.json 摆在一起逐字段对，结论出乎意料地简单。

| 版本 | 发布 | 尺寸 | 骨架 | 相对上一版的变化 |
|---|---|---|---|---|
| V2-Flash | 2025-12 | 309B / 15B | 48 层 | 首发，上下文 256K |
| V2.5 | 2026-04 | 310B / 15B | 与 V2-Flash 相同 | 上下文扩到 1M（全局层 RoPE 底数随之调大），加视觉和音频 |
| V2.5-Pro | 2026-04 | 1.02T / 42B | 70 层 | Pro 首次开源权重，纯文本 |
| V2.6-Flash-RL | 2026-09 | 310B / 15B | 与 V2.5 相同 | 专家权重改存 MXFP4 |
| V2.6-Pro-RL | 2026-09 | 1.02T / 42B | 与 V2.5-Pro 相同 | 加视觉和音频，专家权重改存 MXFP4 |

**Flash 这条线，从 2025 年 12 月到现在，层数、隐藏维、专家数、注意力头数、窗口大小，连每一层是什么类型的排列顺序都一模一样。** Pro 这条线从 4 月的 V2.5-Pro 起也没再动过。config 里其他字段是有变化的：上下文长度、位置编码底数、归一化的 epsilon、QKV 权重的存法、量化设置，再加上新挂的视觉和音频配置。**变的是这些周边字段，主干拓扑没换。**

这张表里有一格值得多看一眼：V2.5-Pro 的 config 里没有视觉部分，是纯文本模型；而 V2.6 技术报告写的是，Pro 预训练共 30T token，其中 27T 纯文本、只有 3T 全模态，Flash 是 26T 文本加 22T 全模态。两条放在一起，看起来像是**在 V2.5-Pro 的底座上补了一段多模态训练**，而不是从头重新预训练。这是我对着两份材料推出来的，报告没有这么说，分阶段训练的数字也不能唯一确定起点就是发布过的那份 V2.5-Pro 权重。

有意思的是 V2-Flash 技术报告自己的结论一节，原话是：

`our current architectural exploration remains preliminary, with limited analysis of design trade-offs. Future work will focus on designing more robust and efficient, agentic-oriented model architectures.`

说架构探索还很初步，以后要设计新架构。结果九个月、三代，主干拓扑没换。**这也是一种判断：主干够用就不大动，报告的重心转向了训练** ——V2.6 技术报告 44 页，讲架构的只有两页，其余几乎都是强化学习。当然周边也一直在改：多模态编码器、投机解码草稿头、量化和推理系统，都不是原样。

◆ 第三章：每个模块过一遍

━━━━━━━━━━━━━━━━━━━━

下面按 V2.6 的 config.json 和推理代码，一个模块一个模块地看。两个尺寸并排列，Flash 在前、Pro 在后。

**主干**

| | Flash | Pro |
|---|---|---|
| 层数 | 48 | 70 |
| 隐藏维（hidden_size） | 4096 | 6144 |
| 总参数 / 激活 | 310B / 15B | 1.02T / 42B |
| 词表 | 152,576 | 152,576 |

每一层都是最常见的前置归一化（pre-norm）写法：RMSNorm → 注意力 → 加回残差 → RMSNorm → 前馈网络 → 加回残差。推理代码里就这么几行，没有 DeepSeek 那种改残差流的超连接。

前馈网络的例外在**第 0 层：全局注意力配一个稠密前馈网络**，中间维 16384。从第 1 层起，前馈网络全换成 MoE。V2-Flash 报告给的理由只有一句，“稳定早期的表征学习”，没附实验。

**注意力：大部分层只看眼前 128 个 token**

这是整台机器最有辨识度的地方。每一层要么是滑动窗口注意力（Sliding Window Attention，SWA），要么是全局注意力（Global Attention，GA）：

- 滑动窗口层：每个 token 只看自己和前面最近的 **128 个** token 以内
- 全局层：看全部历史

| | Flash | Pro |
|---|---|---|
| 滑动窗口层 / 全局层 | 39 / 9 | 60 / 10 |
| 窗口大小 | 128 | 128 |
| Q 头（查询头） | 64 | 128 |
| KV 头（滑窗层 / 全局层） | 8 / 4 | 8 / 8 |
| 每个头的维度（QK / V） | 192 / 128 | 192 / 128 |

排列方式是 config 里一串 0 和 1（`hybrid_layer_pattern`，0 是全局、1 是滑窗）。Flash 除了开头那一层，大体是“五层滑窗、一层全局”循环（官方说的 5:1 指的就是这个循环）；Pro 大体是“七层滑窗、一层全局”，开头和末尾几组是六层。

128 这个窗口很小。Gemma 系列的滑动窗口在一千到四千；和小米一样开到 128 的是 OpenAI 的开源模型 gpt-oss。两家靠的是同一个配套零件，叫注意力汇（attention sink），V2-Flash 报告明说是照 gpt-oss 的设计做的。它在推理代码里是这样的：每个头多一个可学习的标量，拼在注意力分数的最后一列，一起做 softmax，**算完再把这一列扔掉**。被扔掉的那一列分走的概率，就是这个头“这一步哪儿都不看”的份额。V2-Flash 报告在一台 32B 稠密模型上做过对照：不带注意力汇的 128 窗口混合模型，比全部用全局注意力的还差；带上之后反超。config 里还有个细节：**只有滑动窗口层开了注意力汇，全局层没开**。

**位置编码**

每个头 192 维的查询和键，**只有前 64 维加旋转位置编码（RoPE），后 128 维不直接做旋转** （config 里 `partial_rotary_factor` 是 0.334）。而且全局层和滑窗层各用一套：全局层的底数是 1000 万（为了撑 1M 上下文），滑窗层是 1 万（反正只看 128 个，用不着大底数）。

推理代码里还有一处文档没交代的：V 在进注意力之前乘了一个常数，Flash 是 0.707，Pro 是 0.612（`attention_value_scale`）。技术报告、模型卡、配置注释里都没解释它，我也不替它补一个理由。

**MoE**

| | Flash | Pro |
|---|---|---|
| 路由专家 | 256 | 384 |
| 每 token 激活 | 8 | 8 |
| 共享专家 | 无 | 无 |
| 每个专家的中间维 | 2048 | 2048 |

路由用的是 sigmoid 打分，再加一个只用来“挑哪几个”、不直接加进权重的纠偏项——这是 DeepSeek-V3 那套不靠辅助损失做负载均衡的办法，246 期 https://mp.weixin.qq.com/s/EwUO9tVfrpCrcwsyPI42uw 讲 MoE 路由时写过。**没有共享专家**，这点和 GLM（1 个）、Qwen（1 个）都不同。

推理代码支持两种 QKV 权重存法：Q、K、V 三个投影矩阵分开存，或者合成一个存。代码注释写的是 Flash 分开、Pro 合并，但这次两份 config 实际都选了合并（`attention_projection_layout: fused_qkv`），注释已经过时。两种存法算完投影之后走的是同一套代码。

**投机解码草稿头：对标 DeepSeek 的 DSpark**

现在每家大模型旁边都挂一个“猜词的小弟”：小弟一次猜后面好几个 token，主干一次性并行验证，猜对几个就白赚几个。236 期 https://mp.weixin.qq.com/s/fQc0hRxEIZxkPzGTDhj78g 讲 DeepSeek 的 DSpark 时把这一类方法梳理过，这里直接拿 DSpark 当参照。

小米这边分两代。V2-Flash 用的是 MTP（多 token 预测）：每块只有 0.33B，稠密前馈加滑动窗口注意力，报告给的数字是 3 层 MTP 平均接受长度最高 3.6、解码最多快 2.6 倍。V2.6 预训练时仍然带着 MTP 这个训练目标，但推理时的草稿头换成了 DFlash 路线，放在仓库的 `dflash/` 目录里单独加载。它的 config 和 DSpark 并排是这样：

| | DeepSeek DSpark（V4-Flash-0731） | MiMo-V2.6 DFlash |
|---|---|---|
| 从主干哪几层取信号 | 第 40 到 42 层（最后几层） | 5 层，从头到尾均匀取：Flash 是第 0、11、23、35、47 层 |
| 草稿头本体 | 并行主干 + 一层很薄的 Markov 头 | 5 层 Transformer，稠密前馈 |
| 一次猜几个 | 块大小 5 | 块大小 8（1 个已知 token 加 7 个待猜） |
| 块内怎么出 | 半自回归：并行出一版，再按顺序修正 | 纯并行：块内双向注意力，一次前向全出 |
| 注意力 | — | 滑动窗口，最多回看主干的 1024 个位置 |
| 体积 | 约 20B（268 期 https://mp.weixin.qq.com/s/SlC6kaPk6eZPSCgSH6duHQ 按权重差估的） | Flash 这份约 2.9 GB，bf16 下约 15 亿参数 |

两家最大的区别在“块内怎么出”。236 期讲过，DFlash 这条路每个位置独立预测，快，但可能拼出前后不搭的词；DSpark 的半自回归就是冲着这个毛病来的，多加一层按顺序修正。小米选的是纯并行那条，块开得更大，代价由主干的验证兜住。

另一个区别是取信号的位置：DSpark 只看主干最后几层，小米的草稿头从浅到深均匀取五层。至于哪种取法更好，两家各自的报告都没有拿对方做对照，我也没法替它们比。

体积上差了一个数量级：DSpark 约 20B（估计值），小米这份不到 1.5B。V2.6 报告里还提了一句：强化学习阶段生成数据时，默认用的是块大小 6 的 DFlash，平均接受长度比原来 3 层 MTP 的配置高 31.3%，块大小 6 比 8 的总吞吐又高约 6%。这组数是训练时生成数据用的配置，和上表发布的块大小 8 不是一回事。

💡 视觉塔又撞在同一个量级上

V2.6 的视觉编码器叫 MiMo-ViT，28 层（24 层滑窗、4 层全局），隐藏维 1280，**约 6.8 亿参数**。音频那边是两段：音频分词器的编码端约 3.1 亿参数，把声音切成离散编码；再加一个约 1.3 亿参数的编码器，把每四帧打成一包送进主干。

292 期数过 GLM-5.3-Flash 的视觉塔约 0.5B，293 期 Qwen3.8 约 0.4B，308 期 DeepSeek V4.1 不到 0.5B。**小米这台的眼睛稍大一点，但仍是同一个量级**，挂在 310B 和 1.02T 的主干旁边，Flash 那边约千分之二，Pro 那边不到千分之一。

视觉编码器里也用了滑动窗口：滑窗层在“按行扫”和“按列扫”之间交替排 token，横竖两个方向的信息都能传开。

◆ 第四章：放进五款 Flash 的对照表

━━━━━━━━━━━━━━━━━━━━

先说为什么是五款：DeepSeek 的 V4-Flash 和 V4.1-Flash 虽然名字只差一个小版本号，架构却几乎换了一台——V4.1 把 40 层切成编码、解码两半，KV 在压缩之外又加了跨层共享，还装上了 196B 的 Engram（上文 308 期逐个读过）。**所以这里把它们当两台机器算。** 小米正好相反，版本号从 V2 走到 V2.6，主干拓扑没换。

零件清单先摆出来：

| | GLM-5.3-Flash | Qwen3.8-Flash-Next | DeepSeek V4-Flash | DeepSeek V4.1-Flash | MiMo-V2.6-Flash |
|---|---|---|---|---|---|
| 总参 / 激活 | 320B / 18B | 125B / 6B（另有 51B 词典） | 284B / 13B | 552B / 解码 16B（另有 196B Engram） | 310B / 15B |
| 省长上下文的主要办法 | 3/4 层线性注意力（KDA），其余 MLA + 稀疏 | 3/4 层线性注意力（GDN），其余稀疏 | 按序列压缩 KV（CSA/HCA） | 压缩 KV + 跨层共享（CSA2）+ 切成编码解码两半（CED） | 大部分层只看 128 个 |
| 查表记忆 | 无 | N-gram 词典 | 无 | Engram | 无 |
| 共享专家 | 1 | 1 | 1 | 1 | 无 |

**五款里，小米的主干走得最保守。** 把这一年各家装上去的新零件列一张清单，再对着小米的 config 逐项找，一个都找不到：

| 零件 | 干什么的 | 谁装了 | 小米 |
|---|---|---|---|
| mHC（流形约束超连接） | 把残差流拓宽成几条 | DeepSeek V4 系、GLM-5.3-Flash | 无 |
| Gated Residual（门控残差） | 同上，超连接家族的低秩版 | Qwen3.8-Flash-Next | 无 |
| AttnRes（注意力残差） | 用注意力决定从哪几层取残差 | Kimi | 无 |
| CSA / HCA（压缩稀疏注意力 / 高度压缩注意力） | 按序列压缩 KV | DeepSeek V4-Flash | 无 |
| CSA2 + CED（因果编码-解码） | 跨层共享 KV、切成编码解码两半 | DeepSeek V4.1-Flash | 无 |
| KDA（Kimi 增量注意力） | 线性注意力（Kimi 在 GDN 上改的） | GLM-5.3-Flash、Kimi | 无 |
| GDN（门控 DeltaNet） | 线性注意力 | Qwen3.8-Flash-Next | 无 |
| 查表记忆 | Engram / N-gram 词典 | DeepSeek V4.1-Flash、Qwen3.8-Flash-Next | 无 |
| 共享专家 | 每个 token 都过的那个专家 | 其余四家 | 无 |

残差流那三样，126 期 https://mp.weixin.qq.com/s/iArmZhtv1Q_aobLkEm3BBw 从字节的超连接讲到过 mHC 和 Kimi 的 AttnRes。别家的 Flash 基本是从这张公共货架上挑零件组装，**这张清单上的，小米一件没拿**：最普通的前置归一化残差，标准的注意力，大部分层把窗口收到 128。它也不是什么都没借——GQA、注意力汇、DeepSeek 式的路由、DFlash 草稿头都是现成的——但在残差流、线性注意力、KV 压缩、查表记忆这几条这一年最热闹的线上，它一条都没跟。放在这一代 Flash 里，非常格格不入。

零件少，代价落在 KV 缓存上。照 277 期 https://mp.weixin.qq.com/s/j8Dr2sdRUZIdPfGWr9r5nw 的算法，用 config 里的数字现算一遍：只有全局层要存全部历史，每层每个 token 存 K 和 V 两份。

```python
# 每 token 全局 KV（bf16，2 字节）
# = 全局层数 × KV 头数 × (192 + 128) × 2 字节
Flash = 9 * 4 * 320 * 2     # 23,040 字节 ≈ 22.5 KiB
Pro   = 10 * 8 * 320 * 2    # 51,200 字节 = 50 KiB
```

乘上 1M（这里按 2²⁰ = 1,048,576 个 token 算）上下文：**Flash 约 22.5 GiB，Pro 约 50 GiB**。滑动窗口层每层只留最近 128 个 token，整台机器加起来不到 40 MiB——这本身就是滑窗省下来的：这 39 层要是也存全部历史，KV 要再多好几倍。长历史的大头，全落在那 9 层全局注意力上。

| | 约百万 token 的主 KV | 精度 / 统计范围 | 出处 |
|---|---|---|---|
| DeepSeek V4.1-Flash | 不到 1 GB | FP4 主 KV，含索引器的 K（官方 890 字节/token） | 308 期 |
| DeepSeek V4-Flash | 6.72 GiB | bf16 主缓存 | 277 期 |
| GLM-5.3-Flash | 约 11 GiB | bf16，11 层 MLA，不含线性层定长状态和索引器 | 292 期 |
| **MiMo-V2.6-Flash** | **约 22.5 GiB** | bf16，9 层全局层 | 本期按 config 现算 |
| Qwen3.8-Flash-Next | 约 24 GiB | bf16，12 层稀疏注意力层，不含索引器和线性层状态 | 本期按 config 现算 |

口径要说在前面：这张表只看数量级，精度和统计范围并不统一，V4.1 那行是官方给的 FP4 口径，其余几行是 bf16 推算。小米和 Qwen 这两行是我按 config 推的，不是官方数字，按 2²⁰ 个 token 算；bf16 那几行推理时如果用 FP8 存还能再减半。这些都是缓存布局下的估算，不是整台机器部署时的显存。Qwen 那 12 层是稀疏注意力，但稀疏省的是计算：每次只挑一部分历史来算，全部历史的 KV 照样得存着，算法是 12 层 × 2 组 KV 头 × (256 + 256) × 2 字节，每 token 约 24 KiB。

**同样是撑 1M 上下文，五款走的是三条路：GLM 和 Qwen 把 3/4 层换成线性注意力，把历史折成定长状态；DeepSeek 压缩 KV 本身；小米让大部分层只保留最近 128 个 token。** 三条路都在省 KV，也都顺带省了计算，差别在剩下的那几层全局注意力怎么处理：GLM 用 MLA 压了，Qwen 没压，DeepSeek 两代都在压，小米也没压。所以在显存这个刻度上，小米和 Qwen 同一档，比 GLM 和 DeepSeek 大出一截。

说得再直白一点：**小米这台没有用任何新的 KV 压缩技术。** 省 KV 只靠两样老办法：滑动窗口，加上全局层少放几组 KV 头——也就是分组查询注意力（Grouped-Query Attention，GQA），几十个查询头共用几组 KV，168 期 https://mp.weixin.qq.com/s/YqcTnIrGKEYZ2n-sMAelKg 讲注意力从 MHA 到 MLA 的演化时写过。没有 MLA 那种把 KV 压成低维向量的做法，没有按序列压缩，没有跨层共享，config 里也没写 KV 要用低精度存。结果就是不管 Pro 还是 Flash，长上下文都很占显存。

────────────────────

💡 不压 KV 的那套骨架，反而拿了第一

这里有个我很想追下去的问题：**KV 压缩是不是在悄悄掉分？**

主干最保守、全局层不压 KV 的这套骨架，它的大份 Pro 拿了开源第一（上面对照的是 Flash，Pro 是同一套骨架放大）。一个自然的猜想是：全局层保留每个历史位置的 KV，不做序列压缩也不跨层合并，长上下文里能回看的东西更完整；而压缩也好、挑着看也好，总有丢掉的时候。

手上有几条材料指向这个方向。V2-Flash 报告拿自家的预训练底座（还没做后训练）在长上下文推理测试 GSM-Infinite 上比过 DeepSeek-V3.2-Exp 的底座（DSA 稀疏注意力那一代）：上下文 16K 时 DeepSeek 最高，50.4 对小米的 37.7；拉到 128K，DeepSeek 掉到 25.7，小米还有 29.0。报告的原话是稀疏注意力在带噪声的长输入推理上有内在劣势。上文 308 期读 V4.1-Flash 时，DeepSeek 自己在 Limitations 一节也写了，跨层复用可能选错位置、有界回放是近似重建，没测到的边界上可能掉能力。

但也有一组方向相反的材料，而且更贴近机制：同一份 V2-Flash 报告在 32B 稠密模型上、用同一套训练流程，比过全部用全局注意力和 128 窗口混合两种结构。GSM-Infinite 上全局注意力 12.3，混合结构 17.3；长上下文检索 MRCR 上 32.5 对 34.4。**少看一部分历史，反而更好。** 作者自己的解释是正则化和局部、全局分工更清楚，并强调只限于那组实验设置。

所以要把这个猜想说成结论，还差得远。跨厂商那组对照，两家的训练数据、配方完全不同，对手是 V3.2-Exp 而不是 V4.1，而且是小米自己的报告；AA 的综合指数也不是专门测长上下文的。现有这些实验都没有单独隔离出 V4.1 那套压缩和跨层复用，相对小米这套方案到底损失多少，还回答不了。

所以这里先记成一个待验证的问题：**省下来的显存，是不是有一部分是拿长上下文的能力换的。**
