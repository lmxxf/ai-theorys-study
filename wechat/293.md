◆ 第二章：config——又是 3/4 线性，方言不同

━━━━━━━━━━━━━━━━━━━━

292 期读 GLM-5.3-Flash 是从 config 里数出来的 34+11；Qwen 这边更直接，README 把层排布写成了一个公式：

**12 × (3 × (Gated DeltaNet → MoE) → 1 × (Qwen 稀疏注意力 → MoE))**

48 层 = 36 层线性 + 12 层稀疏，`full_attention_interval: 4`——**又是 3:1，又是“线性 + 稀疏”**。292 期那句“GLM 是三家里唯一连 1/4 也不给全量的”，成立了不到一天：Qwen 的新架构同样一层全量注意力都没有，那 1/4 也是稀疏的。两家前后脚发的 Flash，落在同一张配方上。

配方相同，方言各异，逐项对：

**线性层**：Qwen 沿用 Gated DeltaNet（48 个 value 头、16 个 key 头、head_dim 128）——188 期 https://mp.weixin.qq.com/s/jcQlCc3XtaCEEnjUaxw93w 读 Qwen3.6-27B 时讲过这套机制，这次是它的延续。GLM 则用了 Kimi 在 GDN 基础上改出的 KDA。 **一个沿用上一代零件，一个借邻居改过的版本。**

**稀疏层**：Qwen 的叫 QSA（Qwen 稀疏注意力，Qwen Sparse Attention），和 DeepSeek 的 DSA 差在挑法——DSA 的索引器逐个 token 挑，QSA **按小块挑**：把历史序列切成 4 个 token 一块，索引器给块打分，选中 512 块（合 2048 个 token）来算。块级挑选索引开销更小，官方说这是冲着 agent 任务的长上下文延迟去的。技术报告还交代了它的装配顺序：**预训练时这 12 层用的是普通全量注意力，续训（continued pre-training）阶段才换装 QSA**——先拿全量注意力的分布蒸馏索引器一千步，再让主干和索引器联合训练八千步适应稀疏。这套流程眼熟：DeepSeek V3.2 引入 DSA 时就是这么干的，预训练底座不动、续训阶段换装稀疏——**借的不只是“稀疏索引”这个零件，连换装流程都是照着来的**。报告给的内核测速：1M 上下文下，QSA 比稠密注意力 prefill 快 7.6 倍、decode 快 4.9 倍。

**位置编码**：这里是两台 Flash 之间**最实质的一处技术分歧**。GLM 的选择是主注意力干脆不要位置编码（NoPE）；Qwen 的 config 里则是 `partial_rotary_factor: 0.25`——256 维的头里留 64 维带 RoPE。有意思的是，这不是保守惯性：**技术报告明说他们试过 NoPE 变体**——预训练阶段和 RoPE 几乎没差别，**但后训练之后，NoPE 版“停不下来”的比例显著升高**（endless generation，生成不终止），所以留了 RoPE。同一个问题，GLM 押了 NoPE 没报告问题，Qwen 实测说会刹不住车——两家用真金白银的训练跑出了相反的判断，哪边对，可能要等两台机器都被用户用久了才见分晓。另外，Qwen 留下的这 64 维 RoPE 还是多模态版 M-RoPE（`mrope_section: [11, 11, 10]`，时间、高、宽三个分量各管一段）——图片和视频的位置不是“第几个 token”能表达的，得告诉模型这块图在第几帧、哪一行、哪一列。

**残差流**：config 里有 `hc_count: 4`、`hc_lowrank: 320`。官方文章里这个零件叫 **Gated Residual（门控残差）**：把残差流拓宽成 4 条支流，读的时候按元素开门、写的时候按分支给权重。字段名的 `hc` 两个字母已经泄露了血统，技术报告干脆明写：这是在 AltUp 和超连接（Hyper-Connections）两条工作线上做的改良——正是 126 期 https://mp.weixin.qq.com/s/iArmZhtv1Q_aobLkEm3BBw 从字节的 HC 讲到 DeepSeek 的 mHC 那条线。GLM-5.3-Flash 用的是 mHC，Qwen 用低秩版 HC 配上门控——**残差流改造，两台 Flash 也都上了，又是同一张配方的不同方言。**

**MoE**：512 个专家激活 10 个路由加 1 个共享，专家中间维只有 640——切得非常碎的细粒度专家，和 GLM 的 288 选 8 属于同一思路的不同刻度。

────────────────────

💡 QSA 和 DSA 的差别：一个逐字挑，一个按段挑

都是“索引器先打分、再挑一部分历史来算”，差在颗粒度。DSA 给每个历史 token 打分，挑 2048 个——像从一本书里挑 2048 个字；QSA 先把书切成 4 字一段，给段打分挑 512 段——字数一样，打分次数少了四分之三。代价是段里可能夹带没用的字，换来的是索引本身更便宜。config 里 `indexer_compress_ratio: 4` 就是这个 4 字一段。

────────────────────

稀疏了这么多，长上下文的“记忆力”伤没伤？292 期读 GLM-5.3-Flash 时专门找过这张体检单，官方没给；**Qwen 给了**——技术报告直接列了 RULER 和 8 针 MRCR 两项长上下文检索基准，而且把换装 QSA 前后的对照摆了出来：

| | RULER ≤128K | RULER 512K-1M | MRCR 512K | MRCR 1M |
|---|---|---|---|---|
| 全量注意力 | 99.84 | 90.08 | 30.66 | 20.71 |
| 换装 QSA 后 | 99.89 | **93.00** | **40.53** | **26.44** |

短上下文两边打平，**长上下文稀疏版反而更高**——512K 以上 RULER 涨 3 分，MRCR 涨 10 分和 6 分。索引器先把明显无关的历史筛掉，核心注意力反而少受干扰，这个反直觉的结果报告自己也点了。MRCR 的绝对分不高（1M 才 26.44），这个基准本来就难，重点是方向：**稀疏没有伤记忆力，还帮了点忙**。同一张体检单，一家没交，一家交了还考出了意外的分——这也算两台 Flash 的一处对照。

顺手把它和自家 8 月 5 日先发的 Qwen3.8-27B 也对了一下 config，结果有点意外：**27B 的 model_type 还是 `qwen3_5`**——挂着 3.8 的号，骨架是上一代的（dense、1/4 层纯全量注意力、没有 MoE）。真正属于 `qwen4_exp` 的新零件全在 Flash-Next 身上：Gated Residual、N-gram 嵌入、QSA，一件没少，恰好就是官方 Highlights 列的那几样。 **同一个“Qwen3.8”版本号底下，一台是旧架构续用，一台是下一代预览**——292 期说 GLM 版本号语义倒挂，Qwen 自家也一样：版本号记录的是发布批次，model_type 记录的才是机器本身。

两家在这件事上走到了同一步：**换代架构不上旗舰，先装进各自最小的量产机，把效率压榨到极限**——GLM 拿 320B-A18B 试新注意力路线，Qwen 拿 125B-A6B 试 Qwen4 全套零件。到这里为止，两台 Flash 像是平行研发的同一台机器。但 Qwen 有一个零件是 GLM 没有的，也是这台机器最值得单独一章的东西。

◆ 第三章：N-gram 嵌入——51B 参数，塞的是内存

━━━━━━━━━━━━━━━━━━━━

规格表里那独有的一栏：主干 125B 之外，**另有 51B 的 N-gram 嵌入**。这 51B 特殊在哪？它可以不住显存，放在主机内存里异步预取。

这东西的机制，今年 1 月的 49 期 https://mp.weixin.qq.com/s/4DqR-WYNf2ww61MDJVAFZw 讲过——那时它叫 **DeepSeek Engram**，梁文锋 1 月 12 日放的论文：给常见“词组”也配上向量，两三个相邻 token 的组合（学术上叫 N-gram）直接查表拿到现成表示，不用靠前几层网络现场算。词典查得到的就查词典，查不到的才动脑子。

七个月过去，**这篇论文的思路出现在了 Qwen 的量产机器上**，而且细节对得上：

| | DeepSeek Engram（1 月论文） | Qwen3.8-Flash-Next（8 月装机） |
|---|---|---|
| 存什么 | n-gram 词组向量 | bigram/trigram（二连、三连词组）向量 |
| 放哪层 | 单放一个时**第 2 层最优**；浅深各放一个更好 | config 原值 `ple_layer_ids: [2]`——**只装一个，取了“单放第 2 层”那档** |
| 参数怎么分 | U 型曲线：**20-25% 给词典**、其余给 MoE 时 loss 最低 | 51B / (125B + 51B) ≈ **29%**——落在谷底附近 |
| 存哪 | 表放 CPU 内存，异步预取 | 51B 塞系统内存 |

“放第 2 层”这个结果和 Engram 对上了。不过 Qwen 不是照表抄答案，它自己的技术报告也重新跑了层位消融：分到第 2+25 层只能让 loss 再低一点，下游分数没有稳定收益，最后选单独第 2 层，还能用第一层的计算时间掩盖主机内存预取。292 期说零件从公共货架上拿——GLM 拿了 Kimi 的 KDA 和 DeepSeek 的 DSA，这次 Qwen 拿的是 DeepSeek 一月论文里的思路。**论文到量产，七个月。**

这中间还有个值得记一笔的转折。Engram 论文放出来的时候，所有人都当它是 DeepSeek 下一代的基建预告——49 期结尾我自己就写了“春节档的 V4，大概率会把这些全整合进去”。结果半对半错：mHC 真进了 V4，**Engram 没进**。原厂发了论文、原厂自己没装机，八个月后反倒是 Qwen 把它装上了量产线。公共货架就是这样：零件摆出来，谁用不归发明者管。

51B 这个数字自己就能算出来。config 里 `ngram_size: 3`，所以查 bigram 和 trigram 两种长度；每种又有 `heads_per_ngram: 8` 个哈希头，一共 16 张表。每张表约两千万槽，每个槽存 2560 ÷ 16 = 160 维：

2 种 n-gram × 8 个头 × 20M 槽 × 160 维 ≈ **51.2B**

不是“一张两千万词条、每条 2560 维”的大表，而是 16 张约两千万槽、每槽 160 维的小表；总数一样，实际查表方式不同。作为对照，整个主干才 125B，这本“词组词典”超过主干的三分之一。

为什么敢塞这么大？因为**嵌入表是查表，不是矩阵乘**。普通稠密权重每个 token 前向都要全量上场；而这 16 张大表，每个 token 只从每张表命中一个槽，一共取回 16 个 160 维小向量，其余槽全在睡觉。整张表放进 CPU 内存，查到的那些向量传给 GPU 就行。官方的定位说得很清楚：这是**参数扩展的另一条轴**——比 MoE 更适合挪出显存、放去便宜地方住（offload）。MoE 的专家再稀疏，轮到谁上场谁还是要做矩阵乘；查表连乘法都没有。

────────────────────

💡 参数扩展的三条轴：都变大，贵法不一样

**第一条轴，堆稠密参数**：能力涨，但每个 token 全量参与计算，算力显存一起涨，最贵。 **第二条轴，MoE**：总参涨、激活不涨，省算力，但整套专家权重仍要有地方放，显存或内存照涨。 **第三条轴，嵌入表**：只涨查表条目，算力几乎不涨，而且很适合从显存搬到主机内存——甚至可以住磁盘，热词条留内存。三条轴里最便宜的一条，代价是它只能存“查得到的知识”，存不了推理能力。Qwen 这台机器三条轴全用了：125B MoE + 6B 激活 + 51B 词典。

────────────────────

这也解释了它为什么敢把激活压到 6B 还能打 284B 的机器：**词典垫了底，小主干就不用把宝贵的层数花在重建常见组合上。**

词典还能放得更远。每个 token 总共取回 16 个 160 维向量，bf16 合计约 5KB；更要紧的是，**查哪 16 个槽是提前确定的**——key 只由最近两三个 token 算出，当前 token 一出来，下一步查哪里就已知，可以立刻异步预取、和计算重叠。这一点比“把 MoE 专家挪出显存”那套方案优越得多：专家路由到谁要算到那层才知道，预取只能靠猜。再加上词组频率天然是少数高频、多数长尾的分布，高频词条会被操作系统的页缓存热在内存里，真正下盘的只有冷门词条。Engram 论文做到的是“表放 CPU 内存、异步预取、额外延迟不到 3%”；SSD 这一步是顺着同一条路继续走，不过有个现成旁证——谷歌去年在端侧模型 Gemma 3n 上用过一个更简单的近亲：PLE（逐层嵌入，Per-Layer Embeddings），按单个 token 查表、每层注入一份，官方文档明说了表可以缓存到本地高速存储。Qwen config 里那些 `ple_*` 字段名就是沿用它的叫法——**机制照 Engram 的 n-gram 词典，工程接口的名字随 Gemma 的 PLE**，一个零件两处血统。

于是这台机器可以住进**三级存储**：每个 token 只激活主干里的 6B 参数，但整套主干权重仍放在统一内存里；词典的热词条留在内存，冷门词条睡在 SSD 上——按访问频率分层住宿，和计算机体系结构里的缓存层级一个道理。 **6B 是每步参与计算的参数量，不是只需常驻 6B 权重。**

参数这么分层之后，一类硬件突然够得着它了：**128G 统一内存主机**——52.01 期 https://mp.weixin.qq.com/s/yciCclJW1lhKd4Mz0Ttiwg 横评过的那个品类：AMD AI Max 395、DGX Spark、Mac 128G。官方 BF16 权重索引是 360.00GB，官方 FP8 权重索引也有 **185.50GB**，单台 128G 都装不下；但 Q4 加 SSD 分层就不一样了。现在社区的 IQ4_XS 量化文件是 **93.7GB**，已经有人在 128GB 的 DGX Spark 这类统一内存机器上把它跑起来。剩下三十来 GB 还要塞系统、运行时、KV cache 和词典热页，肯定不好用；但“180B 级模型能不能在 128G 机器上启动”这道门，确实已经跨过去了。现在缺的不是装不装得下，是推理框架把 QSA、PLE 分层和 GPU 路径磨稳定。

而且这个门框马上还要变宽：AMD 新发布的 Ryzen AI Max PRO 400 系列把统一内存推到 **192GB**，官方计划 2026 年第三季度上市。它离 FP8 权重索引的 185.50GB 只剩 6.5GB，系统和 KV cache 都还没进来，原生 FP8 依然不实用；但换成 93.7GB 的 IQ4_XS，能留给运行时和长上下文的空间就比 128G 宽多了。这台机器发布时瞄的天花板，硬件半年内就长上来了。

◆ 第四章：两台 Flash 对照表

━━━━━━━━━━━━━━━━━━━━

把这一周的两台机器摆在一起，同与不同一目了然：

| | GLM-5.3-Flash | Qwen3.8-Flash-Next |
|---|---|---|
| 官宣 | 8 月 26 日 | 8 月 24 日建仓，8 月 26 日官宣 |
| 总参 / 激活 | 320B / 18B | 125B / 6B（另 +51B 词典） |
| 层数与配比 | 45 层，34 线性 + 11 稀疏 | 48 层，36 线性 + 12 稀疏 |
| 线性方言 | KDA（借 Kimi 的） | Gated DeltaNet（沿用上一代） |
| 稀疏方言 | DSA（借 DeepSeek 的）+ 自补 IndexPool | QSA（自家的，块级挑选） |
| 位置编码 | 主注意力 NoPE | 1/4 维度 RoPE + 多模态 M-RoPE |
| 残差流 | mHC（借 DeepSeek 的） | Gated Residual（HC 家族低秩版） |
| 独门件 | — | N-gram 嵌入 51B（DeepSeek 论文思路） |
| 多模态 | 原生视觉塔约 0.5B | 原生视觉塔约 0.4B |
| 命名 | 老名字藏新机器 | Next / qwen4_exp 直接明说 |

同的部分——3/4 线性加 1/4 稀疏、没有一层全量注意力、残差流拓宽、原生多模态、主打便宜快——是**这一代轻量旗舰的公共配方**，两家独立收敛到了一起。不同的部分几乎全是“方言”：机制同构，实现各家。真正的路线差异只有两处：位置编码（激进的 NoPE 对保守的部分 RoPE），和那本 51B 的词典。

还有一个对照有意思：**GLM 直接沿用了 KDA、DSA、mHC 这些带名字的外部零件；Qwen 则沿用 GDN，再自己做 QSA 和 Gated Residual，N-gram 嵌入吸收 Engram、Gemma PLE 等公开路线。** 同一张公共货架，一家直接拿成熟零件装机，一家拿基础零件再加工——开源生态里两种都成立，比拼的还是那句话：谁组装得好、谁训得动。

◆ 第五章：视觉塔——SigLIP 的尺寸，管到视频

━━━━━━━━━━━━━━━━━━━━

和 GLM-5.3-Flash 一样，这台机器的 config 里也装着一节 `vision_config`：27 层、隐藏维 1152、16 个头——熟悉视觉模型的读者看到 1152 这个数会心一笑，**这是 SigLIP-So400m 的标志尺寸**，谷歌开源的那个经典视觉编码器的形状。按结构算参数量约 0.4B，和 GLM 的视觉塔一个量级：又一次印证“眼睛不用大，贵的是看懂之后的推理”。

输入侧：patch 16×16、空间 2×2 合并、`temporal_patch_size: 2`——和 GLM 那台一样，时间维也切块，视频原生支持，单图是特例。输出 2560 维直接对齐语言主干的隐藏维。

配合前面说的 M-RoPE 三分量（时间、高、宽），这台机器看视频时每个视觉 token 都带着“第几帧、哪一行、哪一列”的完整坐标。第一章视觉跑分里长视频理解 LVBench 76.6、手机操作 AndroidWorld 84.5，背后就是这套“原生视频 + 空间坐标”的底子——**屏幕操作类 agent 要的不是看懂一张图，是盯着一块不断变化的屏幕连续做决定**，这正是这套输入管线的主场。
