◆ 开篇：两家撞车，两种性格

━━━━━━━━━━━━━━━━━━━━

292 期 https://mp.weixin.qq.com/s/qGbCm3qJB6SNumftansUtw 读了 GLM-5.3-Flash 的 config：名字像旗舰的小份，里面是台换了注意力路线的新机器。写的时候我就知道还有下文——**同一周，阿里也发了一台 Flash**，配方惊人地像，性格却完全相反。

先把 8 月的时间线摆出来（发布日期按 Hugging Face 仓库创建时间，一手）：

  • 8 月 5 日：Qwen3.8-**27B**（小杯，dense）
  • 8 月 8 日：Qwen3.8-**2.4T-A95B**（超大杯，2.4T 总参）
  • 8 月 24 日：**Qwen3.8-Flash-Next** 建仓，26 日前后官宣开源
  • 8 月 26 日：GLM-5.3-Flash 开源

也就是说，两家的 Flash 前后脚、几乎同两天上架。谁抄谁？都来不及——这种撞车只能说明**两家各自独立走到了同一个地方**。

但命名哲学是镜像的。GLM 把全新架构藏进“5.3 的轻量版”这个老名字，谦虚到需要读 config 才能发现它是台新机器；Qwen 反过来，把实验性写在脸上——名字里挂着 **Next**，官方文章第一句就说这是 **Qwen4 架构的实验预览**，连 config 里的 model_type 都直接叫 `qwen4_exp`。一家藏，一家亮。

这期照 292 期的规矩办：官方文章可以晚点看，先读 config。

> 材料来源：Hugging Face 模型卡与 config.json（ huggingface.co/Qwen/Qwen3.8-Flash-Next ）、官方 README（规格与跑分表都在里面，给得非常细）。技术报告 PDF 官方也放了，这期主要读 config 和模型卡，报告细节留给以后。

◆ 第二章：config——又是 3/4 线性，方言不同

━━━━━━━━━━━━━━━━━━━━

292 期读 GLM-5.3-Flash 是从 config 里数出来的 34+11；Qwen 这边更直接，README 把层排布写成了一个公式：

**12 × (3 × (Gated DeltaNet → MoE) → 1 × (Qwen 稀疏注意力 → MoE))**

48 层 = 36 层线性 + 12 层稀疏，`full_attention_interval: 4`——**又是 3:1，又是“线性 + 稀疏”**。292 期那句“GLM 是三家里唯一连 1/4 也不给全量的”，成立了不到一天：Qwen 的新架构同样一层全量注意力都没有，那 1/4 也是稀疏的。两家前后脚发的 Flash，落在同一张配方上。

配方相同，方言各异，逐项对：

**线性层**：Qwen 用自家的 Gated DeltaNet（48 个 value 头、16 个 key 头、head_dim 128）——188 期 https://mp.weixin.qq.com/s/jcQlCc3XtaCEEnjUaxw93w 读 Qwen3.6-27B 时讲过这套机制，这次是它的延续。GLM 则直接借了 Kimi 的 KDA。**一个用自家方言，一个借邻居的。**

**稀疏层**：Qwen 的叫 QSA（Qwen 稀疏注意力，Qwen Sparse Attention），和 DeepSeek 的 DSA 差在挑法——DSA 的索引器逐个 token 挑，QSA **按小块挑**：把历史序列切成 4 个 token 一块，索引器给块打分，选中 512 块（合 2048 个 token）来算。块级挑选索引开销更小，官方说这是冲着 agent 任务的长上下文延迟去的。

**位置编码**：这里两家分道了。GLM 是主注意力干脆不要位置编码（NoPE）；Qwen 保守一些，`partial_rotary_factor: 0.25`——**256 维的头只有 64 维带 RoPE**，四分之三裸奔，四分之一留位置信号。而且它的 RoPE 是多模态版 M-RoPE（`mrope_section: [11, 11, 10]`，时间、高、宽三个分量各管一段）——图片和视频的位置不是“第几个 token”能表达的，得告诉模型这块图在第几帧、哪一行、哪一列。

**残差流**：config 里有 `hc_count: 4`、`hc_lowrank: 320`。官方文章里这个零件叫 **Gated Residual（门控残差）**：把残差流拓宽成 4 条支流，读的时候按元素开门、写的时候按分支给权重。但字段名的 `hc` 两个字母泄露了血统——这是超连接（Hyper-Connections）家族，126 期 https://mp.weixin.qq.com/s/iArmZhtv1Q_aobLkEm3BBw 从字节的 HC 讲到 DeepSeek 的 mHC 那条线。GLM-5.3-Flash 用的是 mHC，Qwen 用低秩版 HC 配上门控——**残差流改造，两台 Flash 也都上了，又是同一张配方的不同方言。**

**MoE**：512 个专家激活 10 个路由加 1 个共享，专家中间维只有 640——切得非常碎的细粒度专家，和 GLM 的 288 选 8 属于同一思路的不同刻度。

────────────────────

💡 QSA 和 DSA 的差别：一个逐字挑，一个按段挑

都是“索引器先打分、再挑一部分历史来算”，差在颗粒度。DSA 给每个历史 token 打分，挑 2048 个——像从一本书里挑 2048 个字；QSA 先把书切成 4 字一段，给段打分挑 512 段——字数一样，打分次数少了四分之三。代价是段里可能夹带没用的字，换来的是索引本身更便宜。config 里 `indexer_compress_ratio: 4` 就是这个 4 字一段。

────────────────────

到这里为止，两台 Flash 像是平行研发的同一台机器。但 Qwen 有一个零件是 GLM 没有的，也是这台机器最值得单独一章的东西。

◆ 第三章：N-gram 嵌入——51B 参数，塞的是内存

━━━━━━━━━━━━━━━━━━━━

规格表里那独有的一栏：主干 125B 之外，**另有 51B 的 N-gram 嵌入**。这 51B 特殊在哪？它不住显存，住内存。

这东西的机制，今年 1 月的 49 期 https://mp.weixin.qq.com/s/4DqR-WYNf2ww61MDJVAFZw 讲过——那时它叫 **DeepSeek Engram**，梁文锋 1 月 12 日放的论文：给常见“词组”也配上向量，两三个相邻 token 的组合（学术上叫 N-gram）直接查表拿到现成表示，不用靠前几层网络现场算。词典查得到的就查词典，查不到的才动脑子。

七个月过去，**这篇论文的思路出现在了 Qwen 的量产机器上**，而且细节对得上：

| | DeepSeek Engram（1 月论文） | Qwen3.8-Flash-Next（8 月装机） |
|---|---|---|
| 存什么 | n-gram 词组向量 | bigram/trigram（二连、三连词组）向量 |
| 放哪层 | 消融实验发现**第 2 层最优** | config 原值 `ple_layer_ids: [2]`——**就放第 2 层** |
| 存哪 | 表放 CPU 内存，异步预取 | 51B 塞系统内存 |

连“放第 2 层”这个消融结论都一起继承了。292 期说零件从公共货架上拿——GLM 拿了 Kimi 的 KDA 和 DeepSeek 的 DSA，这次 Qwen 拿的是 DeepSeek 一月论文里的思路。**论文到量产，七个月。**

51B 这个数字自己就能算出来：`ngram_vocab_size_base: 20,000,000`——两千万条 n-gram 词条，每条一个 2560 维向量，20M × 2560 ≈ 51B。作为对照，整个主干才 125B，这本“词组词典”比三分之一个主干还大。

为什么敢塞这么大？因为**嵌入表是查表，不是矩阵乘**。普通权重每个 token 前向都要全量上场，必须住显存；而这两千万条词条，每个 token 只查中自己那两三条，其余 99.99% 在睡觉。整张表扔进 CPU 内存，查到的那几条（KB 级）传给 GPU 就行。官方的定位说得很清楚：这是**参数扩展的另一条轴**——比 MoE 更适合卸载（offload）。MoE 的专家再稀疏，轮到谁上场谁还是得进显存做矩阵乘；查表连乘法都没有。

────────────────────

💡 参数扩展的三条轴：都变大，贵法不一样

**第一条轴，堆稠密参数**：能力涨，但每个 token 全量参与计算，算力显存一起涨，最贵。**第二条轴，MoE**：总参涨、激活不涨，省算力，但专家得住显存，显存照涨。**第三条轴，嵌入表**：只涨查表条目，算力不涨、显存也不涨，涨的是内存——三条轴里最便宜的一条，代价是它只能存“查得到的知识”，存不了推理能力。Qwen 这台机器三条轴全用了：125B MoE + 6B 激活 + 51B 词典。

────────────────────

对内存大、显存小的设备——家用机、手机、端侧盒子——这条轴几乎是量身定做的：机器智力的一部分从金价的显存挪到了白菜价的内存里。这也解释了它为什么敢把激活压到 6B 还能打 284B 的机器：**词典垫了底，小主干就不用把宝贵的层数花在重建常见组合上。**

◆ 第四章：两台 Flash 对照表

━━━━━━━━━━━━━━━━━━━━

把这一周的两台机器摆在一起，同与不同一目了然：

| | GLM-5.3-Flash | Qwen3.8-Flash-Next |
|---|---|---|
| 官宣 | 8 月 26 日 | 8 月 24 日建仓，26 日前后官宣 |
| 总参 / 激活 | 320B / 18B | 125B / 6B（另 +51B 词典） |
| 层数与配比 | 45 层，34 线性 + 11 稀疏 | 48 层，36 线性 + 12 稀疏 |
| 线性方言 | KDA（借 Kimi 的） | Gated DeltaNet（自家的） |
| 稀疏方言 | DSA（借 DeepSeek 的）+ 自补 IndexPool | QSA（自家的，块级挑选） |
| 位置编码 | 主注意力 NoPE | 1/4 维度 RoPE + 多模态 M-RoPE |
| 残差流 | mHC（借 DeepSeek 的） | Gated Residual（HC 家族低秩版） |
| 独门件 | — | N-gram 嵌入 51B（DeepSeek 论文思路） |
| 多模态 | 原生视觉塔约 0.5B | 原生视觉塔约 0.4B |
| 命名 | 老名字藏新机器 | Next / qwen4_exp 直接明说 |

同的部分——3/4 线性加 1/4 稀疏、没有一层全量注意力、残差流拓宽、原生多模态、主打便宜快——是**这一代轻量旗舰的公共配方**，两家独立收敛到了一起。不同的部分几乎全是“方言”：机制同构，实现各家。真正的路线差异只有两处：位置编码（激进的 NoPE 对保守的部分 RoPE），和那本 51B 的词典。

还有一个对照有意思：**GLM 的零件大量外借，Qwen 的零件几乎全是自家的**（GDN、QSA 自研，N-gram 借的是公开论文的思路而非现成实现）。同一张公共货架，一家直接拿零件装机，一家看了图纸自己造——开源生态里两种都成立，比拼的还是那句话：谁组装得好、谁训得动。

◆ 第五章：视觉塔——SigLIP 的尺寸，管到视频

━━━━━━━━━━━━━━━━━━━━

和 GLM-5.3-Flash 一样，这台机器的 config 里也同装着一节 `vision_config`：27 层、隐藏维 1152、16 个头——熟悉视觉模型的读者看到 1152 这个数会心一笑，**这是 SigLIP-So400m 的标志尺寸**，谷歌开源的那个经典视觉编码器的形状。按结构算参数量约 0.4B，和 GLM 的 0.5B 一个量级：又一次印证“眼睛不用大，贵的是看懂之后的推理”。

输入侧：patch 16×16、空间 2×2 合并、`temporal_patch_size: 2`——和 GLM 那台一样，时间维也切块，视频原生支持，单图是特例。输出 2560 维直接对齐语言主干的隐藏维。

配合前面说的 M-RoPE 三分量（时间、高、宽），这台机器看视频时每个视觉 token 都带着“第几帧、哪一行、哪一列”的完整坐标。第一章视觉跑分里长视频理解 LVBench 76.6、手机操作 AndroidWorld 84.5，背后就是这套“原生视频 + 空间坐标”的底子——**屏幕操作类 agent 要的不是看懂一张图，是盯着一块不断变化的屏幕连续做决定**，这正是这套输入管线的主场。
