# 380.md 基础事实与数据审核

审核时间：2026-11-26。只写审稿意见，未修改正文、配图或 Git index。以当前工作区正文为准。

## 结论

实验汇总的大部分得分与原始归档一致，但存在明确的分支数据串台、指标误译、架构误写，以及迁移实现与原论文实现混称。建议先处理下面第 1—8 项再发布。这里不评文风。

## 一、明确需要纠正的事实和数据

### 1. ASTC 的 2.38% 读数属于另一分支（正文总表、第三章第三节及配图）

正文把 `L63 C1479 z=0.025 / 2.38%` 配给 `ASTC-GDN-25%`，实际归档是：

| 分支 | z | 相对 Full |
|---|---:|---:|
| Full-KV | 1.069295 | 100% |
| ASTC-Native | 1.069132 | 99.9848% |
| ASTC-GDN-25% | 0.957122 | 89.5097% |
| L10-Forced-4to1-Merge | 0.025458 | 2.3809% |

依据：`/home/lmxxf/work/memory-of-my-gemini/doc/grocery-haven/icalens-v3-exp4-astc-20261122/DevHistory.md` 的“ICA候选轴实例”。`soft-token-blind-eval.svg` 第 55 行也有同样串台。

因此，“ASTC-GDN 输出数字串时木匣子轴只剩 2.38%”这个证据链不成立。数字串输出是真的，但对应轴仍有约 89.51% 的 Full 读数；不能拿另一个分支的轴坍缩解释它。

### 2. α=0.5 不能把四张选票完全补回来（第二章 SelKV 手算）

恒等式 `exp(s+ln4)=4exp(s)` 正确，但正文随后同时写“论文取 α=0.5”和“1 个位置投出 4 张选票”，两者冲突。实际 `exp(s+0.5ln4)=2exp(s)`，只是两票；α=1 才是四票。若四个值向量只具有相同 q·k 得分，也不能据此推出其平均向量“方向没变”，只能推出平均后的该次点积仍相同。

建议把 α=1 的理想示例与论文 α=0.5 的阻尼补偿分开说明。配图的完整补偿恒等式本身成立，但图题不能让人误以为这就是默认系数的效果。依据：[SelKV §3.6](https://arxiv.org/html/2607.16213v1#S3.SS6)。

### 3. GLM 架构写错（正文第 84 行）

“Qwen3.5/3.6/3.8 和 GLM-5.3 都是 GDN＋Full Attention”不成立。自家 `wechat/292.md` 第 74、96—104 行已经明确区分：GLM-5.3-Flash 是 34 层 KDA＋11 层稀疏 MLA/DSA，不是 GDN＋全注意力；GLM-5.3 旗舰又是另一种结构。建议本段只用本次实测的 Qwen 混合结构举例。

### 4. 论文 D-KV 指标被写成显存（正文第 94 行）

ASTC 表 1 的 OfficeBench `48.42 → 54.74` 正确；但与之配套的 `42.09% D-KV` 表示累计解码 query–cache 交互次数，不是 GPU KV 内存字节。论文附录 M.1 专门区分这些解析计数与实测延迟、内存。因此不能据表 1 写“省掉约60%解码KV显存”。同样，LCLM 的 `641.30% / 1643.65%` 是 Attention Pairs 计数，不能直接等同实际 FLOPs 或运行时长。

依据：[ASTC 表1与附录M.1](https://arxiv.org/html/2610.41291v2)。

### 5. “旧方案都必须给目标模型配训 LoRA”有直接反例（第一章）

ICAE 的 LoRA 用在编码器，解码使用未修改的目标 LLM，不是必须给目标解码器配训 LoRA。Gist Tokens 也不是统一的“外部压缩网络＋MLP＋目标 LoRA”架构。SKIM 才直接符合正文所描述的这种组合。建议把这一段限定为 SKIM 一类，不要把 Gist/ICAE 全部装进同一实现模板。

另，“只能保住粗略大意”也不符合 ICAE 的全部实验：其重构实验在较短输入上接近逐字恢复，长度增加后才明显退化。这不否定本次负面实测，但不能给前人安上从未成立的普遍结论。

依据：[ICAE §2.1、§3.2.1](https://arxiv.org/html/2307.06945)、[Gist Tokens](https://arxiv.org/html/2304.08467)、[SKIM §3](https://arxiv.org/html/2606.12203v1)。

### 6. “每一层都保存逐 token KV”不适用于本篇这台混合模型（第一章例子）

正文以64层叙述“每层1000列KV→每层250列KV”，但本次模型只有16层全注意力保存这种随序列增长的KV；48层GDN维护定长循环状态。应说明例子是假设纯注意力模型，或直接说16层FA。开篇按16层计算16 GiB的口径与第一章的64层口径目前冲突。

### 7. ASTC 强制25%分支放宽了原约束，不能写成原版算法自动压到25%

本地 `exp4/README.md` 与 `DevHistory.md` 都明示：`ASTC-GDN-25%` 是人为强制预算消融，允许突破选择阈值、重构误差界，必要时合并保护词。两个SVG样本各有257个保护成员被合并；纪事题保护词未被合并，但最大组误差约0.65—0.66，超过Native的0.50界。

正文“保护掩码只护住数字”“所有数字必须原样保留”可用于介绍Native，不能无条件覆盖强制分支。原版在本地的48.0%结果可以报告，0.0%则要注明是约束放宽的压力测试。

### 8. SelKV 本地实现与原论文有差异，“严格照原论文复现”不准确

本地 `selkv_core.py / selkv_exp3b_core.py` 对每个KV头独立选位并独立加bias；原论文GQA路径有跨头选位并集、预算裁剪与R平均。本地分桶目标按观察窗口累计注意力最大值选取，与原文式3按被移除词到目标的路由定义也不完全相同。这里是迁移变体，不是原模型、原基准、原实现的逐项复现。

ASTC的本地README也明确写“27B迁移实测，不是原9B AppWorld基准复现”，并用了4×768 tokens独立语料重新校准reader。应在正文交代这一点，再比较本地各分支。依据：[SelKV §3.3、§3.4、§3.6、§4.1](https://arxiv.org/html/2607.16213v1)，以及本地两份实现文件。

## 二、数字是真的，但描述范围需要收准

### 9. 98.5%—98.8% 是首轮8道事故QA证据token的保留比例

`evidence_retention.json` 中 `qa0..qa7` 为98.5102%—98.7645%，证据长度41—44 tokens；不是全测试集所有答案统一保留98.5%，也不是“字”的比例。逐字纪事题的证据保留率约80.82%—89.48%，与QA不同。

首轮 `98.0%` 是 keyword_hit_rate；盲压表的54.0%等是 fact_hit_rate。表内应标出指标变化，不能直接当成同一评分尺子。

问题参与压缩是“已知当前问题后压缩”的合法评测场景；本次盲压测的是未知未来问题的缓存复用。实验确实展示两种任务的差异，但仅凭这个差异不能判定原论文造假或复现了原LongBench分数。

### 10. “R天然上界约1.6”未找到原文依据，“不裁剪就顶炸”也说过头

本次打开的SelKV正文§3.6确实把R描述为受重分配注意力质量限制，但没有找到数值上界1.6。建议去掉这个具体数字，除非能补出原表/公式位置。

本地R最大1596.9282（盲压）、2457.0417（强制分支）、3337.50（首轮）均有记录。不过未裁剪分支也完成了运行，盲压得分同样54.0%；记录并不支持“必须裁剪否则数值爆炸”。可以写“发现大比率并增加上限8的稳定性对照”，不能把偏置过大与NaN/溢出混为一谈。

### 11. 25%是文档预算近似值，不全是严格整包KV字节比例

SelKV保留了文档外前后缀，且forced组按分段floor取整；正文表格统一25.0%是预算简称。不能将它称为精确“全16层KV显存占比25.0%”，尤其与ASTC精确统计到34.8%并排时。还要区分槽位计数与附加bias、索引等元数据字节。

开篇BF16 16GiB、FP8 8GiB的KV算术本身成立（16层×4 KV头×256维×K/V两份×262144词元×2字节）。但17.5GiB底盘是特定量化/运行时假设，不是所有4-bit后端的固定开销；本次也没在5090D2上直接跑256K验证OOM。因此“按这个配置估算会超”成立，“4-bit+FP8必然都爆”不成立。24GB型号规格可见[NVIDIA官方产品页](https://www.nvidia.cn/geforce/graphics-cards/50-series/rtx-5090-d-v2/)。

### 12. ASTC省略了拒绝合并条件，也混用了层编号

Native不只按χ/ψ筛选后无条件求平均，还执行组内离群点剔除、转dtype后的重构误差界、不足提交收益则不压缩；不合格的普通词也保持原词，不是“只剩数字＋软词元”。本地exp4直接复用了bounded pooling并保留上述检查。

本地与原文的边界是零基L10之后、L11之前，即前11层、后53层。正文有“第0到第10层”又有“前10层”，建议统一。GDN判据预测的是其value/状态读出，不是直接预测汉字或完整残差。

### 13. 结论中几处机制断言超出这些数据本身

- “一槽一词铁律”“所有零训练方案都会失败”不是10题、一个模型能证明的普遍规律。
- Key不是一个原字的独占门牌号，本来就是带上下文的特征；混合Value造成的错误输出可以观察，但没有隔离干预证明具体错字必然由“旧Key配混合V”导致。
- 同层同预算的本地L10对照：均值合并事实得分2.0%，直接驱逐3.33%，但均值合并平均KL反而更低（2.5963 vs 3.2781）。因此不能用所有指标都支持“揉必然比扔差”的语气。
- “4个token刚好是中文最小短语”不成立，token不等于汉字或词，分词边界和短语长短都可变。

建议保留实测失败与典型输出，把以上机制写成解释候选，不必删除实验主线。
