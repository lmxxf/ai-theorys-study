处理办法：换一份真正不重叠的测试文本，重跑受影响的输出 SNR、KL、PPL；如果本次不重跑，明确为“含重复句的小型演示”，撤掉严格留出与泛化结论。只删正文里的“严格”却继续宣称没见过，不够。

### 2. “277 号通道恒定等于 18、替代被删 bias”没有测到；原论文还明确区分了两类现象

正文第 86—118 行的整块解释，以及第 320、352、373、384 行。

脚本第 330—349 行测的是 `mean(abs(X[:,277])) = 18.2959`。它不能告诉我们通道每个词元是不是 18，也不能告诉我们正负号、方差、跨领域稳定性或消融后的功能。**平均绝对值大，不等于恒定偏置。** 脚本没有逐 token 分布、替换均值或置零干预。

[Massive Activations 论文 §2.3](https://arxiv.org/html/2402.17762v2)专门说明：极少数 token 上的 massive activation 标量，与多数 token 都偏大的 outlier feature 通道不是同一个概念。其 §4 的偏置机制是注意力向少数 token 集中并形成隐式偏置；加入的是额外可学习 K/V，而不是单纯补回 Linear 的 `+b`。因此不能拿它给 Qwen 的 277 号通道直接定性，更不能推出“因为裁了线性 bias，才必然长出这 1% 通道”。

**建议保留齐次坐标例子，但改成机制类比**：“如果一个通道近似常数，它确实能承担偏置作用；有论文在特定巨型激活上观察到类似现象。我们这次测到的 277 号是不是同一种，还没有做干预。”如果不想在正文加这层分支，直接去掉这块的确定性归因，主线不受损。

“随便抽 128 句话就够了，因为它恒定不变”也随之失去依据。1% 是选择比例和论文中的经验观察，不是任何模型必有的固定生理比例。

### 3. 50.7%／51.4% 不是“整层真实输出误差能量的贡献率”

正文第 61—78 行；脚本第 297—302 行计算：

```text
每通道指标 = mean_t(x_j²) × mean_output(Δw_j²)
再把前 1% 通道的指标求和，除以所有通道的指标之和。
```

这只是忽略通道相关性的 **对角项贡献比例**。真实输出误差是：

```text
mean(||Σ_j x_j Δw_j||²)
= 各通道误差平方项之和 + 不同通道之间的交叉项
```

反例：两个输入均为 1、误差分别为 +1 和 −1。对角项总和为 2，真实输出误差却为 0。通道误差可能抵消，也可能叠加，恰好正是后文 GPTQ 要考虑相关性的原因。

最小修法：表头与正文改为“**忽略通道相关性时的误差平方项占比**”，不要说已经解释整层一半的实际错误。若想给因果贡献，需定义消融测法，不能从当前数直接换名。

同时，代表层的 `hessian_ratio_to_median` 是 **平均绝对幅度比的平方**，不是 `mean(X²)` 的比。第 347 行直接把 `val/median` 平方，所以 1,131.2 只能叫“幅度比平方”，不能当真实二阶重要性。真实二阶量应由每通道 `mean(X²)` 另算。表里平均权重幅度也不是某个具体权重，把整列均值当成“277 那一个权重”举例时需注明是示意。

### 4. 本地 AWQ 是缩放思想演示，不是“完整版 AWQ”

正文第 23、129—132、189—191、287、298、317—320 行。

本地 `awq_quantize_group` 做了独立 Linear 的对称 RTN 与 21 个 alpha 搜索；官方实现还包含裁剪搜索，且按模型结构联合处理共享输入的投影、搜索模块输出、实际应用缩放关系。参考：[AWQ §3.2](https://arxiv.org/html/2306.00978v5)、[官方 auto_clip](https://raw.githubusercontent.com/mit-han-lab/llm-awq/main/awq/quantize/auto_clip.py)、[官方 auto_scale](https://raw.githubusercontent.com/mit-han-lab/llm-awq/main/awq/quantize/auto_scale.py)。

脚本分别给 q/k/v、gate/up 搜不同倍率后，把 `Q(Ws)/s` 直接写回 BF16。真实部署若把倍率融合到共同的前置 RMSNorm，就必须协调这些分支，不能把几套不同的 s 同时塞进同一个 gamma。本轮没有这种模型级变换，也没有低比特打包文件或 Marlin 执行。

**表名改为“AWQ 风格缩放搜索原型”，把第四章结论限定在本原型。** 不应从省略环节的实现推出 AWQ “天生精度一般”“2023 年快餐”“精度上限就这样”。论文自身的多模型对比并不是这个统一排名。

GPTQ 核心 Cholesky／逐列补偿结构与官方代码对应得上，可以讲；但本地用全精度模型预先收集所有层 X，而原论文还将前面量化块的输出传到后续块再校准。本地为固定静态分组、对称网格、开启 actorder 的特定变体，并非完整复刻所有默认流程。[GPTQ 原论文](https://arxiv.org/html/2210.17323v2)、[官方实现](https://raw.githubusercontent.com/IST-DASLab/gptq/main/gptq.py)。

### 5. 这里仍然是 BF16 假量化；耗时也不是压好可部署模型的总耗时

正文第 287—320 行；脚本第 411 行将 `w_hat` 写回 `torch.bfloat16`，所有前向仍是原始浮点层。应在总表前写明 **“所有指定线性层参与量化模拟，随后重构回 BF16 做前向”**。它能测某配方的数值影响，不能证明磁盘压缩、真实低比特内核精度或部署速度。

计时从第 366 行开始，包含恢复权重、求量化解和抽样 SNR 的额外矩阵乘；不含前面的校准 X 收集、模型加载，不含打包与保存。3.51 s／44.45 s 是**本脚本这段处理的耗时**，不是 AutoAWQ/GPTQModel 的全流程打包速度。

层输出 SNR 也只有 5 个 Transformer 层的 35 个矩阵，而且用的是 BF16 基准模型捕获的固定输入，不是量化后逐层传播到这里的实际输入。请标明“35 矩阵平均 SNR”。模型 PPL 是另一个包含误差传播的指标，二者可以并列，但不能混称。

### 6. “AWQ 绝不会过拟合”以及通用选型表，应撤回

正文第 317—320、339—341、354 行。

即便没有重复文本，一组 398/152-token 结果也不足以证明泛化定律。AWQ 搜索的 alpha 同样以校准数据上的输出误差为准，数据换了，最优 alpha 与表现就可能变。官方论文对较好跨域泛化有实验支持，但不等于对所有数据分布的绝对保证。

GPTQ 的校准／测试 SNR 差距可以作为小样本拟合较强的迹象，不能凭它单独确认“背诵”，尤其两组输入本身可能具有不同输出能量和难度。建议保留“本次 GPTQ 的校准收益比测试收益大，后续可换语料检查”，删除“随便喂什么都不变”“不怕校准偏移”。

结尾可总结 **机制取舍**：AWQ 用少量缩放参数保护重要通道，GPTQ 利用输入的二阶相关性修正后续权重。不要把 75.82、60.50 和 12.6×写成两类算法的普遍等级。

## 二、机制与数学的局部修正

### 7. AdamW “按平方惩罚并把所有权重锤平”又回来了

第 31 行及实验校准文本中的同类表述。AdamW 的 decoupled decay 是按比例收缩，不等于在 Adam 里加入 L2 平方惩罚；也不保证所有通道一样平或权重服从高斯。该问题在 357 已修过，本期不要重新引入。

单看静态 W 无法知道实际输入 X 的分布，这是足够充分的教学理由，不需要先证明权重都一样。写成“本次测得各通道平均权重幅度比激活幅度平缓”即可，直接由表支持。

### 8. XᵀX 不是见到就叫 Hessian，要先给出对应损失

第 206、241、275 行。按正文 `X=[样本,输入通道]`、`W=[输入通道,输出通道]` 的约定：

```text
L(W_hat) = (1/T) ||X W_hat − X W||²
对一个输出通道的权重求二阶导：H = (2/T) XᵀX
```

XᵀX 本身是 Gram／未中心化二阶矩阵，在这个平方误差问题里才与 Hessian 成比例。它不是整个语言模型交叉熵损失的 Hessian。“同进同退”可以作为直观描述，不要等同去均值归一化的相关系数。

单列补偿 `Δw₂ = δ₁ Σ(x₁x₂)/Σ(x₂²)` 是使 `Σ(δ₁x₁−Δw₂x₂)²` 最小的解，不是把一个样本的分式“上下乘 x₂”后自然换成求和；补一句最小平方误差即可把桥接稳。

本地 T=398 而输入通道至少 1024，所以 `rank(XᵀX)≤398`，未加阻尼前必然秩亏。damp 的作用是使求解稳定并限制补偿，不仅是某个数“防除零”。手算两个通道完全成比例时同样奇异；手算是无阻尼理想例，不能声称与当前带阻尼实现完全同算。

此外，按大激活顺序是本次 `actorder=True` 的选择（实际按二阶量对角线排序），不是 GPTQ 的必然规定。补偿值可正可负，后面的权重不总是“垫高”，写成“调整”更准确。

### 9. AWQ 不要求前面必须有 RMSNorm，ReLU² 恰好有可利用的齐次性

第 187、334—335 行。“每个线性层前面都有 RMSNorm”不对，down_proj 和 o_proj 就不满足这个排列。官方代码除了 norm→linear，还有 linear→linear 的融合与 ScaledActivation 包装；Gated MLP 的 down 缩放可通过 up 分支处理，具体要看共享关系。[官方 scale 应用代码](https://raw.githubusercontent.com/mit-han-lab/llm-awq/main/awq/quantize/auto_scale.py)。

文中拿 ReLU² 当“非线性挡死、不能穿透”的例子也选反了。对正尺度 s：

```text
ReLU(z / sqrt(s))² = ReLU(z)² / s
```

因此在简单的前置投影→ReLU²→后置投影链中，可以把除 s 转成上游投影除 sqrt(s)，并补偿下游权重。复杂共享分支是否可融合需看图，但不能因非线性就判不可能。

AWQ 的核心等价缩放可用，不等于所有结构都零额外运行开销；把“能不能量化”“能不能融合”“现有工具是否支持”分开说即可。

### 10. 其它事实／口径修正

- **GPTQ 的 Generalized Post-Training Quantization 全称没有原论文支持。** 直接用方法名及论文标题，别替缩写造词。标题在参考资料里已有准确版本。
- **NVFP4 不自动等于免校准。** 它是数值格式，可搭配 RTN、搜索或校准方法。g16 通常更细，并不保证任何模型都能不校准。357 的 65.24 来自普通 INT4，67.59 来自双网格搜索，不能统称 NVFP4 的结果；NVFP4 那项是 68.09。
- **跨期 g16→g128 不是严格单变量实验。** 357 的尺度经过 E4M3＋global scale，358 直接使用浮点 absmax/qmax，且其它配方也不同。要确认粒度本身的代价，最好在本脚本用同一 RTN 函数分别设 g16/g128；否则写为两个配方的观察。
- **4.125 bit 只对应 4-bit 码字＋每 128 个值一个 FP16 scale，未计 zero point 等字段。** 实际 AWQ/GPTQ 格式不同，脚本没打包；别写成行业唯一存储开销。参数占比也不等于量化后的权重字节占比。
- **第 336 行将 MiniMax-M3.1 与 MLA 矩阵吸收混在一起。** 351 明确写的是 GQA＋MSA，不是 MLA；保留高精度注意力也不能只归因于矩阵吸收。静态权重“在任何大模型都占九成以上”同样不能泛化，词表大、层数少的模型就不同。
- **动态 QK/AV 没有常驻权重，不是经典 weight-only AWQ/GPTQ 的直接对象，这个区分能留。** 但“查表层绝不能用”说过头：查表矩阵也能量化，只是不能照搬本篇的输入通道缩放流程。MLA 是架构压缩，KV 量化是另一层方法，不是 KV 压缩只剩旋转／MLA 两选一。
- **第 299 行“全场最佳”应改“量化组最低”**，BF16 56.55 仍低于 60.50。188.93 是 1876.29 的约 1/9.93，不是“不到十分之一”；改“约十分之一”。
- **43 倍对应平均 dB 差换算出的误差比几何平均**，不是先汇总全网误差能量再比较的结果。脚本是先算每个矩阵 SNR 再平均；可写“按平均 SNR 换算约 43 倍”，不要当真实全网总能量比。
- 本地 alpha 搜索 `range(21)`，含 0 和 1 共 **21 档**，正文写 20。官方实现常见 20 档不含 1，注明本地取法即可。
- “不更新梯度”改为“不通过梯度下降训练”；GPTQ 明明在修权重，不能把不反传等同参数不改变。低比特存盘是主要误差来源，但浮点转换与累加也可能舍入，“精度丢失全部发生在存盘一瞬间”过满。
