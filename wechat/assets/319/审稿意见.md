## 一、影响论证的七项

### 1. KV 的层间关系写错；“所有内容的一份加权总和”也不是 KV 的定义

位置：103—117、125、165 行。

“这一层的 KV 查的是前面 token 在上一层的 KV”这句应改。**执行查询的是 Q；同一层的 Q 查同一层的 K、V。** 下一层的 K、V 来自这一层更新后的隐藏状态，所以能间接携带前文信息。

可用下面的机制替换递归式（省略归一化、多头、位置编码等细节）：

```text
第 l 层：
q_l(t), k_l(t), v_l(t) = 从该层输入 x_l(t) 投影得到
a_l(t) = softmax(q_l(t) · K_l(1:t)ᵀ / √d) · V_l(1:t)
x_(l+1)(t) = 经过注意力输出投影、残差连接和前馈网络后的状态
下一层再从 x_(l+1)(t) 算 k_(l+1)(t)、v_(l+1)(t)
```

第一层 KV 尤其直接说明问题：在常规因果 Transformer 中，它由该 token 的嵌入经归一化/投影等操作得到，还没通过本层注意力吸收前文。深层 KV 才带有前文影响；它也经过了非线性变换，不是原文向量的单纯加权和。

因此可以写“深层 KV 带着前文参与计算后留下的信息”，但不能写“每个 token 都是一份前文总和”，更不能由此推出“最后一个 token 已经替整段对话做完摘要”。Gist 的一个位置能压指令，靠的是专门训练出来的瓶颈；不是任意末尾 token 天生有这个保证。

依据：[Infini-attention §2.1 的 Q/K/V 与注意力公式](https://arxiv.org/html/2404.07143v1)、[Gist 的掩码训练机制](https://arxiv.org/html/2304.08467v2)。上面的层间关系判断是按标准因果 Transformer 公式作的推导。

### 2. “注意力分数就是哪件事重要”把计算权重和任务优先级混成一件事

位置：59—63、117、161—165、292—294、末尾第二句金句。

注意力权重取决于**当前 Q、层和头**，不是全局不变的“哪些事对用户重要”。KV 缓存保存 K、V，并不保存历次全部注意力分数；未来生成时会重新算分数。本文自己介绍的 attention sink 就是反例：开头 token 可以拿到很高权重，却不因其语义重要。

“摘要丢掉优先级，模型退回常见做法”可以保留为这次工程经历的解释；“训练数据里最多的就是找热点”没有本文证据，建议改成“它又回到了找热点、改热点的惯常做法”。“坡度”“坍缩”也可以保留，但应是帮助理解的比方，不能当成已测出的梯度或信息损失定理。

真正有依据的对比是：**压成少量自然语言，会受摘要长度、目标和措辞选择限制；内部表示可以提供另一种有损压缩方式。** 文字能明确写出优先级和转向理由，KV 压缩也可能丢掉它们。KV 的字节多，不等于那些字节全是额外语义；在固定模型和输入下，原始 KV 本来就能重新算出。

可保留的说法：“那些没写进摘要的倾向，能不能通过内部表示多留下一些？”现有文献支持提出这个问题，尚未直接测出这次编程任务的“方向”会被留住。

依据：[StreamingLLM §3.1—3.2](https://arxiv.org/html/2309.17453v4)。这是计算机制与文章所用心理比方之间的范围判断，不是要求删掉作者的设想。

### 3. 去掉 softmax 能得到另一种递推，但不能无损把现成 Transformer 的 KV 折成该状态

位置：125—155、310 行。

`q·Σ(kᵀv)` 的结合律变形没错；问题是它等价于**无 softmax 的点积注意力**，不等价于上面那条 softmax 注意力。换掉运算后，模型行为也变了。

所以“久远的事折成 RNN 状态”是一个需要相应读写机制的模型方案，不能说 Cartridges 或任意现成模型的压缩“就是第二章那一步”。Cartridges 留的是少量每层 KV 位置，仍供原模型查询，不是同一种固定矩阵递推。

建议保留线性注意力这一段，但加一句实质性的衔接：“这说明可以设计另一种记忆结构；现成的 softmax 模型并不能直接换上这个矩阵。”收尾则写“把经历压成供同一模型读取的内部记忆”，不用指定它必然是 RNN 状态。

另两处一起改：

- “RNN 损失大，KV 不丢东西”改为“完整 KV 缓存没有再删减各位置的 K、V”；这不保证模型完整理解和提取原文。
- “这些都是从训练第一天就这么设计”过头。Infini-attention 明确展示替换已有 LLM 的注意力模块，再继续预训练和微调的路径。

依据：[Transformers are RNNs §3](https://arxiv.org/html/2006.16236v3)、[Infini-attention 的适配与实验部分](https://arxiv.org/html/2404.07143v1)。

### 4. “凡是压缩都得训练”被文中 Attention Matching 反驳

位置：205、274—290 行，参考资料 Attention Matching 条目。

这不是措辞问题，会改变第三个“难处”的立论。Attention Matching 就是在冻结模型下按注意力行为拟合压缩 KV，不需要每次对模型或整包 KV 做端到端反向传播训练。

同时，205 行“完全不做梯度下降、直接解方程”也过于整齐：论文附录 D 的 NNLS 求解器允许投影梯度迭代；OMP 版本取 0 次，Highest Attention Keys 版本取 2 次。可改成“省掉端到端训练，改为逐头匹配注意力，主要用最小二乘求解”。正式标题是 **Fast KV Compaction via Attention Matching**。

第三个难处建议写“得压得对，还得接得上”：训练是一类方法的成本，另一类方法有拟合开销和压缩误差，所有方法都要让目标模型读得有效。

论文附录 F.3 还做过推理中途反复压 KV、继续生成的实验；它离本文问题比一笔带过更近，但仍不是长期编程 agent 的跨会话验证。

依据：[Attention Matching §2、附录 D、F.3](https://arxiv.org/html/2602.16284v1)。

### 5. CacheBlend 的“缺交叉注意力”被套到了不缺的场景

位置：278—284 行。

CacheBlend 处理的是：A、B 分别预计算，再拼成 A→B。独立计算 B 时没看见 A，所以 B 的深层 KV 与完整预填充所得的 KV 不一致。

而把旧历史作为前缀，**新 token 在这个前缀上正常前向计算**，新 Q 可以直接查询旧 K，注意力关系会正常算出来。旧 token 不看未来的新 token，本来就是因果掩码的定义，不是记忆缺陷。

这里需要区别“历史被压缩后的近似误差”“前置条件改变后的缓存失配”和“独立缓存块的拼接”。前者真实存在，但不能用 CacheBlend 来证明“旧 KV 与新内容之间天然缺关系”。同理，补转 RoPE 只修位置那一部分，不能自动修正因前文变化产生的隐藏状态差异。

建议删掉 284 行的等同判断，改成：“如果把分别计算的记忆块拼在一起，还要处理它们此前没有互相看过的问题。”论文的低比例重算结论保留，并限定为其实验中的质量恢复。

依据：[CacheBlend §3.3—4](https://arxiv.org/html/2405.16444v1)。关于正常前缀续算的判断是因果注意力公式直接给出的结果。

### 6. “拿它当跨会话记忆，还空着”不成立；窄一些的目标仍可保留

位置：179、240—242 行。

查到了 **MemArt**：把历史会话存成可复用 KV 块，以新请求的查询向量检索相关块，调整位置编码再读取。作者自己的年度总结已介绍这条路线。OpenReview 的论文搜索索引也能检出 §3；本次直接打开 PDF 遇到浏览器验证，因此这里以作者公开说明作可核依据，不把它的实验数字搬进正文。

它主要是存储、检索与复用，**不是把一段经历训练成更短卡带**。因此它不推翻“尚未找到完整符合我设想的方案”，但足以推翻后一句广义的“跨会话内部记忆是空白”。正文已有 Mem-W，它也支持历史经验的潜在表示复用；输入端软向量和每层 KV 是接口不同，不能把前者排除出“跨会话记忆”。

建议收成：“跨会话 KV 复用已经有人做；把长期工作经历持续压成小包，同时保住任务方向，这几篇还没有替我验证。”不必再扩写一整节文献。

“至少得压缩才叫记忆”也应改成工程需求：持久保存和后续有效利用使它成为记忆，压缩解决容量和开销，不是记忆的定义。

依据：[MemArt 作者的说明，第 5 项](https://pfzuo.github.io/blog/2026/2025-Year-End-Summary-Zhihu/)、[Mem-W §3.3](https://arxiv.org/html/2605.09317v1)。[MemArt 投稿入口](https://openreview.net/forum?id=YolJOZOGhI)供后续回查，会议录用状态本次未核实。

### 7. 现役模型“四层里一层完整注意力”与所引旧文相反

位置：151 行。

292 期明确写 GLM-5.3-Flash 的 34 层 KDA＋11 层 DSA；293 期也写 Qwen3.8-Flash-Next 的 36 层 GDN＋12 层 QSA。那部分是稀疏注意力，不能一概叫全量/完整注意力。GLM 配置里的 `full_attn_layers` 字段名也不能抹掉索引器。

建议：“这些混合架构大致每四层留一层按位置保存 KV 的注意力，其余用递推状态；保留的那层也可能是稀疏注意力。”最好明确所指型号，避免“三家的主力都……”无限扩张。

依据：[GLM 官方配置](https://huggingface.co/zai-org/GLM-5.3-Flash/blob/main/config.json)、[Qwen 官方模型卡](https://huggingface.co/Qwen/Qwen3.8-Flash-Next)；本地 [292.md](../../292.md)、[293.md](../../293.md)。
