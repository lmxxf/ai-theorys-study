# 320 期审稿意见

审阅日期：2026-09-25。正文：[320.md](../../320.md)。只写意见，未改正文、未 stage。

审阅版本 SHA-256：`e0b3189a9444f081b5209d5a0b8292590e28f4597d5b4374f5af25a6dcc63c92`。下列行号对应此版本。

**结论：五步结构和“回日记重新蒸馏”的设想可以保留，但目前需要修后再发。** 最大的问题是收尾把已有工作写成了空白：动作分布蒸馏、反复压缩曲线都有直接反例，而且就在本文已经引用的论文里。另有 CCM 实验配置、TRACE 对照条件、时间与位置的关系需要改准。文章可以收在“把这些部件接成我要的记忆系统”，不必靠“没人做过”来成立。

## 一、影响主线，优先修改

### 1. “没人拿下一步动作当训练目标”有直接反例：Mem-W

位置：137—145、283 行，以及收尾标题、发布摘要。

文中把 Mem-W 只归入“按任务成败强化学习”，漏掉了它的第一阶段。[Mem-W §3.4、附录 A.1](https://arxiv.org/html/2605.09317) 明确采用动作监督加 KL 自蒸馏：同一个冻结 agent，老师看较长原始历史，学生看潜在记忆，梯度只更新压缩器。它也不只压可复用模板：§3.3 的 working memory 路径把当前会话中超出窗口的历史分块压缩，按时间顺序拼起来。

这已经覆盖了“用下一步行为约束具体历史的压缩”这个核心目标。需要保留的区别是：老师看的是较长但有限的窗口，不保证完整历史；记忆是输入端软 token，不是本文设想的每层 KV；固定步长切块也不等于语义事件切分。因此不能说整套方案已经被做完，但也不能说这项训练目标没人做。

建议把“第四种”改成“把蒸馏明确用在下一步动作上”，补上 Mem-W 的第一阶段。本文自己的探索点可以落在：**事件边界、可变记忆预算、时间层级合并与原始日记回放，怎样一起保住长期编程任务的方向。** “计划 token”上的监督可以作为进一步设计，不要凭它把整个动作蒸馏方向判成空白。

145 行“另一篇”没有名字和编号，读者无法核对。若指 Mem-W，“不是具体发生过的事”应删除；若指别篇，补出来源。

### 2. “没人画过反复压缩曲线”被所引论文自己的实验直接否定

位置：188—194、284 行。

[arXiv:2607.08032 §14.2、图 6](https://arxiv.org/html/2607.08032) 就是反复压缩实验：Qwen2.5-1.5B 逐块读入包含 12 条事实的材料，横轴为压缩次数，比较递归文字摘要与归档检索的最终事实召回。正文引用了它关于研究不足的判断，却漏掉了它随后给出的实验。

而且我们自己的 [303 期](../../303.md) 已经介绍过三轮级联摘要与权重巩固的对照。不能一边承接 303，一边把整个反复压缩问题写成无人测量。

建议收窄为：**文字摘要反复压缩已有实验；本文这种事件 KV 在反复合并后，动作方向会漂多少，还需要专门测。** RAPTOR 抽样节点的幻觉率也不是“单次压缩误差曲线”，不要把不同指标混在一起。

188 行“它只睡一次”同样不准确。[Do Language Models Need Sleep? §5、算法 1](https://arxiv.org/html/2605.26099) 描述每个缓存窗口淘汰前执行离线递推，再继续处理下一块。它没有验证本文这种跨会话事件树的长期合并，可以这么说；不能说机制只允许睡一次，也不能把一次睡眠里的递推次数和多轮睡眠混为一谈。

### 3. CCM 的 70.0%／178MB 不是“每例一个 COMP”的成绩

位置：117—121、291 行，参考资料 CCM 条目。

[CCM 表 6、表 18](https://arxiv.org/html/2312.03414) 对应关系如下：

| 设置 | MetaICL 准确率 | 备注 |
|---|---:|---|
| 完整上下文 | 70.8% | 表 6 的峰值 KV 内存 630MB |
| CCM-concat，每段 8 个 COMP | 70.0% | 表 6 的峰值 KV 内存 178MB |
| CCM-concat，每段 1 个 COMP | 69.5% | 表 18；不能沿用上行的内存数字 |

**单 token 的结果其实也很好，换成正确数字即可。** concat 从 1 个到 8 个提高 0.5 个百分点；merge 才是 68.5%→69.6%，不要混用。630／178MB 是包含压缩与推理过程的峰值 KV 内存，不是模型总显存，也不只是最终留下的记忆大小。

117 行训练机制应写“用压缩记忆支持下游目标输出，反传到压缩参数”。论文算法以 `O(t)` 为监督，并非把所有历史原文位置都作为下一词损失；“每件事都算一次动作损失”可作为自己的扩展。

条件 LoRA 只对 COMP 启用这一点正确。注意论文实验先做任务适配，再学习压缩；“冻结基座”应限定在压缩训练阶段。它支持外挂压缩的可行性，不等于任意原版模型已经能无损挂上成品。

### 4. TRACE 的参照组和三种干预被混成了三组

位置：253—261 行，参考资料 TRACE 条目。

[TRACE 所在论文 §3.2、图 3](https://arxiv.org/html/2608.06503) 实际上用**完整原始历史作共同参照**，再比较三种上下文；各组都接上相同的后续记录，并停在相同决策点：

| 对照上下文 | 相对完整历史的动作分布偏移 |
|---|---:|
| 旧摘要＋本次新增的原文 | 0.149 |
| 更新后的摘要 | 0.233 |
| 旧摘要，不给本次新增内容 | 0.289 |

所以“保留原文”不能让读者理解为“保留全部原始历史”。这里保留的是本轮增量，前面仍然压过。方法还包括主 API 调用归一化和采样噪声校正，24 次采样的动作不实际执行。

“走了一大半”按这组数字计算可以保留；但 **0.233 不是通用合格线**，它来自特定模型、任务和压缩流程。应写“在同一实验设置下，比文字摘要更接近完整历史”。TRACE 可借来测决策偏移，也不自动等于完整的长期方向基准。

### 5. 时间顺序、真实时间、KV 的前文依赖，需要分开

位置：20—25、91、149—155、202、218—220 行及第一、第二句金句。

三个地方不能直接画等号：

- **RNN 把历史折入状态，不等于时间被压没。** 状态更新本身依赖顺序；它缺的是可以逐事件寻址的显式历史。这里可写“先后被折进同一个状态”。完整 KV 也不是“每个字一个 token”，应为“每个原始 token 留一组 KV”。
- **序号只保先后，不保日期和间隔。** 两件相邻事件可能隔一分钟，也可能隔半年；一件事用多个 token、旧事件合并以后，位置差更不能当时间差。220 行把日期写进原文的方案可以保留，但“时间不用另外存”应收窄成“先后顺序可以直接用序列表示”。需要精确日期时，还得测压缩后是否保得住。
- **按事件存放不保证内容互相独立。** 按本文的因果计算方式，后一个记忆生成时读过前面的记忆，可能依赖、重述前文。下游损失只鼓励可用，不保证每个槽只装自己的事件。

由第三点还能推出一个真正需要实验解决的接口问题：旧记忆合并、更换或被检索过滤以后，保留下来的后续 KV 仍是在旧前缀下算出来的。可以尝试直接复用，但不能声称它等价于在新前缀下重算。

[KVLink §3](https://arxiv.org/html/2502.16002) 的位置重编码解决 K 的旋转位置问题，并通过训练过的连接 token 补充块间联系；它不会把深层表示对旧前文的依赖自动擦掉。建议加一句：“合并或抽取后，旧 KV 的上下文依赖怎么处理，还需要一起训练和验证。”这是根据计算图提出的接口问题，不是在否定方案。

“回日记重蒸馏”能避开摘要再摘要造成的一条误差累积路径，值得留。但“每段只挨一次误差”需限定：原始覆盖记录确实全部参与重压，且没有再经有损中间摘要；压缩预算变小造成的信息损失、老师自身误差、旧前缀依赖不会因此消失。

### 6. SegTreeMem 不是“最近细、久远粗”的淘汰机制

位置：171、277 行。

[SegTreeMem §4.1—4.3](https://arxiv.org/html/2606.04555) 保留逐条话语叶节点，内部节点总结连续时间区间，多种粒度同时存在。它证明的是按时间组织与检索的价值，没有把“旧叶节点逐步丢掉，只留粗摘要”作为这里所说的年龄衰减机制。

0.639→0.538、0.603→0.583 这组打乱顺序结果能对上。可写“它提供按连续时间区间组织的树；我再考虑让久远区间只常驻粗粒度记忆”。这样论文结果与自己的设计就接得上。不能由打乱实验进一步推成“RoPE 的序号已经保存了所有时间关系”。

### 7. “情绪重建不丢，细节每次现编”不是心理学结论

位置：305—309 行。

回忆具有重建性，可以支持这段类比；但不支持“当时害怕还是高兴一直不变”。[Levine 1997 原论文《Reconstructing Memory for Emotions》](https://www.researchgate.net/publication/232552587_Reconstructing_Memory_for_Emotions) 追踪同一事件的即时情绪与事后回忆，发现情绪回忆会朝当前评价发生系统性偏移。情绪本身也会被重建。

“三四岁以前几乎没人真记得，记得的多半是拼出来的”也过强。[Bauer 与 Larkina 的前瞻追踪实验](https://pmc.ncbi.nlm.nih.gov/articles/PMC4025992/) 记录儿童 3 岁时谈到的实际事件，之后几年仍可测到对这些事件的记忆。童年遗忘不是一个“年龄以下皆为假记忆”的判定器。

建议保留你的主张，改成：“人不保存每个字，回忆也会重建；我希望留下的，是重要性和方向。”这是设计愿望，不能包装成心理学已经证明情绪永久保真。Bartlett、Loftus 可作为重建与可诱导性的例子，不要推出所有细节都在现编。

### 8. “不用改模型”和“能推理就基本能训”分别说过头了

位置：119、289—299 行。

“不更新原有权重、不更换主干架构”可以说；“模型不用改”容易让读者以为普通 LoRA 加载器就能直接运行。这里至少要新增特殊 token、对特定位置启用适配器、训练时施加分段掩码，以及管理压缩 KV 的读写和位置。

冻结权重省的是权重梯度与优化器状态，**不代表反向传播不用穿过冻结网络**。长序列激活、老师前向及分布蒸馏都有开销，机器刚够推理不代表能训练。同样，“不碰原来的参数”也不保证读取压缩记忆时效果不降。

建议写：“训练量比全参数训练小得多，有机会在本地做；具体能训多长，要看模型、量化和显存。”同一家模型换版本也不宜断言一律重训，准确说是不能假定兼容，需要验证，必要时重新适配。这个段落不必展开工程清单，把‘外挂可行’与‘已经即插即用’的距离交代清楚即可。

## 三、写法与发布检查

- 标题“一件事一个 token”可以保留。正文已经允许一件事占几个 token，不必为此改成抽象学术标题；但应把“一个 token”说明为一个记忆位置所对应的多层 KV，读者才不会以为只是词表里一个字。
- 229—232 行是靠空格对齐的前缀示意图，公众号比例字体容易错位。建议用一句话串起来，或改 SVG；不必为这个小图另增正文篇幅。
- CCM 首次出现补中文名“压缩上下文记忆”；TRACE 首次出现补一句它是动作分布偏移的诊断方法。KL 初次出现可先解释成“两张概率表有多不同”，不必增添推导。
- 参考资料中 Kumar 缺标题，2607.08032 缺标题和作者，145 行有匿名“另一篇”；这是优先补齐的检索入口。本文既然讨论了 Mem-W 的具体训练机制，也应在参考资料直接列它，不只指回 319。
- 319、303 的公众号链接与本地前文互引一致；两条链接各出现一次。没有据此宣称远端页面内容逐字验证完成。
- 薄线提示块、日期格式没有发现需要改动的问题；署名日期 2026 年 9 月 26 日符合次日发布。发布摘要按字符计 102 字符，长度合规，但末句“没人拿方向当目标”需随正文同步修改。

**建议保住的句子与落点：** “在每段后面钉一张空白表格很容易，训练的是填表的人”、原始日记作为校准锚点、按切／压／整理／读／测梳理自己的学习过程。这些是文章的声音。要修的是前人到底做了什么、数字对应什么设置，以及部件接起来还有哪些没验证，不需要把正文改成验收报告。
