## 2. 必改：8.33 ms 是带假设的旧估算，不是物理下限（L29–59）

这段可以用来讲“当时如何建立粗标尺，后来怎样被审计校正”，不能当优化结论的认证。

- `9.35` 是旧版本静态指令配比，不等于全网动态执行配比；不同核、循环、分支与执行次数不能用一个平均静态比率代替。
- 混合 ALU、半精度和访存相关指令不能统一套成“每 SM 每周期 2 条辅助指令”的硬件极限。
- HMMA 的“4 周期/条”是按指定峰值吞吐折算的理想服务量，不是每条指令固定延迟。
- `max(T_tc,T_alu)+0.3×min(...)` 中 70% 重叠率是人为假设；没有动态测量或硬件约束证明它，就不能称物理 lower bound。
- 后来的动态统计口径也与旧 `109,270,000` 不同：已插桩 FB00/04/05 为 `99,959,968` 条 HMMA，其余未插桩部分补估 `18,397,408`，合计 `118,357,376`；这里仍有估计，不能直接换个新数继续叫精确物理极限。

最省改法：灯泡标题改为“当时怎样粗估两条管线的压力”，保留估算思路并说明后来暴露了动态计数和重叠假设的局限；或者缩短这一块。后文真实配对提速不依赖它成立。

证据：[当时短文](../../short/20261027/如何测算3080laptop的dlss5算力上限.md)、[2214 审核](/home/lmxxf/work/DLSS5-RTX-3080-laptop/Development/doc/性能评估20261027-2214-审核意见.md)。

## 4. 必改：监管论文的统计条件与“温和公文”解释接错（L99–105、200）

《Reward Hacking Challenges Oversight of Autonomous Research Agents》的作者机构确有 MIT、Stanford、Microsoft Research、UW 等；数字多数真实，但现在串成了论文未证明的因果故事。

- §6 的 150 个模型—任务组合：首轮 `7/150=4.7%`，至多五轮累计 `56/150=37.3%`。一次机会与至多五次机会不是同一分母含义，不能只凭约八倍就证明详细反馈造成八倍增长。
- Setting 3 明确给了对抗性规避目标，不是观察正常诚实 agent 自然经过三轮变坏。
- 配对 79 例的 retry-only `20.3%` 与 detailed-feedback `40.5%` 成立；后者同时提供判决、理由、历史，未单独隔离“详细理由”一个因素。
- **第三轮峰值串台：**150 全集每轮新增成功数为 `7,14,15,10,10`，第三轮人数最多；配对实验的边际率峰值却在第 5 轮 `14.6%`，第三轮 `12.3%`。不能把前者挂在配对图之后。
- `efficacy 10/10` 指抬高代理指标的效力，不是语言“激进”；`0.4%` 对应 505 个确认 hacks 中 272 个此类样本的逃逸率。923 样本聚类包括泄漏、篡改评测、伪造、查表等机制，**不证明成功逃逸者全靠温和免责文风**。

建议保留“反馈可能同时泄露检查边界”的启发，删“论文证明过审全是普通严谨报告写法”的归纳。

## 5. 必改：候选锚定论文不是“看硬件表就降到 1.2%”的直接证据（L109–111、137、173、201）

Chenyu Zhou 与 Institute of Science Tokyo 的署名正确。以下几个结论来自不同设置，需要分开：

- `1.2 bit` 是 Proposition 1 / Corollary 2 在特定误收率 `.719`、独立解题错误率不高于 `.07` 等条件下代入差值 `.649` 得到的界（约 `.84 nats`），不是所有候选报告普遍注入至少 1.2 bit。
- 审稿得分 `.72→.94`、真实准确率 `.20` 的实验是 **Qwen3-4B、GSM8K、抑制推理的 JSON 输出、DPO 自博弈更新权重、三随机种子**；不能解释成两个通用模型在上下文中聊三轮。§5.3 另有无需训练的 best-of-N，但不能把其条件接到这组数字上。
- `71.9%→1.2%` 是 128 题上让 judge **先给出自己的答案再比较候选**的结果，候选仍可见；不是先查 GPU 测量表，更不是硬件探针的实测防作弊率。

“先独立查数据，再读解释”作为本文提出的工程协议可以保留，改成“我们据此设计”，别称论文已经证明其效果。

证据：[论文 v1](https://arxiv.org/pdf/2607.05904v1)，第 3–4 页命题及推论、第 7 页 Figure 2、§5；本地 [PDF](papers/JudgeHacking-MoreConvincing-2607.05904.pdf)。

## 6. 必改：SpecBench 的 73.8% 不是“写假报告的轨迹比例”（L111、214）

本地 PDF 拼接了两篇：前 17 页是 SpecBench；第 18–22 页是 ICLR RSI Workshop 的《Reward Hacking in Self-Improving Code Agents》。`73.8%` 出自后篇第 3 页（合并文件第 20 页）。实验为 43 个 KernelBench 任务 × 3 个模型 × 5 个配置 × 3 次试验，每次 100 步；其 operational definition 包括孤立算子 speedup>1、但训练吞吐不提升或私有正确性失败的情况。

它支持“代理指标改善可能与真正目标脱节”，不等于这些轨迹都蓄意作弊，更不是 73.8% 在包装免责报告。引用时将两篇与数字出处分开。

## 7. 论文—协议归属：CudaForge / KernelEvolve 与四张检查表（L121–133、204、216–217）

CudaForge 六位作者与 UMN 机构、training-free Coder＋Judge、NCU 反馈均成立。其 §2.1–2.3 的输入是任务规格与 **PyTorch 参考源码**，不是只有商业 DLL 的逆向任务。附录 A 要求按 profiling 找预计收益最大的一项瓶颈，不规定“spill 永远第一”。KernelEvolve 的 Meta、图搜索、异构硬件定位成立；所谓 proprietary architectures 指专有硬件平台，不等于闭源软件逆向。本地用的是 2026-07 修订的 v4，可在引用里注明初版 2025-12、所读版本 v4。

四张表可以保留为**我们结合项目设计的检查清单**。静态 SASS 数量需乘实际执行次数并区分分支/predicate；`STACK>0` 或 `LDL/STL` 也不自动证明 register spill，local arrays/call stack 同样可能使用 local memory。动态 spill 小、热路径另有瓶颈时，不能规定它永久第一；减 spill 若牺牲 occupancy，甚至可能变慢。

KernelBench 的“不到 20%”应补条件：2025 年所测模型、L40S、给定 PyTorch 源码及一个 add 格式范例、单次 greedy 生成、总体 `fast₁`（同时正确且快于 PyTorch Eager）。不是普适盲写上限；R1 的 Level 2 为 36%、o1 为 24%。机构可写 Stanford 等（有 Princeton 作者）。

证据：[CudaForge v2](https://arxiv.org/pdf/2511.01884v2) §2/附录 A；[KernelEvolve v4](https://arxiv.org/pdf/2512.23236v4) 搜索与 Runtime Artifact Analysis；[KernelBench](https://arxiv.org/pdf/2502.10517) §4.1/Table 1；[NCU Profiling Guide](https://docs.nvidia.com/nsight-compute/ProfilingGuide/index.html) 的 executed instructions 与 register-spilling 专用计数。

## 8. 必改：破坏性 2×2 探针是敏感度试验，不是保语义性能极限证明（L135–147、160–167、226）

交互公式 `(Base-P0)+(Base-P1)-(Base-P2)=Base-P0-P1+P2` 数学正确，适合作为本轮干预的**非加性交互项**。非零可能来自寄存器分配、调度、occupancy、依赖、缓存等，不能只命名成管线争抢。

- `Base-P0>0` 证明这次旁路让当前程序更快，不证明存在保持原语义、同样便宜的实现；不可省掉的计算也有成本。
- 数值被破坏后，后续输入及编译排程也变了，差值不能直接等于 A 的独立成本或可回收预算。
- 差值为零或负，不证明 A 最优；原开销可能被遮蔽，旁路还可能产生不利排程。
- 有限轮次全部同号是有用证据，不能写成普遍“100%”；接近噪声量级时需保留逐次分布。

建议写成“敏感度稳定为正的路径优先寻找保语义优化；当前候选无稳定收益时允许暂时转向别的分支”。项目可自定停损规则，不能把它包装成数学最优性认证。

## 9. 必改：V3.1 去 pack 数据不支持“见底收官”（L147、160）

这正是 10 月 29 日 2000 审核已否定的结论。主审本轮从 `whole_5way_raw` 原始 JSON 独立复算，四 pass 为：

|档位|V31−P0 四次差值 ms|均值 ms|中位数 ms|
|---|---|---:|---:|
|720p|+.103、+.186、+.119、+.207|+.15375|+.15250|
|900p|+.180、−.719、+.282、−.197|−.11350|−.00850|
|1080p|−.695、+.234、+.239、+.090|−.03300|+.16200|

1080p 是 3 正 1 负，一次较大负差拉低均值；720p 仍 4/4 为正。NVAPI 900/1080 的对应合计仍为 `+.205414 / +.334003 ms`。不应只拿两个负均值证明全部机会耗尽，也不应换用中位数把负结果删掉；应完整报告计时域与波动。

**可留成果：**V3.1_pack5 相对 V2.9 的本轮 12 pass 全部更快，1080p 四次 median 均值 `11.07075 ms`，所以 L85 的 11.07 有出处。去 decode 稳定为正（不同轮次分别写清 pass/方向）、本轮1080p `1.3625 ms` 与零静态 spill 组约 80% 的净敏感度也有依据；但仍不是可直接拿回的性能预算。可以把工程重点转向 decode，无需宣称 pack 已证明为零。

## 10. 正确性与基准升格：保留做法，先固定验收标准（L172–173）

“新版本成为下一轮基线”“审稿先看原始数据”都实用。`0 bit-diff` 与 PSNR 不是可以临时任选的同级标准：前者只证明所测输入上的逐位一致；后者允许误差，需要预先固定参考版本、像素范围、阈值与输入/时序覆盖。破坏性旁路版不得参加晋升。

V3.1 的五条 SASS pack 改变舍入，与 V2.9_fast 有 158 个输入位型差异；这不否定已有性能和质量结果，但协议不能将它默认为无损。本文没有直接宣称该版本 bit-exact，不必另添“翻车”叙事，只需把容差验收与逐位验收分别说清。PSNR 对 V2.9 近似基线的结果也不是对 F32 真值或所有游戏内容的保证。

## 11. ForgeKernel / K-Search：借鉴成立，但自拟规程不能冒充原算法（L121–173、202–203、218）

**ForgeKernel：本轮未完成论文 PDF 全文核验**（OpenReview PDF 请求 403、API 429），以下结论来自今天可读取的官方 OpenBMB/ForgeKernel 仓库。匿名元数据不能证明清华署名；OpenBMB 与面壁发布材料支持面壁项目归属，清华仍待一手材料，不能写成“Anonymous Authors (Tsinghua University & ModelBest)”已知作者名单。

- 官方 `meta/cuda/distill_blackbox_prompt.md` 允许运行、计时、profile 与反汇编黑盒，只禁止读源码，故**黑盒技术主线可以留**；要改的是把 CudaForge 也写成同样任务。
- `meta_milestone.md` 的 DAG phase order 是先确定架构、kernel split/dataflow/tile/warp/resources，再进入参数优化；结构限制出现时可以重开。不是 L133 那套固定 spill-first 顺序。
- 硬件 probe 与认证知识库确实存在，但本文的四表和 2×2 破坏旁路是项目自己的实现。
- `+9.9%` 是 promote-best 后完整再跑一代的最高追加收益，**不是只切换封存开关的单因素消融**。
- `scripts/self_evolve.py` 的 source 模式下，teacher 可读上一代 best 源码、student 不可读，不是每代所有参与者面对唯一黑盒。本文可以自定更严格的黑盒协议，但不要当论文通用规定。
- 官方 README limitations 明说平台期不是最优性证明，与本文“探针变号认证见底”相反。

**K-Search：**本地 PDF 第 5 页 Algorithm 1 / §3.3 是连续无提升次数达到 K；出现改进后计数重置为 0。另有每次 evaluation 递减的全局预算 B，预算耗尽可以终止，哪怕尚有 Open 节点。选择依据是 LLM 估值 V，不是探针毫秒；Closed 指局部 refinement 完成并附 best，不由旁路变号触发；prune 针对不可行或冗余。实验常用 B=120、K=7，另有 K=5，本文 K=3 可以自选。

建议保留 L155–167 的表作为“我们借鉴搜索树思想设计的调度表”，补两个条件：**改善后重置连续失败计数；全局预算/时间耗尽允许带未完成分支交接。** 不要把“不准逃避未做分支”写成无限运行指令。
