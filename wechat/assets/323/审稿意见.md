## 一、影响开篇和结论的两件事

### 1. 19.0、58.4、72.6、71.9 都是真数，但不能直接当成一条贡献分解曲线

**位置：13、31–58、79、108、342、401、416 行。**

原报告 §4.1 / 图3明确给出本轮 RL 的同口径变化：Pro 的 DeepSWE v1.1 avg@3 从 58.4 到 72.6，Flash 从 48.7 到 65.7。表3则给出 V2.5-Pro 的19.0，以及 V2.6 最终版的71.9/67.9。这些数字没抄错。

问题有两层：

- 表3没有写明 avg@k、具体 harness、每题预算等是否与训练曲线完全一致。正文解释 avg@3 和 pass@1 的关系是对的，但只能解释采样估计，不能补齐其他评测条件。第58行“随机波动吃不掉”没有回答这个问题。
- 旧版最终模型并不是新版这轮训练的起始检查点。第44行已承认不知道新版是否沿用旧底座，也没有预训练、mid-training、SFT 的逐阶段消融；第79行却又把差值写成“把后训练分出一层”，第二章进一步用 mid-training 解释了这段差距。这里把已承认的不确定性又跨过去了。

**建议保留所有数字，但把“精确分账”改成“两组观察”：** 本轮 RL 确实涨了14.2个百分点；另据报告表3，新版进入 RL 前的成绩已明显高于旧版最终成绩，说明新版的 RL 起点值得认真研究。可以说“高分不只是最后这一轮 RL 的故事”，不宜说已经证明“这一代总提升有近40分由 RL 前的阶段贡献、14分由 RL 贡献”。

表中加一列“来源/口径”：19.0和71.9来自表3，58.4和72.6来自图3及§4.1。第40行“蒸馏后基本持平”可写成“报告另列最终版71.9”，不要用跨表差值测量蒸馏的净效果。

**标题里的“开源第一”对应 AA 智能指数，正文分阶段分析的是 DeepSWE。** 这两把尺子也应在开头点明。AA 第一可以作为引子，但这份 DeepSWE 曲线不能解释 AA 第一具体由哪个阶段贡献。当前 AA 模型页确有46分及同档开源模型第一的显示。

### 2. 带 KL 的闭式解可以帮助理解起点，但不是小米这次 RL 的更新规则

**位置：87–108、256、348、373、401 行。**

Korbak 的闭式解针对固定参考分布、正的 KL 惩罚系数。第五章又说明小米报告列出的 RL 目标没有 KL 项；所以“放回公式看，mid-training 做的就是抬 π₀”应作为理解初始化和探索的类比，不能作为这轮算法的直接推导。

尤其是“RL 只能放大模型已经采得到的东西”反复出现在金句和速查表里，会被读成固定初始分布给 RL 划了永久边界。没有被采中的完整答案，确实不能在这批样本里直接获得自己的奖励；但参数共享、其他轨迹的更新和后续重新采样，仍可能改变它的概率。

**建议：** 保留公式和学习者回扣，接成“这不是小米本轮的损失函数，但它提醒我先看训练起点：好的解题轨迹越容易被采到，有限预算里的 RL 就越容易得到有效反馈”。“抬 π₀”具体写成“提高有效轨迹的初始概率”。一百次变十次明确标为例子，不当小米的实测。

这也能保住教育学结尾：**基础打得好，后面的练习更容易得到有效反馈。** 不必把它写成 RL 能力上限定理。

## 二、具体机制需要修正

### 3. GAR 的例子算得通，但把简化式写成了实际算法的无条件性质

**位置：175–183、273、377 行；报告 p18，§4.3.2，式(3)。**

报告这里确实用 `A_i = R_i − 组均值`，因此两过两不过的 ±0.5 正确。若两个成功解的质量因子取1和0.5，归一化后得到约0.67和0.33，也正确。**不要为了套一般 GRPO 的标准差归一化把数字强行改掉；把表头“普通 GRPO”改成“小米这里的原始优势”即可。**

但原报告区分了两步：

1. 未设上限的重分配：只动成功解，正优势总量守恒，失败解不变。
2. 实际实现：给共同放大系数设上限，然后成功、失败轨迹一起减去组均值。上限生效时，失败优势也可能随之改变。

**最小修改：** 表前加“先看一个未触及放大上限的例子”，表后补“实际训练还会限制放大倍数，并把整组优势重新调整到均值为零”。第五章、速查表把无条件“总量不变”收成“通过重分配维持正负信号的平衡”。

### 4. 格式错误的优势重分配发生在整个训练批次，不是同一条轨迹

**位置：274行；报告 p20，§4.3.3，式(5)。**

报告先在整个训练 batch 内，按轨迹优势的正负，将报错与未报错 token 分组，再计算缩放系数。正文的“挪给同一条里没出错的 token”把操作范围写错了。

此外，正负总量分别守恒只在缩放系数没有触及限制时成立；发生截断或者分母为零，报告明确说不保证守恒。

**建议替换这一个要点：**

> 格式错误按段处理：正优势轨迹里的错误 token 不再受奖励，拿掉的优势在整个训练批次里分给其他正优势、未报错的 token；负优势一侧加重错误 token 的惩罚，同时减轻未报错 token 的惩罚。缩放未触及限制时，正负两边分别保持总量。

### 5. GRS 表格的“不看失败答案”没有依据；两种机制也不等于简单题/难题的绝对分界

**位置：167、191–197行；报告 pp16–18，§4.3。**

GRS 离线构表会比较多条轨迹、寻找反复出现的错误，报告没有说只看成功解。训练时逐条对表评分，与“不看没过的答案”也不是一回事。

**建议将该行改成：**

| 比较项 | GRS | GAR |
|---|---|---|
| 训练时是否整组比较 | 否，逐条按预先生成的评分表评估 | 是，对照成功与失败轨迹，给成功解排序 |

GRS 选在部分高通过率任务上，不要求每组全过；GAR 用于其余代码任务中的混合结果组，也不是每个组天然都有过有不过。第197行改为“通过率高的题，GRS 连全过的组也能分出好坏；其余代码题碰到有过有不过的组，GAR 就现场排序”。

### 6. V2.6-SFT 的身份从通用 agent 判分移接到了代码 GAR

**位置：221行。**

报告 §4.2.2（p12）在通用 agent 环境里明确点名 V2.6-SFT。代码 GAR 的 §4.3.2（p18）只说判分 agent 经过 SFT，没有点名模型。

**建议：** “代码组内判分器经过 SFT；通用 agent 任务的判分器，报告则明确点名了自家的 V2.6-SFT。”也可以删掉这句，第三章论证不受影响。

### 7. 图8测的是通过率、轮数和长度，没有测熵；任务类型与熵方向的概括也过头了

**位置：268、278、381行；报告图8、§4.3.3、§5.1。**

长输出不等于高 token 熵，重复输出甚至可以又长又确定。图8不能直接当“熵往上失控”的实测图。报告确实多次解释设计是为了限制额外负向压力导致的熵增长，保留这个作者动机即可。

“数学题容易坍缩，长程 agent 更容易爆炸”没有对应的跨任务对照。DAPO 自己也讨论过熵过高导致乱码或重复，不是数学只需要防一头。

**建议：** “315期重点讲熵往下掉，小米这份报告则多次提醒，还得防额外负向压力把熵往上推。长程训练里另一个看得见的问题，是轨迹越跑越长。”速查表把“高熵=又长又散”改成对概率分布的描述。

第278行数据配比也写准：报告的68%是 **agentic coding + competitive coding**，不是所有“代码和 agent 任务”合计；通用工具使用还另占12%。

**第272行四个边界按熵双向调整的方向，与报告原文一致，不要按一般 PPO 的直觉反向改。** 若补解释，可说这里对概率比超出区间的 token 做 mask，别直接理解成 DAPO 同一个 clip 算子。

### 8. 不用生产壳的理由，译成“分不清模型与壳谁有功”偏了

**位置：300–302、356行；报告 p14，§4.2.5。**

原段接下来解释的是：生产壳施加许多要求，而任务完成奖励没有衡量这些要求，结果它们容易被忽略。还有第二个理由：模块紧耦合，不方便单独改变某个交互机制。

**建议改为：** “壳要求模型守很多规矩，奖励却只问任务做完没有，模型就容易忽略那些不计分的要求。极简壳还方便把工具、提示和上下文管理分开组合。”

教室表格也相应改成“练习要求和评分标准要对得上”，比“辅导书抢功劳”更贴报告。

### 9. “这不算作弊，没篡改测试”不是报告得出的结论

**位置：215行；报告 p19，图8后的代码审查段。**

报告列出这些维护者不喜欢的写法，说它们旨在提高测试通过概率，没有保证每种手法一定有效，也没有排除它们属于广义 reward hacking。尤其“针对评测改配置”，本身就可能在钻奖励漏洞。

**建议：** “这些写法都奔着提高过测试的概率去，却可能把代码越写越糟。除了去网上找现成补丁，奖励还会诱导这种应付测试的写法。”这样仍能自然转到第四章，不需要先替它们判定“不算作弊”。

### 10. MXFP4 不只是少占存储，多模态训练也不能因评测纯文本就被排除影响

**位置：42行；报告 p7，§3.1–3.2，以及§6.4。**

报告明确有 MXFP4 量化感知训练，让模型适应低精度计算；训练/推理一致性一节还描述专家权重的量化—反量化。它不是不改变数值计算的无损文件压缩。“存储格式只影响权重占多少空间”应删除。

纯文本评测不调用视觉和音频输入路径，这句话可以保留；但预训练时全模态联合训练会更新语言主干，不能据此排除多模态训练对文本能力的影响。

**建议保留结论的准确部分：** “两代语言主干的层数、注意力布局和专家配置相同；新版又加入多模态训练和低精度适配。”不必把“主干拓扑没换”扩成“其他变化都与成绩无关”。
