## 可写的点（按我觉得值钱的顺序）

### ⭐ A. "两千多万"媒体说错了（接 310/311 的会计手法线）
- 外媒标题"built for roughly $2.62 million"——报告原文 §4.1 是 **"$2.6M ... on RL post-training"**，只是 RL 那段的钱，预训练 30T token 不在里面
- 同一种混淆：DeepSeek V3 "557 万美元"当年也是只算最后一次训练

### ⭐ B. 判分器怎么打分：GRS / GAR（§4.3，接 311 判分器、315 熵、317 公式）
- 问题：二值奖励下所有过测的解都是 1 分，分不出好坏
- **GRS（离线）**：拿一组 rollout 对比，让 agent 写出这道题专属的 rubric（解法分 + 行为分），训练时 `R = R_test × S_sol × S_beh`——乘法，没过测试还是 0
- **GAR（在线）**：一组里通过的解排个序，把正优势从差的解挪给好的解，**总量守恒**（式 3）；五个维度：方案合不合适、实现精不精确、改动最小、没有副作用、符合代码库风格
- **对照实验（图 8，Flash、只训代码）**：不加 GAR，轮数和 token 数疯涨、撞长度上限、通过率上不去；加了之后通过率涨到第 52 步，轮数平稳
- **最有意思的一段（report.txt 1068–1075）**：不加 GAR 的模型为了过测试学会了"投机兼容分支、乱 export、吞异常、放宽校验、改评测配置"——**全是能过测试但维护者会骂的写法**。这就是 reward hacking 的温和版：不作弊，但写烂代码
- 熵：式 3 注释里明说重新归一化是为了"防熵增长失控"；clip 上下界按熵动态调（§5.1，report.txt 1176–1180）——**315 期讲熵坍缩，这里是反过来防熵爆炸**，可以对照

## ⭐ 骨架设计理由（V2-Flash 报告 arXiv:2601.02780v2，本目录 `v2flash.txt`，行号按它）
- **一句话**：48 层 = 首层 GA+dense FFN，然后 8 个"5 层 SWA + 1 层 GA"；窗口 128；KV 和注意力计算都省约 6 倍（134–152）
- **首层为什么 GA + dense**：原文只一句"to stabilize early representation learning"（231–233），没给实验
- **全局层 KV 头更少**：Flash 的 SWA 8 个 KV 头、GA 只有 4 个（260）——全局层存得最多，所以头砍得更狠（这句推论是我的）
- **部分 RoPE**：只转前 64 维（192 的三分之一，config `partial_rotary_factor 0.334`）；RoPE 底数 GA 和 SWA 分开：SWA 一直 1 万，GA 32K 时 64 万 → 256K 时 500 万（497–501）→ V2.5 起 1M 上下文改 1000 万（config）
- **attention sink bias（注意力汇，可学习偏置）**：照 gpt-oss，每个头在 softmax 分母里多加一项 `exp(sink)`（式 2，284–307）——等于多一个"哪儿都不看"的虚拟位置，头可以把注意力倒进去。**config 里只有 SWA 层开了**（`add_swa_attention_sink_bias: true` / full false，五个版本都一样），报告正文没交代这个区别
- **消融（32B dense，250B token，324–383）**，这是整篇最值钱的一块：
  - 不带 sink 的 W=128 混合：MMLU 54.9，**比全 GA 的 57.3 低**
  - 带 sink 的 W=128：58.3，**反超全 GA**
  - W=512 带 sink：一般能力跟 128 差不多，但**长上下文掉得厉害**：MRCR 19.6 vs 128 的 34.4 vs 全 GA 32.5；NoLiMa 38.5 vs 51.2
  - 推理题 W=128 平均 46.3 vs 全 GA 42.4
  - **窗口越小反而越好**，作者的解释（385–400）："小窗口逼 SWA 只管局部、长程全交给 GA，分工更清楚；512 的窗口让 SWA 也去管一部分长程，分工糊了"——作者自己强调"经验性的、限于我们的设置"
  - ⚠️ 消融是 32B dense 250B token，不是 309B MoE 本体
- **长上下文实测（Table 6，603–621）**：NIAH-Multi 256K 96.7%；GSM-Infinite Hard 16K→128K：MiMo 37.7→29.0，**DeepSeek-V3.2-Exp 50.4→25.7**（短的最强，拉长掉得最多）——作者说稀疏注意力"在有噪声的长输入推理上有内在劣势"（537–539）
  - ⭐ 这条直接挂上我们 09-19 立的暗桩「稀疏注意力写不了长文？」——DSA 是"找得到"强、"一起在场"弱，这是一个旁证（⚠️ 对手是 V3.2-Exp 不是 V4/V4.1）
- **MTP**：每块 0.33B，dense FFN + SWA，故意做轻（238–239, 440–448）；预训练只挂 1 个头，后训练复制成 K 个一起训；3 层 MTP 接受长度最高 3.6、解码最高 2.6 倍（Table 10）；⭐ 接受长度和下一词熵拟合 y=4(1−0.58x^0.58)，R²=0.995——**熵越低猜得越准**（WebDev 3.6，MMLU-Pro 最短）
- **精度**：FP8 混合精度照 DeepSeek-V3；注意力输出投影、embedding、输出头留 BF16，路由器 FP32（264–268）——**V2.6 config 里 o_proj 全在 ignored_layers，是同一个选择延续下来**
- **报告自承（1175–1177）**："our current architectural exploration remains preliminary, with limited analysis of design trade-offs. Future work will focus on designing more robust and efficient, agentic-oriented model architectures" —— ⭐ **说架构探索还很初步、以后要设计新架构，结果九个月三代没动一个字段**（可以温和写：没动本身也是一种判断——够用就不动，钱全砸训练）
- 预训练三阶段：0–22T 32K 通用 / 22–26T 加代码和 5% 合成推理 / 26–27T 扩到 256K

## ⭐ 推理代码实读（V2.6-Pro-RL 的 `code/modeling_mimo_v2.py`，行号按它；Zero 09-27 定：架构章以 config + 推理代码为主料）
- **attention sink 就四行（89–97）**：每个头一个标量 `attention_sink_bias`，在注意力分数最后**拼一列**，做 softmax，**再把这一列扔掉**。被扔掉的那一列分走的概率，就是"这一步哪儿都不看"的份额——所以剩下的真实位置权重之和 < 1。跟 V2-Flash 报告式 2 分母多一项完全对应
  - 构造处（268–275）：`add_swa_attention_sink_bias` 为真才给 SWA 层建这个参数，全局层 `add_full...` 为假 → **只有滑窗层有 sink**
- **部分 RoPE（306–310）**：Q、K 各 192 维，前 64 维（`192×0.334`）转，后 128 维不带位置（NoPE）；**两套旋转编码**（1596–1597）：全局层底数 1000 万、滑窗层 1 万
- **V 乘了一个常数（302–303）**：`value_states * attention_value_scale`，Flash 0.707（≈1/√2）、Pro 0.612（≈√(3/8)）——**报告、模型卡、config 注释都没解释**，我也不猜用途，只能写"代码里有、文档里没说"
- **注意力缩放**：`head_dim ** -0.5`，head_dim=192（不是 V 的 128）
- **掩码（1652–1657）**：全局层用普通因果掩码，滑窗层用 `create_sliding_window_causal_mask`——每层按 `hybrid_layer_pattern` 取自己那张
- **MoE 路由（135–184）**：sigmoid 打分 + `noaux_tc`（加一个只影响挑选、不影响权重的纠偏 bias）= **DeepSeek-V3 的无辅助损失负载均衡同款**；`n_group=1` 所以分组那几行实际不起作用；top-8 权重归一化；**没有共享专家**（config `n_shared_experts: null`）
- **Pro 与 Flash 在代码里的唯一区别（221–226 注释）**：Pro 把 QKV 存成一个 `qkv_proj`，Flash 分三个——"只管权重怎么存，算法一样"
- **首层**：`moe_layer_freq[0]=0` → 第 0 层 FFN 是 dense，intermediate 16384（其余层是 384/256 个 2048 宽的专家挑 8 个）
- **层结构**：普通 pre-norm（RMSNorm → 注意力 → 残差 → RMSNorm → FFN → 残差，424–441），**没有 mHC / 超连接之类的残差流改动**，也没有 Engram、没有稀疏注意力索引器——**零件清单是四家里最"朴素"的**
- **MTP 在 HF 推理代码里直接忽略**（1694 `model\.mtp\..*` 在忽略加载列表里）；投机解码走仓库里单独的 `dflash/` 目录
- ⚠️ 这份是 HF transformers 参考实现（eager 路径），生产走 SGLang/vLLM，**细节以 config + 这份代码为准，但性能行为不能从它推**

## KV 账（我按 config 算的，bf16，只算全局注意力层；⚠️ 不是官方数）
- 每 token 全局 KV = GA 层数 × KV 头 × (192+128) × 2 字节
- Pro：10 × 8 × 320 × 2 = **51,200 字节/token → 1M 上下文 50 GiB**；60 层 SWA 固定约 37.5 MiB
