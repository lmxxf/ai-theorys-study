# Strata：家用 9070 XT 的实验计划

状态：2026-10-12 22:41 已完成Windows原生HIP部署及两条中文短问答；正式性能对照、专家预测和LoRA实验尚未执行。实机配置与原始结果见[实验结果.md](实验结果.md)。以下保留最初计划。

用户确认的目标机：48GB 系统内存、RX 9070 XT 16GB 显存。CPU、系统、内存速率、SSD、PCIe 实际链路和驱动版本待现场读取。先完成并通读公众号草稿，再进入远程实验；此文件不代表实验已经执行。

## 切到家里电脑后的接续顺序

1. 先部署，暂不训练预测器。阅读本计划、`../../338.md` 和同目录两份核查记录；不要把公众号中的作者测速当成本机测速。
2. 现场读取系统、CPU、可用 RAM/VRAM、SSD 空间、PCIe 链路和 AMD 驱动。用户已确认的只有 48GB RAM 与 RX 9070 XT 16GB；不沿用其他机器的 SSH 地址或环境。
3. 核对官方仓库的安装说明和当时可用的 HIP 构建，再决定用哪个固定版本。研究入口为 https://github.com/Niko1221/Strata ，安装说明为该仓库 `docs/INSTALL.md`、`docs/AMD_HIP.md`。准备 Q2_0 完整专家量化版、MTP 文件与运行 pack 的磁盘空间，记录下载与实际构建的版本。
4. 先用纯文本、单请求、短上下文跑通启动和问答，读取实际内存分配、专家缓存与启用开关。确认没有因内存压力频繁读专家文件或发生输出异常，再开始性能对照。
5. 然后按下面三个阶段执行：原版基线 → 现成预取对照 → LoRA 预测旁支。当前没有训练数据、预测器权重、HIP 移植或已实现的 LoRA 推理代码。

安装、下载、编译、模型运行等耗时命令按用户习惯分步给出，脚本落文件并在同一文件迭代；不把部署和训练揉成一条长命令。

## 1. 要回答的问题

1. 完整专家的 Q2_0 能否在这台机器上稳定运行，系统和显存各实际占多少？
2. 简单聊天、长文检索和代码修改的首 token 等待及生成速度差多少？差异与专家缓存、CPU/GPU 分工、MTP 接受率有什么关系？
3. 同一专家被多个 token 使用时，MTP 是否实际减少了每个有效输出 token 的权重搬运和等待？
4. 提前预测下一层专家，是否能在这台 AMD 机器上减少等待？
5. 单独训练预取预测器是否优于原样借用下一层路由器？预测更准之后，端到端速度是否真的提高？

不把“预测准确率提高”“输出 token/s 提高”和“完成同一任务更快且正确”合并成同一个结论。

## 3. 第一阶段：跑通与速度基线

### 对照配置

| 配置 | 用途 |
|---|---|
| 安装器推荐配置 | 看普通用户实际拿到什么行为、速度和输出 |
| 相同配置，关闭尾部专家省略 | 建立路由选出的专家均参与计算的调度对照基线；仍是 Q2_0 量化，不叫原精度 |
| 上述基线，开／关 MTP | 看投机收益及其资源占用 |
| 上述基线，切换缓存容量 | 看显存容量与实际调用命中率、CPU 开销的关系 |

尾部专家省略开关为 `STRATA_ROUTE_TAIL_SKIP=0`；当前研究快照中的 CUDA 及部分 RDNA4 路径均可能默认启用。每次以实际启动日志为准。后面的预取对照保持这项设置相同，不把少算专家得到的收益算到预测器上。

MTP 对照分两种口径：

- 固定专家缓存容量，尽量分离“多 token 验证”本身的影响。
- 允许关闭 MTP 后把释放显存分给专家缓存，评估实际部署哪种更快。

两种结果分别记录，不混成一组提升百分比。

### 提示集合与冷热状态

先准备每类多个独立样本，固定输入、文件、采样与输出预算。建议先测 4K、16K、32K；确认余量后再扩长。

| 场景 | 内容 | 主要观察 |
|---|---|---|
| 短聊天 | 日常中文问答，使用多个不同话题 | 低成本输出下的缓存与 MTP 行为 |
| 长文检索／关系核对 | 固定文档、可核答案，同时测单点检索与多处信息组合 | 首次读入开销、回答准确性 |
| 代码修改 | 固定仓库片段与改动要求，含可执行检查 | 草稿重用、专家路由与有效任务耗时 |
| 任务切换 | 聊天后转代码、代码后转长文 | 原来的热门专家集合能否继续命中 |

冷热状态分开：新会话首次读入、同一前缀的后续请求、已有专家缓存但换新前缀。程序重启不等于 OS 文件缓存已冷；不为每次小测试清空全机页缓存。确需磁盘冷启动对照时单列，不能混进会话缓存对照。

初轮每格至少 3 次，交错 A/B 顺序，保留全部运行及异常，不只挑最快一轮。输出预算可先统一 256 token，但记录实际输出数、EOS 和有效内容；循环或空话不能凭高 token/s 算作成功。

### 每次保存

- 实际输入／输出 token 数，预填充时间与速度、首 token 延迟、解码时间与速度、完整请求耗时。
- 进程内存峰值、显存峰值、专家缓存字节数与槽数、KV 与临时缓冲区占用。
- GPU 缓存命中、CPU 执行、PCIe 临时传入分别计数；附原始指标定义。
- CPU 专家计算时间、GPU 等待时间、传输字节、MTP 提议数和接受数、每轮实际接收 token 数。
- SSD 实际读取量，以及读取属于词组表还是专家文件。专家都在 RAM 不代表词组表也不读 SSD。
- 原始回答、代码检查／问题答案和明显重复等质量记录。

项目自带 `hit_rate` 的统计口径会受 PCIe 分担影响，不直接当成“所有路由调用中多少已在显存”。能取路由 trace 时，另算以 `(token, layer, expert)` 调用为分母的命中比例，并与按验证窗口去重后的专家数分开。

## 4. 第二阶段：现有专家预测和预取

Strata 的 look-ahead 用当前层的较早表示送入下一层已有路由器，预测下一层专家。它不是另外训练的网络，也不是 MTP 预测 token。

- 文件预读：让预测到、且未在 GPU／RAM 驻留的专家页提前进入文件缓存；48GB Q2_0 常规模式可能没有多少专家文件读取可省，先看实际 I/O。
- Foresight 显存槽：给刚未命中及预测专家准备临时显存位置。它会挤占长期热门缓存，官方多机实验曾出现负收益。
- 先确认 `STRATA_LOOKAHEAD_STATS`、`STRATA_FS_SLOTS` 等在目标 HIP 版本的实现范围。若不支持，先离线评估预测质量，再决定是否移植，不把 CUDA 开关当成 AMD 已实现功能。

若可运行，对照“不开预取”“只预取刚未命中专家”“加入下一层预测”，保持总显存预算、其他开关和提示相同。记录预测耗时、预取到达时机、白搬字节、被预取槽挤掉的缓存量及最终耗时。测量型 profiling 开关可能增加开销，预测质量采集与正式速度测试分开。

## 5. 第三阶段：低秩专家预取预测器（2026-10-12 21:15 更新的猜想）

前提：部署稳定、等待瓶颈已经测明、预取通路能在 AMD 上执行。原模型和真实路由器全部冻结，保持真正选择专家的逻辑不变。

### 优先方案：复用当前层路由分数的 LoRA 旁支

令 `x` 为第 l 层真实 router 的输入（须核对归一化、残差折叠后的实际张量），`W_l` 为其投影矩阵。

```text
真实当前层分数：z_l = x W_l                # 原模型本来就算
预测下一层分数：z_hat_next = z_l + (x A_l) B_l
监督目标：真实执行得到的下一层路由分数或 top-10
```

- `W_l` 和实际用于 top-k 的 `z_l` 不修改。A、B 仅供预取旁支，不合并进原 W。
- 尽量复用现成的原始路由 logits，而非仅剩 top-k 的结果；具体能否复用、输出是否有额外变换，由 hook 核验。若必须重新算完整 `xW_l`，就不能再按“仅多算低秩分支”报告成本。
- 预测应在当前层真实路由算好后尽早发出，用当前层专家及后续计算的时间隐藏预取；所有额外同步和 GPU 小算子开销都计入。
- 相邻层专家 ID 没有天然语义对应。这里假设跨层映射可由低秩修正有效近似，不把该假设当成已证实。

由官方配置 `hidden_size=2560`、`num_experts=512`、48 层计算，矩阵 A 为 `2560×r`，B 为 `r×512`。不含优化器、训练激活、工作缓冲和可选偏置：

| 低秩维度 r | 单层 BF16 参数大小 | 前 47 层合计 | 额外乘加量 / 原路由投影乘加量 |
|---|---:|---:|---:|
| 8 | 约 0.049MB | 约 2.31MB | 1.875% |
| 16 | 约 0.098MB | 约 4.62MB | 3.75% |
| 32 | 约 0.197MB | 约 9.24MB | 7.5% |

以上为十进制 MB 和矩阵运算量估算，不是实际时延。完整 `2560×512` 预测器副本按 BF16 是每层约 2.62MB，47 个约 123.21MB；已有下一层 W 本身就在模型里，原样借用它不需再存一套，但提前额外算它仍有计算开销。

### 对照与训练

1. 基线一：不预测，按真实路由处理。
2. 基线二：现成的下一层 router look-ahead，即用较早表示代入下一层已有路由器，不训练。
3. 实验：上述当前层分数＋LoRA 旁支，先试 r=8/16/32。
4. 可选比较：训练一个完整的下一层路由器副本，看多花资源能得到多少覆盖率。它是对照，不再是优先部署方案。
5. 正常推理收集提前可用的 x、当前层原始 logits，以及下一层真实路由分数／专家 ID。先少量层、抽样 token、限制文件大小，避免保存全模型所有激活。
6. 训练只加载收集的数据和小预测器。比较匹配路由分布与学习 top-k 标签，不对整台模型反传。若使用低秩乘积，初始化至少一边为非零，避免两边全零导致无梯度。
7. 按整份提示／文档／任务划分训练与测试，不能将同一上下文相邻 token 分散到两边。
8. 在不同候选数与预取字节预算下，量未缓存专家覆盖率、误取量、按路由权重加权的覆盖率。预测器可以多猜候选，但实际计算仍保持真实 top-10。
9. 接入预取后测端到端：预测准确却来不及搬完，同样没有价值。比较时记录临时槽挤占的缓存空间，保持总显存预算可比。

预测器只给调度建议。预测失败不授权删掉真正选中的专家。CPU/GPU 执行位置变化可能改变浮点舍入，不能仅凭设计宣称逐位一致；保存输出差异，必要时做固定序列概率对照及任务正确性检查。

### 后台采集、磁盘留存与批量更新（21:27 讨论补充）

用户倾向：使用中持续收集路由预测错误，低优先级写盘，更新时批量训练 LoRA。先实现采集并测开销，再打开自动更新；这不是已部署能力。

- 样本以预测器输入为界：当前层 2560 维输入 BF16 为5120字节，512维当前路由分数BF16为1024字节，下一层top-10编号用uint16为20字节，合计6164字节。额外记录层号、样本/会话分组和版本元数据。若保存下一层完整分数、归一化权重或FP32输入，重新计算大小。
- 不保存完整 KV、主干反传图或所有中间激活。主模型运行中取得的特征须脱离梯度图；路由旁支训练仅加载样本和A/B。
- 当前层到下一层的待配对输入只暂存；拿到真实目标后按策略抽样。失败样本优先，同时随机保留成功样本和历史任务，避免只学错误或只记最近对话。
- 推理线程只尝试提交有界队列；拥塞时丢弃或降低采样，统计丢弃数。GPU到CPU复制尽量使用小型锁页缓冲池和异步事件，只有复制完成后后台才能读取，不在推理主路径等待磁盘flush。
- 独立写入线程/进程以低优先级顺序写入二进制分片，先聚合再写，避免每个样本单独小I/O或把浮点数组写成JSON。逐条形状、数据类型和分片索引要可校验。
- 磁盘比内存宽裕，但仍设可配置的总大小/天数上限并轮换。每秒若留10条约62KB，连续一天仍约5.3GB；低优先级只改变竞争顺序，不减少总量。初轮可用一万条、约62MB有效载荷验证链路，再按实测调整。
- 每个分片绑定模型文件hash、量化配置、引擎commit、输入hook与层号、预测器版本。升级模型或改变特征定义后不混用旧训练样本。
- 更新以明确的样本快照批量训练，优先在无交互请求或用户安排的空闲时段进行。训练新A/B时仍保留旧版本供推理，避免训练与生成抢同一张16GB卡的资源。
- 保留独立历史与新任务验证集，比较覆盖率、误搬量和端到端耗时。通过后在请求/验证窗口边界切换完整版本，并保留回滚版本；不在一轮验证中途混用两套旁支参数。
- 单独对比关闭采集、只进内存队列、异步落盘三种情况；SSD同时承担词组表读取，写盘低优先级也不保证没有尾延迟影响。

## 6. 停止与升级条件

- 若基线内存压力造成换页或重复输出，先把稳定性定位清楚，不在异常基线上计提速。
- 若等待主要在别处，或预取挤占缓存造成净退化，记录负结果；不因猜想好听而继续堆复杂机制。
- 只有在固定任务集、包含不同任务类型的重复对照中，同时看到有效时间下降和质量保持，才把结果写成该配置下的收益。
