# LoRA 专家预取：prefill 与纯自回归速度

2026-10-13，RX 9070 XT 16GB、Core Ultra 7 270K Plus、48GiB RAM，Qwen3.8-Flash-Next Q2_0，独立 Strata 0.1.43 HIP 实验引擎。

**这套配置没有测到稳定的 LoRA 提速，整套预测预取的平均速度也低于不预取。** 离线覆盖率提高，不等于实际完成得更早。

## 完整36次请求的结果

各组4份相同输入，每份重复3次；各组共15657输入token、1536输出token。速度用总token数除以总耗时，不取最快一轮，也不直接平均各请求的token/s。

| 配置 | prefill（token/s） | 纯自回归生成（token/s） |
| --- | ---: | ---: |
| A：不预测、不预取 | **109.29** | **56.30** |
| B：下一层原路由器预测＋预取 | 105.40 | 53.44 |
| C：相同预取＋未缓存目标 LoRA | 104.38 | 51.40 |

C相对B：prefill吞吐−0.97%，生成吞吐−3.81%。生成均值受到一次明显慢请求影响，不能解释成固定3.81%的开销：

| 轮次 | LoRA相对普通预取的prefill变化 | 生成变化 |
| --- | ---: | ---: |
| 1 | −1.00% | +2.05% |
| 2 | +0.27% | +0.52% |
| 3 | −2.15% | −12.65% |

第三轮C的片段23生成只有33.8 token/s，同轮其余C请求为52.4、54.2、54.8；该片段前两轮C为54.5、54.4。日志未发现配置变化、复制失败降级或模型异常。原因未定位，原样保留，没有丢弃或重刷这条结果。

同一输入下，A的三次回答哈希一致；B/C的回答哈希各有3种。预取改变了哪些专家由CPU或GPU执行，两条算术路径不保证逐位一致；本轮没有隔离输出序列差异与其他运行波动的贡献。因此生成速度是相同提示、固定输出预算下的实测，不是完全相同token轨迹的微核开销测量，也没有据此宣称质量相同。

## 对照条件

- 固定4份此前留出的文本片段，输入长度947、1245、1488、1539 token；每次输出128 token，全部以length结束。
- 三轮顺序为ABC、BCA、CAB，每个组别重新启动引擎、做一次不计时的统一暖机；9次启动均成功。
- temperature=0、reasoning_effort=none；关闭MTP、suffix draft、lookup chain。36次请求draft_n全部为0，测的是纯逐token自回归。
- 关闭会话前缀缓存，cache_n全部为0。模型加载及暖机不计入表格。
- 最大上下文65536，int8 KV；`--prefill 128 --short-read 65536`。测的是当前可运行的验证窗口兼容读取路径，不是之前崩溃的批量BLAS预填充路径；没有测32K输入吞吐。
- 长期专家缓存全部固定3437槽（4.43GiB），15个CPU worker加主线程；PCIe分担固定0.3，关闭动态专家缓存调换，route-tail-skip=0。
- B/C均为每层16个Foresight临时槽、每窗口每卡最多32次复制、提前1层、预测10个未缓存专家。A不分配这块额外预取空间，长期缓存槽数仍相同。这是固定长期缓存的对照，不是分别替三组寻找最优显存配置。
- 三组都强制发布新鲜的host路由输入，避免缓存全命中时读取旧输入；因此A也使用实验引擎的共同发布设置，不冒充未经修改的发布版测速。
- LoRA只加载第二轮未缓存目标训练中选出的17对层，rank16，其余30对不修正；原模型及真实路由不修改。CPU AVX2计算`xW_next + (xA)B`，排序前排除已缓存专家。无LoRA组使用同一候选排除规则。

## 接入与验证

只在独立worktree `C:\Strata-Lab\Strata-speed` 和独立 `speed-engine` 操作，原服务exe未替换。

1. 转置BF16 A/B，复用现有CPU BF16行点积函数。6-token夹具覆盖全部48个目标层，C++修正值对训练端最大绝对误差约1.335×10⁻⁵，通过atol=2e-4、rtol=1e-4的门槛。
2. 将预测结果送入已有Foresight复制流，真实路由仍然决定计算哪些专家。
3. 原诊断开关在等待CPU的GPU图期间做同步默认流回读，30-token预检卡住并由引擎结束。实验版改用独立复制流回读校验；正式计时关闭校验开关。失败日志保留。
4. 原Foresight窗口计数只在生成阶段推进。为实际测试兼容prefill的预取，在每个已完成验证窗口之后也推进计数，刷新复制预算和安全复用期限。没有这个接入，长输入只消耗最初的一批额度。
5. 最终预检6507次权重回读校验正确、0 BAD。随后正式36次全部正常结束。

正式日志确认B的LoRA调用为0，C每轮约26800次有效LoRA调用；原路由器预取、临时槽复制与使用均实际发生，没有用“设置了环境变量”代替启用证据。LoRA内部计时每轮累计约0.46秒，但它在异步预测线程里，不能把这个累计数直接当作主路径增加的延迟。
