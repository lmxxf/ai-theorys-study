# Strata 机制核查：小显存装的是工作集，不是整个模型

核查日期：2026-10-12。仅讨论 **Niko1221/Strata**，固定提交 `7695859aa13afb248bdb4d36f9b2e95707db079d`。以下行号按 raw 文件从 1 开始计数；不是搜索工具重新排版后的行号。未运行模型、编译或性能测试；性能与精度数字均为作者自报。

## 一、可以用于文章的结论

12/16GB 显卡能跑，依赖的是**量化、CPU/GPU 协同计算、专家缓存、按需读取 n-gram 表、MTP 投机解码**的组合。不能写成“把 176B 模型塞进 12GB 显存”，也不能写成“所有冷专家都从 SSD 搬到 GPU 算”。

常规足内存配置下，专家权重主要常驻系统 RAM；GPU 常驻注意力、Gated DeltaNet、路由、共享专家、输出头、MTP，以及热门路由专家缓存。生成时，命中缓存的专家在 GPU 上算，未命中的一部分由 CPU 原地算，另一部分走 PCIe 给 GPU 算。**CPU 是计算参与者，不只是搬运工。**缓存分配与 PCIe 分工会随会话/测得吞吐调整。

此外，当前默认引擎确实存在**跳过低权重未缓存专家**的近似加速，不能宣传成完全无损、每次始终完整执行原 top-10。早期 0.1.26 基准与当前默认 0.1.42/0.1.43 路径必须分开。

## 二、CPU / GPU / SSD 各管什么

| 部分 | 通常在哪里 | 做什么 |
|---|---|---|
| 注意力、Gated DeltaNet、路由、共享专家、输出头、MTP | GPU | 每层的主干与草拟/验证计算 |
| 热门路由专家 | GPU 缓存 | GPU 执行，缓存随会话调整 |
| 未缓存专家 | RAM 为主 | CPU 原地计算一部分；另一部分经 PCIe 交给 GPU |
| KV | 默认 GPU；长上下文可 RAM+GPU | 64K 起 setup 可启用 KV streaming，GPU 保留被读的部分 |
| n-gram / PLE 表 | SSD | 每个 token 仅按索引读少数行，不把整张表放进显存 |
| 低 RAM 模式的专家 | GPU + RAM / 文件映射 | 不够放时依赖 OS 文件缓存及 SSD 缺页，通常更慢 |

直接证据：

- [DETAILS.md L1826–1856](https://github.com/Niko1221/Strata/blob/7695859aa13afb248bdb4d36f9b2e95707db079d/docs/DETAILS.md#L1826-L1856)：三层存储、CPU 原地算专家、PLE 表和 prefill 流式专家。
- [DETAILS.md L1642–1655](https://github.com/Niko1221/Strata/blob/7695859aa13afb248bdb4d36f9b2e95707db079d/docs/DETAILS.md#L1642-L1655)：未缓存专家由 CPU 和 GPU 分担，`--pcie-frac` 控制比例；默认会依据 CPU 速度与 PCIe 带宽修正。
- [hit_hook.hpp L13–36](https://github.com/Niko1221/Strata/blob/7695859aa13afb248bdb4d36f9b2e95707db079d/include/strata/core/hit_hook.hpp#L13-L36)：GPU launch 在 CPU pool 前启动，两者并发，最后 combine。
- [verify.cpp L1611–1639](https://github.com/Niko1221/Strata/blob/7695859aa13afb248bdb4d36f9b2e95707db079d/src/core/verify.cpp#L1611-L1639)：PCIe 部分的 staging 与未命中计算结果合并；[L2914](https://github.com/Niko1221/Strata/blob/7695859aa13afb248bdb4d36f9b2e95707db079d/src/core/verify.cpp#L2914) 实际调用 CPU pool。

**生成与读 prompt 要分开讲。**长 prompt 批量计算以 GPU 为主，专家经 PCIe 流入、与其他工作重叠。当前版本还默认把短于 1024 token 的单 GPU CUDA prompt 的部分专家工作交给 CPU，见 [DETAILS.md L1543–1550](https://github.com/Niko1221/Strata/blob/7695859aa13afb248bdb4d36f9b2e95707db079d/docs/DETAILS.md#L1543-L1550)。不能把生成期 CPU/GPU 分工机械套到所有 prefill。

## 三、是不是 NVMe 流式推理

答案是：**部分确实是，但不是“整套专家平时全在 NVMe、逐 token 全搬进 GPU”的路线。**

常规模式把全部专家复制到 pinned RAM，GPU 再存热门专家。真正长期放 SSD 按需取的是默认约 28.8GB 的 IQ4_NL n-gram 表。其读取默认绕过 OS 页缓存，源码的 Windows `FILE_FLAG_NO_BUFFERING` 与 Linux `O_DIRECT` 分支均可见：[direct_file.cpp L167](https://github.com/Niko1221/Strata/blob/7695859aa13afb248bdb4d36f9b2e95707db079d/src/platform/direct_file.cpp#L167)、[L309](https://github.com/Niko1221/Strata/blob/7695859aa13afb248bdb4d36f9b2e95707db079d/src/platform/direct_file.cpp#L309)。PLE reader 自己组织读取任务与后台线程：[ple_reader.cpp L95–100](https://github.com/Niko1221/Strata/blob/7695859aa13afb248bdb4d36f9b2e95707db079d/src/ngram/ple_reader.cpp#L95-L100)。所以“只在启动时读盘，此后完全不读 SSD”也不正确。

RAM 紧张时支持 `--mmap-experts`，把 `experts.bin` 或 GGUF 映射进地址空间，OS 页缓存能留下多少算多少。文件映射并不等于已经全部读入内存；缺页时仍要读 SSD。源码：[expert_source.cpp L961–965](https://github.com/Niko1221/Strata/blob/7695859aa13afb248bdb4d36f9b2e95707db079d/src/core/expert_source.cpp#L961-L965)、[L1102–1158](https://github.com/Niko1221/Strata/blob/7695859aa13afb248bdb4d36f9b2e95707db079d/src/core/expert_source.cpp#L1102-L1158)。

另有 resident 模式：仅把 GPU 没有的专家复制到锁定 RAM，避免重复存储；若补集能装下，稳定生成期间无需从 SSD 读**专家**。这不意味着 PLE 表不读盘。详细模式与限制见 [DETAILS.md L148–190](https://github.com/Niko1221/Strata/blob/7695859aa13afb248bdb4d36f9b2e95707db079d/docs/DETAILS.md#L148-L190)。

## 四、速度里面包含 MTP，不是普通单 token 解码

顶部测试明确开启 MTP。模型自带 MTP 层先草拟至多 3 个 token，再通过全部 48 层批量验证；作者称平均一轮推进 2.4–3.2 token。重复上下文时还可用 prompt lookup 草拟。草稿接受率随语言、任务和输出变化，因此同机同量化也没有一个固定 tok/s。

证据：[DETAILS.md L14–19](https://github.com/Niko1221/Strata/blob/7695859aa13afb248bdb4d36f9b2e95707db079d/docs/DETAILS.md#L14-L19)、[L1839–1843](https://github.com/Niko1221/Strata/blob/7695859aa13afb248bdb4d36f9b2e95707db079d/docs/DETAILS.md#L1839-L1843)。**不能把这些数字归因给专家缓存单项，也不能直接拿来对比另一引擎关闭投机的解码速度。**

投机验证原则和逐位一致性也要分开：CPU 单 token / 多 token kernel、CPU/GPU 专家位置会有浮点舍入差异；切换投机/缓存状态不保证逐字相同，见 [DETAILS.md L97–112](https://github.com/Niko1221/Strata/blob/7695859aa13afb248bdb4d36f9b2e95707db079d/docs/DETAILS.md#L97-L112)。

## 五、精度代价：有量化，也有默认跳专家

**当前最值得写清的事实：**0.1.42 CUDA 默认 `STRATA_ROUTE_TAIL_SKIP=7`。在一个多 token 验证窗口中，若某个不在显存的专家对窗口所有 token 都排在 top-10 的低权重尾部（源码/文档称 rank≥7），这个专家不搬也不算，贡献置零，其余专家权重不重新归一。显存内专家仍照常算；任一 token 给它更高排名，也仍算。`STRATA_ROUTE_TAIL_SKIP=0` 可关闭。

这作用在**目标模型验证过程**，不是只少算不影响答案的草稿层，也不是永远固定把 top-10 改 top-7。是否跳过取决于窗口和专家缓存位置。当前 GPU 缓存比例很高、batch 等配置存在例外。固定提交也已包含 0.1.43 对 HIP gfx1200/gfx1201 的默认启用；文档后面残留“不适用 HIP”的旧句，不能照抄。源码 [generate.cpp L1569–1580](https://github.com/Niko1221/Strata/blob/7695859aa13afb248bdb4d36f9b2e95707db079d/src/program/generate.cpp#L1569-L1580) 的 `decode_defaults_arch_ok()` 在 HIP 下明确判断 gfx12；其他 AMD 架构不因此自动启用。

- 文档：[DETAILS.md L1586–1640](https://github.com/Niko1221/Strata/blob/7695859aa13afb248bdb4d36f9b2e95707db079d/docs/DETAILS.md#L1586-L1640)。
- 实际默认开关：[generate.cpp L8203–8237](https://github.com/Niko1221/Strata/blob/7695859aa13afb248bdb4d36f9b2e95707db079d/src/program/generate.cpp#L8203-L8237)。
- 作者自报：3060 IQ3_XXS 单卡综合约 +15.6% decode，A4000 Q2_0 约 +12.9%；teacher-forced top-1 一致率约 97.5–98.2%，不是 100%。少量任务实验未分出明确优劣，**不足以证明通用任务完全无损**。

另须区分：普通 Q2/IQ2/IQ3 是权重量化；可选 4-bit KV 也有精度损失；**Coder 是独立的专家剪枝模型**，每层从 512 保留 256、仍路由 10 个，不能把 Coder 的内存和速度当成原版 512 专家的成绩。[DETAILS.md L365–375](https://github.com/Niko1221/Strata/blob/7695859aa13afb248bdb4d36f9b2e95707db079d/docs/DETAILS.md#L365-L375)。

## 六、与 llama.cpp 的关系

较准确描述是：**独立组织模型执行、内存层级和调度的专用推理引擎，复用 ggml/llama.cpp 的重要内核与组件。**它不是简单给 llama-server 套一个网页，也不是从零独立实现所有数学内核。

CMake 自建 `strata_engine`、`strata_prefill` 和 `strata` 可执行文件：[CMakeLists.txt L472](https://github.com/Niko1221/Strata/blob/7695859aa13afb248bdb4d36f9b2e95707db079d/CMakeLists.txt#L472)、[L586–601](https://github.com/Niko1221/Strata/blob/7695859aa13afb248bdb4d36f9b2e95707db079d/CMakeLists.txt#L586-L601)。CPU native expert 明确调用 ggml 类型 trait、量化与 vec_dot：[native_expert.cpp L1–3](https://github.com/Niko1221/Strata/blob/7695859aa13afb248bdb4d36f9b2e95707db079d/src/kernels/cpu/native_expert.cpp#L1-L3)、[L49–73](https://github.com/Niko1221/Strata/blob/7695859aa13afb248bdb4d36f9b2e95707db079d/src/kernels/cpu/native_expert.cpp#L49-L73)。官方鸣谢也列出 i-quant、GPU dot/dequant、CPU backend、mtmd 视觉编码及 gguf-py：[DETAILS.md L1872–1875](https://github.com/Niko1221/Strata/blob/7695859aa13afb248bdb4d36f9b2e95707db079d/docs/DETAILS.md#L1872-L1875)。

## 七、参数口径与专用性

当前官方模型卡明确：**主干 125B、激活 6B，另加 51B n-gram embedding 和 4B MTP**。因此 176B 是 125+51、未计 MTP 的口径；若把 MTP 一并加上约 180B。不能把 125B 与 176B 当成两个不同主模型，也不宜用单一“大模型参数量”掩盖大量参数其实是按行查表。

官方 [模型卡](https://huggingface.co/Qwen/Qwen3.8-Flash-Next/blob/main/README.md) 第 46–64 行（2026-10-12在线读取）；[config.json](https://huggingface.co/Qwen/Qwen3.8-Flash-Next/blob/main/config.json) 第 101–103 行为 512 experts、每 token 10、48 layers。这里 HF 链接为实时 main，未锁版本，不与 Strata 的固定 commit 混称。

**24,576 = 48×512，是整个网络的路由专家总数；10 是每层、每 token 的路由数，另有每层 1 个共享专家。**完整原始路径跨 48 层名义上执行 480 次路由专家计算，不是整网只选 10 个。上述尾部跳过属于引擎近似执行的额外变化。

Strata 的 `ModelGeometry` 明确把 2560 hidden、48 层、每 4 层一次 QSA、512 experts 等设为 kernel contract：[layout.hpp L24–56](https://github.com/Niko1221/Strata/blob/7695859aa13afb248bdb4d36f9b2e95707db079d/include/strata/core/layout.hpp#L24-L56)。这体现了它针对 Qwen3.8-Flash-Next 及其兼容衍生包深度优化的性质。不同量化、Swift/Coder 等不等于任意 MoE/GGUF 都能直接接上，更不能推广成任意 176B dense 模型均可在 12GB 卡上同速运行。
