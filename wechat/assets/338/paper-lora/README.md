## 实际速度结果

沿用之前4个固定AGENTS输入（947–1539 token），每次128个输出，关闭MTP/其他草稿/前缀缓存。每组3轮，每轮重新启动并暖机，顺序ABCD、BCDA、DACB。第三轮在启动失败后间隔约14分钟恢复，所有组别均补齐；第三轮四组速度整体低于前两轮，保留全部数据。

| 组别 | prefill token/s | 自回归 token/s |
|---|---:|---:|
| A 无预取 | 111.38 | 57.50 |
| B 原路由器预取 | 106.60 | 55.07 |
| C 旧LoRA预取 | 106.24 | 55.10 |
| D 论文LoRA预取 | 106.60 | 55.41 |

按总token/总耗时汇总，新LoRA比原路由器预取prefill +0.004%、自回归+0.605%；比旧LoRA +0.340%/+0.566%。新旧LoRA自回归每轮分别+0.67%、−0.57%、+1.56%，未见稳定提速，无预取依然最快。

这轮证明的是论文留出集上的预测覆盖率提高。速度使用原先固定AGENTS输入，且预取组输出哈希随运行变化，不是锁定同一生成轨迹的对照；不能把上述微小吞吐变化归因为论文集命中率改善。兼容prefill路径、固定3437个专家缓存槽、CPU线程数和预取预算等沿用route-speed配置，未做各组单独调优。
