# 337 期独立通读意见

已作为未参与本稿修改的新读者，从标题到发布摘要完整通读一遍。只看阅读流畅性和文内逻辑，没有调阅旧审稿意见，也没有复核外部论文或改动正文。以下行号对应本次读到的 `wechat/337.md`。

总体判断：主线是通的——压缩方式 → 位置周期 → 实测差距 → 自训对照 → 形成机制 → 评测启发。不需要重新组织全文。主要卡点是几处解释插入得太早或收回来太晚，以及两个“训练”的问题没有明确接起来。

## 主要问题

### 1. 第一章刚建立起窗口画面，就被长灯泡块岔开了

- **位置：第 27—69 行，尤其第 33—53 行。**
- **短摘录：**“窗口是 8……步长是 4”之后，进入“压缩以后，组内的混合比例就固定了”；灯泡结束才解释“相位 = token 位置 % 步长”。
- **哪里卡：**初读者此时最想知道的是“8 个位置、每次推进 4 个，究竟怎样形成四种站位”。图刚出现，就要先理解逐维混合、三类权重、输入变化、更新参数不改旧缓存，最后再捡回窗口。这个灯泡有用，但插在了空间关系尚未讲完的位置。开篇又已经讲过一次 8/4，读起来像反复起步。
- **最小建议：**把第 57—69 行的位置表和相位定义紧接在示意图后面，再放这个灯泡。灯泡内第 51 行可压短，尤其“更新参数本身也不会自动改写已经存好的 KV”不是当前主线必需的解释。无需删掉三种权重的区分。

### 2. Qwen 小实验最后说“没看到收益”，会让人回头核对刚读到的 50% / 75%

- **位置：第 159—165 行。**
- **短摘录：**先说“相同续写输入下……16K 反而下降”，随后说聊天模板达到“50% 和 75%”，最后又说“这次小实验没看到收益”。
- **哪里卡：**第 159 行的限定很清楚，第 161 行也解释了两种问题。但第 165 行一概括，就把“相同续写输入下”丢了。读者刚看到聊天方式明显提高，很容易把最后一句读成与上一段冲突。紧接着又提出“V4 的收益是否在补偿压缩”，容易让人觉得实验已经排除了普通后训练收益，而前文其实明确说还没分开能力与回答方式。
- **最小建议：**第 165 行改为“这次在相同续写输入下没看到收益，换成聊天模板却明显改善，所以目前还分不开检索与回答方式的影响。”然后保留作者直觉和待验证的猜想。这里只需补回条件，不必删掉实验或观点。

### 3. 第二章“后训练减轻偏心”和第四章“训练学出偏心”之间，缺一句接线

- **位置：第 134—140 行与第 239—265 行。**
- **短摘录：**前面“后训练能减轻这种代价”，后面“为什么训练会学出‘偏心’”“集中保留本身就可能有利于降低损失”。
- **哪里卡：**这不是必然矛盾，但第一次读会自然问：训练到底是在补偿偏心，还是在制造偏心？第四章讲简化检索任务下的门控学习，第二章讲整套模型的后训练版本；文章没有在切换处主动告诉读者，现在研究的是不同阶段、不同范围的问题。读者必须自己把这层区别补出来。
- **最小建议：**第四章开头补一句：“前面看的是后训练怎样减轻整套模型的差距；这里先退一步，看压缩器在训练中为什么会形成位置偏好。”此外，将第 297 行“固定平均压缩也有相位波动，门控偏好只是其中一条机制”的提醒提前到本章开头或定理之前。否则读者会先把整章当成完整解释，读完最后一个长灯泡才发现它只解释一部分。

### 4. 最后一个灯泡先算存储账，再讲真正相关的机制，收尾被拖住了

- **位置：第 275—293 行。**
- **短摘录：**“压缩器有多大：它负责打分，上游负责理解”，随后依次讲 4096/512/1024、两张矩阵、BF16/FP32、MB 口径、Indexer，之后才讲计算过程。
- **哪里卡：**门控移位实验已经把本章推到很好的落点，此时读者期待的是“所以找到了什么原因”。突然要先算一遍参数存储量，读完才发现真正用于理解偏心的是第 289—293 行的浅层门控与上游表示。数字本身并没有直接推进这条解释，Indexer 还是第一次出现。这个灯泡可以保留，但当前顺序让它更像另开一篇代码笔记。
- **最小建议：**把第 289—293 行的机制放在灯泡前半，矩阵表作为随后可选的具体补充；或者只保留表，压掉第 287 行的运行精度及 Indexer 分支说明。标题中的“理解”建议也加引号，与正文的解释口吻一致。不要把参数少直接改写成理解能力差，原文这层分寸是对的。

### 5. 两类 key/value 和“头”的含义，需要各补半句话

- **位置：第 114—118、183、225、259—263 行。**
- **短摘录：**先说注意力的“键向量和值向量”，后来实验又说“16,000 个键值对”“目标 key”；再后来出现“8 个 KV 头”“一个头把键的权重放在某个位置”。
- **哪里卡：**程序员理解数据表的 key/value，但不一定立即知道这与模型内部的 K/V 向量是两回事。第三、四章也把“头”当成已知概念，然而理解“不同头可以守不同位置”正是理解偏心和补偿的重要一步。
- **最小建议：**第一次介绍大海捞针时，补“这里的键值对是文本里的查找记录，例如某个代号对应某个值”；首次出现 KV 头时，用半句话说明它们是并行保存和读取信息的通道。第 219 行窗口边界例子还可补明“这项测试里 key 和 value 各占一个 token”，前提是实验设置确实如此；否则读者不明白为什么只有第 7 格会跨界。这里只提出解释缺口，不据此改实验事实。

## 两处顺手可改的小卡顿

- **第 177 行“到这里还只是 DeepSeek 上的现象”**：刚读完作者自己的 Qwen 实验，字面上会顿一下。改成“回到论文：前面的周期性证据还来自 DeepSeek”，就能清楚接回研究者的主线。
- **第 255 行“两个位置各留了一份”**：前面刚说把两条平均成一条 K，“各留了一份”像是在说仍然分别保存。改成“两个位置的信息都掺进去了一部分”，更贴合公式，也更好接后面的取舍。

## 可以放心保留的部分

FP8 转回 FP32 的例子好懂，能把“挪几个 token 就翻答案”落到程序员熟悉的错误上；第三章平均分接近、最差组悬殊的表，是全文最有力也最顺的一处；两条定理分别回答“最优解是什么”和“训练怎样走到那里”，次序清楚。尾声的评测启发也自然。没有发现需要推倒主线的结构问题。

优先处理第 2、3 项的衔接，再调整第 1、4 项灯泡位置或长度即可。参考资料后的三句摘录和发布摘要属于版式用途，不把它们算作正文赘述。
