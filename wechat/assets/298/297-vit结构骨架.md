# 297 期骨架 —— DLSS 5 (H-Net) 模型结构(从 DLL 符号确认)

## 一手证据(strings 抠出,可复现)

**Swin 招牌 = shifted window 坐实:**
- `cc_split_swin_16h_qkv_shifted_`
- `cc_tinlayout_fused_swin_1h_shifted_` / `_ds_shifted_` / `_upsample_shifted_`
- 每个尺度(1h/2h/4h/8h)都有 shifted 变体
→ 这是正宗 Swin Transformer,不是随便命名。shifted window = Swin 论文核心机制

**四级金字塔,编码器↓ 解码器↑ 完全对称:**
| 尺度 | 通道 | 窗口 | 下采样kernel | 上采样kernel |
|---|---|---|---|---|
| 1h | 32 | 1 | swin_1h_32_1_ds | swin_1h_32_1_upsample |
| 2h | 64 | 2 | swin_2h_64_2_ds | swin_2h_64_2_upsample |
| 4h | 128 | 4 | swin_4h_128_4_ds | swin_4h_128_4_upsample |
| 8h | 256 | 8 | swin_8h_256_8_ds | swin_8h_256_8_upsample |
- 通道逐级翻倍 32→64→128→256,窗口逐级变大 1→2→4→8
- `_ds` = downsample(编码器下行),`_upsample` = 解码器上行,镜像对称

**bottleneck(最深处):**
- `cc_vit_attention`(标准全局 ViT attention,不分窗)
- `cc_dec_input_upsample_1024_512`(从 1024 通道开始往回上采样)
- 1024 通道是最深瓶颈(比 256 还深一级,可能是 8h 后再降一次)

**其他零件:**
- `inpview`/`outview` = 窗口视图进出重排
- `BSUpsampleSkip` = U-Net skip 连接(解码器接回编码器同级特征)
- `BSFusedConvBlock`/`BSGroupedConvBlock`/`FusedSubtiledConvBlock` = 卷积块(不是纯 Transformer,是卷积+Transformer 混合)
- `layer0.conv_weight`/`out_conv_weight` = 首尾卷积层
- 每个 kernel 有 `_fp8`/`_tilesync`/`_wait`/`_chained` 变体 = 性能优化

## 整体结构(可支持的结论)
```
输入(游戏画面 RGB+depth+mvec)
  → layer0 conv(入口卷积)
  → Swin enc: 32ch窗1 ↓ 64ch窗2 ↓ 128ch窗4 ↓ 256ch窗8
  → ViT bottleneck(1024ch,全局注意力,不分窗)
  → Swin dec: 上采样一路还原,每级 skip 接回编码器
  → out conv(出口卷积)
  → 输出(重绘画面)
```

## 不能支持的(别过断言,296教训)
- 精确层数、每级几个 block:符号看不全
- 完整连接图、每层精确宽度
- 训练配方、精确 FLOPs

## 297 叙事线索(待写)
- 钩子:大语言模型那个 Transformer,怎么跑去处理图像了
- 核心教学点:
  1. ViT = 把图切成小块(patch),每块当一个"词",用 attention
  2. Swin = 为什么图像不能像 LLM 那样全局 attention(像素太多,平方复杂度爆炸)→ 开窗口,只在窗内算 → shifted window 解决"窗之间不通信"
  3. U 形 = 为什么先压缩再还原(编码理解 + 解码重画)
  4. 卷积+Transformer 混合 = 各自擅长什么(卷积管局部纹理,attention 管全局关系)
- 落点:这套结构不是为了跑分,是为了在 16ms 内理解整帧+重画,每个设计都是被"实时"逼出来的
