【Agentic RL】几万道训练题，是谁出的？

━━━━━━━━━━━━━━━━━━━━

◆ 一个没被回答的问题

━━━━━━━━━━━━━━━━━━━━

282 期（ https://mp.weixin.qq.com/s/4aDzx6lxkVxTUSj8NnCSYA ）讲了半个月里的一件事：好几家把 agent 能力大幅提上去，明说基座没动，增益全来自后训练。其中智谱那篇博客里有一句话，当时我把它当结论抄了下来：

> 随着 agent 能力提升，**后训练扩展的困难，很大一部分从模型转移到了环境。**

环境这个词，说的是模型练本事的那个场子——给它一个任务，让它在里面动手，干完了自动判分。写代码就给它一个能跑测试的仓库，用工具就给它一批能调的接口。

这句话写完就过去了，但它其实什么都没解释。困难转移到环境上了，然后呢？

我昨晚想了想，觉得自己漏掉了一个更朴素的问题。

**agent 训练要的不是一道题，是几万道题。**

而且每一道都不是"问一句答一句"那种题，是一个能跑起来的场子：有初始状态，有一堆能调的工具，有个沙箱让模型折腾，干完之后还得有个东西能自动判出成没成。

这种东西，人写一个要多久？

我自己写过一点自动化脚本，凭感觉估：**认认真真写一个能自动判分的任务环境，一个熟练工程师大概要一天。** 几万个就是几万人天。而这半个月里，好几家都做出来了，还不止一个领域——写代码、跑终端、优化 GPU 算子、当个人助理，一个领域一大堆。

三个星期一个版本的节奏（Gemini 3.6 到 3.7 就隔了三周），中间还得留出训练和评测的时间。

**这个账，用人手是算不平的。**

所以我今天去翻了 Kimi K3 的技术报告。这份报告我们 264 期（ https://mp.weixin.qq.com/s/W6CUq0xrJP3MdPBXw56v4A ）精读过一次，但那次盯的是架构——三个门、遗忘旋钮、沙漏结构那些。后训练那一章当时整个跳过了。

翻开一看，第 4 章第 2 节整整七个小节，标题就叫《RL 任务合成与 agent 环境》。

**题不是人出的。**

◆ 先建立一点印象：一道 agent 训练题长什么样

━━━━━━━━━━━━━━━━━━━━

在说"怎么批量造"之前，得先对"造的是什么"有个印象，不然后面全是空的。

拿最好懂的一类举例：**修 bug**。

你想训模型修 bug，光有"这段代码有问题，请修好"这句话是没用的——模型改完了，谁来判断改对没有？这一步没有答案，整个强化学习就转不起来。261 期（ https://mp.weixin.qq.com/s/nLFv6m-ONkXd7frHevgPOQ ）里说过，reward 是这条流水线上唯一从外部世界进来的信息，它必须能被机器自动核对。

所以一道能拿来训练的修 bug 题，大致得凑齐这么几样东西：一个装好依赖能跑起来的代码仓库（模型进去的时候看到的初始状态）、一组它能用的动作（读文件、改文件、跑测试、跑命令）、一个装着这一切的沙箱（让它随便折腾且互不干扰），还有一个终点判据——**测试从红变绿，就算成了。**

最后那条是关键。**测试套件就是判分器**，它不需要人来看，跑一遍返回 0 或者非 0，reward 就出来了。

那这样一道题从哪儿来？最省事的办法是去现实里捞：GitHub 上有的是"某个提交修好了某个 bug"的历史记录。把时间倒回修复之前那一刻，代码库是坏的，测试是红的；那次提交改了什么，就是标准答案；测试变绿，就是判据。**一道题就这么现成地躺在版本历史里。**

反过来还有一招更狠的：**拿一个好好的仓库，故意把它弄坏。** 挑一个能跑通的项目，让程序自动往里注入一处改动——改个边界条件、删个判断分支、把某个变量名换掉——跑一遍测试，只要原本绿的变红了，一道 bug 题就出生了。而且它天生自带标准答案：把注入的那处改回去就行。这种做法能把一个仓库变成成百上千道题。

**这就是第一个让人有点惊讶的地方：题目可以是被"制造"出来的，不是被"想"出来的。**

不过先别急着高兴。这条路好走，是因为**代码这个领域运气特别好**——它自带一个不需要人参与的判分器（测试跑不跑得过），还自带一座现成的题库（全世界程序员几十年的提交历史）。

换个领域试试看：训模型做投行分析、做法务、当个人助理，去哪儿找几万个"自带标准答案的真实任务"？

**没有。得自己造。**

━━━━━━━━━━━━━━━━━━━━

◆ 第一条路：现实里本来就有的，直接搬

━━━━━━━━━━━━━━━━━━━━

先说 K3 里最像"捡现成"的一类：**GPU 算子优化**。

报告里说，他们做了一大批 kernel 任务，从单个算子一直到融合起来的大 kernel，素材直接取自 GitHub 上的高质量仓库——报告点名了 Flash Linear Attention 这个项目。覆盖的写法有 CUDA、Triton、CuTe DSL、Gluon、ThunderKittens、TileLang，硬件和精度覆盖 BF16、FP8、FP4。

判分怎么办？这里有个很利索的设计。**每个 kernel 都自带一份 PyTorch 的参考实现**——PyTorch 那版慢，但结果是对的。于是：

- 先验对错：模型写的 kernel 跑出来，和 PyTorch 参考实现比数值，**误差超过阈值，直接零分**，跑得再快也没用；
- 再验快慢：跟一份专家实现比，**追平专家给 0.5 分**，越接近硬件理论上限（roofline），分数越往 1 靠。

这个 reward 是有刻度的，不是简单的对错两档。而且全程不需要人看一眼——**参考实现给正确性，秒表给性能，两个都是机器能读的。**

**为什么这条路特别顺？因为"什么叫做对了"在这个领域里本来就有定义。**

算子有参考实现，bug 有测试用例，数学题有标准答案。这些领域幸运在：人类早就为了别的目的，把判分这件事自动化了。做 agent 训练的人只是把这套现成的东西接了过来。

**但绝大多数活不是这样的。**

━━━━━━━━━━━━━━━━━━━━

◆ 第二条路：让模型自己长一张知识图谱，再从图谱里出题

━━━━━━━━━━━━━━━━━━━━

这是我今天看到最有意思的一段，也是这篇文章真正想讲的东西。

K3 报告的出发点是一句挺朴素的话：

> 后训练任务的质量和多样性，**在很大程度上由它们的素材来源决定。**

意思是，想造出好题，关键不在出题那一下，在**你手里有什么素材**。素材要是从几个热门话题里翻来覆去找，造出来的几万道题会长得一模一样；素材要是够细够杂，题目自然就散得开。

所以他们没有直接去造题，而是先造了一个**索引**——一张能不断自己长大的知识图谱，专门用来回答"该去找什么素材"。

**这张图是模型自己长出来的。**

报告里描述的过程是这样的（我按自己的理解复述）：

**第一步，先撒一把粗粒度的种子节点。** 就是一批很大的概念，比如"分布式系统"、"税务"这种级别的。

**第二步，给每个节点派一个 agent。** 这个 agent 的活儿是：上网搜，把这个概念研究一遍，看看它下面还能分出哪些更细的东西。

**第三步，加新节点之前，先去已有的图里翻一遍。** 这一步是我觉得整套设计里最见功夫的地方——agent 得先看看图里有没有等价的或者相近的概念，**能复用就复用，尽量别重复造**。几百个 agent 同时在图上撒野，没有这一步，图很快就会长满同义词。

**第四步，边永远从粗指向细。** 不管 agent 先发现的是哪一头，连线的方向都是从大概念指向小概念，整张图是一个有向无环图。

**第五步，新加进来的节点，再派新的 agent 去展开。** 一层套一层地递归下去。

**第六步，什么时候停？报告的说法是：当负责这个节点的 agent 认为，当前这个概念已经足够"原子"了，这条枝就不再往下长。**

这句话我看了两遍。**没有人规定图该有几层，也没有人列出该收录哪些概念。停在哪儿，是 agent 自己判断的。**

图长起来之后，出题就成了一件采样的活儿：

按照想要的领域分布和题型分布，**从图里挑节点**——可以挑一个，也可以挑几个相关的凑一块儿（挑几个不相关的凑一块儿，出来的就是跨领域的题）。挑完之后，用这些节点的关键词，**再加上它们在图里的祖先节点作为上下文**，拼成搜索词去网上捞真实材料。材料捞回来，交给一个负责合成的 agent，产出具体的训练任务。

这里有两个旋钮，报告说得很明白：**挑得细，就能捞到冷门的、平时没人写的专门知识；挑得散，覆盖面就宽。** 想要什么样的题目分布，调采样策略就行——人管的是分布，不是题目本身。

**我看完这段的第一反应是：这不是自动出题，这是自动建了一个学科体系，然后按学科体系出题。**

而且整条链上，从"这个领域下面有哪些子领域"，到"去搜什么关键词"，到"拿这份材料能出一道什么题"，全都是 agent 在做。

━━━━━━━━━━━━━━━━━━━━

◆ 第三条路：连题目所在的那个世界，一起造出来

━━━━━━━━━━━━━━━━━━━━

上面两条路，题目本身是新的，但场子多少是现成的——代码仓库是现成的，GPU 是现成的。

**那要是场子也不现成呢？**

比如你想训模型当个人助理，去处理真实的职场活儿：人力、法务、财务那些。这活儿的场子是什么？是 Gmail、是 Notion、是 Slack、是 Canvas。总不能真去连这些公司的接口——有速率限制，有账号成本，还没法复现（同一道题跑一千遍，收件箱早就不是原来那个了）。

K3 的做法是，**把这些应用重做一遍**：做出 Gmail、Notion、Slack、Canvas 的仿真版本，保留核心的行为逻辑，但完全跑在自己这边，可以随便重置、随便并发。

这一步还算好理解。真正让我停下来的是下一句——

> 初始工作区，是由 agent 自主上网搜集参考材料，再把这些材料转化成一个连贯的、与任务相关的环境。

**连"这个模拟员工的收件箱里原本该有什么邮件"，都是 agent 自己上网找资料编出来的。**

不是人手写一批假邮件当测试数据，是 agent 去看真实世界里这类工作长什么样，然后布置出一个说得通的工作现场。

场子搭好之后，任务跑起来是这样的：agent 在一个**持续演化**的环境里干活，跨越多个模拟出来的"天"，期间会遇到几十个分散在各个应用里、彼此还互相牵连的事件。报告里给的量级是：**单条轨迹可能涉及上千次工具调用、上百万 token 的上下文。**

每个事件自带自己的判据，有的用确定性的规则判，有的交给模型来判。

**读到这儿，"环境"这个词的分量才对上。**

它不是一道题目，是一个持续了好些天、事情一件接一件发生的工作现场。而这个现场是被生产出来的。

━━━━━━━━━━━━━━━━━━━━

💡 那人还在干什么

━━━━━━━━━━━━━━━━━━━━

看到这里容易生出一个印象：人已经完全不用管了。不是的。

K3 报告里，SFT 阶段的数据明说走的是"多阶段验证 + 人工介入标注"；调节推理长度那个旋钮，报告写的是"按领域配置，人工在环引导"。

智谱那边说得更直接，上文 282 期引过一句：这套流水线**"仍然需要相当数量的人在环工作，让环境生成和验证变得更自主是接下来的方向之一。"**

所以现在的状态不是无人化，是**人的位置往上挪了一层**：以前人写题目，现在人定分布、定难度、抽查、兜底。造题这个动作本身交出去了。

━━━━━━━━━━━━━━━━━━━━

◆ 为什么偏偏是现在

━━━━━━━━━━━━━━━━━━━━

把这三条路摆在一起看，有个共同点：**它们全都需要一个已经挺能干的 agent。**

要长知识图谱，得有个 agent 会上网搜、会判断两个概念是不是一回事、会决定什么时候停；要造仿真工作区，得有个 agent 能查资料、能把资料组织成一个自洽的场景；要出题，得有个 agent 能读懂材料、能设计出一道有难度又能判分的任务。

**造一个长程 agent 训练环境，这件事本身就是一个长程 agent 任务。**

这条路要能走通，前提是手里已经有一台足够强的 agent 模型，强到可以派它去干"给下一代模型出题"这件活。

如果这个说法成立，那半个月里好几家同时发力这件事，就有了一个解释：**不是谁突然想通了什么，是大家手里的上一代模型，差不多同时跨过了那条线。**

三个星期一个版本的节奏，只有在出题不再需要人的时候，才可能。

**这一段是我自己的推测，不是哪家的官方说法，姑且当个猜想。**

它至少是可以被证伪的：如果真是这样，那涨分应该主要出现在**能自动出题、又能自动判分**的领域——写代码、跑终端、优化算子；而在那些没法自动判分的领域（写作、开放式问答），涨幅应该明显要小。这个我手上的数据还不够，验不了。

━━━━━━━━━━━━━━━━━━━━

◆ 不是一家在这么干

━━━━━━━━━━━━━━━━━━━━

写到这儿得补一句，免得给人一个印象说这是 Kimi 独有的路数。

上文 282 期引过智谱那段博客，当时我只当它是"环境变重要了"的注脚，今天回头再读，才看清它讲的是同一件事：

> 为了把这个过程扩展开，我们构建了**端到端合成环境**的流水线，对一部分任务，**连 RL 的奖励信号也一起合成**。研究型 agent 从真实工作中收集任务模式，把它们变成可运行的长程环境，带多步依赖和隐藏状态；**再由一个裁判 agent 亲自去做一遍这道题，确认它真的做得出来。**

两家的具体做法并不一样。K3 是先长知识图谱、再采样检索素材、然后合成任务；智谱是从真实工作里提取任务模式、造成环境、再派一个 agent 试做一遍验证可解性。

**但方向是同一个：让 agent 去生产训练 agent 所需要的东西。**

两边都没提对方，时间上也咬得很紧（K3 是七月底，GLM-5.3 是八月中）。与其说谁学了谁，不如说这条路现在已经是明面上的共识了。

那句"困难从模型转移到了环境"，写 282 期时读着像一句总结。今天再看，它更像一句战报——**难关是真的转移了，而且已经被翻过去一轮了。**

━━━━━━━━━━━━━━━━━━━━

◆ 留到后面的账

━━━━━━━━━━━━━━━━━━━━

这一期只讲了"题从哪来"。摊开之后，底下还压着几个更麻烦的问题，都够单独写一期的：

**题是模型出的，那判分器也是模型造的，谁来保证它判得对？** 261 期最后落在一句话上——被测到的 reward 和你真正想要的东西之间只要有缝隙，就一定会被优化器找到并放大。当出题和判分都自动化之后，这条缝也跟着自动化了。K3 报告里为此专门做了一套作弊检测系统，而且明说是**边训练边往里加新规则**的。这个下次说。

**训练用的那个"壳子"要是固定的，模型会不会只学会用那一套工具？** K3 在这上面的做法挺出乎我意料，跟大家天天在用的那几个 agent 工具直接相关，单独讲。

**几万条轨迹、每条上百万 token，训练本身怎么跑得动？** 这是另一条线了。

慢慢来，一次说一件。
