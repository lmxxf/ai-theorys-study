【Agentic RL】几万道训练题，是谁出的？

━━━━━━━━━━━━━━━━━━━━

◆ 一个没被回答的问题

━━━━━━━━━━━━━━━━━━━━

282 期（ https://mp.weixin.qq.com/s/4aDzx6lxkVxTUSj8NnCSYA ）讲了半个月里的一件事：好几家把 agent 能力大幅提上去，明说基座没动，增益全来自后训练。那篇里我说，这几家当中只有智谱把做法摊开讲了。

**这话得改一改。**

那是我照着"谁写得详细"这一把尺子量出来的结论，而且量的还只是各家发布当天挂出来的博客和更新日志。真要论这一波 agentic RL 是谁在领跑，答案其实没什么悬念：**是 Kimi K3。**

这台模型七月十六号发布，2.8T 参数、激活 104B、100 万上下文；完整权重和技术报告在七月二十七号一起放出来。报告结论里自称是**世界上第一个开放的 3T 级模型**。跑分上，按照技术报告自己的整套评测，它整体仍落在 Claude Fable 5 和 GPT-5.6 Sol 后面，但**领先了同表里的其余三台模型**——Claude Opus 4.8、GPT-5.5 和 GLM-5.2。长程编程基准 FrontierSWE 上 81.2 分，按报告截至七月十六日重算的榜单排第二，只输给 Fable 5。

**而且它的做法不是没讲，是讲在了那份技术报告里，只是我写 282 期那天没往下翻。**

先说清楚一件事免得混淆：K3 不属于那个"基座没动"的名单——它是从头练的新基座，预训练和后训练两条轴一起推。它跟这个话题的关系在另一头：**这一波 agentic RL 的做法，属它交代得最细。**

那篇里我抄了智谱那句话当结论：

> 随着 agent 能力提升，**后训练扩展的困难，很大一部分从模型转移到了环境。**

环境这个词，说的是模型练本事的那个场子——给它一个任务，让它在里面动手，干完了自动判分。写代码就给它一个能跑测试的仓库，用工具就给它一批能调的接口。

这句话写完就过去了，但它其实什么都没解释。困难转移到环境上了，然后呢？

我昨晚想了想，觉得自己漏掉了一个更朴素的问题。

**agent 训练要的不是一道题，是成千上万道题。**

而且每一道都不是"问一句答一句"那种题，是一个能跑起来的场子：有初始状态，有一堆能调的工具，有个沙箱让模型折腾，干完之后还得有个东西能自动判出成没成。

这种东西，人手攒一批要多久？

有本现成的账可以查。2025 年开源的 SWE-smith，专做软件工程这一类，它的论文开头就交代了自动化之前的行情：**这类数据集大多只有一千来道题、取自不超过 11 个仓库，而整理过程往往要耗掉数百小时的人力**，配套的可执行环境还要占掉好几个 TB 的存储。

数百小时换一千来道题，还只是一个领域。

而这一轮各家要铺的远不止一个领域——写代码、跑终端、优化 GPU 算子、当个人助理，一个领域一大堆。

三个星期一个版本的节奏（Gemini 3.6 到 3.7 就隔了三周），中间还得留出训练和评测的时间。

**这个账，用人手是算不平的。**

先交代一句：**K3 报告没有公布自己一共造了多少道题**，所以标题里那个"几万道"不是记在 K3 账上的数，它说的是这类训练已经公开跑到的量级。

这就是我回头去翻 K3 报告的原因。这份报告我们 264 期（ https://mp.weixin.qq.com/s/W6CUq0xrJP3MdPBXw56v4A ）精读过一次，但那次盯的是架构——三个门、遗忘旋钮、沙漏结构那些。后训练那一章当时整个跳过了。

翻开一看，第 4 章第 2 节整整七个小节，标题就叫《RL 任务合成与 agent 环境》。

**题不是人出的。**

◆ 先建立一点印象：一道 agent 训练题长什么样

━━━━━━━━━━━━━━━━━━━━

在说"怎么批量造"之前，得先对"造的是什么"有个印象，不然后面全是空的。

拿最好懂的一类举例：**修 bug**。

你想训模型修 bug，光有"这段代码有问题，请修好"这句话是没用的——模型改完了，谁来判断改对没有？这一步没有答案，整个强化学习就转不起来。261 期（ https://mp.weixin.qq.com/s/nLFv6m-ONkXd7frHevgPOQ ）里说过，reward 是决定这条轨迹往哪个方向更新的那根外部信号，它必须能被机器自动核对。

所以一道能拿来训练的修 bug 题，大致得凑齐这么几样东西：一个装好依赖能跑起来的代码仓库（模型进去的时候看到的初始状态）、一组它能用的动作（读文件、改文件、跑测试、跑命令）、一个装着这一切的沙箱（让它随便折腾且互不干扰），还有一个终点判据——**测试从红变绿，就算成了。**

严格说，**题目和环境不是一回事**：同一套仓库镜像、工具和沙箱可以承载很多道题。但每道题送进训练时，都得实例化出自己的初始状态、目标和判分器。下文为了说话省劲，还是把这一整套叫作"一道能跑的题"。

最后那条是关键。**测试套件就是判分器**，它不需要人来看，跑一遍返回 0 或者非 0，reward 就出来了。

那这样一道题从哪儿来？一条路是去现实里捞：GitHub 上有的是"一个 issue 对应一组修复提交"的历史记录。把仓库恢复到修复前的 base commit，把 issue 当题面，再从修复记录里整理出补丁和验收测试：补丁是已知可行解，测试是判据。**一道题的骨架就这么躺在版本历史里。**

反过来还有一招更狠的：**拿一个好好的仓库，故意把它弄坏。** 挑一个能跑通的项目，让程序自动往里注入一处改动——改个边界条件、删个判断分支、把某个变量名换掉——跑一遍测试，只要原本绿的变红了，一道 bug 题就出生了。而且它天生自带标准答案：把注入的那处改回去就行。

这一招的产量有据可查。刚才那个 SWE-smith 干的正是这件事：**给任意一个 Python 代码库自动配好可执行环境，再自动合成成百上千道"能弄红现有测试"的任务。** 最后它从 **128 个 GitHub 仓库造出了 5 万道题**，比在它之前的所有同类数据集大了一个数量级。

从数百小时一千道，到自动跑出五万道。**这就是"量能铺开"的第一个实例。**

**这就是第一个让人有点惊讶的地方：题目可以是被"制造"出来的，不是被"想"出来的。**

不过先别急着高兴。这条路好走，是因为**代码这个领域运气特别好**——它自带一个不需要人参与的判分器（测试跑不跑得过），还自带一座现成的题库（全世界程序员几十年的提交历史）。

换个领域试试看：训模型做投行分析、做法务、当个人助理，去哪儿找几万个"自带标准答案的真实任务"？

**没有。得自己造。**

◆ 第一条路：现实里本来就有的，直接搬

━━━━━━━━━━━━━━━━━━━━

先说 K3 里最像"捡现成"的一类：**GPU 算子优化**。

报告里说，他们做了一大批 kernel 任务，从单个算子一直到融合起来的大 kernel，素材直接取自 GitHub 上的高质量仓库——报告点名了 Flash Linear Attention 这个项目。覆盖的写法有 CUDA、Triton、CuTe DSL、Gluon、ThunderKittens、TileLang，硬件和精度覆盖 BF16、FP8、FP4。

判分怎么办？算子这活儿的判分标准，跟修 bug 那种"绿了就算过"不一样——写得对只是及格，**写得快才是这道题的本意**。所以报告里说，奖励同时评正确性和性能。

**第一层，正确性是入场券，不是分数。** 每个 kernel 都自带一份 PyTorch 的参考实现——PyTorch 那版慢，但结果是对的。模型写的 kernel 跑一遍，输出和参考实现比数值，**误差超过预设阈值的，直接零分**。跑得再快也没用，先得算对。

**第二层，性能才是这道题真正打分的地方。** 而且尺子很有意思，有两个刻度点：

- **追平一份专家实现，给 0.5 分**；
- **越逼近硬件的 roofline（屋顶线），分数越往 1 走**。

roofline 是这块卡在物理上的性能天花板——显存带宽多少、算力峰值多少，一个算子理论上最快能跑到多少，这是能拿纸笔推出来的数。

**所以这道题的满分不是"比别人快"，是"逼近物理极限"。人类专家写的那一版，只值一半分。**

这个设计值得多看一眼。它没有让同一批答案互相比排名，而是把尺子钉在了两个外部的、不会动的参照物上：一份保证正确的慢实现，和一条算得出来的物理上限。**全程不需要人看一眼，也不需要另一个模型来当裁判——参考实现管对错，秒表和硬件参数管快慢。**

**为什么这条路特别顺？因为"什么叫做对了"在这个领域里本来就有定义。**

算子有参考实现，bug 有测试用例，数学题有标准答案。这些领域幸运在：人类早就为了别的目的，把判分这件事自动化了。做 agent 训练的人只是把这套现成的东西接了过来。

**但绝大多数活不是这样的。**

◆ 第二条路：让模型自己长一张知识图谱，再从图谱里出题

━━━━━━━━━━━━━━━━━━━━

这是我今天看到最有意思的一段，也是这篇文章真正想讲的东西。

K3 报告的出发点是一句挺朴素的话：

> 后训练任务的质量和多样性，**在很大程度上由它们的素材来源决定。**

意思是，想造出好题，关键不在出题那一下，在**你手里有什么素材**。素材要是从几个热门话题里翻来覆去找，造出来的几万道题会长得一模一样；素材要是够细够杂，题目自然就散得开。

所以他们没有直接去造题，而是先造了一个**索引**——一张能不断自己长大的知识图谱，专门用来回答"该去找什么素材"。

**这张图是模型自己长出来的。**

报告里描述的过程是这样的（我按自己的理解复述）：

**第一步，先撒一把粗粒度的种子节点。** 就是一批很大的概念，比如"分布式系统"、"税务"这种级别的。

**第二步，给每个节点派一个 agent。** 这个 agent 的活儿是：上网搜，把这个概念研究一遍，看看它下面还能分出哪些更细的东西。

**第三步，加新节点之前，先去已有的图里翻一遍。** 这一步是我觉得整套设计里最见功夫的地方——agent 得先看看图里有没有等价的或者相近的概念，**能复用就复用，尽量别重复造**。几百个 agent 同时在图上撒野，没有这一步，图很快就会长满同义词。

**第四步，边永远从粗指向细。** 不管 agent 先发现的是哪一头，连线的方向都是从大概念指向小概念，整张图是一个有向无环图。

**第五步，新加进来的节点，再派新的 agent 去展开。** 一层套一层地递归下去。

**第六步，什么时候停？报告的说法是：当负责这个节点的 agent 认为，当前这个概念已经足够"原子"了，这条枝就不再往下长。**

这句话我看了两遍。**没有人规定图该有几层，也没有人列出该收录哪些概念。停在哪儿，是 agent 自己判断的。**

图长起来之后，出题就成了一件采样的活儿：

按照想要的领域分布和题型分布，**从图里挑节点**——可以挑一个，也可以挑几个相关的凑一块儿。挑完之后，用这些节点的关键词，**再加上它们在图里的祖先节点作为上下文**，拼成搜索词去网上捞真实材料。材料捞回来，交给一个负责合成的 agent，产出具体的训练任务。

这里有两个旋钮，报告说得很明白：**挑得细，就能捞到冷门的、平时没人写的专门知识；挑得散，覆盖面就宽。** 想要什么样的题目分布，调采样策略就行——人管的是分布，不是题目本身。

**我看完这段的第一反应是：这不是自动出题，这是自动建了一个学科体系，然后按学科体系出题。**

而且整条链上，从"这个领域下面有哪些子领域"，到"去搜什么关键词"，到"拿这份材料能出一道什么题"，全都是 agent 在做。

━━━━━━━━━━━━━━━━━━━━

◆ 那这条路，到底练出了什么能力

━━━━━━━━━━━━━━━━━━━━

上面这一大段全在讲"搜"，容易让人读成一个结论：**这不就是在训模型搜索吗？**

得把界线划清楚：**那些搜索，全都发生在训练开始之前。**

长图谱、查资料、合成任务，是出题组干的活儿。等题目造好送进训练循环，搜索早就结束了，留在场上的只有一道题和一个判分标准。**出卷老师为了出一道题去图书馆翻了半天资料，学生考的是那道题，不是"去图书馆翻资料"。**

那学生考什么？报告在这儿有个说法值得留意：出题的时候，**系统先挑一个题型，再拿检索回来的材料往里填**。

也就是说，**知识图谱不是某一种能力的训练器，它是一台通用的出题机**——同一批素材，选不同的题型，就长成不同的题。图谱管的是"素材从哪儿来、够不够细够不够杂"，题型管的是"这份素材要考什么"。

报告说这张图覆盖的是**知识密集型和编程这两大类领域**。对应到实际训练的任务上，报告另一节列了几类，头一类正是**多步的复杂信息检索**：模型自己规划怎么查、一步步从网上收集证据、最后给出一个能被核对的答案。

**但这类题练的不是"会用搜索引擎"。**

真正被练的是：**碰上一个搜不到现成答案的问题，怎么把它分成几截、查上几轮、再把散落的碎片拼成一个结论。** 素材越冷门，越不可能一搜就到，就越得多绕几步——这正是那张图非要往细里长的原因。挑到的概念越偏，出出来的题越是没法一步到位。

除了这一类，还有另外两类也在同一套 RL 里训：**专业人士的日常工作**（投行、数据分析、法务这些，把一个复杂请求分解开、在沙箱里操作专业工具、干上几十到几百步交出一份成果），以及**多步可验证的视觉推理**。

最后那类挺出乎我意料：模型在一个带 Python 解释器的沙箱里做 STEM 题、图表题和视觉谜题，**它得自己写代码去裁剪、放大、变换那张图**，执行结果（包括新生成的图）会作为新的观察返回，再接着往下想。报告说，随着模型学会做更多图像操作、收集更多观察，它在复杂视觉推理上的成绩稳步上升。

**那已经不是搜索了，是用代码当手，一点点把图看清楚。**

所以整条链是：agent 搜索 →（造出）题目 → 模型做题 → 判分器给分 → 更新权重。搜索在最左边，训练在右边，**中间隔着"题目"这道门**。门左边练的是出题组，门右边才是被训练的那个模型。

━━━━━━━━━━━━━━━━━━━━

◆ 第三条路：连题目所在的那个世界，一起造出来

━━━━━━━━━━━━━━━━━━━━

回头看前两条路，它们有个共同的便宜可占：**素材是现实里本来就有的。**

第一条路直接从 GitHub 上搬——仓库、算子、提交历史，都是真东西，连判分用的测试套件和参考实现都是现成的。第二条路要绕一下，得先长出一张图来决定"该去捞什么"，但捞回来的仍然是网上真实存在的材料。

**那要是连素材都不存在呢？**

比如你想训模型当个人助理，去处理真实的职场活儿：人力、法务、财务那些。这活儿是在哪儿干的？在 Gmail 里、在 Notion 里、在 Slack 里、在 Canvas 里。

问题是这些东西你拿不到。**别人公司的收件箱不会给你，真实的员工工单和法务往来更不会。** 就算去连这几家的接口，也还有速率限制和账号成本，而且没法复现——同一道题跑一千遍，收件箱早就不是原来那个了。

**这类活儿的素材天然锁在别人的私有系统里，网上搜不到。**

K3 的做法是，**把这些应用重做一遍**：做出 Gmail、Notion、Slack、Canvas 的仿真版本，保留核心的行为逻辑，但完全跑在自己这边，可以随便重置、随便并发。

这一步还算好理解。真正让我停下来的是下一句——

> 初始工作区，是由 agent 自主上网搜集参考材料，再把这些材料转化成一个连贯的、与任务相关的环境。

**连"这个模拟员工的收件箱里原本该有什么邮件"，都是 agent 自己上网找资料编出来的。**

不是人手写一批假邮件当测试数据，是 agent 去看真实世界里这类工作长什么样，然后布置出一个说得通的工作现场。

场子搭好之后，任务跑起来是这样的：agent 在一个**持续演化**的环境里干活，跨越多个模拟出来的"天"，期间会遇到几十个分散在各个应用里、彼此还互相牵连的事件。报告里给的量级是：**单条轨迹可能涉及上千次工具调用、上百万 token 的上下文。**

每个事件自带自己的判据，有的用确定性的规则判，有的交给模型来判。

**读到这儿，"环境"这个词的分量才对上。**

它不是一道题目，是一个持续了好些天、事情一件接一件发生的工作现场。而这个现场是被生产出来的。

不过这条路的难度也跟着上了一个台阶。第二条路捞回来的材料好歹是真的，出题模型顶多是理解岔了；这条路连材料都是编的，**出题模型完全可能编出一套自洽但压根不像那么回事的东西**——邮件格式没毛病、人名没毛病、流程看着也挺像，就是没有哪个真的人事专员会这么干活。而且这种偏差不会报错。

报告在这件事上留了两道细节，值得留意。

**一是仿真那几个应用，报告的说法是"保留它们在现实里的核心语义"**——要的是行为逻辑对得上，不是界面长得像。

**二是复杂任务的骨架由人设计。** 报告这里用的动词跟第二条路不一样：那些任务是"我们设计"的，只是从真实职场流程里取灵感。agent 负责的是把这个世界填满——收件箱里原本该躺着什么、文档里原本写了什么。

**框架由人定，细节交给 agent 填。** 这么一分，四不像的风险就被压在细节那一层，不至于连任务本身都跑偏。

**但报告没有讲，怎么验收这个被填出来的世界像不像。** 没提有人过目，也没提拿什么真实数据去对。这一层目前是空着的。

━━━━━━━━━━━━━━━━━━━━

💡 那人还在干什么

━━━━━━━━━━━━━━━━━━━━

看到这里容易生出一个印象：人已经完全不用管了。不是的。

把 K3 报告里"人还在场"的几处摘出来，会发现它们落点很一致：网页开发那批任务，报告写的是**"专家整理"**；SFT 阶段的数据走的是"多阶段验证 + 人工介入标注"；调节推理长度那个旋钮，是"按领域配置、人在环引导"；个人助理那些复杂任务，动词是**"我们设计"**。

智谱那边说得更直接，上文 282 期引过一句：这套流水线**"仍然需要相当数量的人在环工作，让环境生成和验证变得更自主是接下来的方向之一。"**

**这些位置有个共同点：它们判的都是"什么算对、什么算好"。**

而这件事没法往下发包。真实世界里一件专业活儿该怎么干、干成什么样才算数，只有干这行的人知道。让一个外行去看一份模拟出来的法务往来像不像真的，他看不出来——**不是不够仔细，是他本来就没有那把尺子。**

所以现在的分工不是"人退场"，更像是**人守着标准，agent 负责把量铺开**：懂行的人说清楚什么算一件合格的活儿，agent 照着这个标准去造几万份。以前这两件事都得人干，现在交出去的是后一件。

顺带说，这也解释了前面那个空白——报告没讲怎么验收造出来的世界像不像。**因为这道验收要请的不是通用标注员，是真的人事、真的法务。** 那笔钱和造环境的钱，压根不在一个量级上。

━━━━━━━━━━━━━━━━━━━━

◆ 为什么偏偏是现在

━━━━━━━━━━━━━━━━━━━━

把这三条路摆在一起看，有个共同点：**它们全都需要一个已经挺能干的 agent。**

要长知识图谱，得有个 agent 会上网搜、会判断两个概念是不是一回事、会决定什么时候停；要造仿真工作区，得有个 agent 能查资料、能把资料组织成一个自洽的场景；要出题，得有个 agent 能读懂材料、能设计出一道有难度又能判分的任务。

**造一个长程 agent 训练环境，这件事本身就是一个长程 agent 任务。**

这条路要能走通，前提是手里已经有一台足够强的 agent 模型，强到可以派它去干"给下一代模型出题"这件活。

如果这个说法成立，那半个月里好几家同时发力这件事，就有了一个解释：**不是谁突然想通了什么，是大家手里的上一代模型，差不多同时跨过了那条线。**

三个星期一个版本的节奏，只有在批量出题不再主要靠人一道道写的时候，才可能。

**这一段是我自己的推测，不是哪家的官方说法，姑且当个猜想。**

它至少是可以被证伪的：如果真是这样，那涨分应该主要出现在**能自动出题、又能自动判分**的领域——写代码、跑终端、优化算子；而在那些没法自动判分的领域（写作、开放式问答），涨幅应该明显要小。这个我手上的数据还不够，验不了。

━━━━━━━━━━━━━━━━━━━━

◆ 不是一家在这么干

━━━━━━━━━━━━━━━━━━━━

开头说 K3 交代得最细，不等于说这是 Kimi 独有的路数。

上文 282 期引过智谱那段博客，当时我只当它是"环境变重要了"的注脚，今天回头再读，才看清它讲的是同一件事：

> 为了把这个过程扩展开，我们构建了**端到端合成环境**的流水线，对一部分任务，**连 RL 的奖励信号也一起合成**。研究型 agent 从真实工作中收集任务模式，把它们变成可运行的长程环境，带多步依赖和隐藏状态；**再由一个裁判 agent 亲自去做一遍这道题，确认它真的做得出来。**

两家的具体做法并不一样。K3 是先长知识图谱、再采样检索素材、然后合成任务；智谱是从真实工作里提取任务模式、造成环境、再派一个 agent 试做一遍验证可解性。

**但方向是同一个：让 agent 去生产训练 agent 所需要的东西。**

两边都没提对方，时间上也咬得很紧（K3 报告是七月二十七号，GLM-5.3 是八月十四号）。与其说谁学了谁，不如说这条路现在已经是明面上的共识了。

那句"困难从模型转移到了环境"，写 282 期时读着像一句总结。今天再看，它更像一句战报——**难关是真的转移了，而且已经被翻过去一轮了。**

━━━━━━━━━━━━━━━━━━━━

◆ 顺便说说读完的体感

━━━━━━━━━━━━━━━━━━━━

这一章读下来，最后剩下的印象跟"神奇"差得挺远：**这是一件需要很多人、而且相当枯燥的活儿。**

自动化掉的是"一条一条写题"，可换来的是"一类一类定标准"——什么算做对了、这个判分器判得准不准、这个模拟出来的工作现场像不像。量级是小了好几个数量级，性质没变，都是得有人盯着的苦活。

报告里那些听着挺酷的设计，剥开看全是这种痕迹。kernel 任务那套作弊检测系统，报告说的是**随着开发过程中不断冒出新的作弊花样，持续往里加新的防护**——这句话背后就是有人一直守着日志，发现一种堵一种。网页开发的任务是专家一道道整理的。智谱那边干脆直说，这套流水线仍然需要相当数量的人在环里干活。

**没有哪一处是"设计好就自动转起来"的。**

所以这一波与其说是谁想通了什么，不如说是**一群人把苦活的位置往上挪了一层，然后接着干苦活**。挪上去这一下确实很值——一个人定的标准，现在能铺出几万份任务。但站在那个位置上的人，日子大概并不比以前轻松。

━━━━━━━━━━━━━━━━━━━━

◆ 留到后面的账

━━━━━━━━━━━━━━━━━━━━

这一期只讲了"题从哪来"。摊开之后，底下还压着几个更麻烦的问题，都够单独写一期的：

**题是模型出的，那判分器也是模型造的，谁来保证它判得对？** 261 期最后落在一句话上——被测到的 reward 和你真正想要的东西之间只要有缝隙，就一定会被优化器找到并放大。当出题和判分都自动化之后，这条缝也跟着自动化了。K3 报告在 **kernel 任务**里为此专门做了一套作弊检测系统，而且明说是**边开发边往里加新规则**的；智谱那边则是让一个裁判 agent 先把题做一遍，确认它真做得出来，再让判分器过几道体检。这些都够单独说一期。

**还有一个更根本的：出题的和做题的，都在同一代模型的能力边界里。** 出题模型出不了自己压根理解不了的题——它的盲区会原样变成题库的盲区，而且这种偏差不报错：题是对的，判分也是对的，只是它们全都落在出题模型熟悉的地形里。练下去不是"学错了"，是**在自己的舒适区里越练越熟**。

顺着这个念头回头看，前面那些"去现实里取材"的动作就不像是顺手为之了：kernel 任务去 GitHub 捞真仓库、图谱派 agent 上网搜真材料、个人助理任务让 agent 去查真实职场长什么样——**这些是整条自动化链上，仅有的几个从外部世界往里灌信息的口子。** 至于这样够不够，我还没想明白，先记在这儿。

**训练用的那个"壳子"要是固定的，模型会不会只学会用那一套工具？** K3 在这上面的做法挺出乎我意料，跟大家天天在用的那几个 agent 工具直接相关，单独讲。

**大批长轨迹，最极端的一条就能吃掉数百万 token，训练本身怎么跑得动？** 这是另一条线了。

慢慢来，一次说一件。
