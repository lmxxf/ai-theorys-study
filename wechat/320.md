【AI记忆】一件事一个 token：把对话记忆压成一条时间流

━━━━━━━━━━━━━━━━━━━━

◆ 开篇：从“压 KV”到“一件事一个 token”

━━━━━━━━━━━━━━━━━━━━

319 期（ https://mp.weixin.qq.com/s/so-08WsOgnQFmXkawoIhnw ）聊的是：编程工具一 `/compact` 压缩上下文，AI 就跑偏。文字摘要留下了名词，丢掉了坡度：哪条线死了、为什么死、现在往哪走。那期最后停在一个想法上：如果压的不是文字，而是模型内部的 KV，是不是能留住些什么。

第二天早上我接着想：记忆到底该怎么压？

感觉只要把两样东西压住就够了：**事实，和情绪。** 发生了什么，以及这件事对我有多重要。

那就让每个记忆 token 装一件事，事实和情绪都在里面。事情多，就多写几个 token；事情少，就少写几个。这些 token 按时间排成一串，**n 个 token，就是一条时间流。**

跟那期碰过的两个极端放在一起看：

```
RNN：          整段经历 → 1 个状态             # 时间被压没了
完整 KV：      每个字 → 1 个 token             # 时间都在，但太长
一件事一个 token：每件事 → 1 个（或几个）token   # 时间还在，长度随事情多少变
```

时间不用另外存。记忆 token 本身也是一串序列，第 k 个 token 的 KV 算出来的时候，前面 k−1 个都看得见。“证伪了 A 之后转向 B”这种先后，会长在 token 和 token 之间的关系里。位置编码也现成：记忆 token 排第几，就是时间轴上的第几。

这个想法分下来是四步：**怎么切** （哪儿算一件事）、**怎么压** （一件事怎么变成一个 token）、**怎么整理** （旧的怎么合并、怎么忘）、**怎么读** （新会话怎么把它们读回来）。再加一步：**怎么测**，拿什么判断它真的记住了方向。

我按这五步挨个去找，看前人已经做到了哪儿。结果是：零件差不多都有人做过，没人按“一件事一个 token、排成时间流”把它们拼起来，当成长期记忆来用。

━━━━━━━━━━━━━━━━━━━━

◆ 第一章：切——哪儿算一件事

━━━━━━━━━━━━━━━━━━━━

先说我们的想法。“一件事”没有固定长度：一上午可能只干了一件事，五分钟里也可能连着出了三件。所以切的时候不能按字数，得按“事情变了没有”。

事情变了，模型应该是能感觉到的：它本来预测接下来会怎样，结果不是那样。

────────────────────

**人就是这么切的。** 认知科学里有个事件分割理论（event segmentation theory）：人一边经历一边预测下一刻会发生什么，预测误差突然升高的地方，就被感知成一件事的结束、另一件事的开始。

**EM-LLM** （华为诺亚方舟实验室伦敦与伦敦大学学院，ICLR 2025）把这套搬到了大模型上。它给每个 token 算一个“意外程度”：

```
surprisal(t) = −log P( 第 t 个 token | 前文 )     # 这个词有多出乎意料
```

超过阈值就在这儿切开。阈值不是定死的：

```
T = μ + γ·σ      # μ、σ：前面一个滑动窗口里 surprisal 的均值和标准差
```

这个设计天然就是“事多切得密”：平淡的时候，一般的起伏越不过阈值；接连出事的时候，处处都是尖峰。切完之后，它还会用注意力 key 之间的相似度微调边界位置，让同一段里的 token 在注意力上更抱团。整个过程不训练。

────────────────────

💡 “意外”有两种，EM-LLM 用的那种可能不对

EM-LLM 的摘要里说自己用的是 Bayesian surprise，正文实际算的是上面那个 surprisal。这两个不是一回事：

```
surprisal(t)        = −log P( x_t | 前文到 t−1 )                      # 这个词本身意外不意外
Bayesian surprise(t) = KL( P(· | 前文到 t) ‖ P(· | 前文到 t−1) )        # 读完这个词，对“接下来”的预期变了多少
```

一个生僻词、一个陌生的变量名，surprisal 很高，但事情没变；一句“这条路不行，换个方向”，每个字都不生僻，预期却整个转了向。

EM-LLM 自己引用的那篇人类实验（Kumar 等，2023，发表在《认知科学》上，用 GPT-2 XL 做的）结论正好是：人感觉到的事件边界，跟 Bayesian surprise 相关，跟 surprisal 不相关。EM-LLM 转述这篇时，只说了“与预测误差相关”，没提后半句。

对“一件事”来说，后者更像我们要的那个信号。

────────────────────

**agent 场景还有更便宜的边界。** HiAgent（ACL 2025）让 agent 先声明一个子目标，一个子目标就是一个记忆块。放到我的 DLSS5 移植项目里，“换一个核来优化”“转去查算力缺口”“我插话纠正了一次”，本来就是天然的分界线，不用算什么意外程度。

**切分器也可以训练。** H-Net（2025）在字节层面做过“按信息量动态切块”：相邻两个位置的表示差得越远，越可能是边界，边界概率由模型自己学；另加一个损失，把平均块长拉向目标值。它切的是字节，平均四五个字节一块，跟“一件事”差了两三个数量级，还没人把它搬到事件粒度上。

所以“切”这一步：第一版用预测转向（两种意外都试）加 agent 的天然边界，设一个最长长度兜底；以后换成可训练的切分器，跟后面的压缩器一起训，让“切在哪儿”由“压完之后下一步还做得对”来决定。后半句是我的推断。

◆ 第二章：压——一件事变成一个 token

━━━━━━━━━━━━━━━━━━━━

我们的想法：切出来的每件事，挤进一个（或几个）不对应任何文字的 token。第 k 个 token 只管第 k 件事，想知道前情，去看前面那些 token，不要把前面的内容再装一遍。

上文 319 期讲过 Gist tokens：改一下注意力掩码，就能把一整段提示挤进一个 token。可 Gist 只压一次。我们要的是一件接一件地压、压出一串。

**这件事 CCM 做过。** Compressed Context Memory（首尔大学与 NAVER，ICLR 2024），在线把对话一段一段压进记忆：

```
[第 1 段原文] <COMP> [第 2 段原文] <COMP> [第 3 段原文] <COMP> …
                ↓                   ↓                   ↓
             记忆 1              记忆 2              记忆 3      # 每个 <COMP> 在各层的 KV 就是这段的记忆
```

关键在掩码：第 j 段的原文和它的 `<COMP>`，**只能看前面各段的记忆 token，看不到前面的原文**。所以模型想知道前情，只能透过记忆去看，被逼着把每一段的要点装进那个 `<COMP>` 里。这正是“n 个 token 就是一条时间流”。

它还有两个细节值得记下：训练一次前向就能把所有段并行算完；`<COMP>` 有自己的一小套 LoRA 参数，正文 token 还走原模型。效果上，MetaICL 任务里完整上下文准确率 70.8%、占 630MB，把记忆拼起来是 70.0%、178MB。每段用几个 `<COMP>` 影响不大，从 1 个加到 8 个只涨约 1%。

────────────────────

**事多多写，有人测过。** Activation Beacon（北京智源与人大，2024）训练时，每一块的压缩率都从 {2, 4, 8, 16, 32} 里随机抽。做过一个对照：改成每个样本抽一次、样本内所有块用同一个压缩率，LongBench 单文档问答从 40.5 掉到 37.7。块和块之间压缩率不一样，模型反而学得更好。

DAST（ACL 2025 Findings）更进一步：按困惑度和注意力，给信息多的块多分 token、少的少分，不用额外训练。长对话数据集上，压缩率从 4 倍加到约 16 倍，它的成绩掉 5.9%，均匀分配的 Beacon 掉 13.9%。

一个工程上的限制：每件事分几个 token，得取离散的档位（1、2、4、8 这种），有论文报告取连续值会训崩。

────────────────────

**训练目标，是这一步真正要想的地方。** 现成的有三种：

- **能复述原文**：自编码，要求从记忆 token 里把原文还原出来（上文 319 期提过的 ICAE）
- **能答一样的题**：蒸馏，老师读完整原文，学生只读记忆，让两者的输出分布对齐（Cartridges、KV-Distill）
- **能把任务做成**：按任务成败用强化学习训压缩器（上文 319 期提过的 Mem-W）

我们想要的是第四种：**下一步做的事，跟看了完整历史的模型一样。** 不考“那天测的数是多少”，考“知道这条线已经死了，所以不往那儿走”。落到损失上，就是蒸馏的 KL 只算在动作、工具调用、计划这些 token 上。

这个目标我没找到有人做过。最接近的是两块：KV-Distill 用“学生读压缩 KV、老师读完整 KV”做蒸馏，正向和反向两个方向的 KL 混着用，比只用一个方向明显好；另一篇在 agent 轨迹上对齐看全文的冻结模型，但压的是可复用的动作模板，不是具体发生过的事。

────────────────────

💡 每件事都算一次损失，就是每件事都考一次旧记忆

在 CCM 那种掩码下，第 k 件事只能透过前面的记忆 token 看过去。所以如果损失不只算最后一步，而是每件事都算，那第 k 件事每预测一次下一步，就是对前 k−1 个记忆 token 的一次考试：该记住的方向没装进去，这里就会答错。

这一个损失顺带逼出两件事：记忆要装方向，不装就做错下一步；第 k 个 token 也不必把前面重装一遍，前面的 token 本来就在那儿。

这个训练设计是我的推断，没人验证过。

────────────────────

还有一个风险要先摆出来。今年 7 月有篇论文（Sparse Event-KV）测过：一段原始观测丢掉之后，留在后面那些事件的 KV 里还剩什么。结论是 “Compact state survives, larger payloads decay toward chance”：在 Qwen3-8B 上，一个二选一的状态还能认对 93%，八选一就只比瞎猜高一点，一个三位数字完全记不住。一个 token 到底能装多大一件事，得先量，这决定每件事到底要分几个 token。

◆ 第三章：整理——睡一觉，越久越粗

━━━━━━━━━━━━━━━━━━━━

记忆 token 一件件往后排，总会排得太长。我们的想法跟人一样：最近的一件事一个 token；上个月的，几件合成一个；去年的，只剩几件大事。被反复提起的留着，其余慢慢淡掉。顺序不能乱。

────────────────────

**顺序真的重要，有人量过。** SegTreeMem（多伦多大学，2026）用一棵保持时间顺序的树存对话记忆，最近的节点细，久远的节点粗，跟我们的想法最像。他们把对话里随机挑出的 30% 轮次两两交换位置，再重建记忆测一遍：它在 LoCoMo 上的准确率从 0.639 掉到 0.538；而一个不看时间的方法只从 0.603 掉到 0.583。

用上了时间顺序的方法，才会因为打乱而受伤。反过来说，时间顺序里确实装着信息。

**按日历分级，有现成的文字版。** TiMem（ACL 2026 Findings）把记忆分成五级：片段、会话、日、周、画像。周级和画像级专门记偏好和价值观，也就是“这个人在意什么”。它是用文字摘要做的，但分级的方式可以直接照搬到记忆 token 上。

**忘，也有现成的公式。** MemoryBank（2023）用的是艾宾浩斯遗忘曲线：

```
R = e^(−t / S)      # R：还记得多少；t：距离上次想起过了多久；S：记忆强度
                    # 每被想起一次，S 加 1，t 归零
```

Titans（Google，2025）则是按意外程度决定写多少，外加一个遗忘门。把几条凑起来，就是一个保留分：**被提起的次数 × 当时的意外程度 × 重要性**。分数低的不直接删，并进时间上相邻的那个 token 里，时间流不断，只是变粗。这个组合是我的推断，每一项各有出处。

**什么时候整理，也有现成的规矩。** Generative Agents（2023）让 agent 在最近事件的重要性累计超过一个阈值时才停下来“反思”；我们没必要天天定点整理，攒够了再整理。

303 期（ https://mp.weixin.qq.com/s/HrrdYj-czN30_Fxrv_KNcw ）提过的《Do Language Models Need Sleep?》，缓存快满时先“睡一觉”，对累积的上下文做几遍离线递推，写进一组快状态，再清空缓存。它只睡一次，没有“睡了很多次之后，旧的怎么合并”。

────────────────────

**整理这一步，最大的空白是漂移。** 合并会反复发生：今天合并的，是上周合并过的加上这周新的。误差一层一层往上叠，跟传话游戏一样。

这个问题没人量过。已有的只是单次压缩的误差，比如 RAPTOR 做层级摘要，抽查 150 个节点，4% 有幻觉。今年有篇论文原话就是：“the repeated compaction that agents actually perform is almost never measured”。

────────────────────

💡 为什么合并时不拿压过的 token 再压

传话游戏走样，是因为每个人只听上一个人说的，听不到最初那句话。

所以合并时，不拿已经压过的 token 再压一遍，而是回到日记，从原始记录重新蒸馏出那个更粗的 token。这样不管合并多少次，每一段记忆都只挨一次压缩误差。

上文 319 期收尾那个“日记加睡眠”，在这里分工就清楚了：日记是蒸馏时的老师，也是校准时的锚点。每个合并出来的 token 记下自己覆盖了哪几条日记（Generative Agents 的反思记忆也是这么做的，每条洞见都带着指回原始记忆的指针）。睡眠时抽几道题，比一比“只看 token 答”和“看日记答”，差太多就重新蒸那一段。

────────────────────

整理好的记忆 token，下一次开会话时要读回来。

◆ 第四章：读——时间怎么排，怎么读回来

━━━━━━━━━━━━━━━━━━━━

新会话开始时，把记忆 token 当前缀放在前面。这里有两个问题：位置怎么排，全放还是挑着放。

**位置。** 上文 319 期讲过，旋转位置编码（RoPE）只看相对位置，存下来的 K 补转一个角度就能挪到新位置。KVLink（2025）就是这么做的：KV 存的时候不带位置，读进来时按顺序统一重新编号；块和块之间再插几个可训练的连接 token，补上各自单独算时缺的那部分注意力。

**真实时间。** 我没找到有人给压缩记忆 token 加可学习的时间嵌入。M+（2025）给每个记忆记了一个“年龄”，但只用来排序和淘汰最老的，不喂给模型。我们的做法更简单：真实日期直接写进被压缩的原文里，让它成为 token 内容的一部分；位置号只管先后。

**全放还是挑着放。** 只看事实题，全部放进上下文最准：Mem0 论文里 LoCoMo 的成绩，全上下文 72.90，他们自己的检索式记忆 66.88。检索换来的是省 token、省延迟。

对我们更要紧的是另一个发现：今年 8 月有篇论文测到，检索得广一些对长文问答有利，可检索过多，会在连续做决策的时候把注意力从跟下一步动作直接相关的内容上拉走。我们要保的恰恰是决策方向。

所以前缀大概是这样：

```
[ 画像 token ]  [ 事件 token 串，按时间排 ]  [ 最近几段原文，不压 ]
   常驻              常驻；太长时远期部分按需检索，      刚发生的
                     检索时带上时间上的前后邻居
```

“刚发生的不压”也有依据：同样是 8 月的一篇论文发现，agent 刚干完的事立刻压缩会掉点，等后面用得上的时候再压，能补回大部分。

◆ 第五章：测——拿什么判断它记住了方向

━━━━━━━━━━━━━━━━━━━━

现有的长期记忆基准，大多在考事实：

| 基准 | 考什么 | 考不考“方向” |
|---|---|---|
| LoCoMo（2024） | 长对话里的事实、时间、多跳问题 | 不考 |
| LongMemEval（ICLR 2025） | 事实、时间推理、知识更新，含单个会话里的偏好 | 只考单个会话里的偏好 |
| PersonaMem（COLM 2025） | 用户偏好怎么变、为什么变 | 离方向近一些，前沿模型约 50% |
| BEAM（2025） | 最长 1000 万 token，含偏好遵循、事件排序 | 偏好遵循算一部分 |

开篇说的那个区别又出现了：它们考的大多是“那天说了什么”，不是“知道该往哪走”。

**测方向，有一个现成的办法可以借。** 今年 8 月有篇论文提出了一个叫 TRACE 的测法：同一个状态下，分别给 agent 三种上下文：完整历史、压缩后的、直接删掉这段的，每种采样 24 个下一步动作，看它们的动作分布跟完整历史差多远（总变差距离，0 是完全一样）：

```
保留原文    0.149
压进摘要    0.233
直接删掉    0.289
```

压进文字摘要，距离从 0.149 升到 0.233，已经往“直接删掉”那头走了一大半。我们的记忆 token 要是有用，这个数就得明显比 0.233 小。

**只看成功率会漏掉跑偏。** 另一篇 8 月的论文里，GPT-5.5 压缩上下文之后，任务成功率从 80% 变成 85%，差别不显著；可检索调用的次数从 21.0 涨到了 63.9。活是干完了，可它一直在重新摸索被压掉的东西。

这就是上文 319 期末尾说的：按“每任务成本”算，这种跑偏看不见。要看见，得把“重新摸索了多少”也算进去。

◆ 收尾：没人做的三块

━━━━━━━━━━━━━━━━━━━━

五步走下来，零件大多有人做过：

- 切：EM-LLM 按意外程度切，HiAgent 按子目标切
- 压：CCM 一段一个记忆 token、按时间拼成串；Beacon 和 DAST 让 token 数随信息量变
- 整理：SegTreeMem 保持时间顺序、越久越粗；TiMem 按日、周、画像分级；MemoryBank 被想起就刷新
- 读：KVLink 读入时重新编号；近期常驻、远期检索
- 测：TRACE 比较下一步动作的分布

没人做的是三块，而且三块都卡在“方向”上：

1. **拿“下一步做的事一样”当训练目标。** 现有的目标考的是复述、答题、成败，没有直接考方向。
2. **反复合并会漂多少。** 没人画过质量随合并次数下降的曲线。
3. **测方向的基准。** 现有的基准大多测事实和偏好。

────────────────────

我手上其实有现成的数据：DLSS5 项目那些长会话记录。里面每一次我插话纠正，比如“主线是解释算力缺口在哪，不是零碎地提速”，就是一条方向的标注：纠正前它往哪走、纠正后它往哪走，天然是一对正负样本。每一次 `/compact` 前后的行为变化，也都是“摘要丢方向”的现成案例。

我不打算自己跑这个实验，一台机器、一个 8B 模型加 LoRA 就能起步，门槛不高，只是我不发论文。把思路和前人做到哪儿记下来，将来哪天有人做出来了，翻出来对一对就行。
