【AI记忆】一件事一个 token：把对话记忆压成一条时间流

━━━━━━━━━━━━━━━━━━━━

◆ 开篇：从“压 KV”到“一件事一个 token”

━━━━━━━━━━━━━━━━━━━━

319 期（ https://mp.weixin.qq.com/s/so-08WsOgnQFmXkawoIhnw ）聊的是：编程工具一 `/compact` 压缩上下文，AI 就跑偏。文字摘要留下了名词，丢掉了坡度：哪条线死了、为什么死、现在往哪走。那期最后停在一个想法上：如果压的不是文字，而是模型内部的 KV，是不是能留住些什么。

第二天早上我接着想：记忆到底该怎么压？

感觉只要把两样东西压住就够了：**事实，和情绪。** 发生了什么，以及这件事对我有多重要。

那就让每个记忆 token 装一件事，事实和情绪都在里面。事情多，就多写几个 token；事情少，就少写几个。这些 token 按时间排成一串，**n 个 token，就是一条时间流。**

这里说的“一个 token”，不是词表里的一个字，是一个位置在模型每一层留下的那组 KV。

跟那期碰过的两个极端放在一起看：

```
RNN：          整段经历 → 1 个状态                  # 先后折进同一个状态，单件事找不回来
完整 KV：      每个原始 token → 1 组 KV             # 一件不丢，但太长
一件事一个 token：每件事 → 1 个（或几个）记忆 token     # 一件一件能找回，长度随事情多少变
```

先后顺序不用另外存。记忆 token 本身也是一串序列，第 k 个 token 的 KV 算出来的时候，前面 k−1 个都看得见。“证伪了 A 之后转向 B”这种先后，会长在 token 和 token 之间的关系里。位置编码也现成：记忆 token 排第几，就是第几件事。不过序号只管先后，管不了隔了多久，两件挨着的事，可能隔一分钟，也可能隔半年。

这个想法分下来是四步：**怎么切** （哪儿算一件事）、**怎么压** （一件事怎么变成一个 token）、**怎么整理** （旧的怎么合并、怎么忘）、**怎么读** （新会话怎么把它们读回来）。再加一步：**怎么测**，拿什么判断它真的记住了方向。

我按这五步挨个去找，看前人已经做到了哪儿。结果是：零件差不多都有人做过，有的比我想的走得还远。要的是把它们接成一套，给长期的编程任务用。

◆ 第一章：切——哪儿算一件事

━━━━━━━━━━━━━━━━━━━━

先说我们的想法。“一件事”没有固定长度：一上午可能只干了一件事，五分钟里也可能连着出了三件。所以切的时候不能按字数，得按“事情变了没有”。

事情变了，模型应该是能感觉到的：它本来预测接下来会怎样，结果不是那样。

────────────────────

**人就是这么切的。** 认知科学里有个事件分割理论（event segmentation theory）：人一边经历一边预测下一刻会发生什么，预测误差突然升高的地方，就被感知成一件事的结束、另一件事的开始。

**EM-LLM** （华为诺亚方舟实验室伦敦与伦敦大学学院，ICLR 2025）把这套搬到了大模型上。它给每个 token 算一个“意外程度”：

```
surprisal(t) = −log P( 第 t 个 token | 前文 )     # 这个词有多出乎意料
```

超过阈值就在这儿切开。阈值不是定死的：

```
T = μ + γ·σ      # μ、σ：前面一个滑动窗口里 surprisal 的均值和标准差
```

阈值跟着前面一段的背景走，比周围明显更意外的地方，才会被切开。切完之后，它还会用注意力 key 之间的相似度微调边界位置，让同一段里的 token 在注意力上更抱团。整个过程不训练。

────────────────────

💡 “意外”有两种，EM-LLM 用的那种可能不对

EM-LLM 的摘要里说自己用的是 Bayesian surprise，正文实际算的是上面那个 surprisal。这两个不是一回事（下面的 KL 散度，可以理解成两张概率表差得有多远）：

```
surprisal(t)        = −log P( x_t | 前文到 t−1 )                      # 这个词本身意外不意外
Bayesian surprise(t) = KL( P(· | 前文到 t) ‖ P(· | 前文到 t−1) )        # 读完这个词，对“接下来”的预期变了多少
```

一个生僻词、一个陌生的变量名，surprisal 很高，但事情没变；一句“这条路不行，换个方向”，每个字都不生僻，预期却整个转了向。

EM-LLM 自己引用的那篇人类实验（Kumar 等，2023，发表在《认知科学》上，用 GPT-2 XL 做的）结论正好是：人感觉到的事件边界，跟 Bayesian surprise 相关，跟 surprisal 不相关。EM-LLM 转述这篇时，只说了“与预测误差相关”，没提后半句。

这不能说明 EM-LLM 在机器任务上就没用，但对“一件事”来说，后者更像我们要的那个信号，两种都值得试。

────────────────────

**agent 场景还有更便宜的边界。** HiAgent（ACL 2025）让 agent 先声明一个子目标，一个子目标就是一个记忆块。放到我的 DLSS5 移植项目里，“换一个核来优化”“转去查算力缺口”“我插话纠正了一次”，本来就是天然的分界线，不用算什么意外程度。

**切分器也可以训练。** H-Net（2025）在字节层面做过“按信息量动态切块”：相邻两个位置的表示差得越远，越可能是边界，边界概率由模型自己学；另加一个损失，把平均块长拉向目标值。它切的是字节，平均四五个字节一块，跟“一件事”差了两三个数量级，放到事件这个尺度上，还得验证。

所以“切”这一步：第一版用预测转向（两种意外都试）加 agent 的天然边界，设一个最长长度兜底；以后换成可训练的切分器，跟后面的压缩器一起训，让“切在哪儿”由“压完之后下一步还做得对”来决定。后半句是我的推断。

◆ 第二章：压——一件事变成一个 token

━━━━━━━━━━━━━━━━━━━━

我们的想法：切出来的每件事，挤进一个（或几个）不对应任何文字的 token。第 k 个 token 只管第 k 件事，想知道前情，去看前面那些 token，不要把前面的内容再装一遍。

上文 319 期讲过 Gist tokens：改一下注意力掩码，就能把一整段提示挤进一个 token。可 Gist 只压一次。我们要的是一件接一件地压、压出一串。

**这件事 CCM 做过。** Compressed Context Memory（压缩上下文记忆，首尔大学与 NAVER，ICLR 2024），在线把对话一段一段压进记忆。

先说 `<COMP>` 是什么。它是往词表里新加的一个特殊 token，跟标记文本结尾的 `<eos>` 一样，不对应任何字。用法是：一段原文读完，在后面接一个 `<COMP>`，让模型对它照常算一遍。`<COMP>` 不是模型生成的，是程序在每段末尾直接插进去的，每次都是同一个 token。它在每一层都会算出自己的 k、v，算的时候看得见这段原文。同一个 `<COMP>`，接在不同的原文后面，看到的东西不同，算出来的 KV 就不同。**这组 KV，就是这一段的记忆。**

推理时一步一步是这么走的：

```
第 1 步：上下文 = [第 1 段原文] <COMP>
        算完，只留下 <COMP> 的 KV（记忆 1），第 1 段原文的 KV 扔掉
第 2 步：上下文 = 记忆 1 + [第 2 段原文] <COMP>
        算完，留下记忆 2，第 2 段原文的 KV 扔掉
第 3 步：上下文 = 记忆 1 + 记忆 2 + [第 3 段原文] <COMP>
        ……
```

上下文里常驻的，只有一串记忆，外加正在读的这一段原文。读过的原文不会跟记忆一起留着。

训练时为了快，是把所有段的原文和 `<COMP>` 连成一条长序列，一次算完。这时候原文确实都在序列里，所以要用注意力掩码挡住：第 j 段的原文和它的 `<COMP>`，**只能看见前面各段的 `<COMP>`，看不见前面各段的原文**。这样训练时模型看到的，跟推理时一步步走的情形一模一样。

不管训练还是推理，模型想知道前情，都只能透过前面的记忆去看，所以被逼着把每一段的要点装进那个 `<COMP>` 里。这正是“n 个 token 就是一条时间流”。

当然，模型天生不会往 `<COMP>` 里装东西。上文 319 期说过，每个 token 的 KV 主要是它自己，只顺手混进一点前文；随手插一个 `<COMP>`，它不知道该替这段原文保管什么。所以要训练的，不是 `<COMP>` 这个 token，而是“`<COMP>` 怎么读这一段”。

训练信号就来自上面那个掩码：模型要照着压好的记忆，给出后面该给的输出（比如新题的答案），而前情只能从前面的 `<COMP>` 里拿。前面的 `<COMP>` 没装进后面要用的东西，输出就会错，误差反传回去，改的就是“怎么读”。在每段后面钉一张空白表格很容易，训练的是填表的人。

CCM 训练的不是整个模型，而是另挂上去的一小套参数（低秩适配，low-rank adaptation，LoRA），而且这套参数只在算 `<COMP>` 的时候启用；读正文时，模型还是原来那个模型。（论文实验里先让模型适配过任务，压缩训练这一步基座不动。）

效果怎么测：给模型一串带答案的例题，一道一道喂进去，每道压成一个记忆；最后出一道新题，看它能不能照着例题的路子答对（这类测试叫 MetaICL）。所有例题原文都留着，准确率 70.8%，KV 缓存峰值 630MB；例题原文全扔掉、每道只留 8 个 `<COMP>` 的 KV，准确率 70.0%，峰值 178MB。每道只留 1 个 `<COMP>`，也还有 69.5%。

────────────────────

**事多多写，有人测过。** Activation Beacon（北京智源与人大，2024）也是把长文切成一块一块来压，但每块压成几个记忆 token 不固定。压缩率 8 的意思是，每 8 个 token 的原文压成 1 个记忆 token；压缩率 2，就是每 2 个压成 1 个，留得更细。

它训练时，每一块的压缩率都从 2、4、8、16、32 里随机抽，同一篇文章里，这块压得狠，那块压得轻。他们做过一个对照：改成一整篇文章只抽一次，所有块都用同一个压缩率。结果在他们那组长文档问答上，成绩从 40.5 掉到 37.7。

也就是说，训练时让模型见惯“同一段历史里，有的地方写得多、有的地方写得少”，它反而读得更好。这是“事多多写”的前提：每件事分到的记忆 token 数不一样，模型得读得惯。不过 Beacon 的压缩率是随机抽的，不看内容；按内容来分配的，是下面这篇。

DAST（ACL 2025 Findings）更进一步：在已经训好的压缩模型上，按困惑度和注意力给信息多的块多分 token、少的少分，这一步不用额外训练。长对话数据集上，压缩率从 4 倍加到约 16 倍，它的成绩从 55.9 掉到 52.6，均匀分配的 Beacon 从 39.0 掉到 33.6。

第一版可以先用几档固定的数，比如 1、2、4、8，训练起来方便。

────────────────────

**训练目标，是这一步真正要想的地方。** 现成的有三种：

- **能复述原文**：自编码，要求从记忆 token 里把原文还原出来（上文 319 期提过的 ICAE）
- **能答一样的题**：蒸馏，老师读完整原文，学生只读记忆，让两者的输出分布对齐（Cartridges、KV-Distill）
- **能把任务做成**：按任务成败用强化学习训压缩器

我们要的是：**下一步做的事，跟看了完整历史的模型一样。** 不考“那天测的数是多少”，考“知道这条线已经死了，所以不往那儿走”。落到损失上，就是蒸馏只算在动作、工具调用、计划这些 token 上。

这一条，上文 319 期提过的 Mem-W 已经做了。它分两个阶段：第一阶段就是动作蒸馏，同一个冻结的 agent，老师看较长的原始历史，学生只看压好的记忆，让两者的下一步动作对齐，梯度只改压缩器；第二阶段再按任务成败用强化学习接着训。它跟我们设想的差别在三处：老师看的是有限长的窗口，不是完整历史；记忆是输入端的软 token，不是每层的 KV；切块按固定长度，不按事件。

蒸馏怎么算也有人比过：KV-Distill 用“学生读压缩 KV、老师读完整 KV”，正向和反向两个方向的 KL 混着用，比只用一个方向明显好。

────────────────────

💡 每件事都算一次损失，就是每件事都考一次旧记忆

在 CCM 那种掩码下，第 k 件事只能透过前面的记忆 token 看过去。所以如果损失不只算最后一步，而是每件事都算，那第 k 件事每预测一次下一步，就是对前 k−1 个记忆 token 的一次考试：该记住的方向没装进去，这里就会答错。

这一个损失顺带鼓励两件事：记忆要装方向，不装就做错下一步；第 k 个 token 也没必要把前面重装一遍，前面的 token 本来就在那儿。只是鼓励，不能保证每个 token 只装自己那件事。

这个训练设计是我的推断。CCM 原文只在最后的输出上算损失，每件事都算一次，是往前再走一步。

────────────────────

还有一个风险要先摆出来。今年 7 月有篇论文（Sparse Event-KV）测过：一段原始观测丢掉之后，留在后面那些事件的 KV 里还剩什么。结论是 “Compact state survives, larger payloads decay toward chance”：在 Qwen3-8B 上，一个二选一的状态还能认对 93%，八选一就只比瞎猜高一点，一个三位数字完全记不住。它测的是普通 KV 里的残留，不是专门训过的 `<COMP>`，量不出压缩 token 的容量，只是提醒：普通 KV 不会自动替你存下细节。一个记忆 token 到底能装多大一件事，还得专门量，这决定每件事要分几个 token。

◆ 第三章：整理——睡一觉，越久越粗

━━━━━━━━━━━━━━━━━━━━

记忆 token 一件件往后排，总会排得太长。我们的想法跟人一样：最近的一件事一个 token；上个月的，几件合成一个；去年的，只剩几件大事。被反复提起的留着，其余慢慢淡掉。顺序不能乱。

────────────────────

**顺序真的重要，有人量过。** SegTreeMem（多伦多大学，2026）用一棵保持时间顺序的树存对话记忆：叶子是一句句原话，上层节点各自总结一段连续的时间，粗细几层同时都在。我想在它上面再加一条：久远的时间段，只常驻粗的那一层。他们把对话里随机挑出的 30% 轮次两两交换位置，再重建记忆测一遍：它在 LoCoMo 上的准确率从 0.639 掉到 0.538；而一个不看时间的方法只从 0.603 掉到 0.583。

用上了时间顺序的方法，才会因为打乱而受伤。反过来说，时间顺序里确实装着信息。

**按日历分级，有现成的文字版。** TiMem（ACL 2026 Findings）把记忆分成五级：片段、会话、日、周、画像。周级和画像级专门记偏好和价值观，也就是“这个人在意什么”。它是用文字摘要做的，但分级的方式可以直接照搬到记忆 token 上。

**忘，也有现成的公式。** MemoryBank（2023）用的是艾宾浩斯遗忘曲线：

```
R = e^(−t / S)      # R：还记得多少；t：距离上次想起过了多久；S：记忆强度
                    # 每被想起一次，S 加 1，t 归零
```

Titans（Google，2025）则是按意外程度决定写多少，外加一个遗忘门。把几条凑起来，就是一个保留分：**被提起的次数 × 当时的意外程度 × 重要性**。分数低的不直接删，并进时间上相邻的那个 token 里，时间流不断，只是变粗。这个组合是我的推断，每一项各有出处。

**什么时候整理，也有现成的规矩。** Generative Agents（2023）让 agent 在最近事件的重要性累计超过一个阈值时才停下来“反思”；我们没必要天天定点整理，攒够了再整理。

303 期（ https://mp.weixin.qq.com/s/HrrdYj-czN30_Fxrv_KNcw ）提过的《Do Language Models Need Sleep?》，缓存快满时先“睡一觉”，对累积的上下文做几遍离线递推，写进一组快状态，再清空缓存，接着往下读，每满一次睡一次。它没验证的，是跨会话、按事件排的记忆，怎么一轮一轮合并下去。

────────────────────

**整理这一步，要防的是漂移。** 合并会反复发生：今天合并的，是上周合并过的加上这周新的。误差一层一层往上叠，跟传话游戏一样。

文字摘要的反复压缩，已经有人量过。上文 303 期讲过一组实验：摘要压三轮之后，答对率只剩 36.8%，保留完整上下文是 90.1%。今年 7 月一篇讲记忆压缩的论文，一边说 agent 真正在做的反复压缩“almost never measured”，一边自己做了个小实验，横轴就是压缩次数。事件 KV 反复合并之后，下一步的方向会漂多少，还得专门测。

────────────────────

💡 为什么合并时不拿压过的 token 再压

传话游戏走样，是因为每个人只听上一个人说的，听不到最初那句话。

所以合并时，不拿已经压过的 token 再压一遍，而是回到日记，从原始记录重新蒸馏出那个更粗的 token。这样就避开了“摘要的摘要”那条误差一路往上叠的路。当然，压得更小丢掉的信息、老师自己的误差，这些还在。

上文 319 期收尾那个“日记加睡眠”，在这里分工就清楚了：日记是蒸馏时的老师，也是校准时的锚点。每个合并出来的 token 记下自己覆盖了哪几条日记（Generative Agents 的反思记忆也是这么做的，每条洞见都带着指回原始记忆的指针）。睡眠时抽几道题，比一比“只看 token 答”和“看日记答”，差太多就重新蒸那一段。

────────────────────

整理好的记忆 token，下一次开会话时要读回来。

◆ 第四章：读——时间怎么排，怎么读回来

━━━━━━━━━━━━━━━━━━━━

新会话开始时，把记忆 token 当前缀放在前面。这里有两个问题：位置怎么排，全放还是挑着放。

**位置。** 上文 319 期讲过，旋转位置编码（RoPE）只看相对位置，存下来的 K 补转一个角度就能挪到新位置。KVLink（2025）就是这么做的：KV 存的时候不带位置，读进来时按顺序统一重新编号；块和块之间再插几个可训练的连接 token，补上各自单独算时缺的那部分注意力。不过它修的是位置和块间联系，深层 KV 里对旧前文的依赖擦不掉：旧记忆合并、替换之后，后面那些记忆还是在旧的前文下算出来的，能不能直接接着用，得一起训练、一起验证。

**真实时间。** M+（2025）给每个记忆记了一个“年龄”，但只用来排序和淘汰最老的，不喂给模型。其实可以更简单：真实日期直接写进被压缩的原文里，让它成为 token 内容的一部分，位置号只管先后。日期压完之后还保不保得住，也得测。

**全放还是挑着放。** 在 Mem0 论文那组实验里，全部放进上下文更准：LoCoMo 上全上下文 72.90，他们自己的检索式记忆 66.88。检索换来的是省 token、省延迟。

对我们更要紧的是另一个发现：今年 8 月有篇论文测到，检索得广一些对长文问答有利，可检索过多，会在连续做决策的时候把注意力从跟下一步动作直接相关的内容上拉走。我们要保的恰恰是决策方向。

所以前缀大概分三段：常驻的画像 token；按时间排的事件 token 串，太长时远期部分按需检索，检索时带上时间上的前后邻居；最近几段原文，不压。

“刚发生的不压”也有依据：同样是 8 月的一篇论文发现，agent 刚干完的事立刻压缩会掉点；多保留一段，等后续的查询出现，再照着它决定压什么，能补回大部分。

━━━━━━━━━━━━━━━━━━━━

◆ 第五章：测——拿什么判断它记住了方向

━━━━━━━━━━━━━━━━━━━━

现有的长期记忆基准，大多在考事实：

| 基准 | 考什么 | 考不考“方向” |
|---|---|---|
| LoCoMo（2024） | 长对话里的事实、时间、多跳问题 | 不考 |
| LongMemEval（ICLR 2025） | 事实、时间推理、知识更新，含单个会话里的偏好 | 只考单个会话里的偏好 |
| PersonaMem（COLM 2025） | 用户偏好怎么变、为什么变 | 离方向近一些，论文所测模型约 50% |
| BEAM（2025） | 最长 1000 万 token，含偏好遵循、事件排序 | 偏好遵循算一部分 |

开篇说的那个区别又出现了：它们考的大多是“那天说了什么”，不是“知道该往哪走”。

**测方向，有一个现成的办法可以借。** 今年 8 月有篇论文提出了一个叫 TRACE 的测法，专门看决策有没有偏：停在同一个决策点上，拿完整的原始历史当参照，再给 agent 三种压过的上下文，每种采样 24 个下一步动作（只采样，不执行），看动作分布跟参照差多远（总变差距离，0 是完全一样）：

```
旧摘要 + 这一轮新增的原文      0.149
这一轮也压进摘要              0.233
旧摘要，这一轮什么都不给       0.289
```

这一轮一压进摘要，距离从 0.149 升到 0.233，往“什么都不给”那头走了一大半。在同一套实验设置下，记忆 token 要是有用，就得比文字摘要更接近完整历史。

**只看成功率会漏掉跑偏。** 另一篇 8 月的论文里，GPT-5.5 用滑动窗口裁掉旧上下文之后，任务成功率从 80% 变成 85%，差别不显著；可检索调用的次数从 21.0 涨到了 63.9。活是干完了，可它一直在重新摸索被裁掉的东西。

只看任务完成率，这种代价看不见。要看见，得把“重新摸索了多少”也算进去。

━━━━━━━━━━━━━━━━━━━━

◆ 收尾：接下来要测的三块

━━━━━━━━━━━━━━━━━━━━

五步走下来，零件大多有人做过，有的比我想的走得还远：

- 切：EM-LLM 按意外程度切，HiAgent 按子目标切
- 压：CCM 一段一个记忆 token、按时间拼成串；Beacon 和 DAST 让 token 数随信息量变；Mem-W 拿下一步动作做蒸馏
- 整理：SegTreeMem 按连续时间区间组织、粗细几层并存；TiMem 按日、周、画像分级；MemoryBank 被想起就刷新
- 读：KVLink 读入时重新编号；近期常驻、远期检索
- 测：TRACE 比较下一步动作的分布

把它们接成一套，接起来以后，还有三块得测，三块都落在“方向”上：

1. **按事件切、按信息量分 token、按时间合并，凑在一起训出来的记忆，能不能保住长期任务的方向。** Mem-W 做了动作蒸馏，但窗口有限、按固定长度切。
2. **事件 KV 反复合并之后，方向会漂多少。** 文字摘要的已经有人测过。
3. **拿什么尺子量方向。** TRACE 能借，但它量的是单个决策点上的偏移。

────────────────────

还有一点，是写到这儿才看清的：**这件事不用改模型的主干。**

CCM 那套办法里，原有的权重一个都不改。挂上去的只有 `<COMP>` 的一行嵌入加一小套 LoRA，而且只在算 `<COMP>` 时启用；压出来的记忆就是普通的前缀 KV，现成的注意力照常能读，不用换成线性注意力，也不用改结构。当然，不改主干不等于下载就能用：要加特殊 token、只在特定位置启用适配器、训练时加分段掩码、推理时管好记忆 KV 的读写和位置，这些都得有。

那它就是一个可以插拔的“睡眠模块”。每个基座模型配一个，跟今天 Hugging Face 上满地的 LoRA 一样，按基座分别训，挂上用。KV 是私有坐标，所以 Qwen 的模块挂不到 Llama 上；同一家换了版本，也不能假定还兼容，得验证，必要时重新适配。可重训的成本是训一个 LoRA，不是训一个模型。

这个模块还带着一种“文化”。它的训练目标是“下一步做的事，跟看了完整历史时一样”，所以它学会保留的，是在那个环境里影响下一步的东西。在编程项目里训出来的，会记住哪条线死了、主线在哪；在陪伴聊天里训出来的，会记住对方上次提到家里人生病时情绪很低。同一个基座，换一个模块，记性就换了一种。人也一样，渔民记得潮汐，会计记得数字。

LoRA 对机器的要求也不高。基座权重冻住，还能量化，要更新的只有那一小套参数，训练量比全参数训练小得多，有机会在本地做。不过冻住的只是权重，反向传播照样要穿过整个网络，长序列的中间结果、老师那一遍前向都要花显存，具体能训多长，要看模型、量化和显存。

卡住它的，反而是模型以外的事：闭源模型只能等厂商来做，因为训这个模块得拿到权重；推理引擎得支持把一串预先算好的 KV 塞进前缀。开源模型这边，社区自己就能先做起来。

────────────────────

说到底，我觉得真能这样压好，记忆就够用了。人脑本来也记不住久远的事。

心理学早就量过：回忆不是把存档调出来，是每一次都重新生成一遍。1932 年 Bartlett 让英国人读一个陌生的印第安民间故事，隔一阵复述一次，越往后，故事越像英国人熟悉的样子，不认识的细节被换成了熟悉的。记什么、往哪儿改，由记住它的人的文化决定，心理学管这叫图式（schema）。上面那个睡眠模块，就是模型的图式。Loftus 的实验里，引导几句，就能让人“想起”小时候在商场走丢过，而这件事根本没发生。童年早期的很多“记忆”，也是后来看照片、听大人讲，自己重建出来的。连当时的情绪，回想时也会往现在的看法上偏。

人不保存每个字，回忆也会重建。我希望留下的，是那件事重要不重要、方向在哪儿。这就是开篇那个区别：记忆该留下的，是“哪件事重要”，不是“第二章第一个字”。

所以对 AI 的记忆，标准不该比人高。我们要的不是一份存档，是**每次重建出来，还是那个方向**。人比 AI 多的，只是几个锚点：照片、日记、别人的复述，偏远了能被拉回来。第三章那一步“合并时回日记重新蒸馏”，干的就是这件事。

────────────────────

我手上其实有现成的数据：DLSS5 项目那些长会话记录。里面每一次我插话纠正，比如“主线是解释算力缺口在哪，不是零碎地提速”，就是一条方向的标注，是很好的候选训练材料。不过纠正前后，环境和信息也可能变了；`/compact` 前后的行为变化，也不一定都怪摘要。得在同一个任务状态下，分别用全文和摘要回放一遍，才能挑出真是压缩造成的方向差异。

把思路和前人做到哪儿记下来，将来哪天有人做出来了，翻出来对一对就行。
