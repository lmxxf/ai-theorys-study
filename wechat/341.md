【阶跃星辰 Step 5 Preview】从 45 层到 92 层：当年不压 KV 的那家，怎么也稀疏了？

━━━━━━━━━━━━━━━━━━━━

◆ 起因：五个月，同一副骨架，两倍的深度

━━━━━━━━━━━━━━━━━━━━

10 月 15 日，阶跃星辰把 **Step 5 Preview** 的权重放出来了——BF16 和 FP8 两个版本，HuggingFace 和 ModelScope 同步上架，vLLM / SGLang 有官方镜像，Transformers 可以离线跑。模型本身 9 月 20 日就发布了：稀疏 MoE，600B 总参数、27B 激活，1M 上下文，原生带视觉。Artificial Analysis 综合指数 44 分，官方口径是开源前三；发布不到一个月，OpenRouter 的 token 用量周榜冲到了第二。

五个月前我们写过它的上一代 Step 3.7 Flash（271 期，链接待补）：198B、256K 上下文，是那期“128G 家用机”的主角之一。当时最有意思的结论是它的赌注—— **不做 KV 压缩** ，标准 GQA 加滑动窗口，把工程重心放在 agent 的吐字速度上，和 DeepSeek V4 的 CSA + HCA 压缩路线正好相反。

这次 Step 5 Preview 的技术博客和 config.json 一起公开了。我把两代的 config 逐字段对了一遍： **骨架一个零件没换，层数翻了一倍，而当年“不压 KV”的那家，给全局注意力层装上了稀疏索引器** 。这期就把这份对照和百万上下文的 KV 显存账算清楚。

━━━━━━━━━━━━━━━━━━━━

◆ 1. 两代 config 摆在一起：骨架没变，三处真变

━━━━━━━━━━━━━━━━━━━━

先放结论：Step 5 Preview 不是重新设计的模型，是把 Step 3.5/3.7 定下的骨架原样放大，再在三个位置上动了真格的。逐字段对照如下（数字全部来自两家 HuggingFace 仓库的 config.json）：

| | Step 3.7 Flash | Step 5 Preview |
|---|---|---|
| 总参 / 激活 | 198B / 约 11B | 600B / 27B |
| 层数（隐藏层宽度） | 45 层（4096） | **92 层（4096，宽度不变）** |
| 层型排布 | 1 全局 + 3 滑窗 | **同一个 1:3 拍子**（23 全局 + 69 滑窗） |
| 滑窗窗口 | 512 token | 512 token（没变） |
| 注意力头 | 全局 64 头 / 8 KV 组，滑窗 96 头，head_dim 128 | 两种层统一 64 头 / **4 KV 组**，head_dim **192** |
| 全局层 | 稠密 GQA | **Sparse GQA（索引器 + 块挑选）** |
| RoPE | 全局 θ=500 万，滑窗层一半维度旋转，128K 插值 ×2 到 256K | 全局 θ=1000 万，滑窗层 1/3 维度旋转，**原生 1M** |
| MoE | 288 专家 Top-8，专家中间维 1280 | **352 专家** Top-8，中间维 1536 |
| 稳定性字段 | 无 | **FP32 残差、FP32 归一化系数、全层 SwiGLU 截断 7.0** |
| MTP（多 token 预测） | 3 层 | 3 层（没变） |
| 词表 | 128896 | 128896（没变） |
| 视觉塔 | 47 层 × 宽 1536 | **逐字段相同，没换** |

没变的那串先说：1:3 的“全局 + 滑窗”拍子、512 的窗口、3 层 MTP、词表、视觉塔，甚至路由器的 FP32 门控和缩放因子 3.0，全部原样继承。这是一套 3.5 时代定下来、被两代模型验证过的骨架。

真变的是三处。第一处是 **层数从 45 翻到 92，宽度一步没加** ——这就是官方说的“窄而深”（narrow but deep），下一节细讲。第二处是 **全局层从稠密 GQA 换成 Sparse GQA** ，第三节细讲。第三处不太起眼但信息量很大：config 里新冒出来一整组稳定性字段——`fp32_residual_connection`（FP32 残差连接）、`norm_dtype: float32`（FP32 归一化系数）、以及 SwiGLU 截断从 3.7 的只有两层设阈值变成 **全部层统一 7.0** 。技术博客的口风是“没有披露具体的归一化与残差结构”， **其实 config 全写了** 。

还有一个 FP8 权重里的小细节：量化清单把 **最后三层 MoE 的专家** （第 88/89/90 层）和视觉塔的注意力排除在 FP8 之外，保留 BF16。最靠近输出的专家不让量化——后面讲 KV 时还会看到同一种思路。

◆ 2. 窄深的理由，和它的学费

━━━━━━━━━━━━━━━━━━━━

为什么加宽不如加深？技术博客给出的论证链条是围绕 agent 场景的：

agent 干活靠工具调用，工具返回的结果堆成很长的 prefill（预填充）输入；考虑到 token 开销，模型没有太多机会写长篇的显式思维链，多跳推理只能在 prefill 过程里“隐式”完成。而 Transformer 的 prefill 里，信息沿两个轴单向流动：时间轴往后、深度轴往下。一条多跳依赖链，必须在“更深的层、更后的 token”上才能汇合—— **层数不够，这条链根本走不完** 。所以 Step 5 Preview 把层数堆到 92，和万亿档的 Qwen3.8-Max、Kimi K3 一样深，但总参数和激活参数分别只有那两家的四分之一和三分之一不到（官方博客原话）。

────────────────────

💡 “层不够深，推理走不完”是什么意思

一个 token 在第 1 层只能看到它的上文；要回答“根据第三章的设定和第七章的伏笔，凶手是谁”，得先把第三章的信息一层层搬到第七章附近、再逐层加工。每一跳都要消耗层数。45 层能走完的链条有个上限，92 层就是把这个上限翻倍。

────────────────────

但窄深是有学费的。博客原话：这种不稳定在更小、更浅、更宽的网络上很少出现，偏偏在加深时冒出来——数值爆炸和梯度尖峰。阶跃交了三种解法：

- **FP32 隐藏状态** 。大模型里早有“巨型激活值”（massive activations）的观察，一般认为它们扮演偏置项的角色，通常无害。但网络加深之后，个别巨型激活值在 BF16 精度下会迅速爆掉；换成 FP32 存隐藏状态和对应梯度，峰值直接降了将近一个数量级，训练开销只多一点点。config 里的 `fp32_residual_connection` 就是这条。
- **FP32 的 RMSNorm 缩放系数** 。这条最绕也最有意思，单独给它一个灯泡块。
- **细粒度梯度裁剪** 。他们观察到梯度尖峰不来自脏数据也不来自输出头，而是在中间层冒出来、几层之内被放大几个数量级，猜测和层冗余有关（深网里相近的层把同一个梯度信号反复放大）。好在异常梯度极其稀疏： **每层只裁掉 0.00004% 的梯度值** ，尖峰就压住了，收敛曲线明显变光滑。

────────────────────

💡 一个卡在 -1 上的数字，怎么让训练来回振荡

Step 5 用的是零中心 RMSNorm：y = x / RMS(x) × (1 + γ)，γ 是可学系数。巨型激活值对应的维度上，γ 会被训得非常接近 -1——也就是 (1+γ)≈0，把这个通道压没。问题在于 BF16 在 -1 附近精度不够：训练里 γ 偶尔真的等于 -1，通道彻底关闭；接下来几步权重衰减之类的扰动又把它推离 -1，通道重新打开。开、关、开、关，输出就这么振荡。把 γ 换成 FP32 存储，-1 附近的微小差别能表示出来了，振荡消失。config 里的 `norm_dtype: float32` 就是它。

────────────────────

这三件套对应 config 里那组新字段，也正是博客语焉不详、config 老实交代的那部分。下面是第三处、也是动静最大的一处变化。

◆ 3. Sparse GQA：不压 KV 的那家也稀疏了，以及百万上下文的显存账

━━━━━━━━━━━━━━━━━━━━

注意力这条演化线我们一路追过（168 期，MHA→MLA→DSA→CSA/HCA，https://mp.weixin.qq.com/s/YqcTnIrGKEYZ2n-sMAelKg ）：DeepSeek 系的答案是把 KV 往小里压，阶跃 3.5/3.7 的答案是标准 GQA 不压缩。Step 5 Preview 变卦了——全局层用上了 **Sparse GQA** ，机制上是 DeepSeek DSA 的同族：一个轻量 **索引器（indexer）** 给历史 token 打分，每个 query 只挑排名靠前的来 attend，博客明说受了 DSA 启发。

但它不是照抄。DSA 长在 MLA 上，阶跃 **坚持留在 GQA** ，博客给了两个理由：长上下文准确率实测更好，以及多卡并行友好——GQA 的几组 KV 可以分摊到不同卡上。代价是他们自己也承认的：GQA 的 KV 组比 MQA/MLA 多，稀疏化的三个瓶颈（索引器的开销、碎计算喂不饱 GPU、挑选粒度与读取量的权衡）全被放大。解法对应三条：

- **8 个 token 合并成一个索引块** 。索引器不用逐 token 打分，按块打，索引和 top-k 选择的开销直接降到 1/8。块变粗会损失挑选精度，那就把名额加大补回来：最终配置是每块 8 token、挑 512 块（共 4096 个 token），注意力覆盖率 78.06%，和“逐 token 挑 2048 个”的 79.09% 几乎持平。
- **相邻 token 的挑选结果取并集** 。prefill 时相邻 token 语义相近，选中的块大量重叠，合并在一起算，GPU 才不会因为计算太碎而空转。
- **主路读的还是原始 K/V** 。索引器只管“挑”，被挑中的 token 以原始精度参与注意力——这也是为什么存储省不下来，下面算账。

现在算这笔账： **1M 上下文的 KV 到底要多少显存** 。先交代算法：每个 token 在每层要存 K 和 V 两份向量，GQA 是 4 组 × 192 维，BF16 每份 2 字节——

```
每 token 每层全局层 KV = 4 组 × 192 维 × 2 路(K/V) × 2 字节 = 3 KB
23 层全局层          → 每 token ≈ 69 KiB
滑窗层窗口 512 封顶   → 全部 69 层合计 ≈ 0.11 GiB（零头）
```

| 上下文长度 | KV cache（BF16） | KV cache（FP8） |
|---|---|---|
| 256K | 17.4 GiB | 8.7 GiB |
| 512K | 34.6 GiB | 17.3 GiB |
| 1M | **69.1 GiB（约 74 GB）** | 34.6 GiB |

对照两杆秤：上一代 Step 3.7 跑满 256K 是 12.1 GiB（8 KV 组 × 128 维 × 12 层全局）；DeepSeek V4-Flash 跑满 1M 只有 6.72 GiB（277 期算的账，https://mp.weixin.qq.com/s/j8Dr2sdRUZIdPfGWr9r5nw ）。 **同样百万上下文，Step 5 Preview 的 KV 是 V4 的十倍** 。

────────────────────

💡 稀疏注意力只省计算，不省存储

69 GiB 里一个 token 的 KV 都不能少存——索引器得先看到全部历史，才谈得上挑。省的是另一边：1M 上下文里，每个 query 实际参与注意力计算的只有挑中的 4096 个加上滑窗的 512 个， **约 0.44%** 。计算省到原来的两百分之一，存储一分没少。这就是为什么 V4 的压缩路线和 Step 5 的稀疏路线不是替代关系：一个砍存储，一个砍计算。

────────────────────

最后是部署账。FP8 权重约 630 GB（最后三层专家是 BF16），官方最低配置是 4 张 B300 或 8 张 H200；BF16 权重约 1.2 TB，要 8 张 B300 或 16 张 H200。上文 271 期那个“128G 家用机跑 200B”的故事，在这条旗舰线上正式落幕——就算降到 4 bit，300 GB 的权重也进不了任何一台 128G 统一内存主机。阶跃这一代押的是机房，不是桌面。

◆ 4. 训练侧速览：bitwise 对齐和“自己整理自己”的 compaction

━━━━━━━━━━━━━━━━━━━━

技术博客的后半程全是 agent 时代的训练工程，不报菜名，挑两个最值得带走的。

**亮点一：训练和推理逐位对齐（bitwise alignment）** 。在线 RL 里同一个模型跑两套实现（训练框架和推理引擎），微小的数值差会经 MoE 路由和深度放大。阶跃把能对齐的算子全部对齐：logprob 差异严格为零，TP=1 的训练和 TP=8 的推理结果逐位相同，总开销不到 10%。对不齐的部分就“回放”（replay）：冻结路由器、把推理时选中的专家索引和系数原样喂给训练侧（323 期小米 MiMo-V2.6 的 RL 也用了路由冻结，https://mp.weixin.qq.com/s/z8Mj5v7QTB-obDIsY-Y3og ），top-p 候选集同样回放。效果是 **熵停止衰减、保持稳定** ——315 期讲过熵坍缩是 RLVR 的头号慢性病（https://mp.weixin.qq.com/s/8jC7pwKN0RFd5O70Dh4Lrw ），阶跃这份病历值得对照着看。

**亮点二：compaction（上下文压缩）被当成一等公民** 。长程任务的轨迹会长到撑爆上下文窗口，阶跃的做法是：预算快花完时，agent 自己把工作现场整理成一份“可恢复状态”，清空后继续—— **这个整理动作不是外挂的工程补丁，是在任务奖励下端到端训进策略里的** 。配套的是信用分配：token 级用一个可学的 critic 折算基线，turn 级只罚出错的那一轮（比如格式错误的工具调用），奖励作弊行为有在线检测器当场拦下。

效果层面的数字各挑一个：DeepSWE 67.7，开源模型里第一（前面是 GPT-6 Astra 的 74.1 和 Opus 5 的 74.0）；金融专项 FrontierFinance 66.4，同样是开源第一。但也不是全面碾压——Terminal-Bench v4 上 33.3 输给了 GLM-5.3 的 41.9。长程案例里最生动的一个：不给任何定制优化，让它玩宝可梦红， **三千多回合、累计 600 万 token 的交互里没丢主线目标** 。定价每百万 token 输入 1 美元、输出 2.7 美元，官方口径单任务成本约为 Opus 5 的八分之一——官方博客标题《Advancing the Pareto Frontier》，押的就是“智能 × 成本”的性价比前沿。

◆ 合上账本

━━━━━━━━━━━━━━━━━━━━

- Step 5 Preview 开源权重：600B/27B、1M 上下文、原生视觉，AA 综合 44，官方口径开源前三
- 骨架和 3.5/3.7 逐字段相同：1:3 的全局+滑窗、512 窗口、3 层 MTP、词表、视觉塔都没动
- 三处真变：层数 45→92（宽度不变，窄深）、全局层上 Sparse GQA（DSA 同族的块索引）、新增一整套 FP32 稳定性字段
- 窄深的理由：agent 的长 prefill 里隐式多跳推理需要层数当跑道；代价是训练不稳定，用 FP32 隐藏状态/归一化系数 + 细粒度梯度裁剪压住
- KV 账：1M 上下文 BF16 要 69 GiB，是 V4 压缩路线的十倍——稀疏只省计算不省存储
- 部署最低 4×B300 / 8×H200，128G 家用机这一代出局；阶跃的赌注从桌面挪回了机房

**年初的 Step 3.5 绕开线性注意力选了滑窗，这次的 Step 5 绕开 MLA 选了 GQA 加索引——两次都没有追“最先进的注意力”，选的都是当时工程上最稳的那个。模型的性格，原来真的会一代代传下去。**

◆ 技术名词速查

━━━━━━━━━━━━━━━━━━━━

| 术语 | 一句话解释 |
|------|-----------|
| MoE（混合专家） | 参数分成很多“专家”，每个 token 只激活一小撮的稀疏架构 |
| GQA（分组查询注意力） | 多个 query 头共享一组 KV 头；4 组就是 16 个头共用一组 KV |
| Sparse GQA | 在 GQA 上加索引器，每个 query 只挑 512 个块参与注意力，Step 5 的全局层用它 |
| 索引器（indexer） | 给历史 token 打分的轻量打分器，决定“哪些历史值得看” |
| 滑动窗口注意力（SWA） | 每个 token 只看最近 512 个 token，不管更远的 |
| MTP（多 token 预测） | 额外的小预测头一次猜后面几个 token，给投机解码当草稿 |
| 窄深架构 | 宽度不变、层数翻倍的设计，用深度换长输入里的多跳推理能力 |
| 零中心 RMSNorm | 归一化系数写成 (1+γ) 的形式；γ 接近 -1 时 BF16 精度不够会引发振荡 |
| 巨型激活值（massive activation） | 隐藏状态里个别维度数值特别大的现象，深网里会爆炸 |
| compaction | 上下文快满时把现场整理成可恢复状态再继续，Step 5 把它训进了策略 |
| bitwise alignment | 训练框架和推理引擎的数值结果逐位相同，RL 里消除训练-推理偏差的做法 |
| KV cache | 注意力存历史 token 表示的缓存；本文的主角，1M 上下文 69 GiB |

**层数不够，长输入里的多跳依赖根本走不完——92 层不是为了榜单好看，是给隐式推理留的跑道。**

**69 GiB 的 KV 一个 token 都不能少存，稀疏省下的只是每个 query 回头读的 0.44%——稀疏注意力只省计算，不省存储。**

**年初绕开线性注意力选滑窗，这次绕开 MLA 选 GQA 加索引：阶跃两次都没追“最先进的注意力”，选的都是当时最稳的那个。**
