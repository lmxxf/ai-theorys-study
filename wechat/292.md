【GLM-5.3-Flash】名字像旗舰的小份，配置文件里是台新机器

━━━━━━━━━━━━━━━━━━━━

◆ 开篇：牛来，和一个信息量为零的名字

━━━━━━━━━━━━━━━━━━━━

8 月下旬，第三方评测里匿名出现了一个代号“牛来”（Ox Alpha）的模型，编程和 agent 任务表现扎眼，没人知道是谁家的。8 月 26 日谜底揭开：智谱把它开源了，MIT 协议，名字叫 **GLM-5.3-Flash**。

这个名字的读法很自然：5.3 是两周前刚发的旗舰版本号，Flash 是各家都有的轻量档——合起来就是“旗舰 GLM-5.3 的小份装”。省钱版，能力打个折，逻辑上应该是同一台机器缩小了。

我照老规矩去读了它的 `config.json`——**新模型发布，官方文章可以晚点看，配置文件不会说谎**，这套读法在 232 期 https://mp.weixin.qq.com/s/4RZlRoFSSDXiLV6W8wZWig 读 GLM-5.2 时用过一遍。

这次读出来的东西和名字对不上。**旗舰用的注意力结构，Flash 一层都没有；旗舰是纯文本模型，Flash 的 config 里装着一个完整的视觉塔。** 官方模型卡也说得明白：Flash 不是从旗舰改的，是**从一个全新训练的底座模型开始**，架构和训练配方整个重新设计。

也就是说：名字起得最保守，架构换得最激进。这期就把这台“披着轻量版名字的新机器”按配置文件过一遍。

> 材料来源：Hugging Face 模型卡与 config.json（ huggingface.co/zai-org/GLM-5.3-Flash ），Z.ai 官方文档，GLM-5 技术报告 arXiv:2602.15763。架构数字全部以 config.json 原值为准；Flash 没有专属技术报告，训练方法只能引 GLM-5 系列报告，下文涉及处会注明。

◆ 第一章：先把报表看完

━━━━━━━━━━━━━━━━━━━━

基本信息一张表：

| 项目 | GLM-5.3-Flash |
|---|---|
| 发布 | 2026-08-26，开源，MIT 协议 |
| 总参数 | 320B（MoE） |
| 每 token 激活 | 18B |
| 预训练数据 | 约 30T token 多模态语料 |
| 上下文 | 原生 1M（官方评测在 300K 下做） |
| 多模态 | 原生视觉，GLM-5 系列首个 |
| 价格 | 旗舰 GLM-5.3 的 1/10，限时促销 1/20 |

跑分挑官方模型卡正式列出的三项说：Terminal-Bench 2.1 得 84.3，DeepSWE v1.1 得 63.4，HLE（Humanity's Last Exam，带工具）55.3。官方对它的定位措辞是：在编程和 agent 基准上**接近（approaching）Claude Opus 4.8**。

有些媒体把这句升级成了“与 Opus 4.8 持平”。一手模型卡写的就是“接近”，这里照原文。另外要留意口径：Flash 报的软件工程基准是 DeepSWE v1.1，别家常报的是 SWE-bench Verified，**两把不同的尺子，数字不能横着并排比**。

报表部分就这些。18B 激活、旗舰十分之一的价格、接近第一梯队的分数——这个组合本身已经够当新闻了。但报表说明不了它是怎么做到的，得打开配置文件。

◆ 第二章：打开 config.json

━━━━━━━━━━━━━━━━━━━━

`config.json` 是模型的户口本：多少层、每层什么结构、注意力怎么配，全是训练前就定死的硬参数，写文章的人夸不进去。逐项读：

**层数**：`num_hidden_layers: 45`。作为对照，媒体报道旗舰 GLM-5.3 是 92 层——Flash 层数只有一半。

**MoE 配置**：288 个路由专家加 1 个共享专家，每个 token 激活其中 8 个。320B 总参里每次只有 18B 干活，这是“存得多、算得少”的标准做法。

**mHC**：config 里有一个开关 `mhc: true`。mHC（流形约束超连接，Manifold-Constrained Hyper-Connections）一出现，来历不用查——**这是 DeepSeek V4 的发明**，残差流上那条技术线在 126 期 https://mp.weixin.qq.com/s/iArmZhtv1Q_aobLkEm3BBw 从字节的 HC 一路讲到过 mHC。GLM 直接拿来用了。后面还会看到，Flash 身上的 DeepSeek 零件不止这一个。

**上下文**：`max_position_embeddings: 1048576`，也就是 1M。但更值得看的是旁边两个字段：`qk_rope_head_dim: 0`、`mla_use_nope: true`——**这个模型没有位置编码**。RoPE 的维度是零，注意力层不加任何位置信号，“谁先谁后”由线性层的递归结构天然携带：token 按顺序进状态，顺序就在状态里。长上下文最头疼的位置编码外推问题，在这里从结构上就不存在——这是它敢标 1M 的一部分底气。这套“不要位置编码”的做法，明眼人一看就知道是从 Kimi K3 那里借鉴过来的——细节下一章聊。

**最重要的一项是注意力**。config 逐层列出了每一层用什么注意力，数出来是：

**45 层里，34 层线性注意力，11 层 DSA 稀疏注意力。** 稀疏层落在第 3、7、11……43 层，每四层插一层，其余全是线性。大约 3:1。

这一项就是 Flash 和旗舰的分水岭，值得单独一章。

────────────────────

💡 1M 和 300K 都是真的：两个口径不冲突

媒体说 Flash 上下文 1M，官方评测脚注又写 300K，看起来打架。其实是两个口径：**1M 是架构支持的上限**（config 里位置编码的原生长度），**300K 是官方跑分时实际用的长度**。类似汽车仪表盘画到 260 码、厂商测油耗用 90 码巡航——两个数字负责回答不同的问题。写进正文的口径是：支持 1M，官方基准在 300K 下评测。

────────────────────

口径厘清了，回到那个分水岭。

◆ 第三章：旗舰的注意力，Flash 一层都没带

━━━━━━━━━━━━━━━━━━━━

GLM-5.2 和 5.3 旗舰的注意力是什么？232 期读 5.2 报告时写过：**MLA**（多头潜在注意力，Multi-head Latent Attention）——DeepSeek 发明的那套“把 KV 压缩进潜在空间”的结构，GLM 改成了适配国产卡的 MLA-256；长上下文那侧配的是 **DSA**（DeepSeek 稀疏注意力，DeepSeek Sparse Attention）加上 GLM 自己的 IndexShare 改进。归结起来，旗舰这条线是“**完整注意力 + 压缩 + 稀疏索引**”的路子：每层都算注意力，靠压缩和挑选把成本摁下来。

Flash 呢？**45 层里没有一层全量注意力。** 34 层换成了线性注意力（linear attention）——一个和标准注意力从数学上就不同的东西。而且 config 把话说得比任何发布文章都直白：这 34 层的字段名就叫 `kda_layers`。**KDA（Kimi Delta Attention）——Kimi K3 发明的那个线性注意力，连名字都没改**，`head_dim: 128`、`gate_lower_bound: -5.0` 这些参数和 264 期 https://mp.weixin.qq.com/s/W6CUq0xrJP3MdPBXw56v4A 精读 K3 报告时核过的数值逐个对得上。K3 那套“注意力层不加位置编码、位置感交给线性层递归”的 NoPE 做法，也一并搬了过来——上一章那个 `mla_use_nope: true` 的来历就在这。

剩下那 11 层也不是旗舰那种“每层全算”：`kv_lora_rank: 512` 这些字段显示它们保留了 MLA 家族的压缩结构，但上面套着 DSA 的稀疏索引，每次只挑最相关的一批历史 token 来算，不做全量。

标准注意力（包括 MLA 这种压缩版）的成本随上下文长度平方增长，而且每个历史 token 的 KV 都得存着，越聊越贵。线性注意力把这套换成一个**定长的状态**：不管聊了 1 万 token 还是 100 万 token，状态就那么大，新 token 来了更新一下状态，不回头翻旧账。代价是它对久远细节的记忆是有损的——所以没有谁敢全用线性，总要留一部分层能“精确回看”。

官方给的效率数字印证了这个结构：相比旗舰 GLM-5.3，注意力计算量降约 3 倍，**KV 缓存占用降约 4.4 倍**。后一个数字的来源现在清楚了：34 层线性层压根不产生 KV 缓存（它们只有定长状态），全模型只有那 11 层稀疏层需要存 KV。

顺带说清 DSA 这个零件省的到底是什么：**稀疏注意力省的是算力，不是显存**——indexer 只决定“算的时候看谁”，每个 token 的 KV 该存还得存，不然 indexer 都没得挑。所以那 11 层的显存开销和普通压缩注意力层差不多，**4.4 倍的节省全部来自 KDA 层**。另外这个 DSA 是 DeepSeek V3.2 世代的零件：config 里是 `index_topk: 2048` 那套 indexer 挑选结构，V4 用来把 KV 存储本身也压掉的 CSA/HCA（那套 `compress_ratios` 字段）并不在——从公共货架上拿零件，拿的也是上一代的稳定款，最新的还在原厂手里。

所以“Flash 是旗舰的小份”这个读法在这里破产了。**它不是把旗舰的结构缩小，是换了注意力的技术路线**——官方模型卡那句“从全新训练的底座模型开始”说的就是这件事。旗舰还在 MLA 的老路上，新路线拿一条全新的产品线来跑。

────────────────────

💡 线性注意力为什么便宜：不存历史，只存状态

标准注意力像记账：每来一笔（token）都记进账本（KV 缓存），要用时整本翻一遍——账本越厚，翻得越慢，存得越贵。线性注意力像只维护一个余额：新的一笔进来，余额更新一下，旧流水不留。**查余额永远一样快，代价是流水细节找不回来了。** 这套机制的具体实现，Qwen 的 Gated DeltaNet 在 188 期 https://mp.weixin.qq.com/s/jcQlCc3XtaCEEnjUaxw93w 逐个零件读 Qwen3.6-27B 时讲过，Kimi 的 KDA 在上文 264 期讲过，这里不重复。

────────────────────

刚才提到 Qwen，这不是巧合——Flash 的 3:1 配比，别家早就在用了。

◆ 第四章：3/4 线性——三家收敛到了同一个配比

━━━━━━━━━━━━━━━━━━━━

Flash 的 34:11 换算下来约等于 3:1——四层里三层线性、一层非线性。这个配比眼熟：

**Kimi K3**：KDA 线性注意力和 MLA 按 **3:1** 交替，上文 264 期精读过。

**Qwen3.6-27B**：64 层 = 48 层 Gated DeltaNet 线性 + 16 层 GQA 全量注意力，还是 **3:1**，188 期逐层读过这台机器。

**GLM-5.3-Flash**：34 层 KDA + 11 层稀疏，约 **3:1**。

三家中国大厂，混合比例全部落在 3/4 线性上。195 期 https://mp.weixin.qq.com/s/C-vsE_ceIv6FYVzeZWFBYQ 写线性注意力五大战场的时候，这还是各家各自摸索的状态；就这几个月，Qwen、Kimi、GLM 接连把它装上主力开源模型，**配比还收敛了**。3/4 这个数不是谁规定的，是各家分别做消融实验试出来的——线性层再多，“精确回看”的能力就保不住；再少，省下的成本不够看。几家独立试出同一个数，说明这大概就是当前这代技术的平衡点。

国内大厂里现在只剩一个还没上线性注意力的：**DeepSeek 自己**。它在 V4 上走的是另一条路——用 CSA/HCA 把 KV 的存储压到极致，全量注意力的骨架不动。上一章说“最新的零件还在原厂手里”，反过来看也成立：**原厂自己压根没往线性这边走**。两条路线谁对，得等下一代模型见分晓。

而 GLM 比“收敛”更进一步：**它干脆不另造零件**。线性层直接用 Kimi 的 KDA，稀疏层用 DeepSeek 的 DSA，残差流用 DeepSeek 的 mHC——开篇说的“DeepSeek 零件不止一个”，加上 Kimi 的，这台新机器的注意力和残差流，**全部关键零件都来自别家的公开发明，GLM 做的是选型、组合和从头训练**。这在闭源时代不可想象；在开源生态里，发明进了公共货架，比拼的东西从“谁先发明”挪到了“谁组装得好、谁训得动”。

三家的差异落在剩下那 1/4 上。Qwen 的 16 层用 GQA——标准全量注意力的省显存变体；K3 的 1/4 用 MLA——全量注意力的压缩版；**GLM 是三家里唯一连那 1/4 也不给全量的**：11 层在 MLA 压缩之上再叠 DSA 稀疏索引。官方模型卡自称“首个稀疏加线性混合架构的开源前沿模型”，指的就是这件事——别家是“线性 + 全量”，它是“线性 + 稀疏”，整台机器没有一层是完整注意力。

这也解释了为什么它敢把原生上下文做到 1M：全量注意力一层都没有，长上下文最贵的那部分成本从结构上就不存在。

◆ 第五章：视觉塔——GLM-5 系列第一次长眼睛

━━━━━━━━━━━━━━━━━━━━

GLM-5.2、GLM-5.3 旗舰都是纯文本模型。Flash 的 config 里则直接装着一节 `vision_config`——**这是 GLM-5 系列第一个原生多模态模型**，而且是装在轻量档上先发的。

视觉塔的配置也逐项读一下：24 层、隐藏维 1024、16 个头的 ViT（视觉 Transformer，Vision Transformer）类结构，内部代号 `glm5_next_vision`。输入 448×448 的图，按 14×14 的小块切开（patch），再做 2×2 的空间合并；`temporal_patch_size: 2` 说明它连视频都考虑了——时间维上也做了分块。

关键在对接方式：视觉塔的输出维度是 4096，语言模型的隐藏维也是 4096，**两边尺寸原生对齐**，中间过一个中间维 10240 的投影层就接上了。视觉塔和语言模型写在同一份 config 里、一起训练——这是“原生多模态”和“外挂一个 OCR 工具”的区别：前者的视觉信号直接流进语言模型的每一层计算，后者是把图先翻译成文字再喂进去，翻译丢掉的信息追不回来。

官方对这个能力的描述是：模型在 agent 任务里能**自主判断什么时候需要“看一眼”**，并用视觉反馈决定下一步操作——比如操作一个图形界面时，看截图确认按钮点没点上。这正是 agent 从纯文本走向操作真实软件需要的那块能力。

一个要说清楚的空缺：**官方没有公布任何标准多模态基准的分数**（MMMU、MMBench、OCRBench 这些都没有）。视觉能力目前只有定性描述和零星第三方数字，量化的成色还没法下判断。

◆ 第六章：一家三口对照表

━━━━━━━━━━━━━━━━━━━━

把 GLM-5 这一家摆在一起，Flash 的位置就清楚了：

| | GLM-5.2 | GLM-5.3 旗舰 | GLM-5.3-Flash |
|---|---|---|---|
| 发布 | 2026 年 6 月 | 2026-08-14 | 2026-08-26 |
| 底座 | GLM-5 base | **复用 5.2 的 base**，只做后训练 | **全新训练的 base** |
| 注意力 | MLA-256 + DSA/IndexShare | 同 5.2 | 34 层 KDA + 11 层 MLA 压缩叠 DSA |
| 多模态 | 无 | 无 | 原生视觉 |
| 激活参数 | 约 40B（媒体口径） | 同 5.2 | 18B |

这张表里最有意思的一行是“底座”。**旗舰 5.3 才是那个“没换机器”的：它和 5.2 用同一个 base，全部提升来自后训练**——这个“只做后训练就大涨”的故事，282 期 https://mp.weixin.qq.com/s/4aDzx6lxkVxTUSj8NnCSYA 写过，GLM 是三家明说这么干的厂商之一。**反倒是名字最不起眼的 Flash，是从头训了一台新机器。**

版本号的语义在这里完全倒挂了：5.2 到 5.3 是“同一台机器调教了一遍”，5.3 到 5.3-Flash 才是“换代”。按架构差异起名的话，这台机器叫 GLM-6-preview 都不过分——但它偏偏叫 Flash。

为什么这么起名？官方没说，只能给一个合理的猜测：**新路线先拿低价位产品线试**。线性注意力这条路各家都在走，但没人敢直接押旗舰——旗舰要背品牌和大客户，轻量档试错成本低，试成了再往上搬。Flash 这个名字装的不是“旗舰的小份”，是“下一代的先遣队”。
