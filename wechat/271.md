◆ 起因：家用大内存机的模型库不只 V4 一家

━━━━━━━━━━━━━━━━━━━━

前几天 268 期（DeepSeek-V4-Flash-0731 正式版，https://mp.weixin.qq.com/s/EwUO9tVfrpCrcwsyPI42uw ）写完之后，评论区反复出现的一个问题是："家用大内存机能跑的开源大模型，除了 V4 还有别的选择吗？"

回答是有——但先把丑话说前面： **综合智力上，V4 依然是这一档的头牌，Step 3.7 打不过** （Artificial Analysis 的 Intelligence Index 上 V4 是 50、Step 3.7 是 30，差 20 分不是小差距）。 **Step 3.7 唯一真值得关注的点是——它自带视觉编码器，能看图** 。这是 V4 没有、这一档其它主流开源模型也没有的能力。

具体信息： **Step 3.7 Flash** ，阶跃星辰（StepFun）2026 年 5 月底发的开源模型，198B 总参数、约 11B 激活/token，256K 上下文，自带 1.8B 视觉编码器。发布当天登上 OpenRouter Trending 全球第 2，被适配进 Claude Code、OpenClaw、Hermes Agent 这些主流 agent 框架。 **128GB 内存的 Mac / DGX Spark / AI Max+ 395 / 秋天要出的 RTX Spark 笔记本，都能装得下** 。

先把这一档"128G 主机 + 开源大模型"的坐标交代一下——210 期讲过（ https://mp.weixin.qq.com/s/WKVRvtr3wt19w7hJm-no7Q ），这里只汇总一下：

- **128GB 家用大内存机现在有四条路** ：Apple Silicon（M4/M5 Ultra 家族）、DGX Spark（NVIDIA GB10）、AMD AI Max+ 395、以及今年秋天要上的 RTX Spark 笔记本。52 期讲过 DGX Spark / Mac M4 Ultra / AMD 395 三家的横向对比（ https://mp.weixin.qq.com/s/yciCclJW1lhKd4Mz0Ttiwg ）。 **共同特点是统一内存架构 + 128GB 容量，第一次让"家用机跑数百亿参数模型"从"不可能"变成"日常"** 。
- **家用机能跑的开源大模型，最主流的是 DeepSeek V4-Flash-0731**（304B/13B 激活），围绕它的部署生态最成熟——ds4/DwarfStar、mlx-lm 2bit-DQ、SSD 流式加载邪道、DGX Spark 双机 recipe，四条路并行（268 期整理过）。
- **同规模档还有一批开源模型能跑** ，热度和生态成熟度差一档，综合智力也普遍打不过 V4。 **Step 3.7 Flash 是其中最值得单独一提的那个** ——不是因为它更强，是因为它是这一档里 **唯一自带原生视觉编码器的模型** 。这个"能看图"的能力开辟了 V4 覆盖不到的新场景。

这一期就当给 268 期补一条支线： **你的 128G 主机在跑 V4 主力之外，可以留个位置给 Step 3.7 做"看屏幕的那双眼睛"** 。下面聊聊它的定位、架构关键点、以及为什么它综合能力打不过 V4 但依然值得留一个位置。

◆ 1. 阶跃星辰是谁——三句话交代完

━━━━━━━━━━━━━━━━━━━━

阶跃星辰不像 DeepSeek、Kimi 那么大众脸熟，三句话补个背景：

- **成立 2023 年 4 月**，创始人姜大昕在微软干了 16 年做到全球副总裁。和智谱、月之暗面、零一万物、百川智能、MiniMax 并称"大模型六小虎"，2026 年初完成一笔超 50 亿的 B+ 轮融资。
- **首席科学家张祥雨** （ResNet 四位共同作者之一，发表时是微软亚洲研究院实习生，后来做到旷视研究院基础科研负责人；ResNet 就是那个把深度学习从二十几层拉到一百多层的经典工作），CTO 朱亦博原来是字节 AI Infra 负责人。班底比公司名气大。
- **战略押的是"原生多模态 + Agent"** 。Step 3.7 Flash 是这条路线上的最新一发——一个从设计上就为 agent 场景优化的开源模型。

◆ 2. 参数和 V4-Flash 放一起看

━━━━━━━━━━━━━━━━━━━━

| | DeepSeek V4-Flash-0731 | Step 3.7 Flash |
|---|---|---|
| 总参数 | 304B | 198B（含 1.8B ViT）|
| 激活参数/token | 13B | 约 11B |
| 上下文 | 百万级 | 256K |
| 原生多模态 | 否 | 是（含 ViT）|
| 发布 | 2026-07 | 2026-05 |
| 主要卖点 | 超长上下文 + KV 压缩 | agent + 多模态 |

激活参数上两家几乎持平（13B vs 11B）， **总参数上 Step 3.7 比 V4 小 100B** —— **这意味着 128G 内存机上，Step 3.7 的量化模型比 V4 更省空间、加载和推理都更轻** 。V4 的 2bit 量化版磁盘约 90GB，Step 3.7 相应会更小一档，具体等 mlx / GGUF 社区跑分。

**综合智力这块得先把话说明白** ：Artificial Analysis 的公开对比里，V4-Flash-0731 的 Intelligence Index 是 **50** ，Step 3.7 Flash 是 **30** —— **V4 高出 20 分，差距不小** 。上下文 V4 也是 Step 3.7 的近 4 倍（百万 vs 262K），API 价格 V4 还便宜 3 倍。 **换句话说，在"综合能力 + 长上下文 + 便宜"这三条主流指标上，V4 全面碾压 Step 3.7** 。这是硬事实，不粉饰。

那 Step 3.7 值不值得关注？值得—— **但只值得为一件事关注：它能看图，V4 不能** 。你的 128G 家用机上想跑一个能看着截图操作电脑、能看着 UI 做 agent 的开源大模型，Step 3.7 目前是唯一的选择。 **它不是"更强的通用模型"，是"128G 主机上唯一能看图的 agent 模型"** ——功能位不同，谈不上替代关系。

◆ 3. 架构关键点——为 agent 场景专门优化

━━━━━━━━━━━━━━━━━━━━

不做全篇技术精读，只讲两条最有代表性的设计选择——这两条恰好把 Step 3.7 和 V4 的路线差异说清楚了。

**关键点一：注意力用标准 GQA（168 期讲过这一族注意力的演化线，https://mp.weixin.qq.com/s/YqcTnIrGKEYZ2n-sMAelKg ），不做 KV 压缩。**

V4 在注意力这一层的核心创新是 CSA + HCA（Compressed Sequence Attention + Hybrid Cache Attention），把 KV cache 多条压一条—— **V4-Flash-0731 上，FP8 KV 下 100 万 token 上下文只占约 5GB，是传统 GQA 架构的约 2%** 。传统架构里这是几百 GB 的量级，压到 5GB 之后百万上下文在家用机上从"不可能"变成"顺便"（V4-Flash-0731 具体数字 268 期讲过 https://mp.weixin.qq.com/s/EwUO9tVfrpCrcwsyPI42uw ）。

Step 3.7 反过来—— **放弃了 KV cache 压缩这条路** ，注意力用标准 8 头 GQA + 滑动窗口的混合结构：45 层解码层每 4 层一组，1 层全注意力 + 3 层滑动窗口（窗口固定 512 token）。KV cache 没有任何低秩压缩。

**为什么放弃压缩？** 论文原文说得直接：他们评估过 linear attention / 类 MLA 的压缩路线，但这类方案的 state-update 机制会让**投机解码（speculative decoding）** 的 draft tree 并行验证变复杂。标准 GQA 保留了完整的注意力语义，通过 KV masking 就能天然兼容投机解码的并行验证。

**Step 3.7 的赌注是：吐字速度比 KV 存储更值钱** 。它宁可多存一点 KV cache，也要让投机解码跑得顺。官方博客宣传的"最高 400 tokens/s"是在他们云端 H100/H200 集群上跑出来的数字，家用机上按目前社区反馈大概在 15 到 40 tokens/s 之间，看部署方案—— **别拿 400 这个数字当家用机的预期** 。

**关键点二：MoE 路由的稳定性打磨。**

Step 3.7 的 MoE 结构是 288 个路由专家 + 1 个共享专家、Top-8 路由，每 token 激活比例 2.8%（作为对比：V4-Flash 是 256 专家 Top-6，激活比 2.3%）。 **Step 3.7 稍微保守一点** ——不追求极端稀疏，重点放在门控本身的稳定性上：

- **门控打分强制 FP32 计算**（避免低精度下的路由不稳定）
- **打分函数用 sigmoid × 3.0 缩放**（放大信号，让路由决策更清晰）
- **288 个专家 Top-8 的配置**（介于 V4 的 256/Top-6 和更激进方案之间，工程风险小）

**这套配方的意图是"agent 场景下路由不能崩"** ——agent 是长时程任务，一步崩全链条都白干，所以路由稳定性优先级高于稀疏极限。这也和 Step 3.7 整体的"agent 优先"定位一致。

────────────────────

💡 三句话总结架构差异： **V4 是"押上下文长度极限"的工程；Step 3.7 是"押 agent 场景吐字速度和路由稳定"的工程** 。两个都是好工程，只是赌的是不同的未来瓶颈—— **V4 赌"上下文会先爆"，Step 3.7 赌"吞吐延迟才是硬指标"** 。

────────────────────

架构讲完，下面这条是它在 128G 主机圈里最特别的位置。

◆ 4. 独特位置：128G 机上唯一能看图的开源大模型

━━━━━━━━━━━━━━━━━━━━

Step 3.7 在这一档里最独特的地方是—— **它是原生多模态** 。

**V4-Flash 只有语言模型**，你想给它看图，得外挂一个视觉编码器再自己缝合。**Step 3.7 直接内置了 1.8B ViT**（Vision Transformer），发布出来就是一个能读图 + 生成文本的完整模型。128GB 家用机上想跑一个能理解图片的开源大模型，Step 3.7 目前是唯一选择。

**这条对 agent 场景特别重要** ——现在 agent 类应用越来越多需要看截图（自动化操作、UI 理解、文档表格识别、代码截图 debug），语言模型看不到图就要打断链条外挂 OCR / 视觉模型。Step 3.7 一个模型端到端解决，链路更短、延迟更低。

阶跃星辰官方给的 benchmark 里，几个和 agent + 视觉相关的场景 Step 3.7 表现不错：

- **Android Daily**（长时程手机 UI 任务）：Step 3.7 Flash 61.87%
- **ClawEval-1.1**（真实环境日常自主任务）：67.07%
- **SimpleVQA + Search**（视觉问答 + 搜索）：79.16%
- **DeepSearchQA**：F1 92.82%

这些数字是官方数据，需要独立验证——但方向对得上"agent 优先 + 多模态"的定位。 **它不是全能选手，是特定场景专才** 。

◆ 5. 128G 主机怎么跑

━━━━━━━━━━━━━━━━━━━━

Step 3.7 Flash 的部署生态没有 V4 那么繁华（V4 有 antirez 手写 C 引擎、mlx-lm 2bit-DQ 动态量化、SSD 流式加载邪道、DGX Spark 双机四条路），但 **社区量化跟得挺齐** ——GGUF 那边官方 stepfun-ai 自己发了一份，unsloth、bartowski、AesSedai 三家社区版本也上线了。 **下面这张表只列 Q4 及以下的量化档** （Q8 / BF16 是 200GB 起步，128G 内存机跑不动，不在这一档讨论范围）：

| 量化档 | 权重大小 | 128G 内存能跑 | 定位 |
|---|---|---|---|
| UD-IQ1_M | 56.8 GB | ✅ 舒服 | 1-bit，精度损失明显但能塞进小内存 |
| UD-IQ2_XXS | 61.7 GB | ✅ 舒服 | 2-bit 起步 |
| UD-IQ2_M | 61.8 GB | ✅ 舒服 | 2-bit 中档 |
| UD-Q2_K_XL | 65.8 GB | ✅ 舒服 | 2-bit 加强版 |
| UD-IQ3_XXS | 73.6 GB | ✅ 舒服 | 3-bit 起步 |
| UD-IQ3_S | 80 GB | ✅ 舒服 | 3-bit 中档 |
| UD-Q3_K_M | 89.3 GB | ✅ 舒服 | 3-bit 主流 |
| UD-Q3_K_XL | 89.4 GB | ✅ 舒服 | 3-bit 加强版 |
| UD-IQ4_XS | 95.3 GB | ⚠ 勉强 | 4-bit 起步，加上 KV cache 顶到 100GB+ |
| UD-IQ4_NL | 97.3 GB | ⚠ 勉强 | 4-bit non-linear |
| UD-Q4_K_S | 114 GB | ❌ 溢出 | 4-bit 主流，128G 装不下运行时开销 |
| UD-Q4_K_XL | 122 GB | ❌ 溢出 | 4-bit 加强版 |

**判据一句话** ： **权重文件 ≤90GB 那档在 128G 主机上舒服跑，95GB 那档勉强，Q4 主流（114GB 以上）超出** ——因为除了权重本身，还要留内存给 KV cache、上下文、操作系统开销。

**具体到四类 128G 主机**：

- **Mac M4/M5 Ultra 128GB**：走 GGUF（llama.cpp 后端）或 MLX 都行。MLX 那边有 Q4_K_M 版本 100GB 左右，压着内存墙跑
- **DGX Spark 128GB**：走 vLLM 或 llama.cpp（CUDA 后端）
- **AMD AI Max+ 395**：走 llama.cpp（ROCm 或 Vulkan 后端）
- **RTX Spark 笔记本（秋天上市）**：还没实机，按 210 期讲过的架构，走 CUDA 路径不会有问题

**别对速度期望太高** —— 200B MoE 在家用机内存带宽下即使量化能装下，实际吐字速度也远低于云端的 400 tokens/s。 **想尝鲜先看 unsloth 的 GGUF README 上的实测数字，或者 Mac Studio 用户群的口口相传** 。

◆ 6. 合上账本

━━━━━━━━━━━━━━━━━━━━

把这一期讲的东西汇总一下：

- 128G 家用大内存机现在有四条硬件路径（Mac Ultra / DGX Spark / AMD 395 / RTX Spark 笔记本），能跑数百亿参数模型
- 这一档的开源大模型除了 DeepSeek V4-Flash-0731，还有 Step 3.7 Flash 这个选择
- Step 3.7 是阶跃星辰押"agent + 多模态"路线的开源产物，198B / 11B 激活 / 256K 上下文 / 自带 1.8B ViT
- 架构上放弃了 KV 压缩，选择了 GQA + 滑动窗口 + 投机解码优化，赌的是吐字速度而不是上下文长度
- 128G 主机上是这一档唯一能看图的开源大模型
- 部署路径 HF Transformers / mlx-lm / vLLM / llama.cpp 都支持，等社区实测数字

**V4 和 Step 3.7 不冲突，各占一头** ——V4 拼上下文长度，Step 3.7 拼多模态 + agent 场景。 **你的 128G 机器如果只跑一个，选 V4 更主流；如果空间够想双开，Step 3.7 补上"能看图"这块** 。

◆ 技术名词速查

━━━━━━━━━━━━━━━━━━━━

| 术语 | 一句话解释 |
|------|-----------|
| MoE（混合专家） | 参数分成多个"专家"，每个 token 只叫一小撮干活的稀疏架构 |
| 激活参数 | 每生成一个 token 实际计算过手的参数量（不等于总参数）|
| KV cache | 注意力机制存储历史 token 表示的缓存，随上下文长度线性膨胀 |
| GQA（Grouped Query Attention）| 多个 query head 共享一组 KV head，减少 KV cache 体积 |
| 滑动窗口注意力 | 每个 token 只看最近 N 个历史 token，Step 3.7 用 512 |
| CSA / HCA | V4 的注意力压缩机制，把 KV cache 多条压一条（168 期讲过）|
| 投机解码 | 小模型先"猜"几个 token，大模型批量验证，提高吐字速度 |
| ViT（Vision Transformer）| 处理图像的 Transformer 分支，Step 3.7 自带 1.8B ViT |
| 统一内存 | CPU 和 GPU 共用一块物理内存，Apple Silicon / DGX Spark / AMD 395 都是这套架构 |
