◆ 起因：家用大内存机的模型库不只 V4 一家

━━━━━━━━━━━━━━━━━━━━

前几天 268 期（DeepSeek-V4-Flash-0731 正式版，https://mp.weixin.qq.com/s/EwUO9tVfrpCrcwsyPI42uw ）写完之后，评论区反复出现的一个问题是："家用大内存机能跑的开源大模型，除了 V4 还有别的选择吗？"

回答是有——而且这次不是换一颗差不多的文本大脑，而是补上了 V4 没有的一样东西： **视觉** 。Step 3.7 Flash 自带视觉编码器，能直接接收图像；DeepSeek V4 则仍是纯文本模型。在 200B 级、可压进 128GB 统一内存的开源权重里，这个功能位很稀缺。

具体信息： **Step 3.7 Flash** ，阶跃星辰（StepFun）2026 年 5 月 29 日发布的开源权重模型，198B 总参数、约 11B 激活/token，256K 上下文，语言骨干外接 1.8B 视觉编码器。官方已给出 Claude Code、OpenClaw、Hermes Agent 等 agent harness 的兼容性，也发布了 GGUF 和本地部署指南。 **128GB 统一内存的 Mac Studio、DGX Spark 和 AI Max+ 395 已有官方实测** 。

先把这一档"128G 主机 + 开源大模型"的坐标交代一下——210 期讲过（ https://mp.weixin.qq.com/s/WKVRvtr3wt19w7hJm-no7Q ），这里只汇总一下：

- **128GB 家用大内存机现在有四条路** ：Apple Silicon（M4/M5 Ultra 家族）、DGX Spark（NVIDIA GB10）、AMD AI Max+ 395、以及今年秋天要上的 RTX Spark 笔记本。52 期讲过 DGX Spark / Mac M4 Ultra / AMD 395 三家的横向对比（ https://mp.weixin.qq.com/s/yciCclJW1lhKd4Mz0Ttiwg ）。 **共同特点是统一内存架构 + 128GB 容量，第一次让"家用机跑数百亿参数模型"从"不可能"变成"日常"** 。
- **家用机能跑的开源大模型，最主流的是 DeepSeek V4-Flash-0731**（284B/13B 激活），围绕它的部署生态最成熟——ds4/DwarfStar、mlx-lm 2bit-DQ、SSD 流式加载邪道、DGX Spark 双机 recipe，四条路并行（268 期整理过）。
- **同规模档还有一批开源模型能跑** ，热度和生态成熟度各不相同。 **Step 3.7 Flash 最值得单独一提的地方** 不是综合排名，而是它把原生图像输入带进了 200B 级、128GB 单机可部署这个档位。这个"能看图"的能力开辟了 V4 覆盖不到的新场景。

这一期就当给 268 期补一条支线： **你的 128G 主机在跑 V4 主力之外，可以留个位置给 Step 3.7 做"看屏幕的那双眼睛"** 。下面聊聊它的定位、架构关键点，以及这双眼睛在家用机上到底跑得多快。

◆ 1. 阶跃星辰是谁——三句话交代完

━━━━━━━━━━━━━━━━━━━━

阶跃星辰不像 DeepSeek、Kimi 那么大众脸熟，三句话补个背景：

- **成立 2023 年 4 月**，创始人姜大昕在微软干了 16 年做到全球副总裁。和智谱、月之暗面、零一万物、百川智能、MiniMax 并称"大模型六小虎"，2026 年初完成一笔超 50 亿的 B+ 轮融资。
- **首席科学家张祥雨** （ResNet 四位共同作者之一，发表时是微软亚洲研究院实习生，后来做到旷视研究院基础科研负责人；ResNet 就是那个把深度学习从二十几层拉到一百多层的经典工作），CTO 朱亦博原来是字节 AI Infra 负责人。班底比公司名气大。
- **战略押的是"原生多模态 + Agent"** 。Step 3.7 Flash 是这条路线上的最新一发——一个从设计上就为 agent 场景优化的开源模型。

◆ 2. 参数和 V4-Flash 放一起看

━━━━━━━━━━━━━━━━━━━━

| | DeepSeek V4-Flash-0731 | Step 3.7 Flash |
|---|---|---|
| 总参数 | 284B | 198B（196B 语言骨干 + 1.8B 视觉编码器）|
| 激活参数/token | 13B | 约 11B |
| 上下文 | 百万级 | 256K |
| 原生多模态 | 否 | 是（含 ViT）|
| 发布 | 2026-07 | 2026-05 |
| 主要卖点 | 超长上下文 + KV 压缩 | agent + 多模态 |

激活参数上两家接近（13B vs 11B），总参数则相差 86B。但“激活参数更少”不能直接翻译成“家用机上一定更快”：MoE 的实际速度还受权重读取、内存带宽、量化格式和推理后端影响。好在 StepFun 这次没只给参数表，而是直接放出了 128GB 三平台的 GGUF 实测。

**综合能力这块要小心比** 。Artificial Analysis 给 V4-Flash-0731 的推理档打出 **50** 分，Step 3.7 Flash 是 **30** 分；但它同时把 V4 Flash 的非推理档估为 **29** 分。所以“50 vs 30”说明 V4 把深度推理拉到了更高的上限，却不能直接写成两个模型在所有模式下都差 20 分。更稳的结论是： **需要长推理上限时，V4-Flash-0731 更强；不开深度推理时，AA 的综合分反而基本打平** 。

另外两条则没有争议：V4 有 1M 上下文，Step 3.7 是 256K；按 AA 的统一口径，V4 Flash 的 API 每百万 token 加权价格约为 Step 3.7 的三分之一。V4 胜在推理上限、超长上下文和价格；Step 3.7 胜在图像输入与本地部署的完整度。

那 Step 3.7 值不值得关注？值得—— **核心就是它能看图，V4 不能** 。你的 128G 家用机如果想跑一个能看截图、读 UI、再调工具的 200B 级开源模型，Step 3.7 是目前少数已把“模型 + 视觉投影层 + GGUF + 三平台实测”都交齐的选择。 **它不是更强的 V4，而是多了一双眼睛的另一个功能位** 。

◆ 3. 架构关键点——为 agent 场景专门优化

━━━━━━━━━━━━━━━━━━━━

不做全篇技术精读，只讲两条最有代表性的设计选择——这两条恰好把 Step 3.7 和 V4 的路线差异说清楚了。

**关键点一：注意力用标准 GQA（168 期讲过这一族注意力的演化线，https://mp.weixin.qq.com/s/YqcTnIrGKEYZ2n-sMAelKg ），不做 KV 压缩。**

V4 在注意力这一层的核心创新是 CSA + HCA（Compressed Sequence Attention + Hybrid Cache Attention），把 KV cache 多条压一条—— **V4-Flash-0731 上，FP8 KV 下 100 万 token 上下文只占约 5GB，是传统 GQA 架构的约 2%** 。传统架构里这是几百 GB 的量级，压到 5GB 之后百万上下文在家用机上从"不可能"变成"顺便"（V4-Flash-0731 具体数字 268 期讲过 https://mp.weixin.qq.com/s/EwUO9tVfrpCrcwsyPI42uw ）。

Step 3.7 反过来—— **没走 V4 那种低秩 KV 压缩路线** ，注意力用 GQA-8 + 滑动窗口的混合结构：45 层中，每组 1 层全注意力 + 3 层滑动窗口（窗口固定 512 token）。这里的“8”是 8 个 KV heads，不是整层只有 8 个注意力头。

**为什么这么选？** Step 3.5 技术报告的原话是：团队在滑动窗口注意力和线性注意力之间做过选择，后者的 state-update 机制会让**投机解码（speculative decoding）** 的 draft tree 生成和并行验证更复杂；滑动窗口仍保留标准注意力语义，可以用 KV masking 并行验证。这里论文比较的是 **SWA 与线性注意力**，不是对所有“类 MLA 压缩”一概否定。

**Step 3.7 的赌注是：吐字速度比把 KV cache 压到极限更值钱** 。它用 3 层 MTP（多 token 预测）给投机解码打前站。官方宣传的“最高 400 tokens/s”没有给出一个能直接外推到家用机的统一硬件条件，但官方 GGUF 页已经给出了更有用的数字：Q4_K_S 在 128GB M4 Max Mac Studio 上，短上下文生成约 51 tok/s；DGX Spark 约 25 tok/s；AI Max+ 395 约 26 tok/s。上下文拉长后速度会继续掉， **400 tok/s 不是家用机预期** 。

**关键点二：MoE 路由的稳定性打磨。**

Step 3.7 的 MoE 结构是 288 个路由专家 + 1 个共享专家、Top-8 路由。配置文件还明确写了两个很工程化的细节：

- **路由 gate 用 FP32 计算**
- **打分函数是 sigmoid，缩放因子 3.0**
- **288 个专家 Top-8 的配置**（介于 V4 的 256/Top-6 和更激进方案之间，工程风险小）

这些配置与低精度路由稳定性相关，但公开报告没有把“sigmoid × 3.0”单独定性为“agent 长时程不崩”的原因。报告真正明说的稳定性问题，是分布式 expert parallelism 下的路由不均衡会造成慢卡，因此另外设计了 EP-Group Balanced MoE Routing。

────────────────────

💡 三句话总结架构差异： **V4 把工程重心放在百万上下文的压缩上；Step 3.7 把工程重心放在 agent 的端到端延迟上** 。前者用 CSA + HCA 压 KV，后者用 SWA + GQA-8 + MTP 服务投机解码。不是一个追求先进、另一个保守，而是它们在解不同的瓶颈。

────────────────────

架构讲完，下面这条是它在 128G 主机圈里最特别的位置。

◆ 4. 独特位置：200B 级大脑，多了一双眼睛

━━━━━━━━━━━━━━━━━━━━

Step 3.7 在这一档里最独特的地方是—— **它是原生多模态** 。

**V4-Flash 只有语言模型**。**Step 3.7 则带了 1.8B 视觉编码器**（Vision Transformer），再通过一个独立的 4GB `mmproj` 视觉投影文件把图像特征送进语言模型。这里更准确的说法是“官方一体发布的视觉语言模型”，而不是一个不可分割的单体。

**这条对 agent 场景特别重要** ——现在 agent 类应用越来越多需要看截图（自动化操作、UI 理解、文档表格识别、代码截图 debug）。纯语言模型需要另外接 OCR 或视觉模型；Step 3.7 则把这条感知链路收进同一套模型接口。链路更短是肯定的，但端到端延迟是否更低，还要看视觉编码、工具调用和部署后端。

阶跃星辰官方给的 benchmark 里，几个和 agent + 视觉相关的场景 Step 3.7 表现不错：

- **Android Daily**（长时程手机 UI 任务）：Step 3.7 Flash 61.87%
- **ClawEval-1.1**（真实环境日常自主任务）：67.07%
- **SimpleVQA + Search**（视觉问答 + 搜索）：79.16%
- **DeepSearchQA**：F1 92.82%

这些数字是官方数据，需要独立验证——但方向对得上"agent 优先 + 多模态"的定位。 **它不是全能选手，是特定场景专才** 。

━━━━━━━━━━━━━━━━━━━━

◆ 5. 128G 主机怎么跑

━━━━━━━━━━━━━━━━━━━━

Step 3.7 Flash 的部署生态没有 V4 那么繁华（V4 有 antirez 手写 C 引擎、mlx-lm 2bit-DQ 动态量化、SSD 流式加载邪道、DGX Spark 双机四条路），但阶跃这次自己交付了 GGUF、`mmproj` 和三种 128GB 硬件的实测。官方仓库当前给出的主要档位是：

| 量化档 | 权重大小 | 128G 内存能跑 | 定位 |
|---|---|---|---|
| IQ3_XXS | 76 GB | ✅ | 最小的官方档，低 bit 质量损失也最明显 |
| Q3_K_M | 94 GB | ✅ | 在容量与精度之间折中 |
| Q3_K_L | 103 GB | ✅ | 官方已测 128GB 三平台 |
| IQ4_XS | 105 GB | ✅ | 与 Q4_K_S 接近，更省内存 |
| Q4_K_S | 112 GB | ✅ | 官方主推的精度/容量平衡档 |

**之前那条“90GB 才舒服、Q4 会溢出”的经验判据，在这个模型上不成立** 。原因就在混合注意力：只有每四层里的一层需要保留全局 KV，其余三层只留 512 token 窗口。所以 112GB 的 Q4_K_S 仍能在 128GB Mac 上实测到 256K 上下文。

**具体到四类 128G 主机**：

- **Mac 128GB**：官方在 M4 Max Mac Studio 上测了 Q4_K_S，短上下文生成 51.2 tok/s，256K 时降到 9.71 tok/s
- **DGX Spark 128GB**：Q4_K_S 短上下文约 24.8 tok/s；IQ4_XS 测到 256K 时约 8.61 tok/s
- **AMD AI Max+ 395 128GB**：Q4_K_S 短上下文约 26.2 tok/s，64K 时约 15.1 tok/s；Q3_K_L 配 Q8 KV 测到 256K 时约 11.2 tok/s
- **RTX Spark 笔记本（秋天上市）**：还没实机数据，只能说理论上属于相同的 128GB 统一内存档，暂时不把它写成“已验证”

**这批官方数字比“社区大概 15—40 tok/s”更有用** 。它同时说明两件事：200B MoE 在 128GB 家用机上不只是“能加载”，短上下文生成已经可用；但当上下文真拉到 128K/256K，吐字会回到个位数到十几 tok/s。“能跑满 256K”和“跑满了还很快”，是两回事。

◆ 6. 合上账本

━━━━━━━━━━━━━━━━━━━━

把这一期讲的东西汇总一下：

- 128G 家用大内存机现在有四条硬件路径（Mac Ultra / DGX Spark / AMD 395 / RTX Spark 笔记本），能跑数百亿参数模型
- 这一档的开源大模型除了 DeepSeek V4-Flash-0731，还有 Step 3.7 Flash 这个选择
- Step 3.7 是阶跃星辰押"agent + 多模态"路线的开源产物，198B / 11B 激活 / 256K 上下文 / 自带 1.8B ViT
- 架构上没走 V4 的低秩 KV 压缩路线，而是用 GQA-8 + 滑动窗口 + MTP 服务投机解码
- 它在 200B 级、128GB 单机可部署的开源权重里，提供了很稀缺的原生图像输入
- 官方已给出 Transformers / vLLM / SGLang / llama.cpp 路径，以及 Mac、DGX Spark、AI Max+ 395 的 GGUF 实测

**V4 和 Step 3.7 不冲突，各占一头** ——V4 拼上下文长度，Step 3.7 拼多模态 + agent 场景。 **你的 128G 机器如果只跑一个，选 V4 更主流；如果空间够想双开，Step 3.7 补上"能看图"这块** 。

◆ 技术名词速查

━━━━━━━━━━━━━━━━━━━━

| 术语 | 一句话解释 |
|------|-----------|
| MoE（混合专家） | 参数分成多个"专家"，每个 token 只叫一小撮干活的稀疏架构 |
| 激活参数 | 每生成一个 token 实际计算过手的参数量（不等于总参数）|
| KV cache | 注意力机制存储历史 token 表示的缓存，随上下文长度线性膨胀 |
| GQA（Grouped Query Attention）| 多个 query head 共享一组 KV head，减少 KV cache 体积 |
| 滑动窗口注意力 | 每个 token 只看最近 N 个历史 token，Step 3.7 用 512 |
| CSA / HCA | V4 的注意力压缩机制，把 KV cache 多条压一条（168 期讲过）|
| 投机解码 | 小模型先"猜"几个 token，大模型批量验证，提高吐字速度 |
| ViT（Vision Transformer）| 处理图像的 Transformer 分支，Step 3.7 自带 1.8B ViT |
| 统一内存 | CPU 和 GPU 共用一块物理内存，Apple Silicon / DGX Spark / AMD 395 都是这套架构 |
