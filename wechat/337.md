【DeepSeek】换个位置就答错：字节解剖出压缩注意力的“相位盲区”

━━━━━━━━━━━━━━━━━━━━

◆ 开篇：一串等号引发的悬案

━━━━━━━━━━━━━━━━━━━━

先讲一个有点邪门的实验。

研究者让 DeepSeek-V4-Flash 的基础模型补全一段代码——补的就是 DeepSeek 自己开源的推理代码里，一个 FP8 量化函数的最后一个数。按代码逻辑，正确答案应该是 8，最容易混淆的答案是 32。

然后他们做了一件看起来很无聊的事：不改代码，只在开头的注释里增减一串纯装饰的等号。这些等号不影响任何逻辑，只是让后面的内容整体往后挪了几个 token。

结果：等号的数量除以 4，余数是 2 或 3 的时候，模型全部答对；余数是 0 或 1 的时候，几乎全部答错。四个不同的填充家族，64 次测量，规律稳定得像钟表。

同一道题，内容一个字没变，只是整体挪了个位置，模型就从全会变成全不会。

这是字节 Seed 团队联合普林斯顿、斯坦福、伯克利的研究者，9 月底挂出来的一篇论文：**《Periodic Weak Spots: Phase Sensitivity from Chunked KV-Cache Compression》（周期性弱点：分块 KV 缓存压缩带来的相位敏感性，arXiv:2609.36322）**。他们把这个毛病从头到尾解剖了一遍，结论很清楚：这不是 DeepSeek 一家的 bug，是**分块压缩这类架构的结构性代价**。而我们在 308 期（ https://mp.weixin.qq.com/s/Rsx8_ygHyXbN6JI1QTNxMw ）讲过 V4.1 的压缩注意力设计——当时只讲了它省显存的好处，这篇论文正好把代价那一半补上了。

顺带说一句：不少媒体报道里写“错误率 71.3%、正确率 91.5%”，这两个数字论文里其实没有，论文报的是两个候选答案的概率差。媒体的转述方向没错，但读原文的好处就在这。

◆ 第一章：机制——压缩块里的“相位”

━━━━━━━━━━━━━━━━━━━━

先复习一下背景。长上下文最烧钱的部分是 KV 缓存：每个 token 的 key 和 value 向量都得存着，上下文越长占的显存越多。DeepSeek V4 的解法是**压缩稀疏注意力（compressed sparse attention，CSA）**：把连续的 token 按固定窗口打包，每个窗口经过一个门控层打分，压缩成一条“摘要”存起来。显存省了，检索时先查摘要在哪几段，再细看。

V4 的具体参数是：窗口 8 个 token，每隔 4 个 token 开一个新窗口——也就是**步长（stride）是 4**，相邻窗口有重叠。

问题就出在这个“每隔 4 个开一个”上。

标准注意力只关心 token 之间的相对距离：一句话不管放在开头还是结尾，只要词序不变，意思就不变。但分块压缩引入了一个新坐标：**这个 token 落在窗口里的哪个位置**。论文给它起名叫**相位（phase）**——位置除以步长取余数。步长是 4，相位就是 0、1、2、3 四种。

门控层给窗口内每个位置打分的时候，对不同相位是有偏好的：有的相位拿到的权重高，信息被加权保留进了摘要；有的相位权重低，信息几乎被丢掉了。于是同一条关键信息，相位好就答得对，相位不好就答错——这就是**相位敏感性（phase sensitivity）**。

开头那个悬案的答案现在清楚了：等号每多一个，后面代码的相位就挪一格；挪到 0 或 1，关键信息掉进了压缩的盲点槽位，模型就看不见那个决定答案的数了。

◆ 第二章：128K 长文本里量一遍

━━━━━━━━━━━━━━━━━━━━

代码补全只是个引子，论文的主实验是 128K 大海捞针（needle-in-a-haystack，NIAH）：每条输入恰好 12.8 万 token，里面埋了 1.6 万个键值对，问模型第 249 对的值是什么。按目标 key 的相位分 8 组，每组的总长度、查询位置、目标绝对位置全部对齐——唯一的差别就是相位。

| 模型 | 平均分 | 最好相位 − 最差相位 |
| :--- | :--- | :--- |
| V4-Flash 基础版 | 52.6% | **40.2 个百分点** |
| V4-Flash 0731（后训练） | 91.4% | 19.1 个百分点 |
| V4-Pro 基础版 | 72.1% | 34.8 个百分点 |
| V4-Pro 0813（后训练） | 84.4% | 14.8 个百分点 |
| V4.1-Flash 0910（步长降到 2） | 92.4% | **6.1 个百分点** |

这张表有三个读法：

第一，**后训练能缓解，但不能根除**。正式版比基础版好得多，但十几个点的相位差还在。

第二，**V4.1 把步长从 4 降到 2，差距压到 6 个点**——这是 DeepSeek 自己交的答卷，方向对了。但仔细看数据：V4.1 所有偶数相位的成绩仍然全部高于奇数相位。盲区的形状变了，盲区还在。

第三，媒体热炒的“最大差 40 个百分点”是基础版上的数字，你实际用的正式版没到那么夸张。但也别安心——你在长文档里提问时答错，说不定就是关键句子恰好站在了盲相位上。

◆ 第三章：这是通病，不是 V4 一家的病

━━━━━━━━━━━━━━━━━━━━

到这里还只是“发现一个现象”。这篇论文最值钱的部分，是他们证明了这是**结构性的通病**。

做法非常扎实：拿 Qwen3-0.6B 的骨架，从头预训了 26 个模型——23 个带各种压缩变体，3 个全注意力基线，唯一的实质差别就是压缩机制。

结果干净利落：

- **所有压缩模型都出现周期性波动**，最严重的差了 78 个百分点；全注意力基线最多差 6.1 个
- **周期严格等于步长**：步长 4 的模型按 4 波动，步长 6 按 6，步长 8、12 同理——像调收音机一样准
- 把 DeepSeek 的 CSA 核原样移植到 Qwen 骨架上，**照样发病**
- 去掉位置编码（RoPE），波动还在；把可学习门控换成固定的平均分配，波动也还在——不是位置编码的锅，也不是门控没调好

还有一组很耐看的对照。8 个 KV 头的压缩模型和全注意力基线比：**平均分 59.4% 对 61.1%，验证损失也几乎打平**——看总分你会说压缩方案“没什么损失”。但看最差相位组：**9.9% 对 58.4%**。

平均分把盲区完全盖住了。这大概是这篇论文对普通读者最有用的一句话：**评价长上下文能力，平均分是会撒谎的，得按相位分开看。**

◆ 第四章：为什么压缩一定会挑相位站队

━━━━━━━━━━━━━━━━━━━━

现象和通病都立住了，最后一个问题：为什么训练会学出相位偏好？是哪里没调好吗？

论文给了一个挺漂亮的答案：**不是没调好，是训练动力学本来就奖励挑相位。**

他们的理论分析（在简化的归纳任务上证了两条定理）说：

1. 当查询的内容事先不知道时，最优的压缩策略本来就是**集中押注**——每个注意力头选定一个相位，key 全押这个位置、value 全押它后面一个，搭成一组bigram 式的配对。均匀分配反而是次优解；
2. 在梯度下降的训练过程里，这种集中会自我强化、**固化成静态偏好**——一旦某个头在第 1 相位上占了一点便宜，梯度就会让它越来越偏好第 1 相位，最后彻底站队。

实证也对得上：把模型的 KV 头逐个做剔除实验，全注意力模型的各层贡献在所有相位上均匀分布，而压缩模型的不同头确实各管一段相位——有的专管窗口前部，有的专管后部。更直接的因果证据是：把门控参数循环移位 k 个位置，准确率的波动模式就跟着平移 k 个相位。

也就是说，相位盲区不是工程瑕疵，是“压缩 + 梯度下降”这套组合的**自然产物**。想根治，得在架构或训练目标上动手，调参是调不掉的。

论文没有给修复方案——他们给的是评估建议：跨相位测，别只看平均分。V4.1 降步长的做法验证了方向，但 6 个点的残留说明这事还没完。

◆ 尾声：省显存的账单，另一种看法

━━━━━━━━━━━━━━━━━━━━

308 期我们讲 V4.1 的压缩设计时，主题是“省”：KV 缓存压到 1M 上下文不到 1 GB。这篇论文补上了账单的另一半：**省下来的显存，是用位置均匀性换的。**

标准注意力对位置一视同仁，分块压缩则必须挑站位——这是机制的内在属性，不是谁家的工程失误。V4 赶上了，GLM、Kimi 这些同样走压缩路线的架构，这篇论文没测，但 26 个自训模型的对照摆在那儿，通病两个字不是白说的。

对日常使用来说，这事的实际含义有三个：

- 在长文档里问关键问题答错了，先别急着骂模型笨——**把关键段落往前或往后挪几百字再试一次**，可能就对了；
- 做长上下文产品的评测，平均分之外记得看一眼最坏情况；
- 看厂商的长上下文宣传，留个心眼：报的是哪个相位？
