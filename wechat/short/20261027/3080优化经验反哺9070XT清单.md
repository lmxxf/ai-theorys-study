## 一、可直接反哺 9070 XT 且确定性有收益（或消除盲区）的三项改进

### 1. 【第一优先级 / 零风险白捡】为 `0.5x Small` 新模型的 `900p / 720p / free_geometry` 放开 `c256_wave2`（`_w16`）整块融合门控
- **9070 XT 现状证据**：
  在 [`Development/HIP/hip_reference_network.h:794-795`](file:///home/lmxxf/work/ai-theorys-study/wechat/assets/297/Development/HIP/hip_reference_network.h#L794-L795) 中，9070 XT 的 `c256_wave2` 门控至今仍硬编码为：
  ```cpp
  c==256 && ((opt.width==1920 && (opt.height==1152 || opt.height==1088)) || (opt.width==2560 && opt.height==1472 && ...))
  ```
  注释写着：`// C256 whole-block fusion wins at 1080; retain the split PDL path at smaller tiers.`
- **为什么在 `0.5x Small` 模型下变成了漏网之鱼**：
  1. 这条注释是 `2026-09-28` 针对 **Original 71 块旧模型（开启了 PDL 与 6 层 `swin-persistent`）** 测出来的；
  2. 但在 `2026-10-18` 引入并设为默认的 **`0.5x Small`（31 块新模型）** 中，Small 模型**显式禁用了 PDL 和 `swin-persistent`**（见 [`hip_reference_network.h:220,824,991`](file:///home/lmxxf/work/ai-theorys-study/wechat/assets/297/Development/HIP/hip_reference_network.h#L824) 的 `!small_active`）；
  3. 结果导致 **9070 XT 在跑 Small `900p` (`1600×1024`)、Small `720p` (`1344×768`) 和自由分辨率（`free_geometry`）时，4 个 C256 块（Encoder 2 块 + Decoder 2 块）既没走 `swin-persistent` 也没走 PDL，而是退回到了非 W16 的分散双核路径**（每个 C256 块拆成 `mh_ffn_fused_c256_frag_project_g128_qkv_[bytein_]fb` + `c256_attention_project_fb[_bout]_diag` 两次发射，4 个块共发射 8 次 kernel，FFN 权重没用上 `W16` `global_load_b128`，中间还要多读写一次全局显存 `ffn` 和 `producer_norm`）！
- **3080 实测旁证与反哺修法**：
  我们在 RTX 3080 Phase 3 & Phase 10 中对 Small 模型 `900p / 720p / free_geometry` 放开 `c256_wave2`（调用 `c256_wave2_bi_bo_w16` / `c256_wave2_bi_w16`），**输出 100% 逐比特一致（`0 bit-diff`）且直接省下 `0.46 ms`**。回迁到 9070 XT 只需在 `hip_reference_network.h:794` 放宽 `small_active` 下的门控条件。

### 2. 【第二优先级 / 零资源代价新候选】消除 `vit_stream_contract` 与 `vit_stream_project` 尾部的 `32 × global_store_b8` 跨行散写（9070 XT 历史上从未测过！）
- **9070 XT 现状与 ISA 铁证**：
  核查 9070 XT 最新 `v0.45` 的 [`results/gap-refresh-20261023/isa/hip-stats.json`](file:///home/lmxxf/work/ai-theorys-study/wechat/assets/297/Development/results/gap-refresh-20261023/isa/hip-stats.json) 发现，谷底四个 ViT 核心的尾部写出状态如下：

| 核函数（`gfx1201` 模块） | 9070 XT `v0.45` 真实 ISA 状态 | 历史原因与反哺价值 |
| :--- | :--- | :--- |
| **`vit_stream_contract_frag_bstream_bout_compactw_w16`**<br>(`vit-stream-fast.hsaco`) | `VGPR=112, LDS=4096`，每 wave 发射 **`32` 条 `global_store_b8`**（步长 1024B，见 [`deep_fast.hip:808`](file:///home/lmxxf/work/ai-theorys-study/wechat/assets/297/hip/deep_fast.hip#L808)） | **9070 XT 从未测过该核的 LDS 转置宽写**！因为 `09-30` 测 `deep-tail` 时它还是 half 输出（`32×b16`），直到 `10-04 / 10-14` 才变成 1B `bout`。更妙的是该核已自带闲置的 **`4,096 B` `occ_pad` LDS**（[`deep_fast.hip:779`](file:///home/lmxxf/work/ai-theorys-study/wechat/assets/297/hip/deep_fast.hip#L779)），直接复用其中 `1,024 B` 做 `16×64` 片上转置 + 每 lane `2 × global_store_b128` 写出，**0 额外 LDS、0 Occupancy 损失、100% `0 bit-diff`**！ |
| **`vit_stream_project_n64_bb_bout_compactw_w16`**<br>(`vit-stream-fast.hsaco`) | `VGPR=112, LDS=0`，每 wave 发射 **`32` 条 `global_store_b8`**（步长 1024B，见 [`vit_stream.inc:66`](file:///home/lmxxf/work/ai-theorys-study/wechat/assets/297/hip/vit_stream.inc#L66)） | **9070 XT 同样从未测过**（`10-14` `HIP_VIT_INTER_BYTE=15` 才新增 `ByteOut=true` 的 `_bout_compactw_w16`）。当前 `VGPR=112` 对应 12 waves/SIMD，引入 `1,024 B` LDS 在 RDNA 4 WGP 模式下（64KB LDS）**丝毫不降 12 waves/SIMD 的 Occupancy**，可将 32 条跨 1024B 散写压为 `2 × global_store_b128`。 |
| **`vit_expand_blocked_fp8_frag_bytein_w16`**<br>(`deep_fast-packed-fast.hsaco`) | `VGPR=77, LDS=0`，每 wave 发射 **`32` 条 `global_store_b8`**（步长 4096B，[`deep_fast.hip:76,725`](file:///home/lmxxf/work/ai-theorys-study/wechat/assets/297/hip/deep_fast.hip#L725) 的 `VIT_EXPAND_TAIL_VEC` 默认 `0` 未开） | `09-30` 曾在非 W16 旧核上测过 `deep-tail2`（当时 900p `+11µs`、1080p `-4~-6µs` 未收），但 `10-14` 升级 `_w16` 且 `10-18` 切 `0.5x Small` 后未重测，可与前两核一同在 `0.5x Small` 下重测。 |
| **`vit_stream_qkv_frag_bin_w5f8[_vfrag/_qkfrag]`**<br>(`vit-stream-fast.hsaco`) | `_qkfrag`（`10-23` Phase 6 新增）已用 `raw` LDS 转置为 `1 × global_store_b128`；但 `_vfrag`（[`vit_stream.inc:313`](file:///home/lmxxf/work/ai-theorys-study/wechat/assets/297/hip/vit_stream.inc#L313)）在 `part < 2`（Q/K）时仍为 **`16` 条 `global_store_b8`** | `v0.45` 中 `Small 720`、`Small free1088` 等未开 `_qkfrag` 的档位仍走 `_vfrag`，将 `VIT_QKV_TAIL_VEC` 补齐到 `_vfrag` 的 `part < 2` 分支即可全档消除 `global_store_b8`。 |

### 3. 【第三优先级 / 宿主路由与配置防呆】`n <= 256 token` 合并路由至 `400` 桶（享 `_vfrag` 加速）+ 常规包 `OptiScaler.ini` 显式补齐 `[DlssNr] 1.0/1.0`
1. **`n <= 256 token` 路由升级（对应 3080 Phase 14）**：
   - 在 9070 XT 的 [`hip_reference_network.h:916-919`](file:///home/lmxxf/work/ai-theorys-study/wechat/assets/297/Development/HIP/hip_reference_network.h#L916-L919) 中，`n <= 256` 仍路由到 `vit_attention_fused_256_bytein_bout`（`4,520 B` 旧路径），且第 893 行的 `InitVitVFragment()` 只为 `400` 和 `640` 导出了 `_vfrag` 变体，未给 `256` 导出 `_vfrag`。
   - 我们在 3080 Phase 14 已通过 172 项全 token 数穷举与数学证明：`vit_attention_fused_400_bytein_bout` 内核循环上限为动态 `tokens`，对任意 `n <= 256` 与 `256` 桶 **100% `0 bit-diff`**，且代码体积减半（`1,876~2,272 B`）、自带 `_vfrag` 加速。直接把 `n <= 256` 合并路由到 `400` 桶即可让自由分辨率小窗自动享受到 `_vfrag` 快路。
2. **常规包 `OptiScaler.ini` 防脸部闪烁配置（对应 3080 `v0.2.0`）**：
   - 检查发现 9070 XT 的 `OptiScaler-REFramework-DLSS5-AMD-0.44.zip` 已包含 `TransferStrength=1.0 / ColourStrength=1.0`，但 **`OptiScaler-DLSS5-AMD-0.44.zip`（用于《剑星》的常规包）中的 `OptiScaler.ini` 缺失了 `[DlssNr]` 段**。
   - 在 3080 上已证实：若 `TransferStrength` 设为 `1.5`，《剑星》快速转动视角触发 DLSS 5 原生运动遮罩（Control Mask）回退时，1.5 倍高强度重打光与原图反差过大会造成主角脸部明暗闪烁；显式锁定默认 `1.0 / 1.0`（另附 `OptiScaler-增强风格.ini` `1.5 / 1.1`）可避免该问题。

## 二、已核实 9070 XT 自身已达最优或无需反哺的项

1. **全网 41 个生产活跃核 100% 零 Spill（无需像 3080 `V2.1` 那样调上限救栈溢出）**：
   - 扫描 9070 XT 全部 40 个 `gfx1201/*.hsaco` 的 ELF `.note` AMDGPU Metadata 确认：**全部 41 个生产活跃核均为 `vgpr_spill_count = 0`、`sgpr_spill_count = 0`、`private_segment_fixed_size = 0`（100% 零 Scratch 栈溢出）**。
   - 唯一可留作远期探索的 VGPR 占用率点是 `c128_wave2_bi_bo` 与 `c256_wave2_bi_bo_w16`（当前均为 `242 VGPR` → 5 waves/SIMD = 10 waves/WGP；若未来能压至 `<= 192 VGPR` 则可升至 8 waves/SIMD = 16 waves/WGP）。
2. **AMDGPU 后端无 `align 1` 拆散单字节 Bug（无需移植 3080 Phase 6 的 `upgrade_ir_alignments`）**：
   - RDNA 4 硬件原生支持非对齐 `b64 / b128` 访存，`c32-wave1-fast` 与 `c64-wave2-fast` 在 `gfx1201` 下 `global_load_u8 = 0, ds_load_u8 = 0`，天然全是 `ds_load_2addr_b64 / global_load_b128`。
3. **偶奇 K16 零洗牌拆解（`ptx-patcher V2`）与权重离线 FP16 预展开（`Phase 17` / Discord V7）**：
   - 这两项是专门填补 **“RTX 30 系无硬件 FP8 Tensor Core、被迫在运行期把 8-bit E4M3 软件解包为 16-bit FP16 并跨线程洗牌”** 的安培专属补丁；
   - 而 RX 9070 XT (`gfx1201`) 硬件原生拥有满速 **`v_wmma_f32_16x16x16_fp8_fp8`**（单指令直接吃 8B E4M3，405 TFLOPS），天然 0 次洗牌、0 次解包；若在 9070 XT 上把权重展开为 FP16 反而会让显存带宽翻倍、算力减半。
