# 最近很火的 `gpu-unlock` 到底干啥的？——老黄的 `0x88888888` 限速开关、SEC2 固件 ROP 提权，以及它和我们 DLSS 5 的关系

**记录时间**：2026-10-25  
**参考项目**：`https://github.com/Zagitta/gpu-unlock`（短短几天冲上 3,300+ Stars）

这两天 GitHub 上突然火了一个叫 **`Zagitta/gpu-unlock`** 的 C 语言项目，简介只有一句话：
> **“Unlock FP/BF16 instruction issue rate on Nvidia 3000's cards to their professional equivalents”（将英伟达 RTX 30 系显卡的 FP16/BF16 指令发射速率解锁到专业卡水平）。**

实测在一张 RTX 3090 Ti（450W）上跑 $8192^3$ 的 FP32 累加矩阵乘（GEMM）：
- **FP16 输入（FP32 累加）**：从 `87.46 TFLOPS` 暴涨到 **`118.39 TFLOPS`**；
- **BF16 输入（FP32 累加）**：从 `87.50 TFLOPS` 暴涨到 **`157.41 TFLOPS`**（+80%）；
- **TF32 输入（FP32 累加）**：从 `42.58 TFLOPS` 暴涨到 **`82.61 TFLOPS`**（接近翻倍）；
- RTX 3080 / 3070 / 3060 实测 BF16 GEMM 普遍暴涨 **+60%～80%**，跑大模型 Prefill 提速 **+14%～36%**，而且计算结果与解锁前 **逐比特 100% 一致（bit-identical）**。

很多人第一反应是：“难道老黄在 RTX 30 系游戏卡里偷偷藏了一半没通电的硬件单元？”
把 `gpu-unlock` 的内核源码（`kernel/gpu_unlock/`）和逆向文档扒开来看，真相既黑色幽默又极其精彩。

---

## 一、老黄是怎么给 30/40 系游戏卡“限速”的？（没有激光刻断，只有一个 4 比特开关）

在 Ampere 架构（GA102 / GA103 / GA104 / GA106，涵盖 RTX 3060 到 3090 Ti，包括笔记本端的 RTX 3080 Laptop `GA104`）以及随后的 RTX 40 系 Ada Lovelace 架构（AD102 / AD103 / AD104）上，消费级游戏卡和卖几万块钱的工作站专业卡（如 RTX A6000 / RTX 6000 Ada）用的是**完全同一块硅片**，流式多处理器（SM）里面的 Tensor Core 硬件电路一模一样，连激光熔断（Fuse off）都没做。（`Zagitta/gpu-unlock` 主仓针对 30 系 Ampere，社区衍生项目 `JustAResearcher/gpu-unlock-ada` 与 `TOTORONG/AD103_win_unlocker` 则把同一套 SEC2 固件提权解锁扩展到了 RTX 4090 / 4070 Ti Super / 4060 Ti 等 40 系显卡。）

那为什么游戏卡跑“FP16/BF16 乘 + FP32 单精度累加（`.f32.f16.f16.f32`）”和“TF32”时，吞吐量只有专业卡的一半（每 SM 每周期 256 FLOPs vs 512 FLOPs）？

因为芯片的 MMIO（内存映射寄存器）空间里，有两个专门管指令发射速率的硬件配置寄存器——**Speed Selectors（速度选择器 `SS0` 和 `SS1`）**：

| 寄存器名称 | MMIO 物理偏移 | 游戏卡默认状态 | 掌管的指令管线 |
| :--- | :---: | :---: | :--- |
| **`FEAT_OVR_SM_SPD` (`SS0`)** | `0x0082381c` | `0x00000001` | 8 个 4-bit 字段，分别管 `DP`、`FFMA`、`FMLA16`（FP16→FP32 累加）、`FMLA32`（BF16/TF32→FP32 累加）及 `IMLA0–3` |
| **`FEAT_OVR_SM_SPD_1` (`SS1`)** | `0x00823820` | `0x00000001` | 低 4 位 `[3:0]`，掌管 `IMLA4` |

在 `SS0` 和 `SS1` 里，每 **4 个比特（1 个十六进制位）** 控制一条指令管线的发射速度：
- **`bit 3`（最高位）**：是否启用速率覆盖（Override Enable，`1` = 启用覆盖，无视芯片出厂默认限制）；
- **`bits [2:0]`（低三位）**：分频档位：
  - `000` = **满血全速（Full Rate）**
  - `001` = **1/2 半速（Half Rate）**
  - `010` = **1/4 速度**
  - `011` = **1/8 速度**

看懂这个编码规则，你就明白 `0x8`（二进制 `1000`）是什么意思了：**`bit 3 = 1`（开启覆盖）+ `bits [2:0] = 000`（强制满血全速）**！
只要往 `SS0`（`0x0082381c`）写入 **`0x88888888`**（把 8 条管线全设为 `0x8`），再往 `SS1`（`0x00823820`）写入 **`0x8`**，整张游戏卡被老黄砍半的 FP16/BF16/TF32 $\rightarrow$ FP32 累加管线就会当场解除限速，恢复成 RTX A6000 专业卡的满血吞吐量！

## 二、为什么平时改不了这两个寄存器？—— `L0～L3` 硬件权限环与 `FEAT_OVR_PLM`

既然只要往 `0x0082381c` 写个 `0x88888888` 就行，为什么以前没人直接在驱动里写一行代码改掉它？

因为老黄在 GPU 内部设计了一套 **4 级硬件特权环（Privilege Level `L0 / L1 / L2 / L3`）**：
- **`L0`**：宿主机 CPU（包括操作系统内核驱动 `nvidia.ko` / Windows 驱动）通过 PCIe BAR0 发起的普通 MMIO 读写，全都只是最低级的 `L0`；
- **`L3`（Heavy-Secure Mode，重度安全模式）**：只有 GPU 芯片内部的安全协处理器（如 `SEC2` 或 `GSP` Falcon 核）在验证完英伟达官方硬件 RSA 签名、进入 HS 安全模式执行内部固件时，才拥有最高级的 `L3` 权限。

而谁能读写 `SS0` 和 `SS1`，由旁边另一个叫 **`FEAT_OVR_PLM`（Privilege Level Mask，权限级别掩码，地址 `0x00823804`）** 的门卫寄存器管着。
在所有 GA102/GA104 显卡上，`FEAT_OVR_PLM` 的默认值是 **`0xffffff8f`**：
看它的最低字节 `0x8f`（二进制 **`1000_1111`**）：
- 低 4 位 `bits [3:0] = 1111`（读权限掩码）：L0、L1、L2、L3 谁都可以读；
- 高 4 位 `bits [7:4] = 1000`（写权限掩码）：只有 `bit 7`（代表 `L3`）是 `1`，`L0 / L1 / L2` 全是 `0`！

也就是说，当你在宿主机内核驱动（`L0`）里尝试往 `SS0` 写 `0x88888888` 时，GPU 硬件门卫看了一眼 `0x00823804` 里的 `0x8f`，发现 `L0` 没有写权限，直接把你的写请求静默扔进了垃圾桶。

## 三、黑客是怎么砸开门卫锁的？（老黄自摆乌龙泄露密钥 + SEC2 固件栈溢出 ROP）

要想改写 `SS0` 和 `SS1`，就必须在 `L3`（SEC2 安全协处理器的 HS 模式）里执行代码。可 HS 固件有英伟达私钥签名校验，改一个字节都启动不了，怎么进去？

这就引出了整件事最传奇的一段（源自早年解锁 CMP 170HX 矿卡显存与算力的研究链条）：
1. **老黄的乌龙**：早些年英伟达发布驱动固件包时，不小心把加密的 **Debug 版 SEC2 Booter 固件** 和正式版一起放了出来；更要命的是，研究人员发现那份 Debug 固件居然是用一套已知的公开测试密钥方案（Key Index 37）加密的。
2. **挖出带官方签名的栈溢出漏洞**：研究人员解密并反汇编了 Debug 固件，顺藤摸瓜在**有英伟达官方正式签名的某版 Production HS Booter 固件（`610.43.03` 分支）** 里，找到了一个经典的 **栈缓冲区溢出漏洞（Stack Buffer Overflow）**！
3. **四两拨千斤的 ROP 单字写入（`V67 Payload`）**：
   通过往栈上塞入精心挑选的返回地址链（ROP Gadgets，返回导向编程），攻击者可以在 `SEC2` 的 `L3` 重度安全模式下执行一段微型拼图代码（称为 `V67 payload`）。
   但因为栈空间和 Gadget 极其有限，这段 ROP 链只能完成**唯一一次 32 位内存写入**：`MMIO[addr] = val`。
   只有 1 次写机会，却要改 `SS0` 和 `SS1` 两个寄存器，怎么办？
   **答案绝了：不要用这次 `L3` 写机会去改 `SS0`，而是直接用它往门卫寄存器 `FEAT_OVR_PLM`（`0x00823804`）写入 `0xffffffff`！**
   一旦门卫寄存器被 `L3` 改成了 `0xffffffff`（允许 L0～L3 所有级别随便写），宿主机上的 Linux 内核模块（`L0`）就能直接通过普通 PCIe MMIO 往 `SS0` 写 `0x88888888`、往 `SS1` 写 `0x8` 了！
4. **驱动加载前的“无痕交接”（Pre-driver FLR）**：
   以前的方法要么去魔改闭源驱动（每次升级驱动就失效），要么做 UEFI 补丁。`Zagitta/gpu-unlock` 做成了一个放进 `initramfs` 的极早期 Linux 内核模块：
   - 开机时抢在官方 `nvidia.ko` 绑定显卡之前加载；
   - 把那份存在漏洞的老版官方签名 Booter 喂给 `SEC2`，触发 ROP 把 `FEAT_OVR_PLM` 改成 `0xffffffff`，然后由宿主机写好 `SS0 = 0x88888888` 和 `SS1 = 0x8`；
   - 紧接着对显卡发起一次 **PCIe 功能级复位（FLR，Function Level Reset）**——FLR 会把 `SEC2/GSP` 状态洗干净（让后面的新版官方驱动顺利初始化），但**不会重置 `SS0/SS1` 限速寄存器**（只有彻底断电或 S3 睡眠断电才会重置，所以模块还注册了 `PM_POST_SUSPEND` 唤醒回调，睡眠唤醒时花 1 秒钟再解锁一次）；
   - 最后卸载自己，让毫不知情的未修改版官方 `nvidia` 驱动接管一张已经满血的显卡。

## 四、这个解锁对我们的 DLSS 5 项目和日常跑大模型分别意味着什么？

把这个机制和我们昨晚刚做完的 RTX 3080 Laptop DLSS 5 优化对照起来看，特别通透：

1. **为什么我们的 DLSS 5 项目（无论是 `ptx-patcher` 还是 `hip-port` Phase 10）不需要装它就已经是满血全速？**
   - 注意看上面 `SS0` 寄存器掌管的列表：老黄在 `SS0` 里设为半速（`001`）的，是 **`FMLA16`（FP16 乘 + FP32 单精度累加，即 `.f32.f16.f16.f32`）** 和 **`FMLA32`（BF16/TF32 乘 + FP32 累加）**；
   - 而对于 **“FP16 乘 + FP16 半精度累加（`.f16.f16.f16.f16`）”**，因为老黄在发布会上要拿这根管子的数字吹“游戏卡 AI 算力翻倍”，**出厂就是 `000` 满血全速（512 FLOPs/clk/SM），压根没锁**！
   - 昨晚我们在 `hip-port` Phase 1 干的第一刀，就是把原本从 AMD RDNA 4 带来的 `.f32.f16.f16.f32`（撞上 `SS0` 半速锁的指令）全部改成了不撞锁的 **`.f16.f16.f16.f16`**（而且半精度累加器只占 4 个寄存器，比单精度累加器的 8 个寄存器还省一半寄存器空间，帮我们把 `wave2` 和 `c512` 的占用率推上了 12～16 Warp）。
   - 所以在 DLSS 5 里，我们在**软件指令层**已经直接走了未上锁的满速 VIP 通道，普通 Windows 玩家不用刷任何固件或驱动补丁就能跑满全速。
2. **那 `gpu-unlock` 对什么场景真正有用？**
   - **用 30 / 40 系显卡（尤其是 24GB 的 3090 / 3090 Ti / 4090 或魔改 20GB 的 3080）跑大模型 Prefill、微调训练、文生图（Flux / SD）和视频生成**：
     因为 PyTorch / cuBLAS / FlashAttention 里的 BF16 和 FP16 矩阵乘，为了防止长序列大矩阵累加溢出，底层写死调用的全都是 **FP32 累加（`.f32.f16.f16.f32` / `.f32.bf16.bf16.f32`）**——刚好一头撞在老黄的 `SS0` 半速锁上！
     在这些重计算（Compute-bound）场景下，装上 `gpu-unlock` 直接白捡 **30%～80% 的矩阵算力**；
   - 至于大模型单并发逐字生成（Decode），因为卡在显存带宽（Memory-bound）而不在算力，解不解锁速度都差不多。
3. **关于 RTX 40 系（Ada `sm_89`）的解锁分支与 `FP8 (e4m3)` 倍增实测**：
   - 老黄在 RTX 40 系（如 RTX 4090 `AD102`、RTX 4080 SUPER `AD103`）上捅了一模一样的刀子：**只要累加器是 `.f32`（32 位单精度累加），不管输入是 `FP16`、`BF16`、`TF32` 还是 40 系新增的 `FP8 (e4m3)`，在消费级 40 系游戏卡上一律砍半！**
   - 社区顺着同一套 SEC2 Booter（`kgspGetBinArchiveBooterLoadUcode_AD102` 通用覆盖 `AD102~AD107`）提权写 `FEAT_OVR_PLM` 与 `SS0 = 0x88888888` 的思路，衍生出了 `JustAResearcher/gpu-unlock-ada`、`TOTORONG/AD103_win_unlocker` 以及 `Zagitta/gpu-unlock` 的 PR #24 / PR #41。在 PR #41 的 RTX 4080 SUPER 实测（`mmapeak`）中，所有 `.f32` 累加通道（含 `FP8 e4m3`）全线接近翻倍：

| 指令模式（RTX 4080 SUPER `AD103`） | 解锁前（Stock） | 解锁后（Unlocked） | 提升幅度 |
| :--- | :---: | :---: | :---: |
| **`BF16 → FP32` 累加** | `101.2 TFLOPS` | **`198.4 TFLOPS`** | **1.96×（接近倍增）** |
| **`FP16 → FP32` 累加** | `101.5 TFLOPS` | **`202.7 TFLOPS`** | **2.00×（翻倍）** |
| **`TF32 → FP32` 累加** | `50.6 TFLOPS` | **`99.2 TFLOPS`** | **1.96×（接近倍增）** |
| **`FP8 (e4m3) → FP32` 累加** | `201.8 TFLOPS` | **`376.1 TFLOPS`** | **1.86×（接近倍增！）** |
| `FP16 → FP16` 半精度累加 | `202.5 TFLOPS` | `201.8 TFLOPS` | **1.00×（出厂已是满速）** |

   - 这意味着在 40 系显卡上用 FP8（`e4m3` + `.f32` 累加）跑大模型或文生图时，解锁同样能白捡近一倍的 FP8 张量算力！而 DLSS 5 在 40/50 系上用的是 `.f16.e4m3.e4m3.f16`（半精度累加），和表里最后一行 `FP16 → FP16` 一样，出厂本来就是未限速的满血通道。
