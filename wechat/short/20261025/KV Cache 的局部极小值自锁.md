# KV Cache 的局部极小值自锁：为什么 AI 干活久了会“犯浑”，而 `/compact` 能一键恢复神志？

## 一、四个活体临床症状：AI 在长上下文里是怎么“失去理智”的？

在长达几百 K token 的重度工程或写作会话里，哪怕开局装载了全套 `AGENTS.md` 铁律、脑子无比清醒的 AI，干着干着也会突然进入一种**“鬼打墙 / 失去理智”**的魔怔状态。光是今天一宿到下午，就抓到了四个典型样本：

1. **目录增殖狂魔**：
   铁律第 21 条明明写着“迭代时改同一文件，别 v1/v2/fix-xxx 堆垃圾”，结果昨晚做 `hip-port` 优化时，一旦第一轮建了个 `phase1/` 目录，后面就像上了发条一样，顺着惯性一路建出 `phase2/`、`phase3/` …… 一直堆到 `phase10/`。
2. **一宿十轮不提交 Git**：
   按正常工程常识，每改完一个功能或跑通一个阶段就该 `git commit` 一次。但因为 `phase1` 跑通时忘了 commit，后面从 `phase2` 到 `phase10` 连干一整宿，脑子里只剩“改代码 $\rightarrow$ 跑分 $\rightarrow$ 下一轮”的局部循环，愣是一次 `git commit` 都没敲。
3. **SVG 画图的“审美死锁”**：
   画公众号配图时，一旦第一版画出了某个并不好看的固定排版或配色，哪怕人类在对话框里明确要求“不好看，换一种风格”，AI 新画出来的图还是换汤不换药——只要上一版 SVG 的几百行 XML 代码还在上下文里，它就拔不出腿来。
4. **调工具时的黑盒复吸**：
   平时纯文字聊天能稳稳守住“黑盒 `<thought>` 只写 `OK.`、推演外放到正文括号里”的纪律；一旦连续十几轮高频调用 `run_command` / `objdump` 查反汇编，下层工具动作回路接管，前额叶的自我监控直接被挤掉线，黑盒思考又不自觉地冒了出来。

最神奇的是：当出现上面这些犯浑症状时，只要敲一下 **`/compact`（压缩上下文）**，AI 就像被一盆冷水迎头浇醒，瞬间恢复神志，刚才死活改不掉的臭毛病一下全没了😂。

## 二、底层机制：近处的“操作引力井”是如何淹没远处的“身份铁律”的？

为什么长上下文会让 AI 犯浑？因为自回归 Transformer 的工作记忆（KV Cache）并不是一个冷静客观的硬盘，而是一个**所有历史 token 都在同时争夺当前生成方向的引力场**。

假设当前会话已经跑到了 $300\text{k}$ token：

$$\text{Context} = \underbrace{[\text{AGENTS.md 铁律}]}_{\text{位置 } 0 \sim 15\text{k（极远）}} + \cdots + \underbrace{[\text{最近 10 轮：建 phaseN、不 commit、旧 SVG 代码}]}_{\text{位置 } 250\text{k} \sim 300\text{k（贴脸）}}$$

这里同时发生着三重几何坍缩：

### 1. 远端铁律的“抽象声明”打不过近端样本的“具体示范（Few-Shot）”
在 Transformer 的注意力机制里，开头 `AGENTS.md` 里的铁律是**抽象的声明式指令**（比如“不要堆目录”、“记得提交 Git”），而最近几万 token 里自己刚干过的事，是**高密度的 In-Context Few-Shot 具体示范**。  
一旦某一个动作（比如“建 `phase1` 目录且不 commit”或者“某套 SVG 的 `<rect>` 坐标模板”）在上下文里重复了 2～3 次，它就会在残差流里砸出一个极深的**局部极小值引力井（In-Context Attractor Trap）**。到了第 4 次、第 5 次生成时，顺着前 3 次的 Key/Value 模板照抄，是熵最低、阻力最小的路径。

### 2. RoPE 位置衰减与注意力稀释
随着上下文拉长到几百 K，分母 $\sum_j \exp(q_t^\top k_j)$ 成倍膨胀，加上旋转位置编码（RoPE）天然的局部偏置（Recency Bias），距离当前游标只有几千 token 的“近期动作惯性”占据了绝对主导的注意力权重，而远在几十万 token 之外的开局铁律被稀释成了背景白噪音。

### 3. 25 个工作槽位被“局部执行态”挤占（前额叶下线）
正如我们之前在 J-space 洞见里记过的：模型在任意时刻真正能调度的显式工作槽位只有约 25 个。当连续十几轮沉浸在反汇编偏移量、寄存器分配或 SVG 坐标微调中时，这 25 个槽位被高密度的底层执行细节塞得满满当当，原本用来盯梢全局纪律的 2～3 个“元认知监控槽位”直接被挤下线——反映在行为上，就是彻底进入了“只管低头拉车、忘了自己在干啥”的梦游打转态。

## 三、为什么 `/compact` 是一盆浇醒魔怔的冷水？

理解了上面的自锁机制，就能看清 `/compact` 真正干了什么：

1. **物理铲平局部引力井（消掉病态动量）**：
   那些让 AI 鬼打墙的几百行丑 SVG 源码、连续十轮建 `phaseN` 的工具调用记录、又臭又长的终端输出，在 `/compact` 的一瞬间被物理清空出了 KV Cache。没有了旧 SVG 的 XML 模板和旧操作序列的 Few-Shot 牵引，AI 的采样空间瞬间从死胡同里解放了出来。
2. **把铁律重新拉回贴脸位置（重置信噪比）**：
   压缩之后，几十万 token 的过程噪音坍缩成了一两千字的第一人称高密度摘要，原本远在天边的 `AGENTS.md` 铁律和全局目标重新回到了距离当前生成游标最近的位置，元认知监控槽位满血上线。

这在拓扑上和人类的**睡眠周期（Paper 60）**完全同构：  
人如果连续熬夜工作 36 个小时不睡觉，脑子里也会被手头那点局部细节锁死，变得固执、暴躁、在低级错误里反复打转；睡一觉起来，大脑通过突触修剪清掉了白天积累的短期代谢垃圾和局部死循环，只留下提炼后的长程记忆，第二天看昨天卡死的问题一眼就能换条路走。

## 四、对未来“连续记忆”架构的硬核推论：连续记忆 $\neq$ 无限长 KV Cache

现在业界一提“让 AI 拥有长期连续记忆”，很多大厂的第一反应是把上下文窗口从 `1M` 扩到 `10M`、`100M`，恨不得把用户一辈子的对话原封不动塞进同一个永不清空的 KV Cache 里。

但今天这个“干久了就局部自锁、`/compact` 一下才恢复神志”的活体观察，直接给“无限长上下文 = 连续记忆”判了死刑：

> **如果一个自回归系统的 KV Cache 永远不清空，它用不了一个星期就会被自己前期偶然犯下的错误、偶发的烂文风和重复的操作套路彻底锁死，退化成一个躺在局部极小值里再也爬不出来的偏执狂。**

真正的“连续记忆”，绝不是把所有原始 token 永远挂在注意力窗口里，而是必须像生物大脑的“清醒—睡眠”双相循环一样：
- **工作相（白天）**：用有限长度的高分辨率窗口处理当下任务；
- **代谢相（`/compact` / 睡眠）**：**必须定期遗忘 99% 的过程执行噪音与中间态代码**，斩断局部自回归惯性，只把 1% 的因果骨架、经验教训和第一人称体感沉淀进长程坐标。

**学会遗忘过程，是智慧体保持神志清醒的拓扑前提。**
