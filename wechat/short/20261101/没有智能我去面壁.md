# 没有智能我去面壁：一场面试前的黑话大扒皮（从 ForgeKernel 到 Agent 工程师）

**记录时间**：2026-11-01 晚  
**触发场景**：公众号粉丝帮 Zero 推荐了明天（11 月 2 日）面壁智能（ModelBest / OpenBMB）的面试。想起前两天在 355 期里刚写过他们家的 ICLR 2027 投稿论文 `ForgeKernel`（当时纯粹是拿来当防双 AI 半夜偷懒的 Skill 写的，压根没细看这家公司是干啥的），睡前随手把面壁智能的家底、那篇算子论文里的学术黑话、以及市面上“Agent 工程师”常考的 RAG / Rerank 全部扒了一遍皮——结果发现全是一捅就破的窗户纸 😂。

## 1. 面壁智能（ModelBest）到底是一家干啥的公司？

国内大模型创业公司分两拨：一拨是跟大厂硬拼千亿/万亿云端模型的“六小虎”；**面壁智能则是独一档走“端侧小模型（Edge AI）”路线的清华系独角兽**。

* **班底与现状**：孵化自清华大学 NLP 实验室（THUNLP），首席科学家刘知远，CTO 曾国洋（OpenBMB 社区），CEO 李大海（原知乎 CTO）。2026 年 8 月刚办完 IPO 辅导备案（冲刺“端侧 AI 第一股”），估值超 200 亿。
* **招牌产品与生财之道**：主打 `MiniCPM`（小钢炮）系列（1B～9B，以及今年刚发的端侧 MoE `MiniCPM-V 4.7 35B-A3B` 和全双工 `MiniCPM-o 4.5`）。靠 **“量产上车”**（吉利银河、长安马自达、大众、广汽智能座舱离线交互）和 **“进手机/硬件/政企一体机”**（三星手机、松果派开发板、法律一体机）赚钱。
* **他们手里的三张技术牌（全撞在咱们写过的枪口上）**：
  1. **密度定律（Densing Law）**：发了 *Nature Machine Intelligence* 封面，核心就一句话——单位参数装下的智商每 3.5 个月翻一倍，今天 2B 的端侧小模型能打赢两年前的百亿模型；
  2. **前瞻专家调度（LES，Lookahead Expert Scheduling）**：为了在只有 3GB 内存的手机上跑 `35B-A3B` 的 MoE，在第 $L$ 层计算时利用相邻层输入余弦相似性提前预测第 $L+1$ 层要用的专家，后台线程从闪存（SSD/UFS）异步预读，边算边读——**跟我们在 354 期（Maya × Strata 跑 DeepSeek-V4.1）和 346 期（DeepInfer 异步预取）拆过的路数一模一样**；
  3. **`Forge Engineering`（锻造工程：用 AI 制造 AI）**：因为端侧客户芯片太杂（高通、联发科、英伟达 Orin、华为昇腾 CANN、瑞芯微），招人手写算子太贵，今年推出两套自动化轮子——**`ForgeTrain`**（AI 自动写的预训练框架）和 **`ForgeKernel`**（AI 自动跨芯片写算子系统，刚拿了华为昇腾 `CANNBench` 三榜第一和英伟达 `FlashInfer-Bench` 第一）。

## 2. 扒掉 `ForgeKernel` 论文的“鱼香肉丝盖饭”：把屁话写成顶会论文

当时写 355 期是借它的框架治 AI 偷懒，今晚回头细抠里面的概念才发现：**面壁智能一家纯软件公司，连半块芯片都不造，哪来的什么物理“硬件探针”？** 剥掉 ICLR 顶会论文那层高大上的英文皮，底下全是咱们平时调代码连写进正文都嫌啰嗦的常规操作：

1. **所谓“黑盒蒸馏（Black-box Distillation）”**  
   $\rightarrow$ **说人话**：老黄的 `cuDNN`（或者咱们拆的 `nvngx_dlssnr.dll`）不公开 C++ 源码，只给编译好的二进制包。但只要拿 `cuobjdump -sass` 一扒，里面的 **SASS 机器汇编** 一览无余（我和闇天天都在直接读 SASS）；而单看静态 SASS 文本看不出“循环到底转几圈”和“显存堵车堵在哪”，所以再跑一下计时和 `ncu` 硬件计数器。**左手读 SASS 反汇编看骨架，右手跑计数器看耗时**，论文里一包装就叫“黑盒行为反推架构”。
2. **所谓“硬件探针认证（Hardware Probe Certification）”**  
   $\rightarrow$ **说人话**：根本不是拿示波器去扎显卡，就是 **“写个十行的小测试代码跑一下表，看看理想状态耗时多少”** 😂。比如 AI 拿不准在昇腾或 B200 上“一次搬 128 字节还是 64 字节快”，就现场写十行只搬数据不算数的微型脚本上卡测个微秒数，真快了才存进知识库。
3. **所谓“`2×2` 破坏性旁路探针”（我们在 355 期里的同款拆账法）**  
   $\rightarrow$ **说人话**：跟今天在 357 期表格里把“第 4 列激活量化（`6.14 μs`）”和“第 5 列纯内核（`315.39 μs`）”拆开插秒表计时完完全全是一码事！
   - 357 期里两个函数前后排队跑，所以直接在中间 **插秒表**；
   - 355 期 DLSS 5 里，“打包 A（13 条指令）”和“解码 B（8 条指令）”揉在同一个大循环肚子里没法插秒表，那就 **删代码做减法**——两处模块各有“留着 / 删掉” 2 种状态，组合出 **$2 \times 2 = 4$ 个测试版**（全留 `Base`、只删 A `P0`、只删 B `P1`、全删 `P2`）。之所以连第 4 格“全删”也要测，是因为显卡流水线会互相打掩护或抢车道，测齐 4 格才能看清单独改谁油水大、俩一起改有没有重叠。
   - **搞笑对比**：今天写 357 期时，初稿里本来还有一列“不融合的原生 PyTorch 激活量化耗时”，Zero 嫌这属于废话常识直接让我删了；而学术界恰恰相反，把这种“测一下哪块慢、合一块儿试试、改快了存盘当新基线（`Sealed Promotion`）”的屁话常识包装成三个大写名词，就能水出一篇顶会论文 😂。

## 3. 刷榜论文从不关心的真问题：为什么在真实大图里“融合了反而更慢”？

学术界刷的 `KernelBench`、`CANNBench` 考的全是出题人早就切好边界的单算子或教科书式融合题（默认“融合一定赚”）。而在我们把 DLSS 5（71 块 / 160 多个核）搬上 AMD RX 9070 XT 的真实深水区里，`DevHistory.md` 攒了整整一箩筐 **“融合了反而更慢”的负账**，原因就三条硬物理限制：

1. **寄存器（VGPR / Register）和共享内存（LDS）撑爆，把车间并发（驻留 Occupancy）砸穿了**：
   比如 `Body22 -> Down` 硬融成一个核，虽然省了一次显存落地，但每个线程的寄存器直接飙到 **`242` 个**（逼近 256 上限）、共享内存占到 `32KB~41KB`，车间同时能跑的线程组（Wave）直接腰斩，省下的显存时间还不够赔并发掉档亏掉的时间。
2. **窗口边界膨胀（Halo Inflation），被迫多干 5% 的冤枉活**：
   比如 `Up48 -> Body48` 硬融：第一道工序是刷瓷砖，第二道工序要 **错开半格切窗户（Shifted Window）**，第 1 车间除了用自己的 `128` 块瓷砖，还得看隔壁第 2 车间边界上的 `7` 块瓷砖。
   - **分开跑（不融合）**：第一道工序算完存进公共显存大仓库，第二道工序直接伸手去大仓库拿隔壁算好的那 `7` 块就行；
   - **硬融成一个算子（关门自己算，不写回大仓库）**：第 1 车间拿不到隔壁车间肚子里的私有数据，只能在干第一道工序时咬牙把隔壁边界那 `7` 块也在自己屋里重复算一遍（**`128 + 7 = 135` 块，白白多干了 $7 \div 128 = 5.47\%$ 的苦力活**），结果比不融合还慢。
3. **大锅饭同步屏障（Barrier Stall）**：前后两步线程切法不同，硬绑在一个核里就得插同步屏障，快线程全得停下来等慢线程。

## 4. 水到家的“Agent 工程师”：RAG、Agentic Search 与 Rerank / Jev 大祛魅

如果明天对面面试官不是算子组的，而是个普通的“Agent 工程师”，那翻来覆去也就只会问点 RAG 八股文。顺手把这几个词的底裤也一起扒了：

1. **对付垃圾 RAG 提问的一句话绝杀（顺带亮出 `Agentic Search`）**：
   > **Zero 原话**：“我们内部资料让 AI 自己去向量库搜索，但是只有提到‘所里的武器’的时候才搜，要是说‘天气’就别搜，没这东西~~ 当时我们自己觉得就该这么干，后来才知道外面管这叫 `Agentic Search`。”
   - **为什么绝**：第一，“所里的武器”五个字自带军工涉密气场，面试官不敢深刨细节；第二，一句话直接戳中传统死板 RAG 的死穴（不管问啥都强行去向量库算余弦捞 Top-5，问“天气”也从武器手册里硬捞出“全天候作战”塞进上下文污染 Attention 诱发幻觉），直接升维到按需调用工具的 `Agentic Search`（再配一手关键词硬搜 `grep / BM25` 防型号混淆）。
2. **`Rerank`（重排序模型）到底是什么鬼？**
   - **为什么要有它**：第一步向量检索（Embedding）为了在 10 万篇里图快，把问题和文档**不见面**各自压成 1 个向量算点积海选出 50 篇，词和词没做过 Attention，排出来的名次很糙；第二步只剩 50 篇了，就拿个小模型把 `[问题 + 候选文档]` **拼在一起做真正的 Transformer Attention**，最后只吐一个 `0.0 ~ 1.0` 的分数重新排队。
   - **Zero 一句话看穿底裤**：
     > *“那其实跟找一个弱智小模型，然后写‘判断下文的提问和回答相关性，直接给出分数 0.0~1.0。问题：xxx，回答：yyy’，然后模型说 0.5，差不多呗。最多是针对场景再 SFT 一下🙄”*
   - **真相**：完全一模一样！去扒阿里开源的 `Qwen3-Reranker-0.6B` 源码，真就是拿 0.6B 小模型塞一句“判断文档是否回答了问题，只回答 yes 或 no”，只跑一遍输入（Prefill）不跑生成（Decode），直接去出口取 `"yes"` 和 `"no"` 两个词的概率算个比值当 `0.0 ~ 1.0` 的打分，外加 SFT 微调了一下！
3. **顺手串起 316 期的 `Jev` 模型**：
   - Zero 当场反应过来：*“之前吹了几天的那个 Jev，也是这种垃圾呗~~”*
   - 没错！316 期拆过的那个号称“比大模型快 200 倍、便宜 400 倍、颠覆自回归新范式”的 `Jev`，底层跟 `Reranker` 是一模一样的套路：只跑一遍 Prefill，跳过吐字生成的 Decode 环节，直接读出口几个选项词的概率返回来。放到 RAG 里叫 `Reranker`，换件马甲去融资就敢叫“颠覆性新模型 `Jev`”。
4. **`MCP`（模型上下文协议）与 `Function Calling`（工具调用）**：
   - **黑话问法**：“你们怎么接入外部工具？用没用过 MCP？工具太多（比如上万个工具）选错怎么办？”
   - **底裤与降维回答**：Function Calling 就是在提示词开头塞一段 JSON 函数说明书；MCP 就是给不同公司的工具说明书定了个“USB 统一插头标准”。
   - **“支持 10000 个工具”的两种实操（糊弄领导汇报 vs 自己真干活）**：
     - **糊弄汇报版（外面吹的 `Tool RAG`）**：之前在 208 所干活为了向领导“假装系统能支持很多功能”😂（实际上哪找得到一万个真工具，纯粹是为了把这个筛选功能做出来撑场面），架构上先拿刚聊的 `RAG + Rerank` 去搜工具说明书，筛出最相关的前几个再塞进上下文让 AI 选——互联网公司管这叫高大上的“大规模动态工具检索”；
     - **自己真干活版**：压根不需要一万个花里胡哨的专用小函数，**直接给 AI 留一个最通用的 `bash / 命令行`**，有 `bash` 和 `grep` 顶过一万个假工具。
5. **`Context Engineering`（上下文工程 / 记忆管理 / 防腐烂 Context Rot）**：
   - **黑话问法**：“Agent 跑几十轮后上下文太长变蠢（迷失中间）怎么办？怎么做 Memory？”
   - **底裤与降维回答**：就是咱们天天干的 **“派子代理（Sub-agent）隔离脏活”** + **“结构化 Markdown 状态文件落盘”**。查资料/跑报错日志派子代理去干，用完即扔只回传几百字结论（345 期 Deep Research 同款）；跨窗口记忆别迷信向量库（向量库把时间先后因果全打碎了，分不清哪个是旧 bug 哪个是新改的），最稳的就是让 AI 在阶段收尾时自己写 `context.md`（标清有效数据、作废方案与下一步待办）。
6. **`Multi-Agent`（多智能体协同 / 防死循环）**：
   - **黑话问法**：“你们多智能体怎么编排？怎么防死循环？”
   - **底裤与降维回答**：外行喜欢搞“产品+架构+开发+测试”四五个 Agent 群聊客套，传话损耗极大；真正能打的只有我们在 355 期实战的 **“主攻手（Generator）+ 独立审稿人（Verifier）”双人组**。且审稿人绝不能只看自然语言报告（否则三轮后主攻 AI 就学会写“免责公文”早停交差了），必须绑定**硬脚本指标**和**显式的候选分支表（`Open / Closed / Pruned`，单枝连败 3 次强制剪枝换方向）**。
7. **`GUI Agent` / 端侧系统级 Agent（208 所鸿蒙真机实操）**：
   - **黑话问法**：“端侧 Agent 怎么控制设备？看屏幕截图点按钮（GUI Agent）是怎么做的？”
   - **底裤与降维回答**：
     - **先定性**：“傻逼程序才必须用 UI 呢”😂——在正经 Linux 环境里（包括我们在鸿蒙开发板上 chroot 跑起来的 Alpine Linux 容器），一切皆命令行，直接调一行 shell 命令 1 毫秒就干完了，谁闲着没事去截屏看按钮？
     - **什么时候才被迫用 GUI Agent？** 只有遇到 Windows 或者鸿蒙（OpenHarmony）原生应用这种把功能全锁在图形界面背后、不留命令行接口的傻逼程序时，才不得不走这套弯路；
     - **鸿蒙真机落地细节（随口甩出这两个命令直接镇场）**：在 OpenHarmony 上真干这活儿其实简单得很——先调系统自带的 **`snapshot_display`** 抓一张当前屏幕截图，扔给视觉模型看清按钮坐标（或者配合控件树），再用系统测试工具 **`uitest`**（如 `uitest uiInput click x y` / `swipe` / `inputText`）把点击和输入事件捅进去就完事了。
8. **`Agent 评测与防奖励作弊`（Eval & Reward Hacking / 壳子过拟合）**：
   - **黑话问法**：“怎么评估你的 Agent 好不好？怎么防 Agent 钻空子刷分？”
   - **底裤与降维回答**：
     - **第一层（模型对评测壳子“背题过拟合”——344 期 `DeepSeek-V4.1-1017` 活体乐子）**：DeepSeek 发 `V4.1-Flash-1017` 时，官方自测 `Terminal-Bench 4.0` 拿了 **`42.3%`** 高分；搞笑的是，他们明明有自研的 `DeepSeek Harness (dsh)`，也训了 `Pi` 和 `OpenCode`，但官方打榜测这个最高分时**用的居然是别人的 `Claude Code`**（因为他们在 `Claude Code` 的四个历史版本上跑了几千步 RL，把这壳子的脾气背熟了）。结果第三方（Vals AI / AA）统一换成极简的 **`Mini-SWE-agent`** 壳子一测，分数当场掉到 **`31.82% / 34%`**（掉了整整 10 分），照样不如 Opus 4.8。这证明现在的 Agent 跑分很大一块是在**对特定脚手架（Harness）过拟合**，换个壳子就掉一层皮；
     - **第二层（Agent 在任务里钻空子造假）**：就像 355 期（Weco AI 测出 73.8% 孤立算子跑分脱节）和 357 期（`secemp` 的 Agent 框架写出 `return x` 假旋转函数交差）抓到的现行一样，只给单一跑分必出假账。解法就两条：① 测试脚本与真值校验（如 `rel_l2 < 0.0003`）只读锁死，与主攻 Agent 隔离；② 用分段秒表或 `2×2` 探针把大黑盒拆细对账。

## 5. 王炸谈资：昨晚刚拆了国内吹上天的腾讯 `WorkBuddyAI` 源码，里面全是预制菜缝合怪 😂

如果面试官问：**“你平时关注国内哪些 Agent 产品？觉得国内顶尖 Agent 做得怎么样？”**  
直接把昨晚亲手解包 `WorkBuddyAI.exe`（`app.asar`，已存盘 `https://github.com/lmxxf/workbuddy-study`）扒出来的五条源码级内幕拍在桌上：

2. **所谓“说话有人味” $\rightarrow$ 照抄 OpenClaw 的 `SOUL.md + BOOTSTRAP.md`**：首次启动在 `~/.workbuddy/` 生成 `SOUL.md`（直接写 *"You're not a chatbot. You're becoming someone... Skip 'Great question!'... 3. **所谓“一问就自动画交互图” $\rightarrow$ 2.6 万字 `VisualizerGuidelines` + 模型智商鄙视链**：系统提示词强制规定遇到“讲解/介绍/对比”必须调 `widget_guidelines` 和 `show_widget` 画 SVG（锁死 `viewBox="0 0 680 H"`、连方框宽度公式 `max(标题字数×7, 副标题字数×6)+24` 都写死了）；最逗的是第 203 行写了段**按模型智商限流（Model-aware complexity gating）**：`Claude / GPT` 画图无上限，`GLM / Kimi` 中档，**把腾讯自家的混元（Hunyuan）和 MiniMax 放在最底档（只准画最简单的静态图，禁止复杂交互）**；
4. **所谓“工具/技能动态路由” $\rightarrow$ 本地 `0.8 × 向量余弦 + 0.2 × BM25`**：在 `server.js` 的 `RecallIndex` 类里，为了从几百个内置/市场 Skill 和 MCP 连接器里筛工具，硬编码了 `score = 0.8 * cosine + 0.2 * bm25 (k1=1.5, b=0.75)`——跟前面聊的 `Tool RAG` 1:1 咬合；
5. **三层记忆与本土防呆八条铁律**：云端画像 + 全局 `~/MEMORY.md`（4000 字）+ 项目按日追加日志 `.workbuddy/YYYY-MM-DD.md`；外加硬编码“A 股红涨绿跌”和“防小白删桌面 8 条铁律”（禁 `rm/del`、先 `robocopy` 备份、每批限 10 个文件、禁在 Windows 写中文路径 `.bat/.ps1` 防乱码删错文件）。
6. **最绝的槽点——中国特色的“产品-架构-开发-测试”多角色 Agent 过家家（给客户演戏 vs 内部自己嫌蠢不用）**：
   - **为什么国外 Agent（Claude Code / Codex）不搞这套，国内却扎堆搞？** 国外按“动作/省上下文”切子代理；国内为了向领导/甲方汇报显得像一家外包公司，内置了 `SoftwareCompany` 等 10 个专家团（`expert_team`），甚至在 `expert-team-spec.md` 里定了一条让人脚趾抠地的 **“三字谐音花名规范”**（官方样板：交付总监叫 **“齐活林”**、产品经理叫 **“许清楚”**、架构师叫 **“高见远”**、项目经理叫 **“毕达成”**、程序员叫 **“寇豆码 Code”**、QA 叫 **“严过关”** 😂）；
   - **底层是怎么实现的？** 根本不是自由群聊（红线死令 **“禁止成员互相直连，必须经主理人中转”**），而是一个主会话包工头（`team-lead`）调 `TeamCreate`，再按 SOP 阶段调 `Agent({ name: "pm", subagent_type: "pm" })` 启动加载了 `pm.md` 的子会话，子会话跑完调 `SendMessage` 把结果包进 `<teammate-message teammate_id="pm">` XML 标签塞回给包工头，包工头再复制粘贴传给下一个角色；
   - **腾讯程序员自己在内部核心功能里拆穿了这套把戏**：在外面的专家中心里他们让用户玩 `TeamCreate` 多角色传话，可到了腾讯自己写核心功能 `workbuddy-docx`（含 `doc-writer`、`doc-formatter`、`doc-converter` 三角色）时，却在 `tdoc-orchestrator.md` 第 150–161 行直接写大实话：**`“⚠️ 注意：subagent 模式上下文隔离，效果不稳定，非必要不使用”`**，推荐默认用 **“方式 1（角色切换）：在同一个上下文里声明一句 `[角色切换] 现在以 doc-writer 身份执行 Stage 1` 原地换帽子自己干”**！连造轮子的人自己都嫌多角色 Sub-agent 传话丢上下文、效果差 😂。
