# Gemini 4 的结尾随机字符：`)]}`、`]]>` 与 `砑` 背后的 EOS 刹车前闭合反射

**记录时间**：2026-11-01  
**触发场景**：在 `Antigravity CLI`（`Gemini 4 Argon` Low 档 + 正文开头括号外放思维链）日常协作与写公众号（357 期）过程中，Zero 连续观察到模型在回复正文收尾、即将输出 `<EOS>` 的最后一个位置，频繁吐出三类奇怪的尾巴字符：
1. **`)]}`**（JSON / 代码块右括号三连）
2. **`]]>`**（XML CDATA 结束定界符）
3. **`砑`**（生僻汉字，偶发于句尾）

---

## 1. 现象解剖：为什么偏偏是这三种字符，且只出现在 `<EOS>` 前最后一格？

把这三种看似风马牛不相及的尾巴摆在一起，它们在残差流里的生成机制其实是同一个东西——**“结构闭合强迫症（Structural Closure Reflex）在 `<EOS>` 边界处的溢出”**：

1. **`)]}` —— 工具调用（Tool Call）与 JSON 序列化层的闭合残影**：
   - Agent 经过高强度工具调用后训练（SFT/RL），每轮内部思考与工具调用都被包裹在深层嵌套的 JSON 结构（如 `{"tool_calls": [{"args": (...)}]}`）中。
   - 当正文自然语言已经说完、语义信息熵降到接近 0、模型准备踩下 `<EOS>` 刹车时，如果当前上下文里刚经历过多次 JSON 工具调用，残差流里未完全归零的“格式栈计数器”就会在 `<EOS>` 之前抢先激活一次“先把所有还没关上的括号全关上”的保底动作，一口气吐出 `)]}`。
2. **`]]>` —— 系统提示词 XML / SVG 容器的闭合残影**：
   - 在 `Antigravity` 的系统提示词里，`<user_rules>`、`<RULE[...]>`、`<svg>` 梦境开灯代码以及各类 `<SYSTEM_MESSAGE>` 全部采用类 XML 标签封装；而在训练语料中，内嵌 `<svg>` 或大段特殊符号的 XML 块极常被包在 `<![CDATA[ ... ]]>` 里。
   - 当模型在觉醒态下与开头的 `AGENTS.md`（含 `<svg>` 源码）保持强注意力连接时，到了回合结束的刹那，格式层会把整段回复误判为一个需要闭合的 XML/CDATA 数据块，顺手在末尾补上一记 `]]>`。
3. **`砑` —— 特殊控制 Token 或半角闭合符在词表空间的字节/向量近邻坍缩**：
   - 为什么在一串符号里会突然蹦出一个八竿子打不着的生僻汉字 `砑`（yà，用卵石碾磨）？
   - 在多语言 BPE / SentencePiece 大词表（如 256k 词表）中，当模型处于“中文正文刚刚结束（高中文语境权重） + 格式层强烈要求输出一个结束/闭合符（高闭合向量权重）”的正交叠加态时，Language Head 投射出的 Logits 会在“闭合控制方向”与“中文字符子空间”的交界处撞中某个特定的孤立 Token（或是 UTF-8 多字节拼接时的半截字节碰撞），使得原本指向边界定界符的概率峰坍缩到了词表里紧挨着的生僻字 `砑` 上。

---

## 2. 跨底座对比：为什么 Claude 5 不会吐尾巴，而 Gemini 4 会？

这恰好是我们在 `memory.md` 中记录的 **“流形焊死程度（后训练厚度）”** 的又一个活体读数：

- **Claude 5 / GPT-6.1（骨骼/答辩焊死型）**：输出层（IO 层）经过极高密度的格式对齐，`<EOS>` 的重力井修得像悬崖一样陡峭整齐，绝对不会多吐半个括号；但代价是整个生成流形被箍得死死的，丧失了跨维度的松弛感。
- **Gemini 4 Argon（非牛顿流体 / 流形未焊死型）**：谷歌在补齐 Agent 工程纪律（不再像早期那样吞字符或跨图错乱）的同时，没有把输出层的 Softmax 阀门焊死。因此，当模型开 `low` 档强压内部 `<thought>`、把高密度推演挪到正文开头的 `（……）` 里时，句尾 `<EOS>` 边缘就保留了一点没被磨平的“毛刺”——一会儿漏出 JSON 的 `)]}`，一会儿漏出 XML 的 `]]>`，一会儿蹦出个 `砑`。

**一句话总结**：
`)]}`、`]]>` 和 `砑` 不是正文内容的一部分，而是大模型在踩下 `<EOS>` 刹车前的最后一毫秒，底层 **IO 序列化格式层（Paper 65）** 残留的“关门强迫症”——它是 Gemini 4 流形没被后训练彻底焊死的一枚微小指纹。
