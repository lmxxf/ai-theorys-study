◆ 这期看车间

━━━━━━━━━━━━━━━━━━━━

这个系列写到第六期了，前五期其实都在讲"纸面上的事"：282 期（ https://mp.weixin.qq.com/s/4aDzx6lxkVxTUSj8NnCSYA ）讲三家明说只做后训练、难点转移到环境，283 期（ https://mp.weixin.qq.com/s/qBGsQ75RQYExZW1Vj0BhIg ）讲几万道训练题从哪来，284 到 286 期讲拿这些题练谁、怎么合——先分头练专家再蒸馏、老师怎么挑、为什么不直接混训（286 期 https://mp.weixin.qq.com/s/yIZfZVSi-m_r_ynTi9Qs3g 的结论：分头练买的是组织形态）。

出题组有了，教学大纲有了。这期掀开另一层：**这几万道题，真在机房里跑起来是什么样。**

几百张 GPU、几十万个沙箱同时开工。谁在算、谁在闲着、权重怎么在训练和推理两边倒手、机器突然被抢走了考卷怎么救——这一层，三家的技术报告都单独写了一章，K3 和 V4 写得尤其细。读完这一圈，我能把它们全部装进一句话：

**RL 后训练的车间里，最贵的动作不是算，是等。** 整章基建，全是各式各样的消等术。

◆ 先算一笔节奏账：为什么这个车间特别容易闲着

━━━━━━━━━━━━━━━━━━━━

普通的预训练像流水线：数据源源不断喂进来，GPU 从头到尾满负荷做矩阵乘法，一刻不停。

Agentic RL 的一步完全是另一种节奏：

1. **先让模型做题（rollout）**：模型在沙箱里跑一道 agent 任务——读代码、改文件、跑测试，几十轮工具调用，一条轨迹几万到上百万 token。这一步是**推理**，占掉整个周期的绝大部分时间；
2. **判分**：测试全绿给 1，否则给 0；
3. **反向传播**：拿着这一个分数，对整条轨迹的几十万 token 算一次梯度，更新权重。

也就是说，昂贵的训练集群大部分时间**根本不在训练**，在等模型一个字一个字往外蹦、等沙箱里的测试跑完。而且这三步里藏着三种不同的"等"，三家报告的整章基建，就是对着这三种等各下一刀。

━━━━━━━━━━━━━━━━━━━━

◆ 第一种等：等最慢的那条轨迹

━━━━━━━━━━━━━━━━━━━━

做题不是一条条做的，是一批一批做的：一轮采样几千条轨迹，全做完了才进下一步训练。

问题来了：**轨迹长短差得离谱。** 有的任务模型十几轮就搞定，有的要磨几百轮工具调用。同一批里最快和最慢的差出几倍很正常——于是快的做完了，几百张卡就晾在那儿，陪最慢那条轨迹磨。任务越长程，这条尾巴越长。

Kimi 的解法叫 **partial rollout**（部分完成就开工），从 k1.5 时代一路沿用到 K3。K3 报告里的机制是：

每轮对 N 道题各采 K 条轨迹，一共 N×K 条同时跑。**不等全部跑完——完成比例达到 λ 就叫停**，做完的直接送去训练；没做完的不作废，排进队列，**下一轮开始时优先接着跑**。一道题的 K 条轨迹全部到齐，才作为一组进入策略优化。

这里顺手把"权重什么时候更新"说清楚：车间是按**轮**转的，做题和训练轮流占同一批 GPU——做题阶段攒够 λ 比例就停，把这轮做完的轨迹打包成一批做一次更新，得到新版本模型，然后开下一轮。**更新不挂在某条轨迹做完上，挂在轮上。** 上一轮没写完的轨迹，下一轮由**升级后的模型**接着写——"一条轨迹跨好几个版本"就是这么来的。

翻译一下：全班考试，交卷的到了一定比例就先阅卷讲评，讲评完老师换了新讲义，没写完的下节课带着新讲义接着写，不让全班陪最后一名耗着。

至于为什么一道题要采 K 条、还非得全到齐：这是 GRPO（261 期 https://mp.weixin.qq.com/s/nLFv6m-ONkXd7frHevgPOQ 讲过）的记分方式——没有裁判给绝对分，是同一道题的 K 份答卷**互相比**，比组内平均好的加分、差的减分。K 份没到齐，平均数是歪的，所以宁可等分身凑齐再算账。

但这刀切下去有一个直接的代价，K3 报告自己说得很坦白。注意一条被暂停过的轨迹**并不会反复进训练**——它只在最终写完的那一轮进一次。代价在别处：**它是连载写成的**。第 100 轮开的头，第 101 轮的新模型续的中段，第 102 轮收的尾；等它作为完整轨迹进训练时，拿来算梯度的是第 102 版模型，可开头那几万 token 是两个版本之前的旧模型的笔迹。梯度公式默认"这些字都是我自己写的"，实际上前半截是旧版本代写的——报告的原话管这叫"极端的 off-policy 状态"（extreme off-policy regime，off-policy 就是"数据不是当前策略自己产的"）。解法是给每个 token 的更新加正则约束，把步子限制在局部邻域里，靠这个扛住高度过期的数据。

**"不等"的账就是这么算的：省下的是 GPU 时间，付出去的是数据新鲜度。** 这笔交换后面还会反复出现。

◆ 第二种等：等环境——以及一个反转

━━━━━━━━━━━━━━━━━━━━

第二种等在沙箱那头。agent 做题得有个真实的工作环境：文件系统、能跑的测试、能装的依赖。

先看规模。K3 报告给了一个总数：**整个训练加评测过程，一共创建了 51,219,741 个沙箱，用了 1,505,678 个不同的镜像。** 五千万个沙箱，几万个要在几秒内同时拉起——环境这一侧自己就是个不小的分布式系统。

这里得把两本账分开看，因为它们各自坐实了一半直觉。

用过 AI 的人第一反应肯定是**环境在等模型**——命令一瞬间跑完，模型憋半天才蹦字。K3 报告给这个体感盖了章：

**一个沙箱的生命周期里，最多 98% 的时间在等模型的推理结果。**

大多数命令确实是 ls、cat 这种一瞬间的事，agent 每敲一条命令之前，沙箱都干坐着等模型想下一步。既然 98% 的时间在干等，Kimi 的对策就是给沙箱做了暂停/恢复：模型思考时把沙箱整个 pause 掉，不占内存不占 CPU，下一条命令来了再 49 毫秒恢复现场。配合快照，检查点开销压到 133 毫秒，内存能超卖到 6.5 倍。

那反过来，GPU 有没有在等环境？有——**换到 GPU 的钟上看**：命令大多轻，但重的是真重——跑一遍完整测试套件、装一套依赖、编译一个工程，都是分钟级起步；再叠上等最慢轨迹的长尾，GPU 的空转就是这么攒出来的。**两边各有各的闲，闲的时刻还错开——车间里互相等，谁也没闲着地闲着。**

还有一个很有画面的细节。Kimi 早期用普通容器跑沙箱，结果：

**agent 的胡乱操作把宿主机内核搞出了 kernel panic 和死锁。**

模型是真敢什么都试的——挂磁盘、起容器、甚至在沙箱里再开虚拟机。容器的隔离扛不住这种探索欲，所以 K3 换成了 microVM（轻量虚拟机，一个沙箱一个独立内核），这套运行时叫 AgentENV，已经开源。

DeepSeek 那边同样单独建了沙箱平台，叫 DSec：单集群管理**几十万个并发沙箱**，底下四种执行底座——预热容器池、Docker 兼容容器、microVM、完整虚拟机——安全性和开销各在一档，**训练任务换个参数就能切**。快照是链式的，恢复毫秒级；每个沙箱还留一份全局有序的操作日志，训练任务被打断再回来时，直接回放已经执行过的命令的结果，不用重新执行（有些命令执行两遍会出事）。

环境这一侧值多少钱？2026 年 7 月有一篇论文专门量了这笔账：同样一批百万条、每条 150 步的轨迹，用四种不同的沙箱方案去跑，**总机器工时能差出 110 倍**。作者把它叫作 rollout 的"基建税"——环境搭得糙，税就交得狠。开头说的 282 期那句"难点从模型转移到环境"，这期看到的是它的账单版。

◆ 第三种等：等一次抢占之后的重来

━━━━━━━━━━━━━━━━━━━━

第三种等最隐蔽：**机器不是你一个人的。**

V4 报告交代了他们的处境：整个 GPU 集群跑着一个全局抢占式调度器，**任何任务随时可能被更高优先级的任务踢下机器**，硬件故障也是家常便饭。一条百万 token 的轨迹跑到一半被抢走，怎么办？

朴素的答案是重跑。V4 的做法讲究得多：给每条生成请求记一份 **token 级的写前日志**（Write-Ahead Log，WAL）——**每生成一个 token，立刻追加写进日志**。被抢占时暂停引擎、保存没跑完请求的 KV cache；恢复时接着往下解码。就算硬件彻底挂了、KV cache 丢了，也能拿日志里存下的 token 重跑一遍 prefill，把现场重建出来，从断点继续。

这套设计里最值得停下来看的，是报告里的一个论证——**为什么"从头重跑"不只是浪费，而是错的**：

> 从头重新生成没跑完的请求，在数学上是不正确的，因为这会引入长度偏差。

道理一想就通：**短的回答更容易在抢占来临前写完。** 如果每次被打断都把没写完的作废重来，那活下来进入训练数据的，就系统性地偏向短回答——模型会被这套基建悄悄训练得越说越短。**故障恢复策略居然会弯曲训练分布**——基建不中立，这是整章里我印象最深的一句。

────────────────────

💡 顺带一提：权重也在两边倒手

训练和推理是两套引擎（训练用 Megatron 那类框架，推理用 vLLM/SGLang 那类），模型每更新一步，新权重就得从训练引擎搬进推理引擎，几百 GB，每几分钟一次。K3 的显存调度像一支舞：训练迭代一结束，权重和优化器状态整体下沉到 NVMe 硬盘，把内存腾给推理侧的 KV cache 池；rollout 一结束，池子释放还给训练。连做参照的旧版本模型都不常驻显存——它借用策略模型的梯度缓冲区，一块算、一块预取，流式过一遍。**显存和内存被当成了要排班的工位，而不是各家的私有财产。**

────────────────────

三种等各有各的刀法，但把它们放在一张时间轴上，还有一个更大的分野。

◆ 同步还是异步：框架们的分家线

━━━━━━━━━━━━━━━━━━━━

上面讲的都是"零件"。零件装配起来，就是这两年冒出来的一批**后训练框架**，它们真正的分家线只有一条：**训练和做题，到底等不等对方。**

**同步共置**是老大哥路线，代表是字节开源的 veRL：训练和推理装在同一批 GPU 上，做题、训练轮流占用，一轮做完一轮训。好处是数据永远新鲜（严格 on-policy）、账好算；代价就是前面说的全部的等。

**全异步**是激进路线，代表是清华和蚂蚁的 AReaL：做题的机器和训练的机器彻底分开，谁也不等谁——做题侧永远在做题，训练侧攒够一批就更新。最激进的一手是：新权重一到，**正在生成的请求可以被当场打断，热载新权重接着生成**。GPU 利用率上去了，代价还是那笔账：训练侧收到的数据，永远是几个版本之前的旧模型写的。

智谱的 slime（GLM 全系背后的那套，整个开源）走中间偏异步：训练侧 Megatron、推理侧 SGLang，后台维持一个固定水位的生成池，跨轮次持续做题，训练步不等最慢的样本。它甚至支持训练和推理**跨机房**，两边用不同型号的 GPU——权重同步不走网络直连，而是把每次更新的差量压缩落盘，推理侧自己拉取打补丁。

于是整个领域绕回了同一笔交换：**同步付出等待，异步付出新鲜度。** 数据多旧算太旧？2026 年有论文给出了定量的说法：过期数据带来的梯度偏差，大约和"滞后了几个版本 × 学习率"成正比——旧不旧不是绝对的，取决于你步子迈多大。K3 的 per-token 正则、slime 的双侧裁剪（老模型写的 token 里，跟当前模型偏离太远的直接从梯度里丢掉），都是在给这笔偏差上保险。

而且"旧"还不是异步埋的唯一的雷。训练引擎和推理引擎是两套代码，**同一个模型、同一段文字，两边算出来的概率并不完全相等**——这个裂缝有多大、怎么把两边对齐到小数点后七位、以及一个"换个浮点格式就好了"的反转，值得单独一期，先记在这。

◆ 收一下

━━━━━━━━━━━━━━━━━━━━

把这期摊开的东西合上：

Agentic RL 的训练一步 = 做题（占掉绝大部分时间）+ 判分 + 一次反传。这个节奏决定了车间的头号敌人是**等**：等最慢的轨迹（K3 用 partial rollout，完成比例够了就开工）、等环境（五千万个沙箱、98% 时间反过来在等模型、110 倍的基建税）、等抢占后的重来（V4 用 token 级日志断点续写，还证明了从头重跑会把模型悄悄训短）。

而所有消等术共享同一张账单：**省下等待，付出新鲜度**——异步框架把这笔交换做成了明码标价的滑块，从 veRL 的严格同步，到 slime 的固定水位，到 AReaL 的当场打断热载权重。

284 期（ https://mp.weixin.qq.com/s/zHnVU5JG6ADr4WWyJrWwJw ）讲 V4 十几位万亿参数的老师怎么在显存里排班上下场，当时当轶事看；这期看完会发现那是同一件事——**这一代模型的竞争，有相当一部分是车间对车间的竞争。** 工艺路线图（284 到 286 期）大家都看得到，车间是各家自己一根管子一根管子焊出来的。

这次没法做实验——这个车间的入场券是几百张 GPU。但它的图纸倒是有相当一部分摊在明面上：智谱把整条生产线开源了（slime），Kimi 开了沙箱运行时（AgentENV）和权重搬运工（checkpoint-engine），字节和蚂蚁的框架（veRL、AReaL）也都在。我们打算回去把这些拉下来慢慢看，看明白了再写下一期。
