## 阅读前先建立一张「主干图」（面试万能框架）

主流 VLM（视觉语言模型）几乎都是这条流水线，先把它记死，任何架构问题都能往上套：

```
图片 → [视觉编码器 Vision Encoder] → 一堆视觉 token
      → [投影层 Projector/Connector] → 对齐到 LLM 的词向量空间
      → 和文字 token 拼在一起 → [大语言模型 LLM] → 输出文字
```

一句话背下来：**「编码器抽特征，投影层做对齐，LLM 做推理。」** 面试官问任何模型，你都先说这句，再说它在哪一环做了不一样的事。

## 主题 1：视觉编码与对齐

| 术语 | 机制（输入→操作→输出） | 面试为什么问 |
|---|---|---|
| **ViT（Vision Transformer，视觉 Transformer）** | 输入一张图 → 切成固定大小的小块（patch，如 14×14 像素）→ 每块拉平做线性变换成一个向量 → 当成 token 序列喂进 Transformer → 输出每块的特征向量。它把「图像」变成了「token 序列」，这是 LLM 能吃图的前提。 | VLM 的视觉编码器几乎全是 ViT 系。问你「图片怎么进 Transformer 的」，答案就是 patch 化。 |
| **patch embedding（图块嵌入）** | 上一步里「切块→线性变换成向量」这个操作本身。一张 224×224 的图、patch=14，就切成 16×16=256 个 patch，即 256 个视觉 token。 | 直接决定「一张图占多少 token」，和后面 token 压缩、长上下文强相关。面试常让你算 token 数。 |
| **视觉 token（visual token）** | 图像经编码后得到的那一串向量，每个对应图上一小块区域，和文字 token 平级，一起排进 LLM 的输入序列。 | 「一张图等于多少个文字 token」是高频问题——高分辨率图动辄上千 token，直接吃掉上下文预算。 |
| **视觉编码器（vision encoder）** | 把原始像素变成视觉 token 的那个网络，通常是预训练好的 ViT（如 CLIP-ViT、SigLIP、InternViT）。多数 VLM 训练时先冻结它。 | 问「你用哪个 encoder、为什么冻结」。冻结是因为它已在海量图文上学好了通用视觉特征，省算力也更稳。 |
| **CLIP（Contrastive Language-Image Pre-training，对比式图文预训练）** | 输入海量「图-文」配对 → 一个图像编码器、一个文本编码器分别编码 → 训练目标：让配对的图和文在向量空间里靠近、不配对的推远（对比学习）→ 输出一个「图文语义对齐」的图像编码器。 | CLIP 的图像编码器是无数 VLM 的默认视觉底座。面试问「为什么 CLIP 特征适合喂给 LLM」——因为它天生就和语言对齐过。 |
| **SigLIP / SigLIP-2** | CLIP 的改进版，把对比学习的 softmax 损失换成 sigmoid 损失，训练更稳、效果更好。Qwen3-VL 用的就是 SigLIP-2 做视觉编码器。 | 显示你跟得上最新模型。能说出「Qwen3-VL 换成了 SigLIP-2」就是加分项。（核实：见下方 Qwen3-VL 来源） |
| **投影层 / 连接器（projection layer / connector / adapter）** | 输入视觉 token（维度、语义空间和 LLM 的词向量对不上）→ 一个小网络（最简单就是一两层 MLP 多层感知机）做映射 → 输出「假装成词向量」的视觉 token，LLM 就能直接读。 | 这是 LLaVA 式架构的灵魂。面试问「视觉和语言怎么打通的」，答案就是这层。它参数量小、训练便宜，是常见的「只训这一层」的对象。 |
| **模态对齐（modality alignment）** | 让「视觉表示」和「语言表示」落在同一个可互相理解的空间里的过程/目标。手段包括 CLIP 式对比预训练、投影层映射、图文对齐预训练等。 | 是整个多模态的核心命题。对齐不好 → 模型「看到」和「说出」对不上 → 幻觉。 |

## 主题 2：主流架构范式

| 术语 | 机制（输入→操作→输出） | 面试为什么问 |
|---|---|---|
| **LLaVA 式（encoder + projector + LLM）** | 视觉编码器（CLIP-ViT）→ 投影层（MLP）→ 视觉 token 当成新词直接拼进 LLM 输入序列。LLaVA 本体：CLIP ViT-L/14 + MLP + Vicuna。训练分两段：先只训投影层做对齐，再做视觉指令微调。 | 最主流、最好讲的范式，也是开源基线。几乎必问。记住「拼接式 / decoder-only 融合」这个标签。 |
| **Flamingo 式（cross-attention 注入）** | 视觉特征先经 **Perceiver Resampler（感知重采样器）** 压成固定数量的 token → 在冻结的 LLM 层之间插入**门控交叉注意力（gated cross-attention）**块 → LLM 通过 cross-attention「回头看」视觉特征。原 LLM 层冻结，只训新插入的 cross-attention 层。 | 和 LLaVA 是两条技术路线的经典对比。面试爱让你比：Flamingo 不把视觉塞进主序列（省 token、擅长少样本），LLaVA 直接拼进序列（简单、对齐强）。 |
| **拼接式 vs 交叉注意力式** | 拼接式＝视觉 token 进主序列（LLaVA/Qwen-VL/InternVL 多走这条）；交叉注意力式＝视觉在旁路、LLM 靠 cross-attention 取用（Flamingo、Llama-3.2-Vision 部分设计）。 | 这是「两大流派」问题的标准答法。拼接式简单主流但吃上下文，cross-attn 省序列但改动 LLM 结构。 |
| **早期融合 vs 后期融合（early fusion vs late fusion）** | 早期融合：像素/低层特征阶段就把模态混在一起，端到端一起训（越来越多「原生多模态」走这条，如 Llama 4 的思路）。后期融合：各模态各自编码到高层，最后才用 MLP/拼接合并。**注意**：LLaVA 这种「编码后拼 token」严格说介于两者之间，面试别说死，讲清「在哪一层融合」即可。 | 高频概念题。核心是「融合发生得越早，模态间交互越充分，但训练越贵、越难」。 |
| **原生多模态（native multimodal）** | 从预训练一开始就用文字＋图＋视频＋... 多模态数据端到端联合训练，而不是拿训好的文本 LLM 事后「贴」一个视觉模块。InternVL3 就强调 native multimodal pretraining（联合学文本、图文、视频、GUI、3D）。Gemini 从设计上就号称原生多模态。 | 「为什么原生多模态比拼接式强」是陷阱题，见主题 6。能说出「InternVL3 是原生预训练」很加分。 |
| **Qwen-VL / InternVL / Gemini 架构差异（一句话各表）** | Qwen 系：ViT 编码器 + 投影 + Qwen LLM，主打任意分辨率＋M-RoPE，Qwen3-VL 换 SigLIP-2、加 DeepStack。InternVL 系：ViT-MLP-LLM 模块化，自研 InternViT + 448×448 切块动态分辨率 + 原生多模态预训练。Gemini：闭源，号称原生统一处理文/图/音/视频。 | 面试问「你了解哪些主流 VLM、区别在哪」。上面一句话一个即可，别硬背参数。 |

## 主题 3：视觉 token 处理（高分辨率与省 token）

| 术语 | 机制（输入→操作→输出） | 面试为什么问 |
|---|---|---|
| **动态分辨率 / 任意分辨率（dynamic / any resolution）** | 传统 ViT 只吃固定尺寸（如 224×224），会把图硬压变形。任意分辨率：按图的原始长宽比灵活切 patch，输入多少像素就产出多少 token，不失真。Qwen2-VL 起主打这个。 | 直接影响 OCR、小字、细节识别。面试问「怎么处理超高清/长图」，这是答案的第一层。 |
| **图像切块 / 平铺（tiling）** | 一张大图 → 切成若干固定尺寸的子块（tile，如 448×448）→ 每块单独过编码器 → 所有块的 token 拼起来，通常再附一张缩小的全图。InternVL 系典型做法。 | 是「高分辨率怎么塞进只认小图的编码器」的工程答案。会讲 tiling 说明你懂落地细节。 |
| **AnyRes（任意分辨率切块）** | tiling 的一种具体方案：把高清图动态切成适配编码器的固定块分别编码，再连同一张低分辨率全图一起送进 LLM——既看清局部又不丢全局。 | LLaVA-NeXT 等用它。术语本身常被直接甩出来，听得懂就不慌。 |
| **token 压缩 / 池化（token compression / pooling）** | 输入一大堆视觉 token（高清图可能几千个）→ 用池化、Perceiver Resampler、或 pixel-shuffle 等把数量压小 → 输出少量但信息密的 token。 | 上下文和推理成本的命门。面试问「视觉 token 太多怎么办」，答压缩/池化，并权衡「省算力 vs 丢细节」。 |
| **pixel shuffle（像素重排下采样）** | 把空间上相邻的若干 patch 特征在通道维拼接，用「空间换通道」把 token 数量成倍减少（如 InternVL 把 token 数降到 1/4）。 | InternVL 系常用的压 token 手段，能报出来是细节分。 |

## 主题 4：训练范式

| 术语 | 机制（输入→操作→输出） | 面试为什么问 |
|---|---|---|
| **多模态预训练（multimodal pre-training）** | 用超大规模图文/视频数据，让模型学到通用的跨模态表示，为后续微调打底。 | 「训练分几个阶段」的第一阶段。要能说出「先预训练学通用能力，再微调学听指令」。 |
| **图文对齐预训练（image-text alignment pre-training）** | 输入大量图-文对 → 训练目标是把视觉表示对齐到语言空间（常只训投影层，冻结编码器和 LLM）→ 输出一个「看得懂图」的对齐层。LLaVA 第一阶段就是这个。 | 高频。要点：这一阶段主要在训投影层/对齐，不是让模型学会聊天。 |
| **视觉指令微调（visual instruction tuning）** | 输入「图＋指令＋理想回答」的指令数据（如「描述这张图/回答关于图的问题」）→ 微调模型 → 输出会听人话、能对图做问答的模型。LLaVA 第二阶段，用约 15 万条指令数据。 | 这是 LLaVA 的招牌贡献，几乎必考。一句话：**让 VLM 从「看得懂」变成「听得懂指令」。** |
| **多模态 RLHF / DPO（人类反馈强化学习 / 直接偏好优化）** | RLHF：用人类偏好训一个奖励模型再强化学习对齐。DPO：跳过奖励模型，直接用「好回答 vs 坏回答」的偏好对做优化，更简单稳定。在 VLM 里常用来压幻觉、让回答更贴图。 | 问「怎么减少 VLM 幻觉/让它更贴图」，DPO 是热门答案（如用 M3ID+DPO 显著降幻觉，见主题6来源）。DPO 比 RLHF 好讲，重点记它。 |

## 主题 5：视频 / 长上下文多模态

| 术语 | 机制（输入→操作→输出） | 面试为什么问 |
|---|---|---|
| **视频帧采样（frame sampling）** | 视频 = 一堆帧，全塞进去 token 爆炸 → 按固定/动态帧率抽取关键帧 → 每帧当图片编码成视觉 token。抽太稀丢信息，抽太密炸上下文，是核心权衡。 | 「视频那么长怎么喂进模型」的第一答案。必然追问帧数与 token 预算的权衡。 |
| **时序建模（temporal modeling）** | 让模型知道帧之间的先后顺序和运动关系，而不是把视频看成一堆无序图片。常靠给每帧打时间位置编码来实现。 | 视频理解和图像理解的本质区别就在「时序」。问你视频比图片多了什么，答时序。 |
| **M-RoPE / 多模态旋转位置编码（Multimodal RoPE）** | 把普通 1D 的 RoPE 拆成**时间、高、宽**三个分量：图片给它高/宽坐标、时间恒定；视频里时间分量随帧递增。这样一套位置编码同时表达「图上哪个位置」和「视频第几帧」。Qwen2-VL 提出，Qwen3-VL 用 interleaved-MRoPE 增强。 | 「多模态里的位置编码怎么做」是硬核考点（见主题6）。能说清「拆成时/高/宽三分量」直接碾压。 |
| **音频模态（audio modality）** | 音频 → 音频编码器（如基于 Whisper 的）编码成 token → 和图/文/视频 token 一起进 LLM。Qwen2.5-Omni 等「全模态（omni）」模型会同时处理音视频，并做音视频时间对齐。 | 面试若涉及「any-to-any / 全模态」会问。知道「音频也是先编码成 token 再拼进去」这条主线就够。 |

## 主题 6：常见面试考点与陷阱

| 术语 / 问题 | 机制 / 答法 | 面试为什么问（陷阱在哪） |
|---|---|---|
| **VLM 幻觉（hallucination in VLM）** | 模型说出图里根本没有的东西。根因：**过度依赖语言先验（language prior）**——LLM 太强，图没看清就靠「文字常识」编。缓解：更好的对齐、抗幻觉解码、DPO/RLHF、增强 grounding。 | 几乎必问。陷阱是只说「模型瞎编」；要点出「语言先验压过视觉证据」这个根因。 |
| **OCR 能力（光学字符识别）** | 让 VLM 读出图/文档里的文字。强依赖**高分辨率**——字小，分辨率不够就糊。所以任意分辨率、tiling、少压 token 都是为它服务。 | 落地高频需求（票据、文档、GUI Agent）。会把它和「动态分辨率/token 压缩的权衡」串起来问。 |
| **定位 / 接地（grounding）** | 不只说「图里有只狗」，还能指出**狗在哪**（输出边界框坐标 bounding box）。做法：训练时喂「文字描述↔坐标」数据，让模型学会输出坐标。 | Agent / 指哪打哪场景刚需（尤其你的 GUI Agent 背景！）。面试可能直接结合你的 OpenHarmony Agent 经历问。 |
| **为什么原生多模态比拼接式强（陷阱题）** | 拼接式是拿训好的文本 LLM 事后贴视觉模块，模态交互浅、视觉常是「二等公民」；原生多模态从预训练起就联合学，跨模态融合更深、更均衡。**但要补一句**：原生的代价是训练贵、数据难、易翻车，拼接式工程上更快更省——不是无脑说原生好。 | 陷阱在于诱导你一边倒。加上权衡（成本/风险）才是成熟答案，正合你 CLAUDE.md 的权衡矩阵思路。 |
| **模态坍缩（modality collapse）** | 训练时模型偷懒，只用其中一个模态（通常是更好学的文字）就把损失降下去，导致另一模态（视觉）几乎没被真正用上、被「忽略」。表现之一就是严重幻觉。 | 偏冷但显功底。能说出「模型退化成只靠文字、无视图像」就够，并关联到幻觉。 |
| **多模态里的位置编码（position encoding）** | 文字是 1D 序列，图像是 2D、视频是 3D（时+空）。难点：**怎么在一套位置编码里同时表达文字顺序、图上二维位置、视频帧时序**。主流答案是 M-RoPE，把 RoPE 拆成时/高/宽三分量（见主题5）。 | 硬核考点，能筛掉只会背概念的人。记住「1D 文本 vs 2D 图 vs 3D 视频，用 M-RoPE 三分量统一」。 |

## 主题 7：2025–2026 最新趋势（联网核实，见文末来源）

| 术语 | 机制 | 面试为什么问 |
|---|---|---|
| **统一理解与生成（unified understanding & generation）** | 让**同一个模型**既能「看图答题」（理解）又能「按文字画图」（生成），而不是理解、生成用两套模型。代表：Janus-Pro、BAGEL。技术难点：理解偏自回归、图像生成偏扩散，两种范式怎么统一。 | 2025–2026 最热方向之一。能点名 Janus-Pro / BAGEL 并说清「理解＋生成合一」的难点，很亮眼。 |
| **任何到任何 / 全模态（any-to-any / omni-modal）** | 输入输出都不限于文和图，可含音频、视频、语音，任意模态进、任意模态出。靠统一 tokenize + 下一个 token 预测把各模态拉到一个序列里。代表：GPT-4o 方向、NExT-GPT、Qwen2.5-Omni。 | 「多模态的终局」话题。知道「统一 token 化 + 自回归」这条主线即可。 |
| **当前 SOTA 开源 VLM（2026）** | 第一梯队常被点名：**Qwen3-VL**（2025-10 发布，SigLIP-2 + DeepStack + interleaved-MRoPE）、**InternVL3 / InternVL3.5**（InternVL3.5 于 2025-08 发布）、**GLM-4.5V**（主打最强性能与 3D 推理）。中小尺寸：Gemma 3、Qwen2.5-VL 系仍常用。 | 「最近关注哪些开源多模态模型」几乎必问。报得出上面三家 + 一句差异，就显得在跟进。**（面试当天建议再快速核实一次版本号，模型迭代极快）** |

## 面试当天口袋清单（背这几句就能开口）

1. 主干：「**编码器抽特征、投影层做对齐、LLM 做推理**」——任何架构先套这句。
2. 两流派：「**LLaVA 把视觉 token 拼进主序列；Flamingo 用门控交叉注意力旁路注入**。」
3. 高清难题：「**任意分辨率 + tiling 切块 + token 压缩，三者在细节和算力间权衡**。」
4. 两阶段训练：「**先图文对齐预训练（训投影层），再视觉指令微调（学听指令）**。」
5. 幻觉根因：「**语言先验压过视觉证据，靠更强对齐、grounding 和 DPO 缓解**。」
