【Jev模型】一个不公开架构的模型，怎么被吹成新范式

━━━━━━━━━━━━━━━━━━━━

◆ 这几天时间线被它刷屏了

━━━━━━━━━━━━━━━━━━━━

9 月 15 日，一家叫 TypeSafe AI 的公司发布了一个模型，叫 Jev。

几天之内，各路消息标题大同小异：前 OpenAI 研究员、ChatGPT 的发明人之一、**不生成文本的全新模型**、比大模型快一百倍便宜一百倍、**不会产生幻觉**。Hacker News 上那个帖子冲到一千九百多分、五百多条评论。Vercel 把它接进网关，二十四小时内付费团队的使用比例接近百分之十三，**是 GPT-5.6 全家的两倍**。

我看了一圈，越看越糊涂：**这些说法单独看都不假，合在一起我却说不上来它到底新在哪。**

于是把一手材料翻了一遍——官网、API 文档、发布博客、HN 上五百多条评论、两家第三方的实测推文，还有几篇论文的作者列表。

这期就是把翻出来的东西摆一摆。**先说结论：它是个挺好用的东西，但吹它的那些话里，有一半说的不是它。**

━━━━━━━━━━━━━━━━━━━━

◆ 先看它到底怎么用

━━━━━━━━━━━━━━━━━━━━

讲任何概念之前，先看 API 长什么样。这是官方文档（ https://docs.typesafe.ai/api ）里的例子，我一个字没改，只加了中文注释：

```json
{
  // state：要判断的那段文本
  //（这句是客服工单：“救命！我的打款已经失败三天了。”）
  "state": "Help! My payouts have been failing for 3 days.",
  "model": "jev-latest",

  // questions：你要问的问题，可以一次问多个
  "questions": {
    "department": {
      "type": "choice",              // 题型：单选
      "instructions": "Which team should handle this?",   // 问题：该派给哪个团队
      "criteria": {                  // 候选答案，以及每个候选的说明
        "billing":   "Payments, invoicing, refunds",      // 账务：付款、开票、退款
        "technical": "Bugs, outages, integrations",       // 技术：故障、宕机、集成
        "sales":     "Pricing, upgrades, new accounts"    // 销售：定价、升级、开户
      }
    }
  }
}
```

一段用户消息，一个问题，三个选项。返回是这样：

```json
{
  "model": "jev-1.13.0",
  "answers": {
    "department": {
      "type": "choice",
      "choice": "billing",     // 它选的答案：账务
      // 每个候选各自的概率
      "probabilities": { "billing": 0.88, "technical": 0.12, "sales": 0.0 },
      "confidence": 0.81       // 置信度（这个数后面要专门说）
    }
  },
  "usage": { "input_tokens": 318, "output_tokens": 34 }
}
```

它一共支持三种问法：

**noul**是是非题，返回“是”的概率。这个名字我第一眼没看懂，后来在 HN 上看到创始人自己解释：**noul 是 bernoulli 的简写** ——伯努利分布，就是抛硬币那个分布。

**choice**是单选，最多 255 个选项。

**score**是打分，按你给的档位排序，最多 10 档。

就这三种。**注意它不是让你传一个任意的 JSON schema** ——你不能定义嵌套结构，不能要它填一个对象。你只能在这三种题型里选一种，然后把候选答案列出来。

看到这儿，懂一点机器学习的人应该已经反应过来了：**这三种题型，就是分类、多分类、有序分类。** 教科书前三章的内容。

这三样在 BERT 那个年代就是标准操作——拿一个预训练好的模型，后面接一个分类头，标一批数据微调一下，判情感、判意图、判优先级，做的就是这些事。

**那它跟那个年代的区别在哪？** 区别不在题型，在你要干的活：那会儿你得自己准备训练数据、自己训、自己部署；现在你运行时把选项列出来，一个 HTTP 请求就完事。

━━━━━━━━━━━━━━━━━━━━

◆ 快一百倍，省掉的是哪一步

━━━━━━━━━━━━━━━━━━━━

官网首页挂着两个数：**比大模型快 193.6 倍、便宜 444.6 倍**。

这个数字怎么来的，等会儿再说。先说一件更基础的事：**它凭什么能快。**

大模型生成一段文字，是一个词一个词往外蹦的。你要它输出 `{"department": "billing"}` 这么一串，它得跑十几次前向传播——先吐一个左花括号，再吐引号，再吐 `department`……**每吐一个词，整个模型从头到尾跑一遍。**

Jev 不生成文字。它跑**一次**前向传播，然后直接读出那三个选项各自的概率。

所以它省掉的不是某个聪明的算法，**是“逐词生成”这整个环节**。

HN 上有人把这层说得很直白：

▎“70-500 毫秒对 3-329 秒”这种比较是苹果比橘子，除非那个大模型基线在做同等的工作。如果 Jev 压根跳过了生成环节去做一个窄任务，那它当然快。

还有一位说得更细——**大模型那几秒里，有相当一部分是在逐字吐出类型名和 schema 结构**。真要公平比，得让大模型也只输出那几个裸数字。

顺带说个我觉得挺好笑的细节。官方定价是这样写的：

▎按输入 token 计费。**输出 token 免费。**

这句话技术上完全正确，读起来却像是让利。但它免费的原因不是大方，**是那一头本来就没什么东西**——它吐的是一组概率，不是一段文字。上面那个返回里 `usage` 确实记了 34 个输出 token，可那是一个固定结构的账，不随你问的复杂度涨。**逐词生成那笔真正会膨胀的账，它压根没有。**

━━━━━━━━━━━━━━━━━━━━

◆ “不会产生幻觉”是什么意思

━━━━━━━━━━━━━━━━━━━━

这是传播得最广的一句，也是最该分开看的一句。

它的原理是：**输出空间是你自己定的。** 你给了三个选项，它只能从这三个里挑，挑不出第四个来。所以它“不会编造”。

但这句话成立的前提是——**它压根没有编造的能力**。

这不是治好了一个病，**是把嘴缝上了**。

同样的道理对任何分类模型都成立。一个判断垃圾邮件的模型不会“产生幻觉”，因为它只会输出“是”或“否”。你不会因此说它比大模型可靠。

HN 上有人当面问了创始人这件事：

▎“不会产生幻觉”这个说法好像不对？它确实吐不出一个非法的类型，**但它照样可以吐出一个完全错误的合法值**。而且大模型加个合适的外壳也能强制结构化输出。

创始人回了一句，说这对所有机器学习都成立，你总不能说随机森林会“产生幻觉”。

底下有人接了一句——**这句我认为说到了点子上**：

▎这个帖子一小时前的原标题是“Jev：全新前沿模型，便宜 40-400 倍、快 20-200 倍”。我同意那个标题有误导性。
▎**类型安全不等于事实正确。**

这句值得单拎出来念一遍。**Type safety is not factual correctness.**

它保证的是“返回值一定是这三个之一”，不是“返回的那一个是对的”。前者是编译期的事，后者是准确率的事。**一个产品叫 TypeSafe，然后让大家把类型安全读成了不会犯错，这件事本身挺值得玩味的。**

━━━━━━━━━━━━━━━━━━━━

◆ 它真正有价值的那一点，反而没什么人吹

━━━━━━━━━━━━━━━━━━━━

前面说了三条，听着像是全在泼冷水。但它确实有一个东西是真的，而且是真问题——**校准**。

先说什么叫校准。

你问大模型一件事，它说“我有九成把握”。这个九成是什么意思？**大多数时候什么意思也没有。** 它是从训练语料里学来的说话方式——人类写文章时说“我有九成把握”，它就学会在类似语境里也这么说。这个数字和它实际答对的比例没有必然关系。

**校准好的意思是：它说 70% 的那些次里，真有大约 70% 是对的。**

像天气预报。预报说 70% 降水概率，如果把所有报过 70% 的日子挑出来，其中大约七成真的下了雨，这个预报就是校准好的。报得准不准是一回事，**报出来的那个数字本身可信不可信，是另一回事。**

这对写程序的人是刚需。你要做自动化，就得决定什么时候放心让机器自己处理、什么时候转人工。**这条线画在哪，靠的就是那个概率数字可不可信。**

TypeSafe 的官方文档里，校准是这么定义的：

▎在同一个模型的许多次预测中：被赋予 0.2 概率的结果，应当大约有 20% 的时候发生；被赋予 0.8 概率的结果，应当大约有 80% 的时候发生。
▎**这些比率描述的是一组预测，不是对任何单次回答的保证。**

这段写得很准确。它甚至主动提醒了边界——校准是群体统计，不保证单次正确。

**所以问题来了：它校准得怎么样？**

我在官网、文档、博客里翻了一圈，**找不到一个数字**。

没有 ECE（expected calibration error，期望校准误差，衡量校准好坏的标准指标），没有可靠性曲线，没有任何量化验证。

更有意思的是那个 `confidence` 字段。听名字像是校准后的置信度，实际上文档里写得清清楚楚：它只是**把概率分布的形状塌缩成一个 0 到 1 的数**。文档甚至给了个例子公式——三个选项的时候，用「(3 × 最大概率 − 1) / 2」凑一个出来。

这是个分布集中程度的统计量，**跟校准是两码事**。

HN 上有人专门提了这个要求：

▎很希望看到 Jev 的基准测试能证明校准后的不确定性确实有价值……这样我们才能问出“要达到 90% 准确率，我们能自动化多少比例的决策”这种问题。

**没有人回答他。**

━━━━━━━━━━━━━━━━━━━━

◆ 那 193.6 倍是怎么测的

━━━━━━━━━━━━━━━━━━━━

回到开头那个数字。

官方有个评测页面，方法论写在上面。标准答案——也就是用来判对错的那套正确答案——是这么来的：

▎GPT-6 Astra 和 Claude Fable 5.1 的回答的平均值，**两者都开高思考档**，取其共识标签。

**即：正确答案是用大模型生成的。**

然后 Jev 在这套由大模型定义的标准上，跟大模型比分数。

创始人在 HN 上确认了这套评测是自家做的。至于为什么不跑公开基准，官方专门写了篇博客解释：

▎我们在做一种新型的模型，这意味着现有的基准并不适用。
▎我们刻意选择不公布在公开基准上的成绩。

底下有人回了一句：**要是分数好看，我赌他们早发了。**

这句话刻薄，但它指出的是同一个结构性问题：**当一家公司同时掌握出题权、答案和判分权，它公布的任何领先幅度，都只是在说“按我们的标准，我们领先”。**

这个结构我们在 310 期（ https://mp.weixin.qq.com/s/C1yIEM-i20LE8AeBN8y-EQ ）讲过一次。那期讲的是怎么把人的贡献藏起来，做出“AI 自进化”的效果。手法不同，**但都是先定义计分方式，再拿这个方式量出一个漂亮数字。**

━━━━━━━━━━━━━━━━━━━━

◆ 第三方实测：两条，都值得看

━━━━━━━━━━━━━━━━━━━━

厂商自述之外，有两家真拿生产任务测了。

**第一条是 Vercel 的工程师**，测他们自己的安全分类器：

▎我们用 Jev 对我们的 fx auto 模式安全分类器做了基准测试。
▎结论：比 gpt-5.6-luna（我们目前的首选）**快 5 到 18 倍，而且更准**。

这是真第三方实测，用的是生产环境的真任务。**但公开的只有这两句** ——没有样本量，没有数据集说明，没有准确率的具体数字。

**第二条来自 Bryo AI 的 CTO**，做邮件分类。这条更有意思，因为它的方法论是三条里最透明的，**而且结论和你在媒体上看到的不太一样**。

原推的第一句是：

▎**Jev 在我们的邮件分类基准上输给了 Gemini。**
▎我仍然有兴趣把它投入生产。
▎我们测了 1565 封德语和英语的商业邮件，来自工业供应商，共 10 个类别。
▎有意思的结果不是准确率，**是错误发生在哪里**。

到了某家科技媒体的报道里，这条变成了“Gemini 准确率略高，但贵 10 到 20 倍”。

**两句话都不算假。** 但一句的开头是“Jev 输了”，另一句的开头是“Gemini 更贵”。**同一份实测，重心挪了一下，读者接收到的东西就反过来了。**

顺带说一句，这条实测的作者自己的判断很值得记——他关心的不是谁准确率高，**是错误发生在什么地方、能不能被概率数字提前标出来**。这恰恰就是校准的价值。**懂行的人在意的点，和媒体在吹的点，不是同一个。**

━━━━━━━━━━━━━━━━━━━━

◆ 那架构到底是什么

━━━━━━━━━━━━━━━━━━━━

写到这儿你可能会问：说了半天，它内部到底是个什么结构？

**不知道。**

不是我没查到。是创始人在 HN 上亲口说的：

▎架构目前先不公开，**不过我们讨论过要写一篇论文**。

没有参数量，没有层数，没有说是不是基于开源权重改的，没有技术报告，没有论文。

**一些流传的说法其实不是官方说的。** 比如“transformer 架构”这个说法出自某家科技媒体的报道，官方文档全站只有一句“a new architecture”。那篇报道自己也写了，外界**猜测**它是基于某个开源大模型做的——这是记者转述的猜测，不是任何一方的确认。

HN 上有人根据 API 行为反推：

▎看起来像是一个专门化的、偏 encoder-only 的 transformer，带标量和有序输出头。效果上可能是非因果的？大概根本不是自回归的？

**注意这也是猜测。** 说它是个 BERT 式的分类器，和说它是个突破，**在证据层面上是对称的——两边都没有公开材料可以支撑。**

HN 上我看到最平衡的一条评论，正好说的是这件事：

▎分类、打分、路由、在预定义选项上返回概率，这些都是已经确立的问题……TypeSafe 说 Jev 有新架构和 RLCD 训练方法，但 Jev 的实际架构、权重和训练细节都不公开。所以我们**既不能断言 Jev 就是个 BERT 分类器，也看不到足够的公开技术证据能把这个想法称为突破**。至少他们应该发篇技术论文来证明自己的想法是突破。

这段话我反复读了几遍。**它说的不是“这东西不行”，是“现在没有人有资格说它行还是不行”。**

━━━━━━━━━━━━━━━━━━━━

◆ 顺手核一下那个头衔

━━━━━━━━━━━━━━━━━━━━

创始人 Diogo Almeida，媒体上的介绍是“ChatGPT 的发明人之一”“RLHF 的共同发明人”。

这两个说法得分开看。

**InstructGPT 那篇论文（arXiv:2203.02155），他是第 4 作者，而且是标星的 primary author 之一。** 这个我去核了作者列表，属实。那篇论文是把 RLHF 用到语言模型上、直接催生 ChatGPT 的工作。GPT-4 技术报告的作者列表里也有他。

**但 RLHF 的奠基论文——2017 年 Christiano 等人那篇《Deep reinforcement learning from human preferences》——作者列表里没有他。**

所以“RLHF 共同发明人”这个说法，取决于你把 RLHF 的发明锚定在哪：**锚在 2017 年那篇原始方法论，他不在；锚在把它用到语言模型上的 InstructGPT，他是核心作者之一。**

官方自己的措辞其实是准确的——“co-invented RLHF and InstructGPT, the methods that **lead to** ChatGPT”，用的是“导向了 ChatGPT”。**“ChatGPT 发明人”是媒体标题化之后的产物，官方没这么写过。**

这事不大，但它和前面那些是同一个形状：**每一层转述都往前挪一点点，挪到最后，说法和原话已经不是一回事了。**

━━━━━━━━━━━━━━━━━━━━

◆ 所以它到底是什么

━━━━━━━━━━━━━━━━━━━━

我自己的理解是这样。

**它真正做对的事，可能不在模型上，在产品形态上。**

“给定一组选项、返回校准过的概率”——这件事技术上不新，新的是**它被做成了一个不需要你准备训练数据、不需要你微调、开箱即用的通用接口**。你运行时把选项列出来就能用。

过去要做一个分类器，你得标数据、训模型、部署、维护。后来可以让大模型来做，但你得忍受它慢、贵、而且吐给你的概率不可信。**Jev 想占的是中间那个位置。**

至于它内部是什么——按目前公开的材料，**没有人知道，包括吹它的人**。

所以这期真正想说的其实不是 Jev 怎么样。是：

**当一个东西被形容成“新范式”的时候，值得先问两句——它省掉了哪一步？以及，说这话的人凭什么知道？**

第一句能解掉大部分的速度神话。Jev 快，是因为它不做逐词生成；任何跳过一整个环节的东西都会快，这不神秘。

第二句更要紧。**在架构、权重、训练细节一律不公开的情况下，“这是突破”和“这就是个分类器”是两个同样没有证据的判断。** 区别只在于，前者更好听，也更容易被转发。

它可能真的有新东西。创始人说讨论过要写论文——**那就等那篇论文。**
