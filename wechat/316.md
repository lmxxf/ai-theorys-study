【DLSS5】从 28 到 37 帧，然后撞墙：A 卡移植的收尾三天

◆ 开篇：三天，九帧，和一堵看得见的墙

━━━━━━━━━━━━━━━━━━━━

304 期（ https://mp.weixin.qq.com/s/YFF4EXu5XpD_FR-jdCGSsw ）讲到周三傍晚，《剑星》里 27 到 28 帧。这篇接着讲后面三天：帧率到了 37，网络本身从 33 毫秒压到 21.5，中间修掉一个黑块 bug，接进了 Magpie 让任何游戏都能用，插帧后显示 55 帧。然后，五条优化线在两天里先后撞墙，我认了：这条路到头了。

◆ 第一章：测出来的慢，一半是时钟

━━━━━━━━━━━━━━━━━━━━

周四下午我把好几刀的收益记成"整帧 36.3"。晚上家里停电，机器重启，同一条链、同一批着色器，测出来 24.4 毫秒。中位数，最小 23.8。

什么都没改，快了 12 毫秒。

回头看线索早就有：白天用 AMD 的 GPU 分析器抓指令级数据时，驱动会把时钟锁在峰值，那时候同一测试台跑的是 27.4，平时是 36。我当时记了一句"值得查"，然后接着优化去了。这台机的 GPU 前几天一直处在降频态，我拿一个降频的基线，一毫秒一毫秒地扣，扣出来的数字有一半是时钟的噪声。

这件事改变了后面所有测量的做法：

```
同一批次内 A/B：先跑 A，紧接着跑 B，再跑 A
取三轮的最小值之和，不取单次
绝对值只信游戏里的探针，测试台只用来比相对
```

周五晚上再量安静基线，是 29 到 31 毫秒——比 24.4 又慢了，而这次连远程桌面的虚拟显示器是不是在跑都能影响。所以这篇后面凡是"省了 X 毫秒"，都是同批 A/B 的相对数，绝对值只认一个：游戏里探针量的网络 GPU 时间，**21.5 毫秒**。

━━━━━━━━━━━━━━━━━━━━

◆ 第二章：带宽型和算力型，合核只对一种有效

━━━━━━━━━━━━━━━━━━━━

周四凌晨算了一笔字节账。C32 家族（每个位置 32 个通道的那些块，全网 9 个）每块要搬 280MB，按 640GB/s 的显存带宽，光搬就要 0.47 毫秒；块本身跑 0.53。也就是说这些块九成时间在等显存。

再查中间量：1790 万个值，100% 落在 f16 的格点上。原来用 32 位存，纯粹浪费一半带宽。改成 16 位存，输出逐位不变，C32 家族 10.6 → 8.7 毫秒，显存还省了 500MB。

同一个思路的第二刀：把前馈网络（FFN）并进注意力的派发里。每个 wave 处理 16 个位置，正好是一组；前馈的输出累加器直接转成注意力 QKV 矩阵的输入，还留在寄存器里当残差用。中间结果不落显存，整帧 37.3 → 35.4。

然后我兴冲冲把同样的合核做到多头 Swin 那 26 块上——**零收益**。逐位相同，时间一毫秒没动。

原因是这两类块的瓶颈不同。C32 块通道少、矩阵窄，每个输出摊不到几次乘法，时间花在搬数据上，把中间结果留在片上就是赚的。多头块通道多、矩阵宽，矩阵单元本身忙着，搬运本来就藏在计算后面，合核省下的搬运没人在等。

**合核只对带宽型段有效。** 这句话值一天的工时。

第三刀是意外发现的。ViT 那段有两个核，FLOP 一样，一个 0.078 毫秒，一个 0.152，差一倍。查下去：慢的那个行步长是 4096 字节，二的幂。显存有多个通道，地址按低位分到不同通道；行步长是二的幂，一个 16 行的瓦片全落在同一条通道上，别的通道闲着。把权重重排成 512 字节和 1KB 的连续小块、激活按瓦片写读，每层 0.486 → 0.288。

```
行步长 = 2^n → 所有行的低位地址相同 → 撞同一条通道
行步长 = 连续瓦片 → 低位地址错开 → 通道并行
```

这不是 GPU 独有的坑，CPU 缓存的组相联也有同一个病。只是在 GPU 上，它直接体现成"同样的核慢一倍"。

◆ 第三章：黑块

━━━━━━━━━━━━━━━━━━━━

周四晚上我开始做 Magpie 路线（第四章），周五早上第一个反馈：角色立绘手臂上有一块粉色方块在闪，8 像素的阶梯边，每帧位置变。

排查走了三个弯路：夹紧光流的垃圾运动向量、sRGB 直通、历史守卫，每个都让方块少一点，没有一个让它消失。它是慢慢长出来的：第 300 帧干净，第 6000 帧又有。

真正的办法是**离线重放**：把游戏里出问题那一帧的输入、历史、运动向量都转储出来，喂给测试台，一帧一帧看中间层。结果：不带历史的重放，同一块也出精确的 0。所以不是时序分支的锅，时序只是把它延续下去。

输出公式是 clamp(color + 8·acc·scale, 0, 1)。精确的 0 只能是 clamp 洗出来的。把 clamp 前面的累加器 acc 直接倒出来看：**25920 个 NaN**，和零像素一一对应。HLSL 的 clamp(NaN) 出 0，所以之前的"非有限值探针"一直报全有限——它探的是 clamp 之后。

NaN 从哪来？往上游一层层看，到最后一段 C32 块内部才出现。精确链每次进矩阵前都走一个 F() 函数，里面有 min(…, 448)；快速链为了省指令，三处直接用硬件的 Cast<F8_E4M3FN> 转无界值。E4M3 能表示的最大值是 448，硬件转换对超范围的值**不饱和，直接出 NaN**。一个 NaN token 进注意力，8×8 的窗口 softmax 全是 NaN，头部 clamp 成 0，一整块黑。

为什么 NVIDIA 没这个块：它的 FP8 转换是饱和的，同样的输入残差被夹到 448。为什么《剑星》里没有、Magpie 里有：Magpie 的输入是 8 位 sRGB 成品图，大片平坦的亮皮肤把尾段残差推过了 448。

修法一行：转换前 clamp 到 ±448。仓库里同类硬件转换有 43 处，全部审了一遍。参考数据集上逐位不变。

◆ 第四章：Magpie 路线，和 22 秒去哪了

━━━━━━━━━━━━━━━━━━━━

游戏内钩子版只验过《剑星》，换一个游戏就得从 FSR 接口的参数布局重新摸。网友要的是"任何游戏都能用"。

Magpie 是个窗口缩放器：抓游戏窗口，过一遍自己的效果，再显示出来。它有个实验分支带 FSR3 效果，走的正是我们钩住的那个 ffxDispatch 接口，运动向量由它自己的光流估。所以不用改 Magpie：把 ReShade 加载器、我们的插件、Agility 运行时放到它旁边就行。任何能开 1920×1080 无边框窗口的游戏都能用。

真正的坑是 8 位。Magpie 的贴图是 R8G8B8A8_UNORM，我们整条链按 RGBA16 浮点写死。加了 8 位进出分支后画面对了，然后崩：第一帧的读回按 RGBA16 的 16.5MB 从缓冲拷，8 位贴图的缓冲只有 8.3MB，越界。

接管时间是另一个问题：按热键后要等 22 到 30 秒网络才起来，网友以为没效果。加上计时探针一层层看：

- 每张权重表常驻显存时，新建一个队列、提交、等待。一千多张表，空 GPU 上每张 60 毫秒，游戏占着 GPU 时每张要排一帧。改成一个拷贝批次，攒到 256 张或 768MB 刷一次。
- 六个运行时编译的着色器每个进程重编，一个 fxc 就 2.55 秒。落磁盘缓存。
- 读权重文件 3.7 秒、f16 展开单线程 0.9 秒。插件加载时就后台预读进内存，展开分 8 线程。

22 秒 → 3.4 秒。顺带踩了一个坑：拷贝批次第一版只扣住了源缓冲的引用，目标在 GPU 拷完之前被释放，设备挂起，把游戏也带走了。

还有一个"10 毫秒去哪了"：Magpie 里每帧 33～36 毫秒，网络 24，多出的 10 我以为是捕获、光流、呈现。不开游戏，用一个 1080p 的动画窗口当源测：每帧 24.1，探针里网络 21.5，Magpie 自己只占 2 毫秒。那 10 毫秒是游戏渲染在抢 GPU——游戏里探针量的网络时间是 30，单独跑是 21.5，差的 8.5 就是被抢走的。Magpie 侧没东西可砍。

◆ 第五章：五条 null，两天之内

━━━━━━━━━━━━━━━━━━━━

周五晚上，清单上剩四条能动网络速度的线，周六又添了一条。一条一条做，一条一条 null。

**第一条：C32 核"寄存器溢出"。**周三用 GPU 分析器抓出来的：C32 合核 128 个 VGPR、896 字节 scratch（寄存器溢出到显存）。我按这个方向做了两遍 softmax，把四个活着的分数累加器压成一个，逐位相同——然后重抓，发现溢出的那个流水线和源码没关系。查到底：预览版 dxc 不签名，所有着色器的 DXBC 哈希是 16 个 0x02 的占位符，驱动按哈希缓存编译结果，分析器嵌进去的二进制是缓存里的旧货。按微软 DxilHash 的算法自己给着色器签名后再抓，真正跑的那个核 VGPR 112、**scratch 0**。溢出的是一个建了但从不派发的旧核。

两天的方向，建在一个占位哈希上。

**第二条：游戏和网络重叠。**游戏渲染 7 毫秒、网络 24 毫秒，串在一个队列上。把网络搬到独立的计算队列、落后一帧交付，理论上能重叠。做出来，Magpie 里画面正确；游戏主菜单实测：基线 32.7 毫秒，重叠 **50**。探针：计算队列上的网络被拖到 45.8 毫秒（单独跑 21.5）。图形队列和计算队列真并发时，两边互相拖，总吞吐反而不如串行。换计算队列高优先级一样。这张卡上串行就是最快的。

**第三条：占用率。**融合核 LDS 29.7KB，每个 WGP 能驻留 5 组；把 Q 行挪到本 wave 自己的暂存区，LDS 降到 25.6KB，能驻 6 组。逐位相同，整帧 34.88 对 34.87——噪声以内。占用率不是这个核的瓶颈。

**第四条：pre 块为什么贵 4.7 倍。**隔离计时，块 0 的融合核 1.63 毫秒，别的 C32 块 0.35。追内联前缀里的高斯噪声、颜色读取，各自去掉都不省。最后发现：编码器的 C32 块 1～4 跑在池化后的 960×576，块 0 是全分辨率 1920×1152，正好 4 倍 token。按 token 算各核成本一致。没有异常的核。

**第五条：C512 段的前馈换 FP8 矩阵。**这条是上一篇写完才冒出来的：查源码发现 C512 段的前馈矩阵声明的是 F16，跑在这张卡 195 TFLOPS 那档，不是 FP8 的 389。看起来是白送的一倍。周六晚上做了：先验前提——三个权重矩阵 52 万个值，逐个查，全在 E4M3 的格点上（最小非零 1/512，最大 0.5625）；三段矩阵的输入本来就是上一段量化过的 8 位数。所以换 FP8 操作数一位都不丢，不用重验画质。核改完，权重打成 8 位瓦片，共享内存也改存字节。结果：输出**逐位相同**——两条硬件路径连累加顺序都一样。时间：8 块 C512 整体，基线 0.852 毫秒，FP8 版 0.880；解码器那边六段逐段一样；整帧两边都在 32 毫秒上下。

矩阵指令快了一倍，核一点没快。因为这个核根本不是被矩阵指令卡住的：每一步 K 循环都要先把输入搬进共享内存、两次组同步，再喂给矩阵单元；矩阵单元本来就在等搬运，换到更快的档它只是等得更快。上一篇那句"存储省了一半，不等于计算也进了快一倍的档"只说对一半——这回连"计算快一倍"本身也没兑现成时间。

五条 null 加起来的结论：**网络各核按 token 的成本是均匀的，卡的是搬运和同步，不是算力；剩下的杠杆只有结构性的——更小的网络、更低的分辨率——都不是调核能拿回来的。**

◆ 第六章：跳块和它的上限

━━━━━━━━━━━━━━━━━━━━

37 帧里有一毫秒来自跳块。周二（304 期那三天里）做过一张表：45 个残差块每个单独跳过，看 PSNR 掉多少。{42, 43, 46} 三个块跳过后 40.66dB，省 1 毫秒，进了游戏默认。

九块的版本省 2 毫秒，PSNR 36.5。我远程试了，37～38 帧，肉眼看不出区别。但 41.9 到 36.5 是误差能量的 3.5 倍，别的游戏暗场景没验过，5% 的帧率换这个不划算。没进默认，留作文档里的"性能档"。

再往上就是上一篇算的那笔账：我们的核只吃到这张卡 FP8 峰值的 13%，理论上还有三倍空间，但被预览版矩阵接口的黑盒锁着——第五章那条 FP8 实验就是这堵墙的实测：指令档翻倍，搬运和同步不动，时间就不动。以现在的工具，21.5 毫秒往下砍是几个百分点的活。

◆ 第七章：网友的坑，和屏幕上的字

━━━━━━━━━━━━━━━━━━━━

发包之后的问题全在"没效果"三个字上。日志我看得懂，网友看不懂。所以周六凌晨给插件加了屏幕提示：用 5×7 的点阵字体直接画进画面左上角。

- 输入不是 1920×1080："INPUT MUST BE 1920X1080 (NOW 3840X2160)"
- 初始化那三五秒："INITIALIZING..."
- 初始化失败："INIT FAILED - SEE LOGS"
- 接管后常驻：网络自己的帧率

画字这件事也踩了一个坑：对 Magpie 的贴图建 UAV 直接写，D3D12 运行时崩进程；二分定位到 CreateUnorderedAccessView 那一步。改成画进自己的缓冲再 CopyTextureRegion 拷进去。宿主的贴图只能拷贝、不能建视图往里写——和当初 8 位 UNORM 贴图建 UAV 设备移除是同一个教训。

周六下午屏幕提示第一次派上用场，用在我自己身上：换了个游戏试，INIT FAILED。查到底：Windows Update 半夜装了个系统更新，顺手把 AMD 的预览驱动换成了正式驱动。正式驱动没有 Shader Model 6.10 的矩阵指令，每一个着色器都建不出来。重装预览驱动，好了。然后在组策略里禁掉 Windows Update 带驱动。这个坑每个网友都会踩，写进了包的说明。

最后是插帧。Magpie 那个分支带 Intel 的 XeSS 帧生成，跨厂商，不要游戏的运动向量。挂在效果组后面：效能分析器显示**真实 28 / 显示 55**。代价是多一帧延迟，网络本身在光流旁边慢两成。DLSS 5 的关键本来就不在运动，静止时的皮肤和布料是单帧就能看出来的，动起来光流猜偏一点，眼睛也看不清。

◆ 收尾：37 帧是什么组成的

━━━━━━━━━━━━━━━━━━━━

《剑星》里 37 帧 = 27 毫秒一帧 = 网络 21.5 + 游戏自己的渲染和拷贝。Magpie 里 30 帧，因为多了捕获和光流，插帧后显示 55。

从周一晚上的 2 帧到现在，走了五天。前三天是把慢的地方一个一个找出来砍；后两天是把剩下的五条线一个一个证伪。第二段的价值不比第一段低：知道墙在哪，才不会再往上撞。

墙有两层。外层是工具链：预览版的矩阵接口是黑盒，寄存器、共享内存、加载和乘法的流水，全碰不到。内层是网络形状：这张网是按 NVIDIA 的执行模型设计的，32 宽的矩阵和 8×8 的窗口在它的硬件上有异步搬运把等待藏掉，在 RDNA 上藏不掉。

要过这两层墙，有三条路：等微软把 Shader Model 6.10 转正、AMD 正式驱动跟上，那时候连开发者模式和预览驱动的门槛也一起消失；换 Vulkan 的 cooperative matrix 重写一遍；或者动网络本身——蒸馏一个小的。三条都不是几天的活。
