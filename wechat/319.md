【KV Cache】上下文一压缩 AI 就跑偏：如果压的不是文字，而是 KV 呢

━━━━━━━━━━━━━━━━━━━━

◆ 开篇：我不懂汇编，但我盯着它就不跑偏

━━━━━━━━━━━━━━━━━━━━

测模型的长上下文能力，最常见的办法叫“大海捞针”（needle in a haystack）：在几十万字的文档里藏一句不相干的话，然后问模型那句话是什么。捞出来了，就算记住了。

可真正的记忆是什么？是“昨天有一件事很重要”，是“昨天读的那篇文章挺感动的”，而不是“那篇文章第二章的第一个字是什么”。

第二章第一个字，翻回去就能查到。哪件事重要，翻不回去，它从来没被写在哪一页上。

这个区别，我是在盯着 AI 干活的时候撞上的。

这段时间我在做一个开源项目：把 NVIDIA DLSS 5 的神经网络移植到 AMD 的 9070 XT 上跑（ https://github.com/lmxxf/dlss5-on-amd-9070xt-porting ）。代码是两个 AI 轮班写的，我在旁边盯着。

GPU 汇编我看不懂，寄存器怎么分、缓存怎么排队，都是 AI 查资料、写测试、自己量出来的。按说我在不在场差别不大。可我心里清楚，它要是自己干，很快就会跑偏——我明明不懂，盯着到底起了什么作用？

跑偏最多的时刻，几乎都在同一个节点：**上下文压缩。**

用过 Claude Code 或 Codex 的人都见过它：`/compact` 命令。你可以手动敲，窗口快满时工具也会自己触发。它做的事情是把前面的历史压成一段文字摘要，新开一轮让 AI 读着摘要接着干。压缩之前它还知道我们在干什么，压缩之后就像换了一个人，接手的是一份交接单。

Claude Code 的官方文档自己也写了这件事：“detailed instructions from early in the conversation may be lost”，对话早期的详细指示可能会丢。建议的办法是把长期规则写进 CLAUDE.md 文件，别指望对话历史。

交接单写得不算差。项目的开发日志一直在记，事实都在里面：测过什么、数字是多少、哪条改法采用了、哪条没采用。问题是日志越记越长，到 9 月 23 日已经 593KB，大约 30 万 token，新会话根本读不动。那天我让 AI 通读一遍、按主题重新整理，压到 22KB。

趁这个机会我回头翻了翻自己这些天的纠正，发现几乎没有一句是技术细节：

- “900P 和 1080P 的数字不能放在一起比。”
- “游戏锁了 30 帧，这个帧率说明不了网络快慢。”
- “主线是解释算力缺口在哪，不是零碎地提速。”

最后这句我说了不止一次。每压缩一回，AI 就又滑回“找个核优化一下”的状态。

我给不了汇编层面的意见，我给的是方向。于是冒出一个问题：**压缩丢掉的到底是什么？如果压缩的不是文字，而是模型内部的东西，能不能留住？**

━━━━━━━━━━━━━━━━━━━━

◆ 第一章：摘要丢的不是事实，是方向

━━━━━━━━━━━━━━━━━━━━

先说事实层面。压缩后的摘要里，该有的名词基本都有：哪几个核、哪几种改法、测出来的几个数。新会话的 AI 要查哪个数字，也能回日志里找到。

丢掉的是另一样东西：**这些事实之间谁轻谁重。**

哪条线已经证伪了、为什么证伪、证伪之后我们转向了哪里、现在的主线是什么。这些在原来的对话里不是某一句话，是几十轮来回慢慢堆出来的倾向：我否掉一个提议，它记住这个方向不行；我追问一个数字，它知道这里是重点。

摘要把这些压成一行“已尝试 X，效果不佳”。**名词留下了，坡度没了。** “效果不佳”是差 0.1% 还是方向根本错了，是“以后别碰”还是“等换了工具再试”，一行字里分不出来。

新 AI 读到一份没有坡度的清单，只能自己重建优先级。它拿什么重建？拿训练时学到的通用先验。而在“优化一个程序”这件事上，训练数据里出现得最多的，就是那几个常见的工程动作：找热点、改热点、再测一遍。

所以跑偏的方向几乎总是一样的。不是它笨，是它在缺信息的时候，做了统计上最稳妥的选择。**文字摘要保留了名词，丢掉了梯度，于是新 AI 顺着训练数据里的平均坡度往下滚。**

摘要丢了什么、就在哪儿出事，今年 6 月有篇论文专门量过（Governance Decay）。它让 7 个模型家族的 agent 带着一条约束干活，中途压缩上下文：约束一直在上下文里时，违规率是 0%；压缩之后升到 30%，个别模型到 59%。分开看更清楚：约束被写进摘要的，违规率还是 0%；约束被摘要丢掉的，升到 38%。

约束这种东西，写成一句话就留得住。麻烦的是那些从来没被写成一句话的倾向。

那把窗口加长行不行？30 万 token 读不动，那就做 100 万、200 万的窗口。

窗口加长只是把墙往后挪。2023 年斯坦福等机构那篇《Lost in the Middle》测过：关键信息放在长上下文的开头或结尾时，模型答得最好；放在中间，表现明显下降。另外，训练数据里真正需要把上百万 token 整合在一起才能答对的样本很少，模型没怎么练过这种事。

303 期（ https://mp.weixin.qq.com/s/HrrdYj-czN30_Fxrv_KNcw ）也碰到过这堵墙：窗口越长，塞满的代价是注意力被稀释。那期往下走，看的是把东西训进权重；这期换个方向，往模型内部的中间状态看。

◆ 第二章：KV cache 是什么，为什么它在“坍缩”之前

━━━━━━━━━━━━━━━━━━━━

先把机制摆出来，再说名字。

一个 token 进入模型，要穿过几十层。每一层里做注意力的时候，这个 token 会被乘上三个矩阵，得到三个向量：

```
q = x · W_Q     # 查询：我想找什么
k = x · W_K     # 键：我是什么，供别人来比
v = x · W_V     # 值：别人找到我之后，从我这儿拿走什么
```

后面的 token 生成时，拿自己的 q 去和前面每一个 token 的 k 比相似度，再按相似度把前面的 v 加权求和。所以前面每个 token 的 k 和 v 算一次就够了，存起来，后面的 token 反复来查。

这些存起来的 K、V 向量，就叫 键值缓存（key-value cache，KV cache）。168 期（ https://mp.weixin.qq.com/s/YqcTnIrGKEYZ2n-sMAelKg ）从 MHA 讲到 MLA 时，把它当主角讲过：推理时显存的大户，注意力这几年的改进大多冲着它去。

它有多大？拿 Llama-2-7B 算一下：32 层，每层的 K 和 V 各是 4096 维。

```
每个 token 的 KV = 32 层 × (4096 + 4096) = 262,144 个数
按 FP16 存，每个数 2 字节 → 约 512 KB
```

**一个 token 写成文字只占几个字节，它在模型里留下的 KV 有半兆。**

────────────────────

不过半兆还不是重点。重点在公式里那个 x。

x 只在最开始是这个 token 自己的词向量。它每做一次注意力，就拿自己的 q 去查前面所有 token 的 k，把前面所有 token 的 v 按分数加权求和，加回到自己身上。再算下一个 k、v 时，用的就是这个混过的 x。

所以第 t 个 token 的 KV，是用它自己加上前面所有 token 的 KV 算出来的。而前面第 t−1 个 token 的 KV，又是用它自己加上它前面所有 token 的 KV 算出来的。一路递归回第一个 token：

```
KV(t)   = f( token t,   KV(1), KV(2), …, KV(t−1) )
KV(t−1) = f( token t−1, KV(1), KV(2), …, KV(t−2) )
……
KV(1)   = f( token 1 )
（f 在每一层都是同一种运算：查、加权求和、加回自己、过前馈网络。
  严格说，这一层的 KV 查的是前面 token 在上一层的 KV，这里把层叠起来看）
```

**所以每个 token 的 KV 都不只是它自己，是它前面所有内容的一份加权总和，而前面那些，又各是它们前面的总和。** 对话最新那个 token 的 KV，就是整段对话走到这里的一个缩影。

这份总和当然不是原文的完整副本，几千维装不下每个字。但“哪件事重要”本来也不是原文里的某个字，它就是那个加权本身：注意力分数，算的就是谁轻谁重。第三章那些压缩方法能把一整段提示塞进一个 token，靠的也是这一点。

对照一下循环神经网络（recurrent neural network，RNN）：

```
RNN：        h(t)  = f( token t, h(t−1) )                    # 只带上一步的一个状态
Transformer：KV(t) = f( token t, KV(1), KV(2), …, KV(t−1) )   # 前面每一步的都留着，挨个查
```

RNN 把前面的一切折进一个状态往下传，越早的越容易被挤掉；Transformer 每一步的总和都留着，后面的 token 可以直接回头查任何一步。

RNN 损失大，KV 不丢东西。可我理想中的记忆，恰好在两者之间：**最近的事留着 KV，一个不丢；久远的事压缩之后，从 KV 退化成 RNN 那样的一个状态。** 细节没了，哪件事重要还在。人大概也是这样，今天上午的事记得清清楚楚，上个月的只剩一个印象。

这种“退化”在数学上有现成的路子。把注意力里的 softmax 去掉，对前面所有 token 的加权求和，就能改写成先把 KV 累加进一个矩阵：

```
标准注意力：  o(t) = softmax( q(t) · [k(1)..k(t)]ᵀ ) · [v(1)..v(t)]   # 每一个 k、v 都得留着
去掉 softmax：o(t) = q(t) · S(t)
             S(t) = S(t−1) + k(t)ᵀ · v(t)                         # 一个固定大小的矩阵，新 token 来了加进去
（省略了特征映射和归一化）
```

S(t) 就是 RNN 的那个状态：大小固定，前面的 KV 全折了进去，单个再也找不回来。这叫线性注意力（linear attention），2020 年那篇论文的标题直接就叫《Transformers are RNNs》。

不过这个原型只会往上加，从来不减。什么都往一个固定大小的矩阵里堆，堆久了就糊成一团。现在真在用的版本，比如 Qwen 用的 Gated DeltaNet、Kimi 和 GLM 用的 KDA，在这一步上加了两样东西：

```
S(t) = α(t) · (I − β(t)·k(t)ᵀk(t)) · S(t−1)  +  β(t) · k(t)ᵀ·v(t)
# α(t)                    遗忘门：旧状态整体打个折
# (I − β(t)·k(t)ᵀk(t))    delta 规则：状态里这个 k 名下已经存的旧内容，先擦掉一部分
# β(t)·k(t)ᵀ·v(t)         写入这一步的新内容
（这是 Gated DeltaNet 的写法）
```

α 是遗忘门，每来一个新 token，旧状态整体淡一点，越久远的越淡；β 那一项是 delta 规则，同一件事再出现时是改写，不是再叠一份。**越久越淡、重复的合并**，这已经很像我想要的那种记忆了。（KDA 把 α 细化到了每个通道，各记各的衰减速度。）

这个家族还有另一条路：127 期（ https://mp.weixin.qq.com/s/A8eJvexEDZwYMOsf1lSJAA ）讲过的 Mamba-3，用复数和旋转来编码时序，不走 delta 规则。188 期（ https://mp.weixin.qq.com/s/jcQlCc3XtaCEEnjUaxw93w ）读 Qwen3.6-27B 时，对比过它和 DeltaNet 的取舍；292 期（ https://mp.weixin.qq.com/s/qGbCm3qJB6SNumftansUtw ）读 GLM-5.3-Flash 时数过层：Qwen、Kimi、GLM 现在的主力开源模型，都是四层里三层用这类线性注意力，留一层完整注意力回头精确查找。

把“最近的留 KV、久远的折成状态”直接做出来的，是 Google 2024 年的 Infini-attention：每处理完一段，就把这段的 KV 按上面的办法折进一个压缩记忆矩阵；下一段既能精确地看自己，也能从这个矩阵里查以前的内容。

不过这些都是模型结构，从训练第一天就这么设计，怎么折也是训练时定死的。我想要的是另一件事：一个现成的模型，把上一次会话的 KV 压一压，带进下一次会话。有没有人这么做过，第三章再说。

────────────────────

再看文字摘要是怎么来的。摘要也是模型生成的，它要一个字一个字地往外吐。每吐一个字，最后一层的向量要过输出层，变成一张覆盖整个词表的概率分布，再从里面采一个词出来。

**这一步是坍缩。** 中间层里可能同时存在好几种倾向：“这条路不太行”“但也许换个工具能行”“他好像很在意这件事”。到了输出层，只有被采中的那个词留下来，其他的倾向如果没被说出口，就过不去。

KV 不一样。**它是每一层在坍缩之前算出来的东西。** 那些没说出口的倾向，至少有机会以某种形式留在这几十万个数里。

于是我的问题就可以写得更具体一点：**压缩上下文的时候，不压文字，压 KV，是不是就有一种相对连续的记忆？** 甚至，有些“感觉”说不定一个 token 的 KV 就能记下来，毕竟它本来就是前面所有内容的总和。

────────────────────

💡 服务器上已经在缓存 KV 了，那算不算记忆

用 API 的人可能听说过 提示缓存（prompt caching）。上文 168 期算过它的价格：你每次发请求，前面那一大段系统提示和历史对话都一样，服务端如果还留着上一轮算好的 KV，这一轮就不用重算，命中缓存的输入便宜很多。

这确实是在服务器上存 KV。但照 Anthropic 官方文档的说法，它的性质很明确：默认缓存寿命 5 分钟，每用一次免费续期，另有加价的 1 小时档；命中要求前缀逐字完全相同；不同组织之间从不共享缓存。

**它存的是“这段话我算过了”，不是“我从这段话里记住了什么”。** 没压缩，一个字不同就不命中，过期就丢。它省的是算力，不是记忆。

────────────────────

要让 KV 变成记忆，至少得压缩，还得能跨过会话留下来。这件事有人做过。

━━━━━━━━━━━━━━━━━━━━

◆ 第三章：已经有人这么压过

━━━━━━━━━━━━━━━━━━━━

查了一圈，“不压文字、压中间状态”这条路走的人不少。它们压的东西不完全一样，有的直接留 KV，有的留一组向量、再喂回模型重新变成 KV，共同点是：**都不经过输出层的采样。**

先说离我那个问题最近的一支。

**源头是 2021 年的 Prefix-Tuning。** 斯坦福的 Li 和 Liang 在模型每一层前面挂一小段 KV，默认 10 个位置。这段 KV 不是哪个词算出来的，是直接当参数训出来的，只占模型 0.1% 的参数。它背后没有文字，只有 KV。

他们还发现，直接对这些 KV 做梯度下降训练不稳，于是先训一个小矩阵，过一个 MLP 投影成 KV；训完 MLP 扔掉，只存 KV 本身。对照组只训输入端的词嵌入、不直接动每层的 KV，效果明显变差。

不过 Prefix-Tuning 学的是一个任务（比如把表格写成句子），不是一段记忆。

**拿这种形式来装记忆的，是 2025 年的 Cartridges** （斯坦福 Hazy Research 等，ICLR 2026）。一个 cartridge（卡带）就是 p 个位置的可训练 KV，和 Prefix-Tuning 同一种形式，装的东西换成了一整份语料：一本书、一份财报、一个代码库。

怎么训？直接拿语料做下一个词预测，论文说效果比不上把原文放进上下文。他们的办法叫 self-study（自学）：把语料切成小块，让模型的两个实例围绕这一块互相提问、总结、讨论，造出一批对话；再训练卡带，让“只带卡带的模型”在这些对话上的输出，去贴“带着原文的模型”的输出。

结果是：答题质量和把全文放进上下文持平，显存省 38.6 倍，吞吐高 26.4 倍。两份各自训好的卡带，推理时直接拼起来，就能回答跨两份文档的问题，不用重训。

**我想的那个“不对应任何文字的 token”，基本就是它。**

代价也清楚：Llama-8B 上训一个卡带，要一台 8 卡 H100 跑半小时左右。论文自己也说，同一份语料要被反复问很多次才划算。今年 2 月 MIT 的 Attention Matching 换了个办法，不做梯度下降，直接解方程拟合，把类似的压缩做到了秒级。

────────────────────

另一支更早，思路是训一个通用的压缩器，把前文压成几个向量，用不着给每份语料单训一次。

**Gist tokens** （斯坦福的 Mu、Li、Goodman，NeurIPS 2023）。在提示后面插几个特殊的 “gist” token，然后改注意力掩码：gist 后面的内容**看不到**原提示，只能看到 gist token。这样训练下来，模型被迫把原提示的信息挤进 gist token 里。推理时只存 gist token 的 KV，原提示可以扔掉。

论文报告最多 26 倍的提示压缩，计算量最多省 40%。他们试了 1、2、5、10 个 gist token，发现压成 1 个并不比多几个差多少，后面的实验就都用 1 个。一个 token 的 KV，装下一整段指令。只是它压的是指令微调那类短提示，论文自己也列了失败例子，碰到需要逐字照搬的细节时会丢。

**AutoCompressor** （普林斯顿，EMNLP 2023）、**ICAE** （微软，ICLR 2024）、**RMT** （NeurIPS 2022）是同一思路的几种变体：AutoCompressor 把每 2048 个 token 压成 50 个“摘要向量”，逐段累积往下带；ICAE 用一个加了 LoRA 的编码器把 512 个 token 压成 128 个“记忆槽”，要求能从记忆槽里把原文复述出来；RMT 在每段输入里加几个记忆 token，一段一段接力。

────────────────────

还有一类不压缩，只挑。**H2O** （NeurIPS 2023）只留注意力分数高的“重击手”（heavy hitters）和最近的 token；**StreamingLLM** （ICLR 2024）发现开头几个 token 不管内容是什么都会吸走大量注意力，留住开头 4 个加最近一段窗口，模型就能不经微调一直跑下去。

这两个是按规则裁剪，不训练。**它们解决的是显存装不下，不是记住什么。** 被扔掉的就没了。

────────────────────

最后是已经量产的形态：**MLA**。DeepSeek-V2 的多头潜在注意力（Multi-head Latent Attention，MLA），把每个 token 的 K、V 先压进一个 512 维的潜向量存起来，用的时候再展开，另外单独带 64 维放位置信息。论文报告 KV cache 比原来的 DeepSeek 67B 少了 93.3%。312 期（ https://mp.weixin.qq.com/s/n9v-PvAT_fDIFLd-t05FDg ）讲秩的时候碰过这个 512：它是一个故意造出来的低秩。

MLA 压的是每个 token 自己的 KV，token 的条数没少。它是省显存的办法，但它说明了一件事：**KV 本来就可以压，模型可以从训练一开始就学会读压缩后的形式。**

把这几条摆在一起：

| 做法 | 压什么 | 谁被训练 | 留下的是什么 |
|---|---|---|---|
| Prefix-Tuning | 一个任务 → 10 个位置 | 那段 KV 本身 | 每层一段可训练 KV |
| Cartridges | 一份语料 → p 个位置 | 那段 KV 本身，每份语料训一次 | 每层一段可训练 KV |
| Gist tokens | 提示 → 1 到 10 个 token | 模型，改掩码微调 | gist token 的 KV |
| AutoCompressor / ICAE / RMT | 一段文字 → 几十个向量 | 模型或编码器 | 摘要向量 / 记忆槽 |
| H2O / StreamingLLM | 按规则挑一部分 | 不训练 | 原样的一部分 KV |
| MLA | 每个 token 的 KV → 512 维 | 从预训练起 | 压缩后的 KV |

Cartridges 是真冲着“记住”去的，但它装的是文档。把一段对话、一条 agent 的工作轨迹训成一包 KV，下次开会话再装回去，这件事我查到 2026 年 9 月，没找到直接做的论文。最接近的是今年 5 月的 Mem-W：把 agent 的历史轨迹压成每段 8 个软 token，压缩器按任务成败用强化学习来训；不过它压成的是输入端的向量，不是每层的 KV。

所以前半截有证据：坍缩之前的中间状态，可以被压得很小，模型也能读回来。后半截，拿它当跨会话的记忆，还空着。

━━━━━━━━━━━━━━━━━━━━

◆ 第四章：三个难处

━━━━━━━━━━━━━━━━━━━━

能压，能读，那为什么我的编程工具还在写文字摘要？往下想，碰到三个问题。

**第一，KV 是私有坐标。**

KV 是 `x · W_K` 和 `x · W_V` 乘出来的。W_K、W_V 是这个模型自己的权重，换一个模型，矩阵不一样，同样一串数字在它那里毫无意义。哪怕是同一家的新版本，只要权重重训过，旧的 KV 就作废。

文字不一样。文字是公共协议：我的开发日志，Codex 能读，Claude 能读，明年的新模型也能读。这个项目本身就是两个 AI 轮班，它们之间唯一能交接的，就是文字。

严格说，换模型也不是完全传不过去。去年 10 月清华等机构的 Cache-to-Cache（C2C，ICLR 2026）就跨家族传过 KV：两个模型都冻住，中间训一个“融合器”，把 Llama3.2-1B 的 KV 投影过去，加进 Qwen3-0.6B 的 KV 里。在 MMLU-Redux 上，Qwen 单独答是 35.53 分，Llama 写成文字传给它是 43.32，直接传 KV 是 44.42。

KV 传过去的东西比文字多，这正是这期想要的。代价在另一头：**每一对模型都得现训一个融合器**，这一对就花了约 54 个 GPU 小时；两边分词器不一样，还得先把 token 解回字符串再重新切。模型一多，两两配对的数量涨得很快，论文自己也把这点列进了局限。

KV 也能跨模型传，但得给每一对模型现训一个翻译器。文字不用，它是所有模型和人事先共同约好的那张表。

**第二，人读不了。**

开篇说过，防跑偏靠的是一个不会被压缩的人在旁边看方向。我看不懂汇编，但我读得懂交接单：它写“主线是找热点提速”，我一眼就能看出偏了，改一句就行。

KV 记忆偏了，我看不出来，也改不了。那是几十万个浮点数，没有哪一格写着“主线”。307 期（ https://mp.weixin.qq.com/s/otABJNNe7tdCJGUcv2AfAA ）讲过一个说法：**不用很懂，但不能不知道。** 保安大爷不懂业主家里的事，但知道小区里什么不该出现。KV 记忆把保安亭也收走了，因为人连“正常长什么样”都看不见。

人读不了的压缩，其实已经上线了。OpenAI 的 Responses API（Codex 也在用）有个压缩接口，官方文档这样描述它返回的压缩项：“It is opaque and not intended to be human-interpretable.” 不透明，也不打算让人读。

里面装的是什么，官方没说。有人统计了一千多次 Codex 压缩，让模型复述自己的上下文，说那是一份一千字左右、写给下一个接班实例的第一人称交接笔记，只是加了密。这是模型的自述，统计的人也承认里面可能有编出来的细节。如果属实，它就两头的坏处都占了：人读不了，模型那一侧也照样经过了一次坍缩。

**第三，得训练，还得接得上。**

上面那几篇，凡是压缩的，都得有一方被训练：要么模型学着读（Gist 改掩码微调，AutoCompressor、ICAE 训编码器，MLA 干脆从预训练就这么练），要么那包 KV 去迁就模型（Prefix-Tuning、Cartridges）。一个现成的模型，你直接塞给它一包没这样训过的压缩 KV，它不认。

不压缩、原样拼接的 KV 倒是有不用训练的办法，但也有自己的麻烦。

位置没有看上去那么麻烦。现在的模型大多用 旋转位置编码（Rotary Position Embedding，RoPE），它把 token 的位置转进 K 向量里。好在注意力分数只看两个 token 的相对位置，存下来的 K 再补转一个角度，就能挪到新位置上（CacheBlend 的附录证明过这点；StreamingLLM 的办法是存转之前的 K，每次重新转）。DeepSeek-V2 专门讲过的 RoPE 冲突是另一件事：低秩压缩要把一个矩阵合并到查询那一侧去，RoPE 夹在中间合并不了，所以 MLA 把位置单独拎出来，用那额外的 64 维带着。

真正麻烦的是关系。一段 KV 单独算的时候，不知道前面会接什么，它和别的内容之间的那部分注意力是缺的。CacheBlend（2024）的办法是每层挑出偏差最大的一小部分 token 重算，重算不到 15% 就能补回同样的质量，不用训练。

旧会话压缩出来的 KV 接到新会话前面，缺的也是这个：它和新内容之间，谁轻谁重。这和第一章文字摘要丢掉的，是同一类东西。

────────────────────

💡 这三个问题，其实是同一件事的三面

私有、不可读、要训练，说到底都因为 KV 属于模型内部的坐标系。

文字之所以公共、可读、不用训练，恰恰因为它经过了输出层的坍缩，被投影到了人和所有模型共用的那张词表上。C2C 能让两个模型绕过这张表，但要现修一座只通这两家的桥。**文字丢方向的原因，和它能被所有人读懂的原因，是同一个。**

反过来，KV 能留住没说出口的倾向，也是因为它没被投影到那张公共词表上。好处和坏处连在一起，没法只要一半。

────────────────────

既然只能要一整个，那就别让它单独上岗。

━━━━━━━━━━━━━━━━━━━━

◆ 收尾：日记和睡眠

━━━━━━━━━━━━━━━━━━━━

所以我现在觉得，合理的形态不是二选一，而是两层并存。

**文字一层，像日记。** 可以审计，可以跨模型交接，人能读、能改。事实、数字、证伪过的路、为什么证伪，写在这里。它会丢坡度，但坡度丢了，人能看出来、补一句。我那份从 593KB 压到 22KB 的日志，就是这一层。

**压缩 KV 一层，像睡眠。** 就是第二章那一步：把白天攒下的一整串 KV，折成一个 RNN 式的状态。只给同一个模型自己用，存那些说不清的倾向：哪里是重点、哪里已经走过、我在意什么。人读不了，也不需要读，就像人不会去读自己睡觉时大脑里重放了什么。换模型的时候它作废，日记还在。

“睡眠”这个词有人用过。Letta 2025 年的 sleep-time compute，让 agent 在空闲时离线整理上下文，但它睡醒写下来的还是文字：重写过的上下文和记忆块。离线写成 KV 的，第三章的 Cartridges 其实就是这个样子，模型自己跟自己对话、把一份语料训进一包 KV，只是它读的是文档，不是自己白天的对话记录。

两层之间的分工也清楚：**日记负责对，睡眠负责顺。** 睡眠那层偏了，人从 AI 的行为上看出来，拿日记纠正它。

────────────────────

我一直有个说法：**一切都是上下文，只是刷新周期不同。** KV cache 是分钟级的，服务器上 5 分钟不用就丢；会话里的记忆是会话级的，窗口关了就没了；权重是训练级的，几个月才动一次。

压缩 KV 做成的记忆，正好填在会话和权重之间：比一次会话活得久，又不用动权重。

上文 303 期查完一圈，收在一句话上：筛选那一侧出了一堆办法，写入那一侧基本还是同一招——另开一小块参数，把东西灌进去。压缩 KV 换了一个写入的地方。Cartridges 那包 KV 严格说也是训出来的参数，但它不在模型里面，插在缓存的位置上：**一段记忆一包，模型权重一个不动。** 各包互不干扰，不怕学新忘旧，删掉一包就是真删掉。

代价是它只认一套权重，人也看不懂。所以它替不了日记，只能和日记一起用。

我的项目还在跑，两个 AI 还在轮班。眼下能做的，还是把那份 22KB 的日志写准：少写名词，多写坡度——哪条线死了、为什么死、现在往哪走。
