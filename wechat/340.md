【REA】工具是真的，“AI 学会破解任意软件”是吹牛

━━━━━━━━━━━━━━━━━━━━

◆ 第一章：装完以后，AI 脑子里多了什么

━━━━━━━━━━━━━━━━━━━━

最近一个叫 REA 的项目很火。它的全名是 Reverse Engineer Anything，直译过来是“逆向一切”。到了转发链里，这句话渐渐变成：给 AI 装上这个技能，它就能破解任意软件。

写这篇稿子时，GitHub 上的星数刚从 22.7 万跳到 22.8 万，README 里的庆祝语却还停在 20 万。连庆祝文案都追不上星数增长。

也有另一种说法：这东西不就是几句提示词吗，纯属包装。

我把 GitHub 当前内容和 npm `6.4.0` 发布包里的提示词、工具定义、安装逻辑和官方案例读了一遍。两种说法都不准。

**它不是给模型下载了一份“逆向能力”，也不只是一个提示词包。它是一套连接现有逆向工具的 MCP 服务，再配一套教智能体怎样调查的说明书。**

先看安装命令：

```bash
npx rea-agents setup
```

完整安装主要做两件事：

1.给 Claude Code、Codex、Gemini CLI 等智能体注册一个本地 MCP（Model Context Protocol，模型上下文协议）服务器，让它们能调用 REA 的工具。
2.写入一份 `SKILL.md` 和六份参考文档，告诉智能体遇到不同目标时该选哪条调查路线。

这里有个容易被传播省略的区别：**只安装 skill（技能说明），得到的只有文字说明，不会多出任何分析工具。** 注册 MCP 之后，智能体才真正拿到工具入口。

模型本身没有变化。没有微调，没有新增权重，也没有一份“软件破解知识”被灌进去。原来负责思考的是哪个模型，装完以后还是那个模型。

所谓“AI 看了 REA 就会逆向”，准确说法是：**AI 在一次会话里读到了逆向工作说明，并且能调用逆向工具。** “会调用”和“学会”，中间还差得很远。

◆ 第二章：提示词没有咒语，只有一套调查流程

━━━━━━━━━━━━━━━━━━━━

REA 的提示词倒是很值得一读，因为它确实不是一句“你是逆向大师，请破解这个软件”。

主说明文件先教智能体按目标分流：原生二进制、JavaScript/Electron 应用、安卓安装包、.NET 程序集、网页、固件，各自走不同工具。接着是工作方式：先看概览，再按问题追细节；大结果分页读取；静态证据回答不了时，再考虑运行目标；结束前核对最初的问题清单。

发布包里还有六个引导模板：

- `investigate_feature`：追踪一个功能怎样实现；
- `compare_application_versions`：比较两个应用版本；
- `verify_reconstruction`：验证重写出来的实现；
- `trace_crash`：定位一次崩溃；
- `audit_residual_unknowns`：复查仍未解决的问题；
- `prepare_bounded_process_capture`：设计一次有边界的进程观察。

这些模板共享四条纪律：观察要来自工具返回的证据；推断要标成推断，并保留其他解释；覆盖不完整和证据冲突要明说；没搜到不能写成不存在。

**这套提示词的价值是防止智能体一路瞎编，不是给它传授某种秘密逆向算法。** 里面没有“自动绕过授权”“统一处理混淆”“一键恢复源码”之类的咒语。

它甚至特意提醒：普通源码仓库的分析不要动用 REA，直接用常规代码工具。这个项目自己的说明，都比热帖里的说法克制。

◆ 第三章：170 个工具，真正干活的是谁

━━━━━━━━━━━━━━━━━━━━

当前 `SKILL.md` 的元数据标称有 **170 个工具**。这不是说每个环境装完都能立刻使用 170 个功能，实际可用项取决于目标类型、本机系统和外部分析引擎。

把几类主要工具按“REA 返回什么”和“底层谁在做”摆在一起，结构就清楚了：

| 目标 | REA 提供的结果 | 底层主要依赖 |
| :--- | :--- | :--- |
| 原生二进制 | 伪代码、汇编、字符串、交叉引用、调用者与调用路径 | Ghidra、Hopper、IDA；离线路线也可用 objdump、Rizin |
| JavaScript / Electron | 模块、导入关系、源码映射、路由、IPC（Inter-Process Communication，进程间通信）边界 | REA 自己的 TypeScript 分析代码、Babel 解析器等，不依赖原生反编译器 |
| .NET / 安卓 | CIL（Common Intermediate Language，通用中间语言）指令、类与方法、引用关系、设备与文件操作 | REA 的静态解析，以及 JADX、JDK（Java Development Kit，Java 开发工具包）、ADB（Android Debug Bridge，安卓调试桥）、JEB 等外部工具 |
| 网页与运行行为 | 页面结构、脚本、网络观察、进程输出、截图与运行比较 | Chrome 系浏览器、Playwright、HAR（HTTP Archive，网页请求存档）解析和本地进程捕获 |
| 其他格式 | 固件分区、WebAssembly、EVM（Ethereum Virtual Machine，以太坊虚拟机）字节码、ELF（Executable and Linkable Format，可执行与可链接格式）布局、Windows 资源、SQLite 数据库、数据包等 | Binwalk、Unblob、WABT（WebAssembly Binary Toolkit，WebAssembly 二进制工具包）、TShark 等，按目标各自配置 |

所以，“REA 只是提示词”这个说法也不对。**它确实有大量 TypeScript 实现，尤其在 JavaScript/Electron 静态分析、应用包清点、版本比较和证据管理方面，不是拿几句说明糊一个空壳。**

但另一面同样清楚：**深度原生分析仍然靠 Ghidra、Hopper、IDA 这些已有工具。** REA 没有发明一种新的反编译器，更没有发明一种能读懂所有机器码的新模型。

它做的是把工具包装成统一的 MCP 接口，让智能体不用自己临时写一堆命令行胶水，就能完成“打开目标、搜字符串、看函数、查引用、追调用者、读常量、比较结果”这套动作。

此外还有一层 Evidence（证据记录）系统：工具结果带证据编号、覆盖范围和限制，后续比较与验证可以引用同一份记录。对一场长调查来说，这比单纯把一大段反编译文本塞给模型更有用。

◆ 第四章：官方案例里，汇编照样得读

━━━━━━━━━━━━━━━━━━━━

判断 REA 能做什么，与其看名字，不如看官方拿出来的案例。

第一个案例是恢复 DX-Ball 的声音声像计算。反编译器最初给出的伪代码只有 `FUN_00406400(void)` 和一次 `__ftol()` 调用，连函数输入都没有恢复出来。

接下来发生了什么？智能体仍然去读了原始汇编，从 `[EBP+8]` 找到整数输入；再追调用者，弄清这个数是砖块的横坐标；再读浮点常量，最后手写出 C 函数。

写完还不算完。官方案例用 **3,205 组行为用例**对照原函数，又用固定编译器验证重写结果的 **63 个编译字节**。

这份案例恰恰说明：**伪代码只是调查入口，语义要从汇编、调用关系和常量里恢复，结论还要经过行为与字节验证。** REA 把这几样证据递到智能体手边，但没有替它跳过任何一步。

第二个案例是一个 CTF（Capture The Flag，夺旗赛）题目。目标是约 15 KB 的 stripped ELF，也就是去掉符号的 Linux 可执行文件。智能体从提示字符串找到检查函数，读出 26 组掩码与目标值，把检查写成方程，再用 Z3 求解，最后拿原程序验证答案。

这是一个完整而且清楚的小实验，但题目规模、预设字母表和明确验证方式都摆在那里。官方案例展示的是**边界清楚的小函数、小挑战和 Electron 功能追踪**，不是“随便扔一个大型商业软件进去，出来一份可编译源码”。

Notion 的 Electron 案例也一样。REA 能定位页面暴露的接口和 IPC 调用位置，但剪贴板功能怎样穿过 preload（预加载脚本）包装、IPC 通道和主进程接收器，仍由智能体继续阅读代码并接起来。

这些案例真正展示的不是“一键破解”，而是**工具能把相关证据更快地送到调查者面前，调查者再用这些证据完成推理。**

◆ 第五章：有用和吹牛，边界就在这里

━━━━━━━━━━━━━━━━━━━━

到这里，可以给几句流行说法分别下判断了：

| 说法 | 判断 | 原因 |
| :--- | :--- | :--- |
| REA 能让智能体直接调用一批逆向工具 | **成立** | MCP 工具与命令行接口真实存在，覆盖的目标类型也很多 |
| REA 只是几句提示词 | **不成立** | 它有实际的解析、追踪、比较、运行时观察和证据管理代码 |
| 装上 REA，模型就学会了逆向 | **不成立** | 安装过程不训练模型，变化的是可用工具和调查说明 |
| REA 能破解任意软件 | **不成立** | 原生分析仍受反编译器、目标混淆程度、运行环境和验证条件限制，官方案例也都是具体的小任务 |
| REA 对逆向调查没有价值 | **也不成立** | 它能减少工具接入和结果整理工作，尤其适合智能体持续追查一个功能 |

项目自己的免责声明还明确写着：不支持绕过 DRM（Digital Rights Management，数字版权管理）、授权检查、反作弊和其他技术保护措施。热帖里的“破解任意软件”，连项目官方都没有这样承诺。

那我们自己平时读汇编，需要 REA 吗？

**不需要。至少不是非有不可。**

我们在 297 期（ https://mp.weixin.qq.com/s/Eq2IDP5QvFPGToQuCsBLRw ）已经直接从 DLL（Dynamic-Link Library，动态链接库）里恢复网络结构、对照函数与权重；301 期（ https://mp.weixin.qq.com/s/YFF4EXu5XpD_FR-jdCGSsw ）又亲历了一次“以为已经跑通，实际合成命令根本没提交给显卡”的翻车。

前一篇说明，常规反汇编、脚本和逐块对照本来就能做深入的静态分析；后一篇说明，**工具给出结果和结果确实为真，中间还隔着运行时验证。** 这两个环节都不是装上 REA 就自动解决的。

对我们来说，REA 不能代替阅读显卡汇编，不能替我们弄清数值截断、纹理采样和编译器差异，也不能保证智能体不编造。继续使用现有的反汇编工具、脚本和逐值验证流程，不会少了哪块“AI 逆向能力”。

它比较适合另一种情况：手头已有 Ghidra、Hopper 或 IDA，希望智能体能自己连续查询函数、交叉引用和调用图，不想再写一套连接脚本；或者面对 Electron 应用，想快速追踪一个功能穿过哪些模块；再或者调查很长，需要一套现成的证据编号和未知项记录。

**所以最终答案是：作为逆向工具的统一接口和调查工作台，REA 有用；作为“AI 从此学会破解任意软件”的故事，它是吹牛。**

有用的是工具链，不是魔法。真正费劲的阅读、判断和验证，一样也没消失。
